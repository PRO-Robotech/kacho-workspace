# class-guard — слой активации скилов на каждой правке

Хук `PostToolUse` на `Write`/`Edit`/`MultiEdit`. Прогоняет по **только что записанному
файлу** предикаты тех классов из скилов `code-authoring`, `gate-authoring`,
`measurement-discipline`, `verdict-and-landing`, чей вердикт зависит **только от
содержимого этого файла**.

Границу провёл так: предикат однофайловый, если вердикт не требует резолва символа в
другом файле, прогона, суждения о смысле или знания намерения. Статическую предпосылку
(лежит ли в дереве `.golangci.yml`) гейт вправе прочесть один раз, но обязан её
**объявить** и громко падать, когда она не резолвится.

**Хук видит больше, чем содержимое:** `PostToolUse` получает и **имя инструмента**.
`Edit` против `Write` — сигнал сам по себе, и один класс (G1, правка применённой
миграции) ловится только им, не читая файл вовсе.

## Что это НЕ делает

Не блокирует запись (правка уже произошла). Не выносит вердикт о готовности. Не
заменяет ревью. **Покрывает 32 класса из 136 — 24 %.** Остальные три четверти требуют
модуля, прогона, суждения или намерения и в момент записи файла ненаблюдаемы; хук о
них не заявляет ничего.

## Устройство

| файл | что |
|---|---|
| `../class-guard.sh` | вход хука; громко падает, когда нет `python3` или самого гейта |
| `guard.py` | диспетчер по роли файла, перепись, журнал, послабления |
| `text_predicates.py` | классы B (shell/Makefile), C (newman), D (YAML), E (markdown), F (TypeScript) |
| `goast/` | классы A (Go) — **разбор дерева**, не текст |
| `allow.json` | послабления с предикатом снятия |
| `prove.sh` | доказательство инъекцией, в обе стороны, по каждому предикату |

Двоичный файл `goast` собирается лениво и кэшируется **вне дерева** —
`${XDG_CACHE_HOME:-~/.cache}/kacho-class-guard/<sha исходников>/`, поэтому
`sync-tooling.sh` его не разносит по репо и он не попадает ни в один индекс.

## Инъекция

```sh
bash .claude/hooks/class-guard/prove.sh     # 65 пар, код 0 — все сошлись
```

Каждая пара: **(+)** дефект → гейт краснеет и **называет координату**; **(−)** законная
конструкция той же формы → гейт **молчит**. Входы обеих сторон взяты из дерева (столбец
«близнец»), а не выдуманы: выдуманный вход доказывает лишь, что регулярное выражение
совпадает само с собой.

Харнесс различает **три** категории исхода: сошлось · разошлось · **гейт сломан**.
Последняя не вычитается из первых двух — первая редакция читала упавший гейт как
«дефект прошёл», то есть сливала сломанный инструмент с отрицательным ответом.

Проверено и на настоящих файлах дерева, с побайтово подтверждённым откатом:
`gateway/internal/middleware/request_id.go` (A4 — дефект дописан **рядом с живым
законным близнецом** в том же файле: гейт назвал строку 94 и промолчал про строку 22)
и `sync-tooling.sh` (B2+B3).

## Что гейт обязан делать сам — и как это проверить

- **Читать исполняемую часть.** Go — `go/ast`. Shell/Python/YAML — после снятия `#` и
  тел heredoc. TypeScript — после снятия `/* */`, `//` и строковых литералов.
  Markdown — без огороженных блоков и инлайн-кода.
  *Зачем:* первая выборка текстового предиката по newman дала **3 комментария из 5**
  попаданий, причём комментарии обсуждали **уже починенный** дефект; текстовый предикат
  на `TODO` дал бы **25 ложных из 25**.
- **Печатать перепись.** Каждый вывод несёт: предикатов прогнано из скольких, узлов или
  строк осмотрено, кандидатов формы по классам, миллисекунды. «Ноль находок» отличимо
  от «ноль прочитанного».
- **Падать громко на своей поломке.** Нет `python3` → `CLASS-GUARD СЛОМАН`. Нет `go` →
  то же, с явным «это НАСТРОЙКА, а не сбой». Вход не разобрался → отдельная строка
  «ВХОД НЕ РАЗОБРАЛСЯ (предикаты не прогнаны)» и **перепись показывает 0 прогнанных**.
  Молчаливого выхода с нулём нет ни в одной ветке.
- **Не блокировать.** Код 2 — «есть что сказать», а не «отменить правку».

## Послабления

`allow.json`. Запись обязана нести `path`, `class`, `why` и `expires_when`.

**Послабление живёт, пока у него есть предмет.** Когда предикат на этом файле перестаёт
срабатывать, гейт возвращает находку класса `ALLOW` и требует снять запись — иначе она
превращается в ложное утверждение о дереве, которое следующий читатель унаследует как
слепую зону. Предикат снятия **внешний** по отношению к записи: сработал ли предикат
сейчас, а не то, что записал автор.

Проверено в обе стороны: с предметом — C1 подавлен; предмет убран — `[ALLOW] послабление
пережило свой предмет`.

## Счётчик срабатываний

Журнал `.claude/class-guard.log` (JSONL) и `.claude/class-guard.stats.json` — оба
git-ignored. После 200 прогонов при нуле находок гейт сам говорит: «прогнан N раз и не
сработал НИ РАЗУ; ноль срабатываний — это подозрение, а не заслуга».

При разносе оснастки в репо (`sync-tooling.sh` зеркалит `hooks/` целиком) добавь в
`.gitignore` репо две строки: `.claude/class-guard.log`, `.claude/class-guard.stats.json`.

## Как добавить предикат

1. **Сначала измерь по дереву**: сколько кандидатов формы, сколько из них законны.
   Если законных больше нескольких процентов — нужен различитель, а не предикат.
2. **Построй обоих близнецов из дерева.** Нет живого отрицательного — предикат не идёт:
   так были отклонены `oneOf`, смешивающий успех и отказ (131 → 23, из первых 12
   не менее 4 ложных; различитель — проза имени шага), и `time.Sleep` как синхронизация
   в тесте (81 файл против 23 с `require.Eventually`; различитель — поток данных).
3. **Отметь кандидатов** через `note(<класс>)` в точке совпадения формы, **до**
   различителя. Без этого ноль предиката неотличим от «ничего не читал».
4. **Допиши пару в `prove.sh`** и прогони: обе стороны обязаны сойтись.
5. **Раздел скила — по имени**, не по номеру строки (иначе E1 сработает на тебе же).

Новый класс попадает сюда только через петлю накопления — см. `code-authoring`
§«Механизм накопления опыта».
