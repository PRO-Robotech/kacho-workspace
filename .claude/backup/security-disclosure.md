## Доводы строк «Предмет признака — записи ревью» (ветка `rules/disclosure-scope`, 2026-09-19; в корпус строками — #790, 2026-09-22)

Ветка писала эти нормы прозой до перевода корпуса в строковую форму (#707). Нормы стали
строками `disc-review-records-subject` … `disc-no-assembly-detector`; здесь — почему и чем
мерилось. Числа — замеры ветки на названных ревизиях; повторно они не мерились.

- **Почему поимённо, а не однажды на каталог.** Имя записи — SHA-256 приёмки или замысла,
  о котором вынесена запись, а не тела: правка тела имя не меняет. Замер на `cf15f29d`:
  расхождений имени и поля `sha256` — 0 из 20. Отсюда «этот файл уже проверяли» ничего не
  говорит о том, что в нём сейчас. Основание то же, по которому вердикт привязан к
  отпечатку, а не к документу.
- **Почему фильтр «жив ли механизм» — разделитель, а не послабление.** Если механизм снят,
  следствия не существует. Замер дня объявления: из восьми записей одного захода сборку
  несли четыре, и граница прошла ровно по этому вопросу. Единица счёта — файл записи.
- **Почему все вхождения.** Разбор этого жанра — перекрёстные ссылки на одно утверждение.
  Замер на четырёх записях того же захода: сборка повторялась в документе 2–7 раз.
- **Почему каталог пакетов.** Под каталогом приёмок лежала одна запись из восьми, семь —
  под `docs/changes/<change-id>/reviews/**`. Норма на одну восьмую объёма не закрывает
  ничего. Отслеживаемых записей по обеим формам тогда было: 22 в воркспейсе `556d0502`,
  51 в клоне `kaname` на `dd66b5be`; под пакетами — ноль, то есть предмет расширен раньше
  первой записи в нём.
- **Почему форма пути несущая.** Подстановка в пути git сопоставляется со всем путём.
  Форма `docs/changes/*/reviews/` со слэшем даёт ноль; на заходе 2026-09-19 она нашла одну
  запись из восьми. Перемер 2026-09-22 (#790): `git ls-files -- 'docs/changes/*/reviews/*'`
  даёт 6, та же форма со слэшем — 0.
- **Почему целевая форма переноса — класс, а не наблюдение.** Признак дважды подряд
  объявлялся пройденным тем же агентом, и самоотчёт разошёлся с замером во всех четырёх
  правленых файлах. В одном из них после «полной» правки целевая форма стояла 12
  вхождениями, прямое утверждение о живом дереве — 10. Обращение однозначно: читателю не
  из чего выбирать. Отсюда `disc-editor-is-not-judge`.
- **Почему гейта нет.** Лексиконный детектор мерился контролем в обе стороны
  (2026-08-02). На 10 размеченных файлах он пометил 12 блоков, из них 3 ложных, пропустил
  5 настоящих сборок и не отличал переписанное от исходного. «5 из 10» было бы подменой
  единицы: 10 — это файлы, а не сборки. Хук `class-guard` читает файл целиком, но граница
  однофайлового предиката проведена там, где вердикт требует суждения о смысле. «Назван
  факт переноса» против «стоит целевая форма» — именно такое суждение.
- **Почему доставка судится по виду.** Предзагрузку сверяет `check-04` по 4-й колонке
  `MANIFEST.md`; строку триггера ищет `grep -l 'Skill rule-security-disclosure'`. Поиск
  одного имени `rule-security-disclosure` сливает оба вида. На ветке он давал 23 при 8
  предзагрузках и 15 триггерах. Перемер 2026-09-22 (#790): из 7 агентов, чьё тело называет
  путь записи ревью, правило не доходило до 3 — `proto-api-reviewer`,
  `db-architect-reviewer`, `system-design-reviewer`. Строку триггера они получили тем же
  изменением; после него — 0 из 7 по обоим предикатам (строка
  `disc-record-producer-holds-rule` и сверка предзагрузки и триггера по отдельности).

### Сняты решением владельца 2026-09-22 («через github mr merge так же не должно быть сквоша»)

- **disc-squash-says-it-is-squashed** — прежняя редакция: «тело squash-коммита обязано
  нести „схлопнуто из <ветка>, исходные коммиты <sha>; ветка удалена“ — правило и для
  cherry-pick». Схлопывания больше нет нигде, место заняла строка
  `disc-merge-publishes-every-message`. Отсюда и главный довод: при схлопывании сообщения
  коммитов ветки в `main` не попадали, а при слиянии каждое становится частью его истории.
- **disc-rewrite-history-needs-owner** — прежняя редакция заканчивалась «штатно — merge
  --squash + удаление ветки». Теперь в строке названо исключение перехода: сообщения
  ветки, открытой до решения, переписываются до вливания.
