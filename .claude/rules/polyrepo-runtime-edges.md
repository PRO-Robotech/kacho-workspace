# Топология: межсервисные рёбра рантайма

Часть правила `.claude/rules/polyrepo.md` (базовый файл; там §«Топология», §«Build-граф» и
§«Порядок работы для кросс-доменной фичи»). Предмет части — **регистр рёбер рантайма между
доменами**: кто из наших сервисов зовёт кого по gRPC на пути запроса, направления вызовов и
запрет циклов. Ацикличность машинного гейта не имеет — держится обзором `system-design-reviewer`;
всякое новое ребро между доменами фиксируется здесь. Грузится, когда полоса заводит или трогает
ребро между доменами.

## Runtime cross-domain edges (gRPC service→service; НЕ build-зависимость)

> Имена `kacho-<svc>` ниже — **домены**, а не репозитории: `vpc compute storage nlb registry
> geo` — каталоги `services/<svc>/` в `kacho`, `kacho-iam` — служба доступа в `kaname`.
> Содержание раздела от раскладки не зависит: рёбра рантайма, направления и запрет циклов
> остаются нормой — сервисы общаются по API и не импортируют друг друга по коду.

> [!note] Здесь стояли два ребра оператора сети — сняты решением владельца 2026-08-09
> Держались «как контракт на случай появления компонента» с честной оговоркой, что репозиторий
> не резолвится, а в дереве ноль файлов по этому имени. Оговорка не спасала: бронь под
> несуществующий компонент держалась **не только здесь** — SPIFFE-имя стояло в кругах доверенных
> отправителей четырёх профилей и двух чартов, а тест круга этих записей **требовал**. Проверка
> безопасности защищала не фактического отправителя, а бронь под будущее. Круг, объявленный шире
> фактического, разрешает говорить за пользователя предъявителю сертификата, которого мы не
> выпускаем; `security.md` требует пинить его по **фактическим** отправителям из графа рёбер.
>
> Записи сняты из шести мест, тест круга **перевёрнут**: падает на любой записи, которой не
> соответствует ни один чарт дерева. Появится компонент со своим чартом — сертификат
> отрендерится и проверка пройдёт сама; послабление истекает от появления предмета, а не от
> чьей-то памяти.
>
> **Что осталось и почему это отдельный предмет:** служебная учётка оператора и её права заведены
> применёнными миграциями, которые править нельзя (ban #5) — снятие идёт новой миграцией, своим
> изменением. Здесь снят только круг отправителей: «кто вправе говорить за пользователя» и «что
> этой учётке разрешено» — разные вопросы.

- `kacho-vpc → kacho-geo` — валидация `zone_id` Subnet/AddressPool (`geo.v1.ZoneService.Get`); Geography — домен geo (KAC-эпик #82). Заменяет прежнее ложное ребро `vpc→compute (zone)`.
- `kacho-compute → kacho-geo` — валидация `Instance.zone_id` (`geo.v1.ZoneService.Get`). Geography больше не «своя» таблица compute — peer-валидация через geo-client (KAC-эпик #82).
- `kacho-nlb → kacho-geo` — валидация `region_id` LoadBalancer/TargetGroup (`geo.v1.RegionService.Get`, sync precheck на request-path, кэша нет). Заменяет прежнее ложное ребро `nlb→compute (region)`.
- `kacho-registry → kacho-geo` (REG-1 F4) — валидация `Namespace.region_id` (**required** на Create, `placement_type` всегда `REGIONAL`, оба immutable) через `geo.v1.RegionService.Get`, sync peer-validate на request-path, per-call 5s deadline + `retry.OnUnavailable`, fail-closed `UNAVAILABLE`. Namespace — regional-anycast (zone-независим). geo — leaf (не зовёт registry обратно) → ацикличность holds. Client `services/registry/internal/clients/geo`, wired в `serve.go` (`GeoGRPCAddr`/`GeoMTLS`).
- `kacho-geo → kacho-iam` — `InternalIAMService.Check` (authz-gate на каждом RPC обоих листенеров; read-RPC `system_viewer`-floor, admin-CRUD `system_admin`). geo — leaf-консумер только iam (как любой сервис).
- `kacho-compute → kacho-vpc` — валидация NIC-spec (Subnet/SecurityGroup) + IPAM-аллокация Address.
- `kacho-compute → kacho-vpc` (subnet-placement, 2026-07-25) — `SubnetService.Get` на **request-path**
  `Instance.Create`: зона подсети каждого NIC обязана совпадать с зоной инстанса (REGIONAL/anycast-подсеть
  из зональной проверки исключена, проверяется регионально). Читается **под identity вызывающего**,
  per-call deadline, fail-closed. Без резолва подсети у владельца зональная когерентность интерфейса ничем
  не обеспечена (`data-integrity.md` §Placement-coherence). Переиспользует объявленную, но мёртвую группу
  mTLS-переменных чарта.
- `kacho-nlb → kacho-geo` (zone→region для instance-таргетов, 2026-07-25) — `ZoneService.Get` через порт
  `ZoneRegionClient`. Заменяет **удалённую** строковую деривацию региона из имени зоны (`regionFromZone`).
  Для nic/ip_ref-таргетов регион берётся из авторитетного `Subnet.RegionID` (peer-ответ vpc), без вызова geo.
- `kacho-storage → kacho-geo` (zone→region для Volume из Image, 2026-07-25) — `RegionOfZone` на request-path:
  регион зоны тома обязан совпадать с регионом образа; сверка **внутри insert-CAS** (`AND i.region_id = $12`),
  0 строк → байт-идентичный hide-existence `Image <id> not found`. Реализует заявление миграции 0007,
  которого в коде не было.
- `kacho-compute → kacho-storage` — **несущее ребро раскола блочного хранения** (не задокументировано
  до 2026-07-25, хотя живо в коде: `services/compute/internal/clients/storage_client.go`, провязано в
  composition root). Резолв boot-источника (`storage.image`/`storage.snapshot`/`storage.volume`) +
  attach/detach тома. **Attach инициируется compute, payload самоописывающийся** (`instance_id`/
  `instance_zone_id`/`project_id`/`instance_name`) → storage валидирует **свою** строку одним CAS-INSERT и
  **никогда не зовёт compute обратно**; проверено: ноль импортов `computev1` в `services/storage`. Таблица
  привязки `volume_attachments` живёт **у владельца-storage**; compute-шная `attached_disks` дропнута. На
  Instance — read-only зеркало с мягкой деградацией при dangling-ref.
- `kacho-nlb → kacho-compute` — резолв Instance-таргетов (`compute.v1.InstanceService.Get`); **только** для Instance (НЕ для geography — region-валидация теперь `nlb→geo`).
- `* → kacho-iam` — `ProjectService.Get` (existence + account lookup, leaf-owner) + `InternalIAMService.Check` (authz-gate).
- `kacho-vpc → kacho-iam` (fgaproxy, SEC-A) — `InternalIAMService.RegisterResource`/`UnregisterResource`: запись/снятие
  owner-hierarchy-tuple в FGA через IAM (модули не ходят в FGA напрямую). Internal-only :9091, идемпотентно, at-least-once
  через transactional-outbox (SEC-D). Least-priv: ReBAC `fga_writer` @ `iam_fgaproxy:system`.
- `kacho-compute → kacho-iam` (fgaproxy, SEC-A) — то же ребро для owner-tuple compute-ресурсов:
  internal-only :9091, идемпотентно, least-priv `fga_writer` @ `iam_fgaproxy:system`.
- `kacho-storage → kacho-iam` (fgaproxy, SEC-D / CS-1 GAP-D) — то же ребро для owner-tuple storage-ресурсов
  (`storage_volume:<id>` / `storage_snapshot:<id>`). Нужен, чтобы gateway scope_extractor'ы
  `{storage_volume,volume_id}`/`{storage_snapshot,snapshot_id}` резолвили target→project (анти-BOLA).
  Internal-only :9091, идемпотентно, at-least-once через transactional-outbox
  (`kacho_storage.fga_register_outbox`) + register-drainer, least-priv `fga_writer` @ `iam_fgaproxy:system`.
  Одностороннее (storage не зовётся обратно).
- `kacho-registry → kacho-iam` (jwks-fetch) — **HTTPS GET публичного JWKS** с cluster-internal iam-эндпоинта
  (`:9097` `GET /.well-known/jwks.json`), **sync** на request-path (data-plane верифицирует подпись
  docker-Bearer'а), **fail-closed** (iam недоступен/5xx и в кэше нет пригодного ключа → verify reject →
  docker-клиенту `401 invalid_token`; **никогда** allow), **server-TLS** (one-way) с trust'ом internal-CA.
  **Замещает** прежний прямой fetch публичного JWKS Hydra: iam — short-TTL кэширующий reverse-proxy
  Hydra-JWKS (байт-в-байт зеркало; **Hydra остаётся issuer'ом/подписантом**, iam ключи не чеканит,
  issuer-pin registry остаётся на Hydra). Ацикличность holds: iam **никогда** не зовёт registry.
  Прочие рёбра `kacho-registry → kacho-iam`: `InternalIAMService.Check`/fgaproxy (:9091) +
  `ProjectService.Get` (:9090). Детали — `edges/registry-to-iam-jwks-fetch.md`.

  > [!important] Предмет этого ребра РАСШИРЕН дважды фазой F1 (задача продукта #897)
  > Ребро остаётся **одним** и направление не меняет; расширяется то, ЧТО по нему спрашивают.
  >
  > 1. **Набор ключей перестал быть только чужим зеркалом.** Публикатор отдаёт записи ПО
  >    ИЗДАТЕЛЯМ: наша — проекция ключницы iam, запись зеркала прежнего провайдера живёт до
  >    последней фазы отказа от внешнего OAuth-сервера. У каждой записи СВОЙ объявленный
  >    путь; потребитель выбирает запись по объявленному издателю токена, а издатель без
  >    записи даёт отказ — **никогда** перебор записей и **никогда** путь, выведенный из
  >    самого издателя.
  > 2. **По тому же ребру читается ОТЗЫВ — на пути запроса.** Контроль, действующий на выдаче
  >    и не действующий на предъявлении, отзывом не является: он лишь не выдаёт нового, а
  >    предъявленное проходит до истечения срока, и это состояние не сходится само.
  >    Недоступность авторитета — **fail-closed**: неполученный ответ не есть «да».
  >
  > Ацикличность держится: iam по-прежнему не зовёт registry ни на одном из двух предметов.
  > Приёмка — `docs/specs/sub-phase-F1-token-signer-acceptance.md`, §2.2 и §2.8.

  > [!note] Фаза F2 (задача продукта #898) НОВОГО РЕБРА НЕ ЗАВОДИТ — и это надо сказать вслух
  > Фаза заводит **токен-эндпоинт платформы**: клиент предъявляет подписанное утверждение,
  > iam сверяет подпись открытым ключом из своего же реестра и выдаёт токен своим подписантом.
  > Поверхность выдачи новая, но **вызывающий у неё не сервис, а арендатор**: рёбра перечня
  > описывают, кто из НАШИХ зовёт кого из НАШИХ на пути запроса, и внешний клиент в них не
  > участвует.
  >
  > Изменился **слушатель** выдачи docker-токена: он несёт теперь второй вид предъявления.
  > Своего слушателя эндпоинт не заводит намеренно — вид выдачи задан формой запроса, а не
  > выбором порта, и второй слушатель об одном предмете разошёлся бы с первым в периметре и
  > посадке TLS.
  >
  > Ацикличность не затронута by construction: новых исходящих вызовов у iam не появилось
  > вовсе, а входящих — ни одного от наших сервисов. Приёмка —
  > `docs/specs/sub-phase-F2-client-assertion-acceptance.md`, §1.6 и §9.1 п. 11.

> [!note] СНЯТО ребро `kacho-{vpc,compute,storage,nlb,registry} → kacho-iam` (величины
> пределов, #656) — у контракта не осталось ПРОИЗВОДИТЕЛЯ (2026-09-13, задача продукта #2117)
> Модуль квотирования выпилен из службы доступа целиком: контракт авторитета величин, обе его
> службы и хранилище сняты в `kaname`. Платформа своего домена величин не завела — в её дереве
> контракты `proto/kacho/cloud/*/v1/quota_service.proto` объявляют арендаторское **чтение**
> учёта, а `proto/corelib/quota/v1/quota.proto` — **форму** ответа, и ни один не объявляет
> службы, назначающей величину.
>
> **Предмет снятия — ОТСУТСТВИЕ ПРОИЗВОДИТЕЛЯ, а не отключение потребителя**, и это разные
> вещи. Отключён потребитель был раньше и настройкой: все пять объявляют домен отсутствующим
> (`services/*/deploy/values.yaml`, `authority: "not-deployed"`; задача продукта #2596 закрыта).
> Снят же он теперь **кодом**, потому что клиент, оставшийся при живом объявлении, прибивал
> платформу к той версии модуля службы, где снятый символ ещё лежит: следующий же подъём пина
> ломает сборку **транзитивно**, у потребителя, который ни одного из путей не называл
> (`polyrepo.md` §«Копия между репозиториями ЗАПРЕЩЕНА», про атомарность переезда).
>
> **Развилку это НЕ решает, и решать её здесь нельзя.** Судьба авторитета величин ведётся
> задачей продукта **#2190** и владельцем не решена. Клиент снят потому, что мёртв в **обоих**
> её исходах: «квоты уходят из продукта» — спрашивать не у кого; «новый владелец в Kachō» — у
> него будет СВОЙ контракт, а не снятый контракт службы доступа. Порт резолва при этом
> **остался** — он переживает смерть своей реализации by construction, тем он и порт.
>
> **Что НЕ снято вместе с ребром, и это названо, чтобы не сняли следующим заходом:** счётчик у
> владельца ресурса, списывающий триггер, арендаторское чтение `/⟨домен⟩/v1/quotas`, посадка
> витрины и ручка объявления. Счётчик живёт рядом со своим ресурсом
> (`data-integrity.md` §«Счётчик потолка живёт РЯДОМ С РЕСУРСОМ»), и уходил **владелец
> величин**, а не учёт.
>
> **Ручка осталась с ОДНИМ действующим значением, и адрес теперь отвергается СТАРТОМ.** Поле,
> которое принимают и не читают, запрещено (`api-conventions.md` §«Принято-и-проигнорировано»);
> из трёх законных исходов выбран второй — отвергать явно, `pkg/quota/quotaedge`
> `ValidateAuthorityHasAProducer`. Молча вести себя «как при отсутствии» было нельзя: названное
> значение перестало бы значить названное.
>
> Предикат: `git grep -lE 'InternalLimitService' -- 'services/**' 'pkg/quota/**'` → **пусто**
> при непустом `git grep -l quota_authority.go -- 'services/*/internal/**'` → **5**. Ноль слева
> без парного замера справа означал бы «перестали читать», а не «перестали находить».
>
> **Остаток назван честно:** край (`gateway/internal/restmux`, `allowlist`, каталог разрешений,
> таблица маршрутов) проксирует снятую административную поверхность службы и **импортирует
> снятый символ** — предмет отдельный, и вместе с ним правятся сверщики каталога, чьи
> послабления его называют.

- `kacho-api-gateway → kacho-{vpc, compute, storage, nlb, registry}` (подписка на изменения
  ресурсов, эпик #1016) — **первые рёбра перечня, где вызывающий КРАЙ**. Server-stream
  `corelib.subscription.InternalSubscriptionService/Subscribe` на **внутреннем**
  слушателе владельца; край проецирует поток в браузер, **сам становясь потребителем
  метода**, а не публикуя его наружу.

  **Префикс `Internal` в имени службы — действующий дискриминатор ban #6**, а не украшение:
  метод с таким именем не попадает во внешний маршрутизатор **by construction**, и проверяется
  это обходом дескрипторов, а не обещанием. Называя ребро, имя пиши целиком — без префикса оно
  утверждает, что служба публичная.

  Пакет — `corelib.subscription`, **без сегмента версии**: форма подписки общая для всех
  доменов и ничьей доменной версии не наследует.

  **Соединение открывает ПОТРЕБИТЕЛЬ, владелец о нём не знает** — это предмет решения, а не
  деталь: направление потребитель→владелец сохраняет ацикличность, тогда как толчок от владельца
  замкнул бы граф (см. снятое ребро ниже).

  **Владельцев ШЕСТЬ, и шестой — в ДРУГОМ РЕПОЗИТОРИИ.** Прежняя редакция говорила «ПЯТЬ, а не
  семь — `geo` и `iam` журнала не служат»; вторая половина неверна с `kaname#69` (закрыта
  2026-09-13). Причина промаха названа, потому что она в самом предикате: он обходил
  `services/**` — корень платформы, — а служба доступа вынесена своим репозиторием, и её
  композиционный корень туда не попадает **by construction**. Ноль означал «не искали».

  ```sh
  git -C kacho  grep -l 'subscription.NewServer' origin/main -- 'services/**/*.go' ':!*_test.go' | wc -l
  git -C kaname grep -l 'subscription.NewServer' origin/main -- '*.go' ':!*_test.go' | wc -l
  ```

  Замер 2026-09-16: платформа **5** (`compute nlb registry storage vpc`, `kacho@45d1719fe8`) ·
  служба доступа **1** (`kaname@83ddd08a`). У `geo` журнала нет — это по-прежнему факт.

  Отличие шестого владельца — **ось вместимости**: его предметы вместимы аккаунтом, а не
  проектом, тогда как оболочка события несёт один авторизуемый якорь. Норма и её сегодняшняя
  цена — `.claude/rules/subscription.md` §«Что заводит САМ владелец»; ось якоря в фундаменте
  ведёт `PRO-Robotech/corelib#5`.

  **Ацикличность не нарушена, и это надо сказать прямо**, иначе следующий прочтёт ребро как
  нарушение: край **и так** импортирует стабы всех доменов — его роль (`polyrepo.md` §«Build-граф»), — а
  владелец журнала края не зовёт ни при каком условии.

  > [!important] Перечень владельцев ЗАКРЫТ, и пустой означает «не объявлен», а НЕ «все»
  > Ручка `KACHO_API_GATEWAY_SUBSCRIPTION_OWNERS` перечисляет владельцев через запятую.
  > Пустое значение даёт **отказ** «владелец не объявлен» (`501`), а не открытие потока ко
  > всем доменам.
  >
  > Это осознанно **обратное** решение к классу «пусто = не сужаем» (`security.md`
  > §«Пустой список — это „не сужаем", а НЕ „запрещаем"»): там пустой круг отправителей означал
  > «доверяем всем» и требовал отказа старта, здесь пустой перечень означает «никого» и
  > безопасен by construction. Разница в том, **что перечисляет ручка**: круг доверия сужает уже
  > разрешённое, перечень владельцев — разрешает. Заводя новую ручку-перечень, спроси, к какому
  > из двух видов она относится: ответ определяет, чем является пустое значение.

- `kacho-api-gateway → kacho-iam` (чтение журнала смены субъекта курсором, #1024) — край
  **сам** читает журнал и гасит свой кэш решений о доступе. Предикат:
  `git grep -n 'subjectchange.NewReader' -- 'gateway/cmd/api-gateway'`. Ребро **заменило**
  снятое обратное (ниже) и по направлению однородно с перечнем: потребитель идёт к владельцу.

> [!note] СНЯТО обратное ребро `kacho-iam → kacho-api-gateway` (толчок инвалидации, #1024)
> Владелец прав дозванивался до края, чтобы гасить его кэш решений. **Предмет снятия —
> НАПРАВЛЕНИЕ, а не механизм**, и это важнее самого факта: iam объявлен **листом** графа
> («их зовут, они не зовут никого»), а адрес края был у него **обязательной ручкой
> старта** — поэтому iam **не поднимался там, где края нет вовсе**, и вынос его отдельным
> продуктом был невыразим. Вынос с тех пор состоялся (`kaname`), то есть снятие ребра было
> его условием.
>
> Имя метода стоит в надгробии `retiredRPCSurface`. Вместе с ним снят **внутренний
> gRPC-слушатель края**: он жил ради одной этой службы. Замер 2026-08-29: прод-файлов края,
> знающих снятый метод, — **ноль**.

> [!note] СНЯТЫ две прежние формы подписки — `compute` и `nlb`
> До эпика об одном предмете говорили **четыре** механизма: два частных потока (у каждого
> свой контракт, сервер и формат события, потребителей — ноль), толчок выше и поллинг.
> Осталась одна форма. Предикат: `git grep -h 'returns (stream' -- proto | wc -l` → **1**.
>
> Поллинг при этом **не отзывается** и остаётся законным путём; для операций он вообще
> единственный — `api-conventions.md` §«Подписки на операции не существует».

> [!warning] Ключ домена и имя каталога — РАЗНЫЕ словари, и оба зовутся «backends»
> Класс, а не координата: домен балансировки адресуется **двумя написаниями** — код края знает
> его по имени proto-пакета, чарт по имени каталога сервиса. Ключ, которым край резолвит
> соединение, — из **первого** словаря; профиль объявляет **второй**.
>
> Цена наблюдалась дважды: клиент, взявший имя из справочной таблицы, получает отказ
> «неизвестный владелец», а оператор, взявший его из комментария чарта, — **отказ старта края**
> (дороже: полный цикл выкатки, потраченный на комментарий).
>
> Правило для новых ручек, перечисляющих домены: скажи, **из какого словаря** берутся имена, и
> сверь его с тем, который читает код. Совпадение имени домена в двух местах — не свойство
> дерева, а совпадение.

**Циклы запрещены**: если A зовёт B — B не зовёт A. Новое ребро фиксируется здесь как runtime-edge.

- `kacho-geo` — **leaf** (как iam): geo никого, кроме iam (authz-Check), не зовёт. Рёбра `vpc→geo` /
  `compute→geo` / `nlb→geo` однонаправлены → циклов с geo нет. После выноса Geography ложные «ради
  geography» рёбра `vpc→compute` и `nlb→compute (region)` удалены.
- `kacho-compute → kacho-vpc` (NIC/IPAM) — единственное оставшееся ребро между vpc и compute,
  **одностороннее**: vpc больше не зовёт compute (zone-валидация ушла в geo). Семантического цикла нет.
