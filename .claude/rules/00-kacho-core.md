# Kachō — ядро: продукт, naming, non-negotiables

Базовый, всегда-загруженный модуль. Импортируется корневым `CLAUDE.md` воркспейса.
Оснастка живёт **в единственном экземпляре** — в `.claude/` воркспейса; копий в рабочих
копиях продукта нет, и раскатки как механизма **не существует** (решение владельца
2026-08-02, скрипт раскатки и его проба сняты вместе с вызовами). Правка — только здесь.

> [!note] Здесь стояло правило про синхронизацию копий — предмета у него нет
> Прежняя редакция объявляла модуль самодостаточным при standalone-клоне сервисного репо и
> направляла за синхронизацией к скрипту раскатки. Ни того, ни другого в дереве нет:
> отслеживаемых файлов у скрипта **ноль**, и `CLAUDE.md` воркспейса **того же дерева**
> утверждает обратное — два места об одном предмете, из которых верно одно. Правило при этом
> загружается `@import`-ом в **каждую** сессию, то есть ложное указание читалось чаще любого
> другого. Канон о распространении — `@.claude/rules/ai-tooling.md`; здесь он не дублируется,
> чтобы расхождение не завелось снова.

## Что это за продукт

**Kachō — самостоятельная облачная control-plane платформа** (только control plane,
без data plane). Домены: **IAM** (Account / Project / User / ServiceAccount / Group /
Role / AccessBinding), **VPC** (Network / Subnet / SecurityGroup / RouteTable / Address /
Gateway / NetworkInterface), **Compute** (Instance / MachineType), **Storage** (Volume /
Snapshot / Image / DiskType — блочное хранение), **Geo** (Region / Zone — топология
размещения, leaf-owner), **NLB** (LoadBalancer / Listener / TargetGroup), **Registry**
(Registry / Repository / Tag — OCI). Это собственный продукт со своими требованиями — описывай и проектируй
API в терминах **конвенций Kachō** (см. `@.claude/rules/api-conventions.md`), без
сравнений с чужими облаками.

## Naming convention (обязательно)

| Контекст | Значение |
|---|---|
| Бренд / README / UI | **Kachō** |
| Технические идентификаторы (ASCII) | `kacho` |
| Proto package | `kacho.cloud.<domain>.v1` |
| Имена репо | `kacho-<part>` (дефис) |
| Postgres database / schema | `kacho_<domain>` (подчёркивание) |
| Env-переменные | `KACHO_<DOMAIN>_<NAME>` |
| JSON-поля (REST) | camelCase: `<resource>Id`, `projectId`, `labels`, `createdAt` |

## Non-negotiables (детали — в соответствующих rule-модулях)

1. **Не кодить без APPROVED acceptance-дока** Given-When-Then (gate: `acceptance-reviewer`).
2. **Никаких упоминаний чужих облаков** в коде/доках/комментариях/env/именах (`yandex`, `aws`, …).
3. **Без ORM** — только sqlc + handwritten pgx.
4. **Без каскадного удаления через границу сервиса** (только same-DB FK cascade).
5. **Не редактировать применённую миграцию** — только новая.
6. **`Internal.*` методы не публиковать на external endpoint** (только cluster-internal :9091).
7. **Без брокера** (Kafka/NATS), пока справляется in-process.
8. **Без общих БД** — database-per-service.
9. **Мутации возвращают `Operation`** (async), не ресурс синхронно.
10. **Within-service инварианты — на DB-уровне** (FK/UNIQUE/EXCLUDE/CHECK/CAS), не software check-then-act.
11. **Никакого тех-долга / отсрочки «на потом»** — закрываем в том же изменении.
    **Держится ГЕЙТОМ, а не обещанием** (введено 2026-08-11): `internal/repohygiene`
    `TestNoDeferredWorkInTheTree` обходит не-тестовое дерево (код · шаблоны развёртывания ·
    конфигурация · контракты) и роняет прогон на маркере отложенной работы — в обеих формах
    корпуса, англоязычной и русской. Исключений у гейта **нет ни одного**: предикат ловит
    форму обращения к читателю кода (`TODO:` / `TODO(тикет):`), а не слово, поэтому проза о
    самих маркерах под него не подпадает. Список прощённых не заводить: каждая запись в нём —
    место, куда отсрочку вносят незамеченной.
    **Исходов ровно три, четвёртого нет:** сделать сейчас · снять вместе с кодом, который
    маркер подпирал · завести ПРЕДМЕТ (issue/приёмку) с причиной и предикатом снятия. Маркер
    отличается от предмета тем, что за ним никто не отвечает — и он переживает своё основание.
    **Цена измерена, а не предположена.** В день заведения гейт нашёл 14 мест: тринадцать
    документов архитектуры, где вместо текста стояло обещание его написать, и один маркер,
    прикрывавший живой дефект — хук завершения восстановления пароля был нацелен на порт, где
    его пути не существует, поэтому событие не доезжало НИКОГДА (восстановивший доступ
    оставался заблокированным, прежние сессии переживали восстановление). Отсрочка при этом
    ссылалась на препятствие, которого давно не было: «RPC не реализован» — RPC существовал.
12. **Строгий TDD** — падающий тест ДО кода; новый RPC/поле/ресурс/багфикс не мёржится без тестов в том же PR.
13. **Test-only PR не трогает прод-код** и не содержит TODO/SKIP/FIXME.
14. **Всегда production-grade, НИКОГДА MVP.** Не строим «минимальную рабочую версию, потом допилим». Каждый ресурс/RPC/фича — сразу в полной production-форме: полный error-handling + фикс. тон ошибок, authz/security на каждом RPC, DB-инварианты, two-projection, observability, тесты, конвенции. Запрещены stub/skeleton, «happy-path пока», «hardening/authz/тесты позже», «временное упрощение». Урезание объёма допустимо ТОЛЬКО как осознанная декомпозиция на под-фазы, где **каждая под-фаза сама production-complete** (полностью реализована+протестирована+безопасна в своих границах, отложенное явно вынесено в `Out-of-scope` следующей под-фазы) — это НЕ понижение качества, а сужение scope. «MVP/прототип/потом доделаем» как обоснование неполноты — нарушение (тесно с ban #11 тех-долг).
15. **Внешняя/URL-адресация — ТОЛЬКО по immutable `id`, НИКОГДА по `name`.** Любая внешне-адресуемая идентичность ресурса — сегмент публичного URL / pull-пути (эталон: **`$domain/$registryId/$repository:$tag`**, как DockerHub/Quay), cross-service ссылка (`projectId`/`zoneId`/`registryId`/…), grant-scope / authz-target, любая durable-координата — привязывается к **неизменяемому `id`** ресурса, не к мутабельному `name`/label. `id` присваивается на Create и **неизменяем на всю жизнь ресурса**: операции смены id НЕ существует (никакого «rename id», никакого `:rename`, меняющего адресуемую идентичность), `id` **глобально-уникален by construction** (crockford-base32) — коллизий между тенантами нет. Человекочитаемое `name` — косметический project-scoped label (`UNIQUE(project,name)`, может меняться свободно), который **НИКОГДА не попадает в URL/pull-путь/ссылку** и не несёт адресацию. Причина: имена меняются и глобально коллизят → URL/гранты/ссылки ломались бы; id-адресация стабильна навсегда и бесконфликтна. Эталоны: GEO (Region/Zone immutable id), registry (`$domain/$registryId/$repo:$tag`, `id` prefix `reg`). Rename `name` (где ресурс его допускает) — чисто косметическая мутация, не затрагивающая ни одной внешней привязки. Деривация «глобального человекочитаемого слага» в URL (вместо id) — **запрещена** (вводит name-в-URL через заднюю дверь и rename-ломкость).
16. **Production-mode ВЕЗДЕ (включая dev/локальный стенд) + iam-единый-фасад-к-Hydra.** Любой РАЗВЁРНУТЫЙ стенд (kind/CI/local/prod) работает в **production-security-posture** (`authMode=production` + mTLS ВЕЗДЕ + `sslmode=require` + Hydra-RS256); dev-insecure posture (anonymous→full, HS256-stand-in, plaintext) — security-долг, ЗАПРЕЩЁн на поднятом кластере (допустим ТОЛЬКО в in-process unit/integration-фикстурах). «Зелёный dev» НЕ доказывает production-готовность (dev маскирует authz-bypass/неверифицированный-mTLS/обойдённые-boot-guards). **Каждый сервис ОБЯЗАН нести production boot-guard** (`Config.Validate()` fail-closed → refuse-to-start при insecure config; `AuthMode` declared-never-read = запрещённый мёртвый guard). **`values.prod` ОБЯЗАН реально boots** (helm-install+rollout-ready в production-mode, не только `helm template`). **iam — единственный фасад к Hydra**: клиенты/сервисы/e2e идут в iam (JWKS-proxy `:9097`, token via `UserToken/SAKey.Issue`, docker-token `/iam/token`), прямой Hydra-dial в обход iam (JWKS `:4444`, admin `/admin/clients`) — нарушение унификации (iam→Hydra ВНУТРИ фасада — легитимно; допустимо-прямое — только OAuth2 `client_assertion→JWT` exchange). Детали и регрессии — `@.claude/rules/security.md` §«Production-mode обязателен ВЕЗДЕ». Выведено из production-mode валидации 2026-07, давшей три разных класса: сервис без production boot-guard вовсе; чарт, который рендерится, но не поднимается в production-посадке; и верификация токена в обход единого фасада.
17. **Имя в коде — ТОЛЬКО латиницей; комментарии и тексты — на любом языке**
    (решение владельца 2026-08-20, дословно: «никаких русскоязычных вставок в коде.
    На русском могут быть комментарии и документация, но не сам код»). Предмет
    запрета — **идентификатор**: имя функции, типа, поля, переменной, параметра,
    константы, импорта. Русская подпись интерфейса, русское сообщение отказа,
    русский заголовок пробы и русский разбор в комментарии — законны, обязаны
    остаться и под запрет **не подпадают**.
    **Это не вкус, и цена измерена.** Кириллица даёт **омоглифы** — знаки,
    неотличимые от латинских на глаз (`В`/`B`, `С`/`C`, `Р`/`P`, `о`/`o`, `с`/`c`).
    Имя с таким знаком выглядит обычным и **не сопоставляется по имени**: пять проб
    разбора доступа в iam назывались с кириллической `В`, отбор `go test -run`
    отвечал «no tests to run», и «прогнал» молча означало «не прогнал». Заметить
    это чтением нельзя ни при какой внимательности.
    **Держится ГЕЙТАМИ разбора, по одному на язык, а не вниманием.** Поиск по
    образцу этот класс не измеряет — он не отличает имя от строки и комментария, а
    законной кириллицы в дереве десятки тысяч строк. Go — `internal/repohygiene`
    `TestIdentifiersAreASCII`; TypeScript —
    `ui-future/shared/src/test/console-ascii-identifiers.test.ts`. Оба обходят
    индекс git, судят по узлу-идентификатору, печатают объём осмотренного и падают
    на пустом обходе; у каждого рядом проба собственной предпосылки — дефект в
    синтетике обязан находиться, законный близнец обязан молчать.
    **Правишь имя — правь по позициям из разбора, а не текстовой заменой.**
    Замена текстом попадает внутрь строки: при первой же правке сообщение пробы
    стало «файлов Go filesRead 4114» вместо «прочитано», и увидеть это можно только
    прочитав готовый текст. Разбор трогает узлы-имена **by construction**.
    Перепись 2026-08-20 по обоим репозиториям: консоль — 520 имён (2973 вхождения,
    75 файлов), пробы Go — 25 имён (208 вхождений, 15 файлов), Python — 4 имени;
    JS, SQL, proto, shell, имена файлов — ноль. Прод-кода Go среди находок не было. Класс и противоядие — [[homoglyph-identifier-cannot-be-selected]].
18. **Всякое решение проходит ПЯТЬ вопросов, а узнаваемость — имитацию клиента**
    (директива владельца 2026-08-24, дословно: «Все решения принимаешь ты. С моей
    стороны только требования: 1) все что ты придумываешь должны быть только на благо
    продукта 2) все что ты придумываешь должно быть максимально конкурентноспособным,
    перспективным, безопасным, производственным 3) все что ты придумываешь должно быть
    узнаваемым и удобным для клиента периодически проверяя через имитацию пользователей
    из разных направлений (архитектор, разработчик, девопс/сре, продакт)»).
    **Связывает КАЖДОЕ решение и применяется там, где остальные пункты молчат.** Решение,
    ничего не нарушающее, ещё не принято. Критерий, которым нельзя **отвергнуть**,
    критерием не является — поэтому у каждого вопроса назван признак отказа, а не одобрения,
    и «нет» на любом одном означает отказ, а не повод к обсуждению.

    | вопрос | ОТВЕРГАЕТСЯ, когда |
    |---|---|
    | **благо продукта** | единственный выигрыш — меньше работы **сейчас**: у исполнителя, у обзора, у проверки |
    | **конкурентоспособность** | выигрыш формулируется только как «как у …» — сравнение запрещено (ban #2) и как довод пусто. Своя ось: предсказуемость контракта · время до первого успешного вызова · цена эксплуатации |
    | **перспективность** | ошибка решения **необратима**: отзыв ломает внешне-адресуемую координату (ban #15) либо требует миграции данных арендатора |
    | **безопасность** | решение расширяет поверхность, и расширение **не названо** — ни в приёмке, ни в профиле, ни в модели (`@.claude/rules/security.md`) |
    | **производственность** | у решения есть режим, годный только для стенда, либо часть, отложенная «на потом» (ban #11, #14, #16) |

    **Узнаваемость и удобство — ПРАКТИКА.** Проверяется имитацией клиента: четыре прогона,
    по одному на направление, каждый с **пустым контекстом** и только тем входом, что
    доступен клиенту (контракт · страница документации · консоль · текст отказа · профиль
    развёртывания). Пустой контекст здесь условие годности, а не аккуратность: имитирующий,
    знающий наши обоснования, изображает не клиента, а нас.

    | направление | что спрашивает |
    |---|---|
    | **архитектор** | чей это домен и почему именно его; что придётся отозвать, если решение неверно; какое ребро заводится и куда оно ведёт через год |
    | **разработчик** | сколько шагов от «открыл страницу» до первого успешного вызова; чем этот ресурс отличается от соседнего и решал ли его кто-нибудь; говорит ли отказ, что делать дальше |
    | **девопс/SRE** | по чему в три часа ночи отличить «сломан продукт» от «не создано условие»; что видно до чтения кода; что откатывают и чего это стоит |
    | **продакт** | какой шаг клиент делает первым; чем платит за переименование, удаление, смену предела; за что выбирает продукт — **его** словами, не нашими |

    **Когда — при закрытии релизной линии, ТРОНУВШЕЙ клиентскую поверхность**, до её MR в
    `main` (`@.claude/rules/git-issues.md` §«Накопительная релизная ветка»); отчёт —
    комментарием в эпике линии (`@.claude/rules/multi-agent-flow.md` §«Агрегат релиза»).
    Линия, поверхности не тронувшая, проверки не требует, и это не послабление: **предмет
    проверки возникает только вместе с изменением поверхности**, поэтому привязка к
    изменению слепого окна не создаёт. **Календарь отвергнут** — у него нет производителя:
    за датой никто не следит, «раз в месяц» вырождается в «никогда», и дальше даёт проверку
    без предмета там, где предмета нет, и молчание там, где он есть.

    **Находка — одно из трёх, каждое самостоятельно достаточно:** продукт **противоречит
    себе** (два ресурса решают одну задачу по-разному, и различие никем не решалось);
    возможность **объявлена и неисполнима** (`@.claude/rules/api-conventions.md`
    §«Принято-и-проигнорировано» и §«Неисполнимая возможность»); отказ **не восстанавливает
    следующий шаг** клиента. **НЕ находка — «мне непривычно»:** роль не вправе требовать
    чужой моды, конвенции Kachō свои, сравнения с чужими облаками запрещены осознанно
    (§«Что это за продукт», ban #2). Разделяет **один вопрос**: назови второе место продукта,
    с которым это расходится, либо цену для клиента в шагах, времени или деньгах. Ни того,
    ни другого — это вкус; он идёт в отчёт отдельным разделом, а не задачей.

    **Держится ПОРЯДКОМ РАБОТ, а не гейтом, и это сказано прямо:** «удобно» и «перспективно»
    машинного предиката не имеют, а правило, обещающее несуществующую проверку, само есть тот
    класс, который корпус ловит. **Проверяемая половина названа отдельно:** отчёт существует,
    несёт четыре раздела по числу направлений, и каждый раздел называет **координату**, по
    которой прогон шёл. Наличие и форма машинно проверяемы, **истинность — нет** (тот же
    предел, что у машинного чтения вердикта приёмки: оно судит объявление, а не одобрение).
    Держателя у проверяемой половины сегодня **нет**, и это остаток, а не обещание: гейт
    заводится своим изменением, потому что предмет у него другой.
