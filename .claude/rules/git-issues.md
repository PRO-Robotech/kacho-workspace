## Имя ветки: `<N>-<суффикс>` (решение владельца 2026-09-30)

Дословно: «Таски именуй по номеру плюс постфикс от себя задачи которую делают что бы придерживаться гит флоу и добавь правило в рул». Формы `issue-<N>`, `epic-<…>`, `ntf/<id>` сняты.

gi-branch-name-form · ветка — `<N>-<суффикс>`: N — задача в ТОМ репозитории, куда уходит ветка, суффикс — суть kebab-case латиницей, ≤ 40 знаков (`^[0-9]+-[a-z0-9][a-z0-9-]*$`); законны ещё `main`, `wip/*`, `tmp/*` · `scripts/hooks/pre-push` отвергает создание иной формы до наборов, проба — check-18; номер — ЗАВЕСТИ · red: `issue-880`, `ntf/c8`, `77`, `2914-Notify`; ветка воркспейса под номером kacho
gi-branch-epic · эпик — его номер плюс суть (`2914-notify`, `77-notify`, `484-notify`); волна — `<N задачи волны>-<суть>`; пакет — `<N задачи>-<пакет>-<суть>` (`2915-c8-feed-put`), подзадача ради имени не заводится · `scripts/hooks/pre-push`; номер — ЗАВЕСТИ · red: `epic-2914-notify`; один номер на три репозитория; задача на каждый пакет
gi-branch-other-repos · форма та же в kacho, corelib, kaname; держатель — свой хук каждого, копий нет (ban20); kacho имени не судит, corelib до правки отвергает `77-notify`, у kaname хука нет · ЗАВЕСТИ · red: новая `epic-…` в kacho уехала молча
gi-branch-legacy · прежнюю форму не заводить; существующая на удалённом дописывается до вливания: хук пропускает удаление и дописывание, отвергает создание · `scripts/hooks/pre-push` · red: создание прежней формы; переименование ветки с открытым запросом
gi-branch-bare-number-release · голый номер `^[0-9]+$` — форма идущего релиза corelib (владелец 2026-09-30: «Нотифай модуль идет после релиза отказа от ори стека»): существующий дописывается, новый отвергается; обход хука — ЗАВЕСТИ · check-18 («26» — пропуск, «27» — отказ) · red: `26` отвергнута; новая `27` уехала

## Волна: сборка — агрегат (решение владельца 2026-09-24 «тестирование агрегатами а не каждую таску отдельно»)

gi-pr-manual-dispatch · у PR в базу без триггера (ветка эпика, волны) — тем же заходом `gh workflow run <файл> --ref <ветка>` КАЖДОГО процесса с `pull_request` и `workflow_dispatch` · `gh run list --commit <headSha>` · red: PR ждёт несуществующего триггера; запущен не каждый процесс

## Трекер — GitHub Issues: когда заводится задача

gi-feature-issue-first · фича (ресурс, API, раздел UI, кросс-доменное поведение) → задача ПЕРВОЙ, ветка с её номером, PR `Closes #<N>` · ЗАВЕСТИ · red: ветка или PR, которым не предъявить задачу
gi-batch-one-per-session · фиксы и мелкий UX — ОДНА batch-задача на сессию («<область> bugfix batch — YYYY-MM-DD»); безопасность — своей задачей (gi-security-finding-issue-now) · ЗАВЕСТИ · red: десять задач на сессию фиксов; находка о безопасности пунктом batch-задачи
gi-security-finding-issue-now · находку, важную и влияющую на безопасность, заводи задачей НЕМЕДЛЕННО, в репозитории предмета (владелец 2026-09-20 «не забывай по ходу создавать задачи в гитхаб ишуе если это важное и влияет на безопасность») · tooling-gate check-13 — норма · red: находка доехала до конца волны, задачи нет
gi-security-issue-high-level-only · немедленность — о СРОКЕ, не об объёме: в задачу — высокоуровневая часть со ссылкой на дифф фикса, разбор не коммитится, рабочий каталог не называется · `security-disclosure.md` §«Публичные артефакты» · red: шаги воспроизведения в публичной задаче
gi-trivia-no-issue · опечатка, однострочник, docs — без задачи, достаточно коммита · ЗАВЕСТИ · red: задача на однострочник
gi-retro-backfill · существенный кусок без задачи заводится ретроспективно; тривию не бэкфиллить · ЗАВЕСТИ · red: в истории работа, которой нечего предъявить
gi-find-own-issue · задачу из находки — ТОЛЬКО о корректности ПО или безопасности, прочее — в записи ревью; в чужом PR не чини (владелец 2026-09-27: «заводи задачи ТОЛЬКО если оно влияет на корректность работы ПО или если не относится к безопасности продукта») · вниманием · red: задача на стиль; находка о корректности без задачи
gi-zero-findings-aloud · ноль соседних находок — законный ответ, названный вслух: «смотрел, чисто» от «не смотрел» отличимо лишь сказанным · ЗАВЕСТИ · red: отчёт без находок и без названного осмотренного места

## Каскад закрытия: задача, волна, эпик, `main` (решение владельца 2026-09-26)

Дословно, 2026-09-26: «не не не задачи закрываются сразу как только закрывается верхнестоящая задача. таск -> волна -> эпик -> main». Норма «задачи волны открыты до посадки эпика в `main`» им отменена; команды — `git-operator.md` §«Вливание и снятие».

gi-close-cascade · уровень закрывается, влитый в следующий (задача → волна → эпик → `main`), и тем же заходом закрывает дочерних · `cascade-census.sh <репо> <волна>` — 0 (расхождение или открытый дочерний — 1, дочерних ноль — 2), tooling-gate check-14 · red: волна закрыта, задачи открыты
gi-cascade-task-test · ветка задачи влита в сборку или волну, PR сборки — в волну: тем же действием `status:in-progress` ЗАМЕНЁН на `status:test` · ЗАВЕСТИ · red: задача в сборке с `status:in-progress`
gi-cascade-wave-closes-tasks · запрос волны влит в эпик — `git-operator` тем же заходом закрывает волну и каждую задачу записью: коммит работы, коммит слияния, исход предиката снятия · перепись `gi-close-cascade` · red: запись без коммита работы; задачи оставлены на потом
gi-cascade-no-auto-close · `Closes #<N>` исполняется лишь в ветке по умолчанию; в волне и эпике каскад — явное действие · ЗАВЕСТИ · red: задачи влитой волны ждут авто-закрытия
gi-cascade-remainder · остаток — задачей следующей волны; непоставленная (её коммита в запросе нет) переводится; сборка закрыта тупиком — задачи в k+1, её задача закрыта записью о тупике; запрос волны снят — задачи переводятся · ЗАВЕСТИ · red: непоставленная закрыта с волной; остаток без задачи
gi-cascade-epic-main · эпик закрывается посадкой в `main`, его волны к ней закрыты · `scripts/cascade-census.sh --children-closed <репо> <эпик>` перед посадкой — 0 (без ключа открытый эпик законно 0; ключ судит check-14) · red: эпик влит с открытой волной; готовность прочитана без ключа

## Снятие влитой ветки — шаг вливания, а не уборка (решение владельца 2026-09-26)

Дословно, 2026-09-26: «старые ветки которые вмержились не удаляются локально и внешне. Обнови рул если не ххватает инфы сделай обязательным.»

gi-prune-same-pass · влитая ветка снимается ТЕМ ЖЕ заходом, что вливание (сборка и её задачи, волна, эпик): origin, все клоны, копия · перепись `gi-prune-session-zero` · red: влитая пережила заход своего вливания
gi-prune-remote · вливание с `--delete-branch`; ветки задач сборки и не снятую голову — `git push origin --delete` под `interim.lock` · `git ls-remote --heads origin <ветка>` пуст · red: голова влитого PR или ветка задачи влитой сборки на origin
gi-prune-every-clone · локально — во ВСЕХ клонах (воркспейс, `project/kacho`, `project/kaname`, `project/corelib`), чистая копия — `git worktree remove`; грязная — автору, без `--force` · `scripts/branch-audit.sh <клон>` · red: влитая или её копия в любом клоне; снята копия с незакоммиченным
gi-prune-commit-predicate · при ВЛИВАНИИ снимаются голова, РАВНАЯ влитой (`--match-head-commit`), и её предки (`merge-base --is-ancestor` — 0); окно свежести не стоп · `BRANCH_AUDIT_FRESH_MIN=0 branch-audit.sh` · red: снята не-предок; влитая оставлена окном
gi-prune-census-predicate · снятие ПО ПЕРЕПИСИ судит байты: ветка из «ВЛИТЫ» того же захода (признаки 1, 5, 6а, 6б), на origin — при голове переписи; стоп — единственный экземпляр, живая копия, окно свежести · `branch-audit-inject.sh` · red: снята вне «ВЛИТЫ»; голова origin сдвинута
gi-prune-session-zero · в конце сессии влитых к снятию ноль по каждому клону и цели каскада, локально И на origin; цели, ветку по умолчанию и без своего коммита не снимать · `branch-audit.sh` (`BRANCH_AUDIT_TRUNK`, `BRANCH_AUDIT_KEEP`) — `к снятию 0`; `branches-clean` — нижняя граница · red: сессия закрыта с влитой; живая волна снята
gi-no-branch-revival · ветку, удалённую при вливании, заново не заводят и такого указания не пишут · предикат — архив правила, раздел «Предикат gi-no-branch-revival»: пусто · red: в тексте оснастки есть указание на повторное заведение снятой ветки
