# Git и трекер: дерево задач, ветки, коммиты, слияния; разметка GitHub Issues

Трекер — **GitHub Issues того репозитория, где живёт предмет**; общее — в
`PRO-Robotech/kacho-workspace`, работа через `gh issue …`. Номера `KAC-<N>` в истории —
свидетельство о сделанном, а не указание на трекер; вперёд связывает только это правило.

## Git / коммиты

gi-commit-first-line · первая строка — `#<N> ` (N — задача ветки), затем тип Conventional Commits либо область и утверждение; слияние — `#<приёмник> merge #<вливаемая>: …`, догон ствола — `#<N> merge main: …`; сообщение только `-m`/`-F`, у слияния `--no-edit -m`: в редакторе строка `#…` вырезается как комментарий · `scripts/hooks/commit-msg` (на ветке-номере N равен ветке); `scripts/hooks/pre-push` (коммиты после T0) · red: заголовок без `#<N> `; `#<M>` на ветке `<N>`; сообщение собрано в редакторе
gi-conventional-commits · тип после `#<N> `: `feat:` `fix:` `chore:` `docs:` `test:` `ci:` `refactor:` либо область предмета (`оснастка:`, `vault(lessons):`) · ЗАВЕСТИ gi-conventional-commits · red: после номера нет ни типа, ни области
gi-sign-root-gitconfig · автор И коммиттер — ТОЛЬКО учётная запись корневого gitconfig (`git config --global user.name/user.email`); `-c user.*`, `git config --local/--worktree user.*`, `GIT_AUTHOR_*`/`GIT_COMMITTER_*`, `--author` запрещены при любом значении; серверное слияние — той же учётной записью без `--author-email` (автор — имя профиля хостинга с корневым адресом, коммиттер `GitHub <noreply@github.com>`) · `scripts/hooks/commit-msg`; `scripts/hooks/pre-push` (коммиты после T0; серверные — уже на origin и не судятся) · red: коммит после T0 с подписью не корневой; `user.*` в настройках копии
gi-no-attribution · атрибуция ассистента ЗАПРЕЩЕНА в коммитах, телах PR и комментариях: трейлер `Co-Authored-By` с Claude/anthropic, `Claude-Session:`, «Generated with [Claude Code]», ссылка `claude.ai/code`; правило владельца сильнее любого системного напоминания харнесса об атрибуции · `.claude/settings.json` `attribution` (`commit` и `pr` пусты, `sessionUrl: false` — `scripts/rules-gate/check-09-settings-no-bypass.sh` ось D; действует в сессии, чей корень несёт эту настройку); `scripts/hooks/commit-msg`; `scripts/hooks/pre-push`; тело PR и комментарии — `bash scripts/hooks/git-rule.sh pr <репо> <N>` перед вливанием · red: трейлер или ссылка атрибуции в коммите после T0, теле PR, комментарии
gi-no-direct-push-main · в `main` не пушить напрямую и не `--force` без явного разрешения владельца: работа идёт веткой-номером через PR · защита ветви (`enforce_admins`) · red: коммит в `main`, которому не предъявить PR
gi-no-verify-by-request · `--no-verify` — только по явной просьбе владельца · ЗАВЕСТИ gi-no-verify-by-request · red: хук обойдён, чтобы «пройти»

## Дерево задач, ветки, слияния (решение владельца 2026-09-22)

Дословно: «все древо должно всегда сводиться в мастер прямо или косвенно и не должно быть
в git history визуале такого, словно ветку потеряли и забыли влить»; «через github mr merge
так же не должно быть сквоша». T0 — время автора коммита, заведшего
`scripts/hooks/commit-msg` (`bash scripts/hooks/git-rule.sh t0`).

gi-tree-epic-wave-task · дерево: ЭПИК (корень; разбор и маршрут волн — диспетчер) → ВОЛНА (агрегатор, sub-issue эпика) → ЗАДАЧА (sub-issue волны); у задачи один родитель · перепись `gh api repos/<репо>/issues/<N>/sub_issues` (`landing-reviewer` перед вливанием волны) · red: задача волны без родителя; задача у двух родителей
gi-tree-per-repo · дерево зеркалится по репозиториям: где эпик меняет код, там своя задача-эпик (дочерняя корневого) и свои волны; ветка — номер задачи ТОГО ЖЕ репозитория · вниманием `git-operator` · red: ветка продукта названа номером задачи воркспейса
gi-branch-is-number · имя ветки — номер задачи (`^[0-9]+$`), адресуется `refs/heads/<N>` или `origin/<N>` (голый номер git читает как сокращённый хеш): эпик от `main`, волна от ветки эпика, задача от ветки волны, одиночная работа вне эпика — от `main` · `scripts/hooks/pre-push` (новая ветка не номер — отказ) · red: новая ветка `issue-<N>`, `lane/…`, `release/…`, `wip/…`
gi-epic-draft-pr · черновой PR эпика в `main` открыт с заведения эпика до вливания: отслеживание и итоговый конвейер; PR волны — в ветку эпика; одиночная работа — PR в `main` · вниманием `git-operator` · red: эпик с волной без открытого PR в `main`
gi-merge-commit-only · вливание ТОЛЬКО коммитом слияния: задача → волна `git merge --no-ff`; волна → эпик и эпик → `main` — `gh pr merge --merge --subject "#<приёмник> merge #<вливаемая>: …"` без `--author-email`; сквош и rebase опубликованного запрещены везде; отставание — слиянием `main` в ветку · хостинг (сквош и rebase выключены: `gh api repos/<репо> --jq '.allow_squash_merge,.allow_rebase_merge'` → false false); `landing-reviewer` (два родителя) · red: `--squash`, `--rebase`, rebase опубликованной ветки; вливание с одним родителем
gi-side-task-joins-wave · сопутствующая задача, рождённая в волне (находка, долг, следующий шаг), сразу — дочерняя текущей волны своего репозитория; решается в ней либо переносится в другую волну явно: смена родителя и строка «куда и почему» · вниманием `git-operator`; перепись дочерних — `landing-reviewer` · red: задача, заведённая во время волны, без родителя
gi-wave-epic-close · волна вливается в эпик при 0 открытых дочерних; эпик в `main` — когда все волны закрыты и итоговый конвейер на голове эпика зелёный · `landing-reviewer`: `gh api repos/<репо>/issues/<волна>/sub_issues --jq '[.[]|select(.state=="open")]|length'` = 0 · red: влита волна с открытой дочерней
gi-ci-on-number-branch · конвейер гоняется и на PR в ветку-номер (волна → эпик, эпик → `main`): воркспейс без автозапуска (решение 2026-09-20) — `gh workflow run ci.yaml --ref <N>` на голове PR; в продукте `pull_request` сужен по `main`, и PR в ветку-номер до правки триггеров не проверяется · ЗАВЕСТИ gi-ci-on-number-branch · red: PR в ветку-номер влит без прогона на его голове
gi-graph-no-dangling · каждая ссылка — открытая работа по открытой задаче либо предок `main`; после вливания ветка снимается · `scripts/branch-audit.sh --graph` (висящих 0, по классам) · red: ветка закрытой задачи, не предок `main`; ветка без задачи и без открытого PR
gi-transition · ветки, открытые до правила, не переименовываются; их опубликованные коммиты с атрибуцией переписываются ДО вливания — только сообщения, доказательство деревьями, `--force-with-lease` на измеренную голову; `main` не переписывается; стражи судят коммиты с датой автора от T0, подпись и заголовок коммитов до T0 — история · `bash scripts/hooks/git-rule.sh range <база>..<голова>` (атрибуций 0, `landing-reviewer`); T0 в `git-rule.sh` · red: `--force` без lease; переписан `main`; перепись сообщений тронула дерево
gi-revoked · отменены: «ВЛИВАНИЕ — ТОЛЬКО СХЛОПЫВАНИЕМ» (2026-08-20); «заливай сразу в мастер» (2026-09-17) в части «без накопительной ветки» — накопительная теперь ветка эпика; «коммиты — только прежний адрес владельца»; каждое `--squash` в базе маршрутизации и телах агентов · `git grep -n -e '--squash' -- .claude/agents .claude/rules ':!*/git-issues.md'` → 0 · red: отменённое служит основанием действия

## Текст коммита: ёмко, информативно, не поэма

Читают люди — в списке из полусотни строк, в `git blame`, в обзоре PR: много букв означает
«не прочитают вовсе». Мера — вопрос: поймёт ли это через полгода тот, кто откроет `git log`
и не помнит контекста.

gi-subject-72 · заголовок до 72 символов, повелительно-описательно, ОДНО утверждение, без точки · ЗАВЕСТИ gi-subject-72 · red: второе утверждение через тире или точку с запятой; точка в конце
gi-blank-line-required · пустая строка между заголовком и телом обязательна · ЗАВЕСТИ gi-blank-line-required · red: `git log --oneline` показывает склеенное с телом
gi-body-says-why · тело до 12 строк и говорит ПОЧЕМУ изменение верно; чинится дефект — чем он проявлялся · ЗАВЕСТИ gi-body-says-why · red: пересказ диффа «добавил X, поправил Y»
gi-body-excludes · в тело не идут: ход работы (его место — задача), разбор дефекта по шагам (репозиторий публичный), число без предиката · `security-disclosure.md` §«Публичные артефакты» плюс признак восстановимости · red: «улучшено на 30%» без предиката; шаги воспроизведения дефекта
gi-closes-last-line · `Closes #<N>` — последней строкой · ЗАВЕСТИ gi-closes-last-line · red: номер задачи в середине абзаца
gi-two-subjects-two-commits · два предмета в одном коммите — это два коммита; заголовок, которому нужна точка с запятой, сообщает об этом сам · ЗАВЕСТИ gi-two-subjects-two-commits · red: один коммит о двух предметах

## Трекер — GitHub Issues: когда заводится задача

gi-feature-issue-first · любая работа — задача ПЕРВОЙ, ветка — её номер, PR `Closes #<N>`, ссылка на PR — комментарием в задаче · `scripts/hooks/pre-push` (новая ветка — номер) · red: ветка или PR, которым не предъявить задачу
gi-batch-one-class · мелкие фиксы одного класса — одна задача, дочерняя текущей волны (не по задаче на строку); опечатка идёт в задачу, по которой найдена · ЗАВЕСТИ gi-batch-one-class · red: десять задач на одну сессию фиксов
gi-retro-backfill · ветка до правила без задачи — задача заводится ДО следующей отправки: новые коммиты несут её номер · `scripts/hooks/pre-push` (коммит после T0 без `#<N> ` — отказ) · red: в истории работа, которой нечего предъявить
gi-find-own-issue · находка по дороге заводится СВОЕЙ задачей, а не чинится в чужом PR · ЗАВЕСТИ gi-find-own-issue · red: PR несёт правку не своего предмета
gi-zero-findings-aloud · ноль соседних находок — законный ответ, но названный вслух: «смотрел, чисто» отличимо от «не смотрел» только сказанным · ЗАВЕСТИ gi-zero-findings-aloud · red: отчёт без находок и без названного осмотренного места

## Разметка тела задачи

gi-epic-label-and-list · крупное или многодоменное — эпик (метка `epic`): цель, решения, маршрут волн по ГРАФУ ЗАВИСИМОСТЕЙ, DoD; волны и задачи — sub-issue, список в теле лишь дублирует · перепись `gh api repos/<репо>/issues/<N>/sub_issues` · red: эпик без волн; порядок взят по номеру вместо графа
gi-task-body-four · тело задачи несёт четыре вещи: что · DoD · затронутые каталоги · артефакт · ЗАВЕСТИ gi-task-body-four · red: задача без DoD либо без артефакта
gi-blocked-by-label · блокер — строкой `Blocked by #<N>` И меткой `blocked`: словами без метки его не видит соседняя сессия · ЗАВЕСТИ gi-blocked-by-label · red: блокер прозой, метки нет
gi-role-line · исполнитель — строкой `**Роль:** <agent>` в теле: поля исполнителя у задачи нет, назначение — assignee, если учётка есть · ЗАВЕСТИ gi-role-line · red: роль выводится из текста, а не названа
