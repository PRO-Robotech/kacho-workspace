# Obsidian vault — обязательный context-источник и trail

Vault: `kacho-workspace/obsidian/kacho/` — самодостаточные записки, **источник истины**
для cross-repo связей, ресурсной модели, RPC-контрактов, runtime-графа. Категории —
каталог верхнего уровня, других нет: `resources/` · `rpc/` · `packages/` · `edges/` ·
`KAC/` · `lessons/` (классы дефектов) · `runbooks/` (операционные процедуры) · `docs/` ·
`legacy/` (переходы прежних репозиториев). Полные правила тегов/frontmatter и **оболочка
записки** (назначение · категория · состояние · чем сверено · связи) —
`obsidian/kacho/CLAUDE.md`.

**Оболочка и связность держатся исполняемыми проверками, а не уговором:**
`./scripts/vault-gate/run-all.sh` (`check-02` — висячие ссылки с двусторонним храповиком,
`check-03` — оболочка записки, `check-04` — свежесть указателя) и
`./scripts/vault-index/generate.py`, который собирает машинную часть `INDEX.md` из дерева.
Каждая проверка печатает **объём осмотренного**, поэтому «ноль находок» отличимо от «ноль
прочитанного», а её способность упасть и смолчать доказана инъекцией
(`scripts/vault-gate/inject-0*.sh`).

**Потолок «1-3KB» снят владельцем (2026-08-05).** Предмет экономии теперь не объём, а
**точность и пригодность к переиспользованию**: записка пишется так, чтобы следующий
читатель применил её, не зная сессии, в которой она возникла — с признаком, отличием от
похожего, противоядием, тем, чем это держится, и тем, где наблюдалось. Прежний потолок
де-факто не соблюдался и раньше — замер на `workspace@788c3a8`: из **533** записок vault
**322** крупнее 3KB, средний размер 4997 байт, — то есть правило было объявлением, за
которым не стояло дерева. Что осталось нормой: **одна записка — один
предмет**, содержание соседа не пересказывается, а называется ссылкой.

**Чтение** (MCP `obsidian` подключён): `mcp__obsidian__get_vault_file` /
`search_vault_smart` / `list_vault_files`. Fallback — прямой `Read` от `obsidian/kacho/`.
MCP-сервер пишет в собственную vault-директорию (не всегда совпадает с repo-путём) —
обновление vault делай через MCP-tools, не Edit по абсолютному пути.

## ДО кода (читать минимум — 1-2 узких файла, не 50KB README)

| Триггер | Файл |
|---|---|
| Работа над ресурсом `<X>` | `resources/<repo>-<X>.md` — FK contract, lifecycle, gotchas, ID prefix |
| Меняем RPC | `rpc/<repo>-<service>.md` — методы, REST mapping, sync/async |
| Меняем пакет | `packages/<repo>-<pkg>.md` — exported API, imports, imported-by |
| Cross-service interaction | `edges/<caller>-to-<callee>-<purpose>.md` — protocol, sync/async, error, history |
| KAC-тикет в работе | `KAC/KAC-<N>.md` (создать если нет) |
| Не знаю с чего начать | `INDEX.md` / `README.md` |

Нужно > 3 vault-файлов → остановись и переосмысли scope.

## ПОСЛЕ работы (обновить trail — НЕ упускать)

- Изменилась структура ресурса (поле/status/FK/immutable) → `resources/<X>.md`.
- Добавлен/изменён/удалён RPC → `rpc/<service>.md`. Изменился exported API пакета → `packages/<pkg>.md`.
- Изменилось cross-service runtime поведение → `edges/<edge>.md` + запись в "History" с KAC-номером.
- Затронуто поведение, которого нет в vault → создай **новую** узкую запись (1-3KB).
- KAC-тикет → `KAC/KAC-<N>.md`: «Затронутые сущности vault» + PR-URL + status. Формат — см. `obsidian/kacho/CLAUDE.md`.

## KAC-trail (обязателен для каждого тикета)

`obsidian/kacho/KAC/KAC-<N>.md` создаётся при первом упоминании тикета / создании ветки.
Содержит: Status (in-progress|test|done|wontfix), Type, Repos, PRs, YT-ссылку, «Что и зачем»,
«Затронутые сущности vault» (wikilinks на resources/packages/edges/rpc), DoD-чеклист, связанные тикеты.
Обновлять после каждого merge и смены status в YT.

## Запреты

- Не загружать большой `<repo>/CLAUDE.md`, если хватает 1-2 файлов из vault.
- Не оставлять stale-данные (факт устарел → fix сразу).
- Не дублировать содержимое vault в коде/комментариях/commit-messages.
- **Vault ПУБЛИЧЕН — пишем так, чтобы выдерживало публикацию.** `kacho-workspace` — PUBLIC-репо,
  записки git-committed и уезжают на origin. Никогда: секреты (токены/пароли) и **сборка**
  «точная координата + условие, при котором защита не действовала + следствие для постороннего».
  Да: предмет, решение, следствие для контракта. Разбор, который иначе не написать, **не
  коммитится вовсе**, а в vault идёт высокоуровневая часть **со ссылкой на коммит фикса** —
  дифф и есть постоянный адрес разбора для всякого, у кого есть код. Рабочая директория
  задачи — черновик, а не адрес: она эфемерна, ссылаться на неё нельзя. Долговременного
  непубличного места нет **по построению** (оба репо публичны) — полное правило, три адреса,
  признак восстановимости и три исключения: `security.md` §«Публичные артефакты».
- Канонические теги — только из `obsidian/kacho/CLAUDE.md` (новые синонимы ломают Bases/фильтры).
