disc-recoverability-predicate · переписывать сообщение коммита, если читатель без доступа к коду восстановит по нему состояние до фикса настолько, чтобы воспользоваться · ЗАВЕСТИ disc-recoverability-predicate · red: «уровень контракта и поведения» как критерий
disc-preservation-proof · давать только после git diff <исходный> HEAD -- $(git show --name-only --format= <исходный>) = пусто · ЗАВЕСТИ disc-preservation-proof · red: «влито» без проверки (слияние могло быть частичным)
disc-rewrite-history-needs-owner · переписывать историю публичной ветки принудительно — только с разрешения владельца; штатно — merge --squash + удаление ветки · ЗАВЕСТИ disc-rewrite-history-needs-owner · red: force-push по своему решению

disc-hash-exception-when-rewritten · исходные хеши не перечислять, если сообщения переписаны по дисциплине публичного репо; называть ветку и причину · ЗАВЕСТИ disc-hash-exception-when-rewritten · red: ссылка на объект со старым текстом

### Предмет признака — записи ревью, поимённо перед каждым коммитом (объявлено 2026-09-19; каталог пакетов — решение владельца 2026-09-19)

disc-review-records-subject · судить признаком каждый файл под `docs/specs/reviews/**` и `docs/changes/*/reviews/**`, входящий в коммит, — поимённо и до `git commit`; судит вносящий коммит; перечень — `git diff --cached --name-only -- 'docs/specs/reviews/*' 'docs/changes/*/reviews/*'`, ноль имён значит «судить нечего», а не «признак прогнан» · вниманием вносящего коммит; перечень выводит предикат · red: «каталог уже проверяли» — имя записи есть отпечаток предмета, тело правится без смены имени; форма `docs/changes/*/reviews/` со слэшем молча даёт ноль
disc-record-filter-live-mechanism · первым спросить, жив ли в дереве механизм сборки: снят или не заведён — публикуемо по построению; жив, а фикс не приземлён — через признак · вниманием вносящего коммит · red: живой механизм пропущен как «старое»
disc-record-three-outcomes · исходов три: публиковать; публиковать после правки, и тело записи называет, что снято и почему; не коммитить — в git идёт высокоуровневое со ссылкой на дифф фикса, разбор не пишется никуда · вниманием вносящего коммит · red: правка без пометки — снятое восстановят по истории правок
disc-record-every-occurrence · снимать все вхождения сборки: строка таблицы, пункт, итог, заказ — в одном документе их 2–7 · вниманием вносящего коммит · red: снято одно вхождение, пересказ абзацем ниже остался
disc-record-keeps-verdict · сохранять вердикт с основанием, решения остатка, названных держателей, прямое «держателя нет», заказы следующему · вниманием вносящего коммит · red: запись вымарана до бессмыслицы — её снимут как непонятную, разбор оплатят снова
disc-target-form-inverts · не оставлять дословную целевую форму переноса, если тот же текст называет факт переноса: исходная восстанавливается обращением · вниманием вносящего коммит · red: следствие и живая форма сняты, целевая стоит
disc-editor-is-not-judge · самоотчёт правившего доказательством не считать: правленый по признаку текст до коммита судит другой агент (`нужен следующий: security-auditor`) · вниманием автора правки · red: «снял всё» принято по самоотчёту
disc-record-producer-holds-rule · агенту, чьё тело называет путь записи под этими каталогами, давать правило предзагрузкой либо строкой `Skill rule-security-disclosure` · предикат `grep -l -E 'docs/(specs|changes/[^ ]*)/reviews' .claude/agents/*.md | xargs grep -L 'rule-security-disclosure'` → пусто · red: производитель пишет запись без правила в окне
disc-no-assembly-detector · детектор сборки держателем не объявлять, пока он не прошёл контроль в обе стороны на размеченном наборе; лексиконный провалил его (10 файлов: 3 ложных, 5 пропущенных) · ЗАВЕСТИ disc-no-assembly-detector · red: детектор без контроля назван держателем

Вне поимённого порядка: синтетика гейта контура `scripts/change-graph-gate/tests/testdata/` (предмета в дереве нет по построению) и прочие публичные артефакты — приёмка, записка vault, тело задачи и PR, сообщение коммита; их связывает общая норма выше.
