# `services/iam/internal/authzguard/`

Дом одного вопроса: **каким типом называть принципала** — и всего, что из ответа
следует (перехватчики пола ступени, политика вызывающего, гейт записи отношений).

## Как принципал попадает в модель прав — один предикат, не сборка на месте

| Функция | Отвечает на |
|---|---|
| `SubjectFromPrincipal(p)` | принципал → субъект модели прав; **единственный** источник истины |
| `PrincipalSubject(ctx)` | то же от контекста запроса |
| `HumanUserID(ctx)` | id **только** если это человек — для колонок с внешним ключом в `users` |
| `PrincipalUserID(ctx)` | id любого принципала — для аудита; **шире своего имени** |

**Fail-closed по построению.** Тип, который модель назвать не может, и пустой id
дают `("", false)`; вызывающий обязан читать это как «субъекта нет → отказ».
Прежние копии, собиравшие строку на месте, умалчиваемо считали неизвестный тип
человеком — то есть скрытая выдача прав. Отказ — единственный корректный исход:
назвать принципала чужим типом значит решать доступ по чужим выдачам.

**Служебная учётка — полноправный принципал, а не исключение.** На боевой посадке
токены неинтерактивным вызывающим выдаются именно ей, поэтому администратором
аккаунта и кластера там по факту является машина; вопрос о её правах задаётся
**про неё саму**, и выданные ей права начинают действовать.

> [!warning] Два имени, одно из которых шире своей семантики
> `PrincipalUserID` возвращает id **не обязательно** из таблицы пользователей.
> Следующий, кому нужна колонка с внешним ключом туда, потянется за именем, а не
> за поведением, — поэтому берётся `HumanUserID`. Это сказано и в godoc самой
> функции: одно место об одном предмете.

## Чем держится

Пробы утверждают **имя спрошенного субъекта**, а не только ответ модели. Без этого
класс невидим: хранилище прав отвечает корректным «нет» про субъект, которого нет,
и это неотличимо от честного отказа. Обе стороны с положительным контролем —
человек и служебная учётка проходят, каждый под своим типом; неназываемый тип
получает отказ **не доходя** до хранилища.

Радиус искался **переписью по механизму**, а не по диффу: тот же предикат
разыскивался во всём дереве, а не там, где заметили первый случай. Второе место
(административный маршрут внутреннего листенера) e2e не покрывает — само по себе
оно бы не проявилось.
