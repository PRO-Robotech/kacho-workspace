# deploy/helm/umbrella — зонт: один чарт, семь цепочек, объявления по корням

Зонт развёртывания платформы. Состав **стендов** объявляет не он, а `deploy/stacks.txt` —
единственное место в дереве, где цепочка `-f` выписана; зонт даёт профили, из которых цепочки
складываются. Цепочек **семь**, и они накладываются слева направо, ровно как их получает helm:

| стенд | цепочка профилей |
|---|---|
| `dev` | `values.dev.yaml` |
| `dev-prod` | `values.dev.yaml` + `values.dev-prod.yaml` |
| `prod` | `values.prod.yaml` |
| `own` | `values.prod.yaml` + `values.own.yaml` |
| `fe3455` | `values.prod.yaml` + три накладки `fe3455*` |
| `prorobotech` | `values.dev.yaml` + `values.dev-prod.yaml` + `values.prorobotech.yaml` |
| `a8f60d` | `values.dev.yaml` + `values.dev-prod.yaml` + `values.a8f60d.yaml` |

Рендерные гейты зонта и их контракт исходов — у соседа, [[packages/kacho-deploy-tests-helm]];
здесь они не пересказываются. Гейты **края** о тех же стендах — [[packages/kacho-gateway-deploy]].

## Посадка личности: было 1 из 7, стало 7 из 7

Посадка `own` объявляется **двумя половинами** — службе доступа и краю, — и расхождение половин
есть стенд, у которого о личности решают по-разному. Покрытие по цепочкам (предикат — в
`verified_against`):

| ручка | ствол `bec320cf47d` | ветка `issue-2735-loginlane-prereq` (координата, не живая ссылка) @`6e222f9c1b9` |
|---|---:|---:|
| посадка `identityProvider` (обе половины) | **1 из 7** (`own`) | **7 из 7** |
| `api-gateway.authn.iamLoginLaneUrl` | **1 из 7** | **7 из 7** |
| `kaname.ports.loginLane` | **3 из 7** | **7 из 7** |
| `kaname.mtls.loginLane` — транспорт слушателя | **6 из 7** | **7 из 7** |
| `selfServiceFreshness` — окно свежести самообслуживания | **1 из 7** | **7 из 7** |

Ветка на origin есть, в ствол **не влита** (база — сам `bec320cf47d`, сверху три коммита).
**В рабочей копии продукта её состояния нет**: `project/kacho` стоит на `main`, и правый
столбец таблицы там не воспроизводится — он снят на самой ветке, а не на дереве, где
записка писалась.

**Почему величины полосы стоят в корнях цепочек, а не в накладке посадки.** Под `external` страж
края их не читает вовсе, и объявление ничего не включает; смысл заблаговременного объявления
ровно один — перевод стенда на `own` **не заводит полосу с нуля**. Пока окно свежести стояло
только в накладке, перевод любого другого стенда ронял старт службы по имени этой ручки.

## `values.own.yaml` опустела — и это исход, а не недоделка

Накладка несла ровно три объявления (посадка службы, посадка края, адрес полосы формы). Все три
переехали в корни обеих цепочек, **копий не оставлено намеренно**: два места об одном предмете
разошлись бы молча, и стенд `own` исполнял бы своё объявление, а шесть остальных — чужое. После
переезда файл содержит только пояснение, почему он пуст.

Сам стенд `own` при этом **не снимается**: состав стендов объявляет таблица, на имя `own`
ссылаются рецепты подъёма и приёмка, и решение об инвентаре — не следствие правки посадки. Это
находка со своим предикатом снятия: стек убирается из таблицы вместе со снятием файла и правкой
ссылок на имя.
