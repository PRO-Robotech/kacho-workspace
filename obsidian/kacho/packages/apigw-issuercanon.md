# gateway/internal/issuercanon — канон формы издателя токена

> [!note] Состояние — `test`: пакет есть только в ветке эпика `1266`
> Заведён волной-1 [[KAC/issue-2964]] (задача [[KAC/issue-2758]], коммит `3e84f9bd3d5`). В `main` продукта его
> нет; предикат: `git ls-tree origin/main gateway/internal/issuercanon` → пусто.

**Предмет.** Значение издателя приходит с двух сторон — из объявления края (перечень издателей,
ключи привязки к наборам, наш издатель) и из `iss` предъявленного токена. Обе стороны вправе
писать одного издателя по-разному, а точное сравнение строк тогда молча отвергает токен, который
обязан приниматься, — при зелёном положительном пути на той форме, что совпала случайно. Класс
снимает один канон на пути сравнения **обеих** сторон; второе место нормализации воспроизвело бы
тот же класс между двумя канонами (приёмка KA1 ред. 7, Р5).

## Канон

Абсолютный URL со схемой `http` или `https`, в котором:

- схема и хост — в нижнем регистре; завершающая точка хоста снята;
- порт по умолчанию схемы (`:443`, `:80`) снят;
- процентные коды незарезервированных символов раскрыты, шестнадцатеричные цифры остальных — в
  верхнем регистре; закодированный зарезервированный символ остаётся закодированным;
- завершающая `/` пути снята (пустой путь и `/` — одно); путь и запрос регистра не теряют.

Значение, не являющееся абсолютным http(s)-URL, — ошибка: такому издателю записи быть не может.

## Чего канон НЕ делает

Канон выбирает **запись** приёма; ключ проверки подписи по-прежнему берётся только из набора
выбранной записи, поэтому круг подписантов канон не расширяет.

## Отношения

- Объявление приёма строится через канон в [[packages/apigw-config]]: два издателя с одной
  канонической формой — отказ в старте.
- Выбор записи и сверка издателя проверенного тела — в [[packages/apigw-middleware]].
