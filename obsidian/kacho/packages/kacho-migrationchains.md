# internal/migrationchains — перечень цепочек миграций дерева

> [!warning] Предмет живёт в ветке эпика, а не в стволе
> Пакет появился в `2914-notify` (координата, не живая ссылка) с merge-коммитом
> `2c283f99f4bc`. Предикат снятия оговорки: путь резолвится на `origin/main`.

Пакет — **единственное** место, где выводится тройка «точка наката → каталог цепочки →
база». Гейты, которые обходят миграции, берут цепочки отсюда.

## Зачем понадобился

Раньше каталог цепочки выводили из имени службы: `services/<svc>/internal/migrations`.
Такой вывод верен, пока у службы одна база. У [[packages/notify-service]] баз две, и цепочка
пробы лежит в `internal/probemigrations`. Вывод из имени эту цепочку **не видит**: гейт не
краснеет, а молча её не читает.

## Как устроен

- Таблица «база → каталог» — файл `services/<svc>/cmd/migrator/chains.yaml` рядом с точкой
  наката. Точка читает его через `//go:embed`, пакет — по пути. Если таблицы у точки нет,
  цепочка одна (`internal/migrations`), и по имени базы точка не выбирает.
- `ParseTable` отказывает с именем точки в пяти случаях: таблица пуста; у строки нет базы
  или каталога; каталог лежит вне `services/<svc>/internal/`; база повторяется; каталог
  повторяется.
- Состав берётся из **индекса git**, а не с диска: неотслеживаемый файл перечень не меняет.
  Синтетические деревья гейтовых инъекций идут через `FromTree`.
- `DatabaseOf(dsn)` называет имя базы тем же разбором, которым соединяется драйвер наката
  (`pgx.ParseConfig`). Так выбор цепочки и соединение не могут разойтись по базе. Пустое
  имя — отказ. Текст отказа не несёт кусков строки соединения.
