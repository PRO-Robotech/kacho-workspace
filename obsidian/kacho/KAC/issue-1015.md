# #1015: долг iam сведён в одну линию

## Что и зачем

На 2026-08-22 открытых задач по iam было **22**; две уже шли, значит работы — **20**.
Они были размечены **пятью** разными релизными линиями, и ни одна из пяти не могла
закрыться, пока в ней висел кусок iam. Долг перестал быть предметом и стал россыпью:
у него не было ни одного места, где видно целое, и ни одного условия, по которому
его можно объявить исчерпанным.

Отсюда решение: одна линия, один агрегат, один вердикт.

## Решение

Работа разбита на **семь полос** по **предмету правки**, а не по размеру, — полосы не
трогают одни и те же файлы, поэтому идут параллельно и собираются одной волной:
мелкие гейты · путь прав · тихие отказы квот · идентичность (внутри себя
последовательна: схема, потом снятие) · журналы аудита · поверхность выдач ·
наблюдаемость квот. Два предмета вынесены из волны отдельными работами как XL —
снятие внешнего поставщика личности и единство квот.

Перечень задач в теле эпика **намеренно не выписан списком**: выписанный разошёлся бы
с трекером молча, и этот класс в корпусе уже срабатывал на трёх рукописных перечнях.
Вместо списка — команда выборки по метке.

2026-08-23 метка линии упразднена решением владельца: её задачи разошлись по **двум**
предметам (личность и квоты), и держать третью линию поверх них значило бы вести один
долг под двумя именами. Остаток по iam ведётся линией `release:identity` —
[[KAC/release-identity]].

## Чем держится

Предикат готовности — **пара** условий, и второе не выводится из первого:

1. открытых задач с меткой линии — **ноль** (выборка `gh issue list --label … --state open`
   даёт пусто);
2. накопительная ветка влита в ствол **настоящим слиянием** — два родителя, с переписью
   потерь по путям ствола.

Ноль задач при невлитой ветке готовностью **не является**: работа существует, но её нет
там, где ею пользуются. Оба условия проверены замером, а не впечатлением: MR #1054,
слияние `34cec3c3a` (2026-08-23), ветка снята с origin.
