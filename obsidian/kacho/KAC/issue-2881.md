# kacho#2881: образ консоли не публикуется для ветки ни одним путём

**Состояние на момент записи**: `to-do` — 2026-09-26. Задача **открыта**, метки: `bug`, `P2`,
`size:S`, `area:ui`, `area:ci`, `release:platform`; родителя нет. Заведена 2026-09-26T12:15:18Z
по итогам выкатки линии эпика `2564` (координата, не живая ссылка). Роль — `deploy-engineer`.
Работы по ней нет.

## Что и зачем

**Признак.** В `.github/workflows/ui.yml` (одинаково в этом месте на `main` @ `1d42a6728bf` и на
`2564` @ `7190c3e5274`) шаг, включающий публикацию, пропускает её на всех событиях, кроме
`push`, а `push` у файла объявлен только для `main`. На `pull_request` и `workflow_dispatch`
образы собираются и выбрасываются — шаг сам это печатает. У служб путь для ветки есть:
`docker-build.yml` через `workflow_dispatch` публикует любую ветку тегом `<ветка>-<sha8>`.
Следствие: консоль ветки линии на стенд не доезжает; при выкатке линии 2026-09-26 её собирали на
стенде вручную (со слов журнала выкатки, по телу задачи).

**Предмет.** У ветки линии (`[0-9]+`) есть путь публикации девяти образов консоли без ручной
сборки — тот же, что у служб, либо другой, выбранный с доводом в задаче.

## DoD

Из тела задачи, раздел «ПРЕДИКАТ» (перечислено как есть):

1. названный путь, запущенный на ветке `2564`, публикует все девять образов
   `kacho-ui-future-<проект>`; по тегу однозначно читаются ветка и ревизия; ссылка на прогон;
2. близнец: событие `pull_request` по-прежнему не публикует — проверяется прогоном запроса в ту
   же ветку;
3. стенд ветки поднимает консоль из опубликованного образа без ручной сборки, ревизия образа
   равна голове ветки.

Артефакт — PR с `Closes` этой задачи, ссылка на прогон публикации и теги образов комментарием.
Проверка на дубли — в теле задачи, дублей нет.
