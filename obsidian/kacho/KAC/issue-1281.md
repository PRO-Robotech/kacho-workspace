# kacho#1281: второй фактор становится предметом продукта — приёмка одобрена, реализация идёт

**Предмет.** Фаза Ф12 эпика `kacho#1266` (вход: Ф3 [[issue-1269]] и Ф11 [[issue-1280]]).
Конфигурация внешнего провайдера объявляла вторым фактором одноразовый код по времени и
запасные коды, а замер живой базы 2026-08-25 давал **ноль и ноль** при `password = 80`,
`webauthn = 3`; у запасных кодов — ноль вызывающих в консоли. Класс «принято-и-проигнорировано».
Ф12 делает фактор предметом продукта: хранение секрета шифрованным, подключение с проверкой
первого кода, ввод при входе, окно расхождения часов, защита от подбора, отключение с
подтверждением; запасные коды — чеканка набором, однократность, перечеканка, предупреждение об
исчерпании. Успешное предъявление поднимает уровень уверенности до «2» (Ф11).

## Посылка задачи — подтверждена (перемер 2026-09-05, `975512cbd`)

`git grep -licE 'totp|lookup_secret'` по Go службы и контракту без проб → **0**, контроль по
`deploy/` → **4**: возможность объявлена конфигурацией и не имеет в нашем дереве ни хранения, ни
глагола, ни читателя. Живая база в той полосе не перемерялась (кластер чужой) — дерево даёт тот
же вывод независимо от неё.

## Приёмка — два круга, одобрена

`PRO-Robotech/kaname:docs/engineering/acceptance/second-factor-totp-and-recovery-codes.md`, PR
kaname#185 (ветка `acceptance/1281-second-factor`, база `release/iam-lines`), редакция 5,
2089 строк. Круг 1 — `CHANGES_REQUESTED` (четыре блокирующих, восемь важных; исход по каждому —
§12 документа, дрейф базы линии перемерен в §12.1). Круг 2 — **APPROVED** 2026-09-16, ревизия
`f366b5e1`, отпечаток `b71c3ff7…`: 4 → 0, каждое проверено тем же предикатом записи круга 1 с
другим результатом (матрица Р4 «8 глаголов × 3 состояния»; §5 «часы сдвинуты после принятого
кода»; Р5/Р6 «строку меняет только полный успех» — неудавшееся предъявление не потребляет
запасной код; стоимость хеша сверяется с полом записи по PWV-16 одобренной ID-PW-1).

**Решения, ратифицированные вместе с APPROVED:**

| ось | решение |
|---|---|
| материал набора запасных кодов | медленный хеш дисциплины ID-PW-1 под той же ёмкостью, что пароль (F4d-18 держится формой) |
| однократность одного кода и годность разных под конкуренцией | сериализацией на строке набора |
| окно ±1 шаг | решение Ф12, а не тела задачи (тело называет окно без величины) |
| «фактор не заведён» | один код и один `reason` на входе, в церемонии, снятии и сбросе |
| защита от повтора | свойство строки, не сессии |
| **обязателен ли фактор и для кого** | решение, которое задача обязана принять, — принимается в документе, не обходится |

Что вердикт **не** утверждает: стенд не поднимался; кода по документу на момент вердикта нет.
Что санкция открывает: реализацию Ф12 после Ф3 (в `main` службы) и остатка Ф11 (A2); пол «2» у
27 записей каталога получает производителя — посадка `own` (`kaname#21`) становится достижимой.

## Предикат снятия (из тела задачи)

Код подключается, применяется и отвергается по истечении окна; запасной код срабатывает один
раз; подбор ограничен; уровень уверенности после предъявления равен «2»; отключение требует
подтверждения. Проба на каждый исход, включая отказы.
