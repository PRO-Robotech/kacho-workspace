# KAC-228: dev-up не сеет cluster viewer:* и не зовёт fga-bootstrap → 403 regions / 503 projects

**Состояние на момент записи**: done
**Type**: fix
**Repos**: kacho-deploy
**PRs**: PRO-Robotech/kacho-deploy#66 (merged)
**YT**: https://prorobotech.youtrack.cloud/issue/KAC-228

## Что и зачем

Persistent-фикс корней permission-ошибок стенда (раньше латались вручную на живом OpenFGA-store):

1. **`/compute/v1/regions` (zones/diskTypes) 403** — `openfga-bootstrap-job` сеял только `cluster:cluster_kacho_root#system_viewer@user:bootstrap_marker`, но НЕ `cluster:…#viewer@user:*`. FGA-модель: `cluster.viewer = [user, user:*, …]` — без tuple любой cluster-scoped reference-RPC (`required_relation=viewer`) → 403 любому юзеру.
2. **`/iam/v1/projects` 503** — `make dev-up` не звал `fga-bootstrap` → store не провижен на signup → iam fail-closed (Unavailable→503), а account/project tuple'ы (`fgahook`, best-effort) терялись. + dev-up собирал только UI-образ → 5 backend в ImagePullBackOff → `helm --wait` timeout → bootstrap-RBAC не применялся.

## Фикс

- `openfga-bootstrap-job.yaml`: + seed `cluster:cluster_kacho_root#viewer@user:*` (Step H2).
- `Makefile`: `build-services` (5 backend-образов) + `dev-up` собирает их до helm + зовёт `fga-bootstrap` после (store+seeds ДО signup).

Verify: `make -n dev-up` (build-ui→build-services→helm→fga-bootstrap→rollout-wait); `helm template` рендерит viewer:*; live-стенд: все ранее падавшие пути → 401 (authz резолвится). Полный fresh `dev-up` не гонял, чтобы не сносить активный стенд — эквивалентный tuple проверен live.
