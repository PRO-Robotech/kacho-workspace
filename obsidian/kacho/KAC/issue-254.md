# #254: правило обещало владельцу послабление, которого нет

**Type**: fix. **Состояние на момент записи**: done — закрыто движением дерева до того,
как за задачу взялись (2026-08-18).
**Чем сверено**: `kacho-workspace@98e208e` плюс ответ API обоих репозиториев.

## Что и зачем

`multi-agent-flow.md` §8а утверждала, что обход защиты ветки оставлен администратору, и
объясняла это тем, что владелец не должен оказаться заперт собственным правилом. Дерево
говорит обратное: защита связывает всех, включая владельца.

Опасность здесь не в самой строке, а в направлении, куда она посылает читателя. Упёршись
в отказ сервера, он ищет причину не там — он ждёт, что для него запрет не действует.
Правило `@import`-ится в каждую сессию, поэтому ложное утверждение о настройке читается
чаще любого другого.

## Предикат и исход

Утверждение правила и ответ API обязаны совпадать в обоих репозиториях:

```sh
gh api repos/PRO-Robotech/kacho/branches/main/protection -q .enforce_admins.enabled
gh api repos/PRO-Robotech/kacho-workspace/branches/main/protection -q .enforce_admins.enabled
```

Обе команды отвечают `true`. Правило на `98e208e` называет ту же величину тем же словом:
прежняя формулировка снята и заменена разбором ошибки, а норма от этого стала строже —
прямой push в `main` отвергается для всех.

Остатка нет: утверждений о послаблении владельцу в корпусе правил больше не встречается,
единственное вхождение имени настройки — сам разбор.

## Кто закрыл

Правка внесена 2026-08-17 коммитом `623b04f` (PR ws#266) в ходе соседней линии, не этой
задачей. Записка заведена ретроспективно, чтобы закрытие имело след: задача была из
перечня `release:gates`, и «закрылось само» обязано быть доказано предикатом, а не
впечатлением.
