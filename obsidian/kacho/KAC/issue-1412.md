# #1412: перенос читателя отзыва в фундамент отменяет обе починки #1022

Закрытие эпика [#1016](https://github.com/PRO-Robotech/kacho/issues/1016) «единый поток изменений ресурсов». Линия работ — [[KAC/watch-unified-change-stream-2026-08]]. **Опасность СВЕДЕНИЯ, а не дефект какой-либо ветки по отдельности.**
Заведена, потому что чат не переживает волну, а предмет переживёт.

## Предмет

[[KAC/issue-1022]] починила в читателе отзыва две вещи:

1. **порт несёт ИМЯ субъекта**, а не только номер, — потому что закрыть открытый поток
   можно только **названного**; голый идентификатор не совпадает с ключом реестра ни при
   каких условиях;
2. **курсор двигается только по прочитанным строкам** — подъём до максимума таблицы
   перепрыгивал через непрочитанное при заделе больше порции, то есть терял отзывы **ровно
   при массовом отзыве**.

[[KAC/issue-1024]] переносит этот читатель в фундамент и несёт там **дореформенную**
версию обоих мест. Слияние «как есть» вернёт оба дефекта — **молча**: код соберётся,
пробы #1024 останутся зелёными (они про сброс кэша, которому имя субъекта не нужно), а
пробы #1022 уедут вместе со снятым каталогом.

Это **третий вид столкновения** из `multi-agent-flow.md` §14: обе ветки правы по
отдельности, ломается сведённое дерево, и по отдельности это не находится ничем.

## Что делать при сведении

Сохранить перенос (#1024), **перенести** в него обе починки, а не выбирать сторону. Вместе
с ними переезжают их доказательства — четыре пробы, названные поимённо в теле задачи.

## Предикат снятия

В **сведённом** дереве: порт читателя отзыва возвращает имя субъекта, а не только номер;
подъёма курсора до максимума вне праймящего пути нет; все четыре пробы живы и зелены.

## Состояние

Открыта, `status:test`. Предмет возникает только на сведении волны.
