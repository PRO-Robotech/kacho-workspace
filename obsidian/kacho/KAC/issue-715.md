# #715: имя ресурса — одна форма по RFC 1123, пустого не бывает, алиасов нет

**Type**: feature

**Состояние на момент записи**: in-progress — канон реализован и лежит в
`release/gates-verdict` (MR #712), фикстуры проб под него приводятся, вердикт
конвейера не прочитан.

**Где ведётся**: `PRO-Robotech/kacho` — `pkg/validate/nameform`, пять сервисов;
`PRO-Robotech/kacho-workspace` — `.claude/rules/api-conventions.md`.
**PRs**: PRO-Robotech/kacho#712 (в работе), PRO-Robotech/kacho-workspace#284 (влит)
**Issue**: https://github.com/PRO-Robotech/kacho/issues/715

## Что и зачем

Валидаторов имени в дереве было **четыре**, и они разошлись по трём осям:

| валидатор | заглавные | подчёркивание | пустое |
|---|---|---|---|
| `Name` | нет | нет | допускает |
| `NameVPC` | **допускает** | **допускает** | допускает |
| `NameCompute` | нет | **допускает** | допускает |
| `NameGateway` | нет | нет | допускает |

Расхождение доходило до хранилища: среди уникальных индексов имени **полных было
пять**, у них пустое имя занимает слот, у частичных — нет. Наблюдаемо арендатору:
вторая сеть с пустым именем в проекте получала `409`, вторая подсеть — нет. Один
контракт исполнялся по-разному в зависимости от ресурса.

## Решения владельца — четыре, все приняты 2026-08-18

1. **Пустого имени не существует.** Пустая строка остаётся законным входом создания,
   но ресурсом с пустым именем не становится: сервер проставляет имя, производное от
   `id`, и возвращает его. Правка на пустое отвергается.
2. **Форма одна на всё дерево** — DNS label по RFC 1123
   `^[a-z0-9]([-a-z0-9]{0,61}[a-z0-9])?$`.
3. **Исключений по доменам нет** — geo и регион тоже. Прежнее изъятие (у geo имя
   свободный ярлык `RU Central 1`) снято.
4. **Алиасов не делаем** — отдельного поля под человекочитаемую подпись не заводится.
   Читаемость обеспечивает сама форма, а не второе поле.

### Почему проставлять, а не требовать

Требование имени — ломающее изменение у каждого создающего глагола (36 публичных
`post:` без `:verb`). Клиент, сегодня законно не шлющий имя, начал бы получать `400`
без выигрыша для себя: адресуется он по `id` (ban #15), имя косметическое.

### Почему от `id`, а не подбором

`id` глобально уникален by construction, значит производное имя уникально в проекте
**без** проверки-перед-вставкой. Любое «посмотреть, занято ли, и взять следующее» —
software check-then-act, запрещённый ban #10: под конкуренцией два создания увидят
одно свободное имя.

### Почему без алиаса

Два имени одного предмета расходятся молча — ровно та болезнь, с которой всё
началось. Пара «канон + подпись» воспроизвела бы её на уровне модели: подпись правят,
канон нет, через месяц они называют разное.

## Как сделано

Форма живёт в **`pkg/validate/nameform`** — новом пакете **без транспорта**. Это не
косметика: `pkg/validate` тянет grpc, а импорт в Go пакетный, поэтому доменный слой
ради одной строки потянул бы grpc и нарушил `architecture.md`.

Простановка — `NameOrDefault` (21 вызов), проверка на правке — `NameOnUpdate`
(45 вызовов, пять исходов). Миграции `715001` у vpc, compute, storage, nlb; geo
добавлен поправкой владельца. Гейтов два: единственность формы и единственность
производства, оба с инъекцией в обе стороны.

**Уточнение исполнителя, принятое как верное**: отказ на правке даётся только когда
маска **называет** `name`. Причина — proto3 не отличает «не прислано» от «пусто», и
безусловный отказ сломал бы всех, кто правит метки полным PATCH'ем.

## Чем это стоило — три измерительных промаха подряд

Класс задачи оказался не в коде, а в измерении, и это главный урок записки.

1. **Предикат цены ужесточения был негоден трижды**: считал заголовки шагов вместо
   имён ресурсов (дал 5286), ловил подстановку `{{runId}}` (750), ловил собственную
   нормализацию — заменял подстановку на заглавную `X` (750). Годный дал **104 из
   768**; исполнитель перемерил по референту — **124 из 892**, живых 42, настоящих
   поломок 3.
2. **Исполнитель мерил цену только по сквозным кейсам** (`cases/*.py`) — пробы Go не
   мерил вовсе.
3. **Я, проверяя его гипотезу, смотрел только файлы `*integration*_test.go` у vpc** —
   нашёл одно ложное попадание и заключил, что фикстуры ни при чём. Падает
   `security_group_rules_domain_integration_test.go`, файл другого шаблона имени.

Предмет вскрылся только воспроизведением на живой базе:

```
ERROR: new row for relation "security_groups" violates check constraint
       "security_groups_name_check" (SQLSTATE 23514)
```

Настоящий радиус фикстур: **170 негодных имён из 888** по всем пробам Go, из них в
сервисах с `CHECK` — 37 (vpc 23, storage 6, compute 5, nlb 3), плюс geo после снятия
изъятия.

## Затронутые сущности vault

- [[checks-with-form-but-no-substance]] — четыре валидатора одной формы, разошедшиеся
  молча, суть тот же класс;
- [[a-declared-predicate-can-be-wrong-and-then-it-lies-confidently]] — три негодных
  предиката подряд на одном предмете.

Отдельно про промахи 2 и 3: у них общий корень — **радиус брался по шаблону имени
файла, а не по механизму**. Записки под этим именем в vault нет; класс покрывается
[[a-declared-predicate-can-be-wrong-and-then-it-lies-confidently]], и заводить второе
место об одном предмете я не стал.
