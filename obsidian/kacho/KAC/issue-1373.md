# #1373: дельта величин читается по голому номеру — смена предела теряется навсегда

Закрытие эпика [#1016](https://github.com/PRO-Robotech/kacho/issues/1016) «единый поток изменений ресурсов». Линия работ — [[KAC/watch-unified-change-stream-2026-08]]. Найдена **по дороге** к [[KAC/issue-1053]]: тело той задачи утверждало, что
все прочие журналы читаются очередью с клеймом. Замер по дереву это опроверг.

## Предмет

Чтение дельты величин идёт строго «больше курсора», без верхней границы, по счётчику,
номер которого выдаётся **на записи**, а строка становится видимой **на фиксации**. Между
этими двумя моментами есть окно, в котором номер уже выдан, а строка ещё не видна.
Читатель, продвинувший курсор за такой номер, эту строку не получит **никогда** —
перечитывание идёт строго вперёд, и сходиться тут нечему.

**Цена именно здесь выше средней**: курсор сохраняется между проходами, а тянут эту дельту
**пять** доменов. Потерянная строка означает, что смена предела администратором до живого
проекта **не доезжает** — и не доедет. Ровно этот механизм `data-integrity.md` §«Счётчик
потолка живёт РЯДОМ С РЕСУРСОМ» называет единственным способом, которым величина догоняет
владельца.

Тот же класс, что закрыт для механизма подписки задачей [[KAC/issue-1053]].

## Предикат снятия

1. чтение ограничено сверху **границей устоявшегося** — техника уже написана и лежит в
   фундаменте ([[packages/corelib-subscription]]), переносится, а не пишется заново;
2. проба воспроизводит окно: писатель держит транзакцию открытой → читатель проходит мимо
   → писатель фиксирует → строка обязана доехать. Образец переносится;
3. запись в самоистекающей ведомости гейта верхней границы снята — она уронит прогон, если
   останется без предмета.
