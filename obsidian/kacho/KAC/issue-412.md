# issue-412 — чтение квот арендатором у всех списывающих доменов

**Назначение:** trail задачи. **Категория:** KAC. **Состояние:** test (сдано в релизную ветку,
ждёт вливания в ствол). **Чем сверено:** `PRO-Robotech/kacho` PR #606 → `release/quota-domain`.

## Что и зачем

Списывали квоту пять доменов, а **отвечал арендатору один**. Предел существовал, потребление
считалось, а увидеть своё состояние арендатор мог только в vpc. Хуже: снимок величины догонял
авторитет тоже только там — в остальных четырёх смена предела администратором не доезжала
никогда, то есть предел был назначен и не действовал.

## Перепись по трём осям — предикаты повторяемые

```sh
git grep -l 'kacho_quota_count('  -- 'services/*/internal/migrations/*.sql' | cut -d/ -f2 | sort -u
git grep -l 'service QuotaService' -- 'proto/kacho/cloud/*/v1/*.proto'      | cut -d/ -f4 | sort -u
git grep -l 'quota_sync_cursor'   -- 'services/*/internal/migrations/*.sql' | cut -d/ -f2 | sort -u
```

| ось | было | стало |
|---|---|---|
| списывают | compute · nlb · registry · storage · vpc | без изменений |
| отвечают на чтение | **vpc** | все пять |
| догоняют величину | **vpc** | все пять |

Контроль в обе стороны: те же множества сняты ещё двумя независимыми признаками (регистрация
сервиса в композиционных корнях; маршрут края и запись allowlist) — все три совпали.

**Ловушка, которую перепись обязана обойти:** `loadbalancer` в контрактах и `nlb` в миграциях —
один домен под двумя настоящими именами. Соответствие объявлено в гейте **явно**; вывод по
совпадению имён молча пропустил бы пятую часть предмета.

Виды закрытого каталога — 31: vpc 12 (8 проектных), compute 3/3, storage 3/3, loadbalancer 4/3,
registry 3/2. Чтение отвечает только про проектные: у вложенного вида единственного значения на
уровне проекта нет by construction.

## Решения, принятые заново (образец vpc был неполон)

1. **Унификация вместо четырёх копий.** Тело чтения, оператор чтения строк, перевод в контракт,
   тяга дельты и подъём тянущего вынесены в `pkg/quota*`; vpc переведён на общее **тем же
   изменением**, иначе эталон разошёлся бы с копиями молча.
2. **`ResolvedLimit` — один тип, пять псевдонимов** (было пять независимых структур).
3. **Два имени сервиса, а не одно:** каталог знает виды как `loadbalancer`, ответ обязан называть
   источником `nlb`.
4. **Схема compute — `public`**, не `kacho_compute`: миграции идут без квалификации. Ошибка здесь
   не ломает сборку, а отвечает «строк нет» — доказано интеграционной пробой.
5. **Чтение и синхронизатор едут вместе.** Порознь чтение показывало бы величину, которая никогда
   не догонит назначенную, — то есть витрину, врущую уверенно.

## Чем держится

Гейт `TestEveryQuotaChargingOwnerAnswersTheTenantRead` написан **до** кода и краснел восемью
координатами (перепись: миграций 263, контрактов 122; списывают 5, отвечают 1, догоняют 1). После
работы — `списывают 5; отвечают 5; догоняют 5`. Плюс по суите на каждый домен: свой предел и
потребление · чужого не видит · пустой проект → отказ по имени поля · непровязанная полоса →
названный отказ. Способность упасть доказана инъекцией в общую полосу.

## Прогоны

`-short` зелено · `-race` по services/pkg/gateway зелено · `-tags integration -run TestQuota`
зелено на всех пяти доменах, включая применение новых миграций · `buf lint` чисто, `buf generate`
дал 12 новых файлов и ноль правок существующих стабов · линт чисто · консоль 207 суит / 1844 пробы
зелено.

## Попутно

- Витрина квот спрашивала одного владельца — теперь всех пятерых, закреплено пробой.
- Документ storage утверждал, что поднятие предела «догоняет через промах снимка» — промаха не
  бывает; исправлено разбором, а не удалением строки.
- `kacho#353` не тронут; находки написаны в его комментарий: вложенных видов в каталоге **6**, а не
  28 — знаменатель той задачи меряет другую ось.
