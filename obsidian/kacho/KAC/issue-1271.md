# kacho#1271: восстановление доступа — код, второе письмо, существующее завершение

**Предмет.** Фаза Ф5 эпика `kacho#1266` по одобренной приёмке
`PRO-Robotech/kaname:docs/engineering/acceptance/recovery-of-access.md` (запись ревью
`e889257f…`, `issued: true`). Чеканка и проверка кода, второй вид письма в нашей почтовой
очереди, вызов существующего завершения, отвязка ответа от постановки письма.

## Решения, принятые здесь (приёмка их не пересматривала)

| ось | решение | почему |
|---|---|---|
| форма завершения | **код и новый пароль — одним обращением** (`POST /iam/v1/auth/recovery/complete`, поля `email`, `code`, `newPassword`, `csrfToken`) | Ф5-17 и Ф1-59: заблокированная личность проходит восстановление до конца (учётные данные сменены) и сессии **не получает** — шага «задать пароль из сессии» у неё быть не может. Требование Ф1-27 «до любого иного действия» держится построением: сессии до записи пароля не существует. Сессия выдаётся с `passwordChangeRequired: false` |
| код | 10 знаков алфавита Крокфорда (50 бит), для человека `XXXXX-XXXXX`; хранится **свёртка** SHA-256; тип не сериализуется | Р1: прочитанное из хранилища предъявлением не является (Ф5-07); граница названа в шапке `domain/recovery_code.go` — свёртка без ключа обратима перебором, второй рубеж против читающего базу — срок и однократность |
| однократность | `UPDATE … SET consumed_at WHERE … consumed_at IS NULL AND expires_at > $now RETURNING` | ban #10; под конкуренцией из 8 предъявлений проходит ровно одно (проба на базе) |
| частота | те же счётчики и величины, что у входа (`login_failures`, `authn.login.address-*`/`source-*`) | Ф5-08 «величины объявлены настройкой»; неверный код и неверный пароль — одно и то же неверное предъявление по адресу |
| порядок в предъявлении | форма → частота → **правило пароля** → чтение адреса → транзакция | негодный пароль называет поле и **не тратит код**; правило от существования адреса не зависит |
| постановка письма | диспетчер вне пути ответа (`GoDispatcher`, свой контекст, предел 30 с; гашение дожидается начатого) | Р2: разница работы двух полос не читается секундомером; замер Ф5-20…22 ниже |
| ключ резолва журнала | `recovery_completions.external_id` стал необязательным (NULL у нашего потока); ключ идемпотентности — `id` строки кода | Р4 и находка оркестратора в `kacho#1271`: у личности нашей регистрации внешнего субъекта нет |
| гейт MAIL-47 | перечень **наших** видов письма закрыт: `invite`, `recovery`; чужой по-прежнему `verification` | Ф5 Д5: вид восстановления переезжает к нам вместе с истечением потока поставщика |
| личность без способа входа паролем | отказ операции (503, код остаётся годным, причина в журнале) | запись нового способа — предмет Ф2 (ID-PW-1), второго писателя способа входа не заводится; названо находкой |

## Пары RED → GREEN

- Ф5-10 гейт: миграция без ветви применителя — `видов письма 2 · с отправителем 1` (FAIL, координата миграции) → `2 · 2` (PASS).
- Пробы кода, завершения, транспорта, ручки, слушателя: не собирались на отсутствующих именах (`undefined: NewRecoveryCodeValue`, `humansession.CompleteRecoveryOutput`, `clients.MailEvent`, `RecoveryCodeTTL`) → зелены: домен 5, use-case 13 + диспетчер, хранилище 8 (на базе), транспорт 4, слушатель 4, настройка 2.
- Ф5-20…22 (ручной прогон, настоящая база): |Δмедиан| 22 µs ≤ IQR 78 µs; инъекция «постановка на пути ответа» — красное, 507 µs при размахе 58 µс; потолок годности = стоимость инъекции 507 µs.

## Что осталось и чем закрывается

- **Ф5-14** — производитель `kacho#1773` (доставка), названо приёмкой; здесь не реализуется.
- **Ф5-23/24** — держит Ф3 (`ClearPasswordChangeRequired`, отказ края `PASSWORD_CHANGE_REQUIRED` на посеянной сессии); поток Ф5 сессии с требованием **не выдаёт** — см. решение выше и находку в отчёте.
- **Край** (`kacho`): ретрансляция шести путей полосы формы и профиль чарта с `KANAME_AUTHN__LOGIN__RECOVERY_CODE_TTL` — вместе с посадкой полосы Ф3 у края, которой в стволе платформы ещё нет (`git grep -c 'iam/v1/auth/login' origin/main -- gateway` → 0).
- **Отчёты R7-1/R7-2/R7-3** пересняты под новую миграцию (гейт свежести считает `REFERENCES kaname.users` в `CREATE TABLE` изменением структуры измеряемой таблицы — `PRO-Robotech/kaname#199`). Находки владельцу: `kacho#2697` (форма завершения), `kacho#2698` (личность без пароля), `kacho#2700` (частота запроса кода), `kacho#2701` (край и чарт).
