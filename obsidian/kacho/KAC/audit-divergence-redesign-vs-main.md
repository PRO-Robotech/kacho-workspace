# Аудит расхождения `redesign/integration` vs `main` — раунд 1

Scope: **230 коммитов, 1024 файла, +127k/−55k** (весь 7-доменный редизайн). Harness —
skill `hardening-audit-loop`, адаптированный под монорепо: 8 per-area finder'ов × 6 дименсий
(security/leak/performance/concurrency/correctness/structure/readability/lean) → **adversarial
refute-verify** каждой находки (default `real=false`).

## Девять HIGH — по классам

Поимённый разбор в git не идёт (см. §«Где лежит разбор»); классы — идут, иначе запись
перестаёт объяснять, зачем раунд проводился.

- **Кредо вместо сетевой позиции (3 находки об одном).** Выдача первого административного
  удостоверения гейтилась тем, **откуда** пришёл вызов, а не тем, **чем** вызывающий себя
  доказал. Комментарии в трёх местах прямо продавали посылку «внутренний периметр
  доверенный» — запрещённую `security.md`. Решение владельца — ниже.
- **Привязка чужого ресурса по ссылке (BOLA), дважды.** Ссылка на объект соседнего сервиса
  валидировалась по размещению, но не по принадлежности проекту: consumer принимал
  caller-supplied идентификатор чужого объекта. Тот же класс отдельно — на источнике
  содержимого при создании образа: содержимое чужого приватного тома утекало в свой образ.
- **Пустая маска обходит админ-гейт.** Гейт на привилегированное значение срабатывал только
  при наличии поля в `update_mask`; пустая маска — законный full-object PATCH по
  `api-conventions.md` — его миновала. Урок общий: **гейт обязан жить там же, где
  применяется значение**, а не там, где оно упомянуто.
- **Область проверки прав выбирается вызывающим.** Переопределение уровня, против которого
  задаётся вопрос о правах, применялось без привязки к методу и читалось из произвольного
  тела запроса.
- **Понижение планки step-up на грант-поверхности.** Метод, атомарно создающий выдачу прав,
  получил планку обычной операции — тогда как выдача прав относится к
  posture-changing ([[step-up-acr-sensitive-only]]).
- **Миграция, не переживающая непустую таблицу.** `ADD COLUMN … NOT NULL` без умолчания и
  без обратного заполнения — апгрейд существующего стенда невозможен. Класс не
  security, но блокирующий: редизайн проверялся только на пустой базе.

## Решение по mint (владелец, 2026-07-24)

Владелец: «если в итоге сделали через рут-токен, встраиваемый секретом и пригодный для
аутентификации с root — то mint можно удалить». **Проверено по коду — такого механизма
НЕТ**, и это главный содержательный вывод раунда:

- переменная бутстрапа с адресом почты **не является удостоверением**: она выдаёт
  административные права уже существующему пользователю, которому всё равно нужен
  интерактивный вход;
- ключ в боевых значениях — это ключ **подписи самого минта**, которым сервис подписывает
  себя перед провайдером токенов; вызывающий не предъявляет ничего;
- выдача ключа служебной учётке требует уже имеющегося административного токена
  (курица-яйцо).

⇒ **mint удалять нельзя** — это единственный неинтерактивный вход в первый настоящий токен,
на него опирается посев боевого стенда. **Фикс — сделать гейтом настоящее удостоверение
вместо сетевой позиции**: снять credential-free маршрут и требовать проверенный клиентский
сертификат из явного круга отправителей (fail-closed в production boot-guard, core rule
#16) и/или доказательство владения уже выданным секретом. Курица-яйцо не возникает —
секрет раздаётся деплоем. Лживые комментарии «внутреннее значит доверенное» — исправить.

## Четырнадцать MEDIUM — по классам

- **Оракул существования на чужом объекте**: структурные проверки читают чужую роль и чужой
  проект **до** проверки полномочий на выдачу, на методе, у которого проверка прав на краю
  отключена.
- **Снимок без блокировки на пути отзыва**: конкурентный проход дописывает то, что отзыв уже
  снял, а повторного снятия по построению не будет.
- **Кардинальность без потолка, трижды**: набор в запросе не ограничен ни контрактом, ни
  проверкой, а обработка линейна по нему; отдельно — по одному синхронному вызову к соседу
  на каждый элемент без дедупликации и общего бюджета; отдельно — набор блоков сети без
  верхней границы.
- **Унифицированный путь собран не полностью**: один из списочных путей потерял ветку
  административного каскада, которая есть у всех соседей.
- **Мягкое удаление без предиката в чтении**: отозванные выдачи остаются видимыми, потому
  что списочный запрос не знает о новом состоянии.
- **Software check-then-act вместо DB-инварианта** (ban #10): проверка вложенности диапазона
  читает родителя обычным SELECT без блокировки.
- **Ссылка в той же БД без внешнего ключа**: строка каталога удаляется без единой проверки
  ссылающихся.
- **Колонка и публичное поле, которых никто не пишет**: объявлены, отдаются наружу, всегда
  пусты.
- **Метод на внутреннем слушателе без записи в карте прав** — fail-closed на каждом вызове
  (обратная сторона того же дрейфа каталога).
- **Контракт дренажа объявляет безопасным то, что безопасно лишь при условии**, которое
  для этой пары эмитентов не выполняется.

## Пять LOW (в раунд 1 не чинились — фильтр проверки отсекает LOW)

пустая маска в административном обновлении молча затирает поля · имена чужих облаков
вернулись в отгружаемый дескриптор (ban #2) · в боевом оверлее административный путь к
провайдеру токенов остался plaintext, а обоснование в комментарии риска не покрывает ·
адрес набора ключей выставлен **только чтобы удовлетворить boot-guard** (класс «контроль
включён, но ведёт в никуда», `security.md` §Hardening-9) · фикстура пишет сырую запись прав
вместо продуктового пути.

## Где лежит разбор

**Не в git.** Оба репозитория публичны ([[internal-vault-is-public]]), а поимённый разбор
по устройству есть сборка «координата + условие + следствие»: заголовки вида `файл:строка`
плюс условие, при котором защита не действовала. Прежняя редакция этой записки такой
сборкой и была (23 координаты). Разбор живёт в рабочем каталоге задачи; здесь остаётся то,
что публикацию выдерживает: числа, классы, решение владельца и порядок работ.
