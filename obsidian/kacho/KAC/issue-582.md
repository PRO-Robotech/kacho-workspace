# #582: имя джобы стало контрактом с защитой ветки — и разошлось

**Type**: fix

**Состояние на момент записи**: test — сделано в линии `release/contract-hygiene`,
PR PRO-Robotech/kacho#671, коммит `5b6b286e`. В `main` ещё не влито.

**Где ведётся**: `PRO-Robotech/kacho` — `.github/scripts`, `.github/workflows`.
**PRs**: PRO-Robotech/kacho#671
**Issue**: https://github.com/PRO-Robotech/kacho/issues/582

## Что и зачем

С заведением обязательных проверок ствол стал требовать **45** зелёных контекстов. Имя
контекста — это строка имени джобы после подстановки матрицы. Тем самым имя джобы стало
**контрактом с защитой ветки**, и у этого контракта не было ни одной проверки:

* переименовал джобу — объявленный контекст перестаёт производиться, а отсутствующий
  обязательный ждётся сервером вечно, то есть **запирается каждый PR**, включая тот, что
  несёт само переименование;
* завёл джобу — она в обязательный набор не попадает, и её краснота слияние не
  останавливает; дыра тихая, набор выглядит полным;
* сняли джобу вместе с предметом — запись переживает её и запирает по той же механике.

## Разрыв был двусторонним, и один его конец блокировал слияния

Замер 2026-08-18: обязательных имён **без производителя — 1**; производится, но не
обязательно — **8** (сборка образов, все пять шардов сквозных проб, и ещё два).

Первый конец опаснее: контекст, которого не производит ни одна джоба, **никогда** не
станет зелёным, поэтому запрос висел в состоянии блокировки при полностью зелёном
прогоне — 52 проверки, 0 красных. Имя разошлось потому, что несло **число модулей**: оно
выросло, джоба честно переименовалась, а список остался прежним.

Устаревшее имя заменено, чтобы разблокировать работу. Но это заплатка: список из 45 имён,
каждое из которых может измениться вместе с составом дерева, разойдётся снова. Решение по
существу — сводный вердикт, один контекст вместо сорока пяти (PRO-Robotech/kacho#646,
влит): он ждёт все проверки и зеленеет, только если каждая завершилась успехом, — тогда и
второй конец разрыва закрывается сам.

## Гейт: `.github/scripts/assert-required-contexts-match-jobs.py`

Прогон по расписанию (`.github/workflows/branch-protection-drift.yml`). Замер на
`007e3e99`: набор **45**, произведено (github-actions) **51**, расхождение **6** — пять
имён шардов и сборка образов. Запирающих записей — **0**.

Пункты предиката снятия закрыты так:

1–2. обе стороны берутся **из API** — защита ветки и проверки последнего прогона ствола.
Сверки с объявлением рабочего процесса нет **намеренно**, по причине из самой задачи: имя
длиннее 100 байт GitHub обрезает в имени проверки и дописывает многоточие, поэтому набор,
собранный из объявлений, не сошёлся бы с производимым **ни при каком прогоне**. Такой
гейт сам стал бы источником запирания.
3. падает и на запирании, и на произведённом вне набора;
4. **исключения ведутся двумя способами, и первый предпочтителен**: имена шардов
**выводятся** из `deploy/e2e-shards.json` по шаблону их джобы — выведенный список не может
разойтись с деревом молча, рукописный может (три копии одного перечня в этом репозитории
уже расходились). Рукописным остаётся только то, что вывести неоткуда, и каждая запись
несёт причину и задачу;
5. печатает перепись (набор · произведено · исключено).

## Расхождение с телом задачи, названное

Задача называла исключениями «пять имён шардов и контексты приложения разбора кода». По
предикату **самой задачи** контексты стороннего приложения в выборку не попадают вовсе —
она отбирает по признаку приложения GitHub Actions. Шестым исключением оказалась сборка
образов.
