# Отношение, выполнимое подстановкой, не сужает ничего

## Что нашли

`cluster.viewer` объявлен `[user, user:*, service_account] or …`, и бутстрап
**намеренно** пишет `cluster:<root>#viewer@user:*` — чтобы глобальный справочник
(регионы, зоны, типы дисков, типы машин) читал любой аутентифицированный тенант.
Правильно для справочника. Следствие: запись каталога `viewer @ cluster` +
`from_request_field: "*"` означает **«аутентифицирован»**, а не «авторизован».

Таких записей было **17**. Шесть — законный справочник. Одиннадцать — нет:

| что гейтилось «аутентифицирован» вместо «авторизован» | почему это не справочник |
|---|---|
| внутренние методы, перечисляющие привязки ресурсов по идентификаторам, которые называет **вызывающий** (сеть, блочное хранение) | у каждого объекта ответа свой владелец, а входы называет вызывающий |
| группа методов iam про **сам граф выдач** | карта прав тенантов, а не глобальный каталог |
| поверхность iam, отвечающая на произвольную пару «субъект, объект» | оракул: сам вопрос раскрывает существование и отношение |

Поимённый перечень — вне git (обе площадки публичны, см. `security.md` §«Публичные
артефакты»). Шесть из девяти методов iam сужали правильно; три места — нет.

## Чем чинили

Авторизация **на уровне данных**: страница курсором из своей БД → вопрос модели про
идентификаторы **этой** страницы, батчами. Метод помечается `ScopeFiltered`, и
production boot-guard отказывается стартовать без работающего фильтра.

Две ловушки, каждая ловилась только на саморевью:
- **пустой субъект отсекается безусловно**, не «когда фильтр подключён» — за
  scope-filtered RPC нет per-RPC Check, откатываться не на что;
- **ошибка фильтра — fail-closed**: недоступный ответ модели не есть «да».

Порядок обязателен: **сначала сузить, потом снимать лишнее.** Самодельный
админ-гейт vpc снимали только после того, как модель стала отвечать за метод —
обратный порядок расширил бы доступ.

## Смежное, вскрытое той же развёрткой

- **iam:** флаг, у которого **нулевое значение выбирает разрешающую ветку** —
  сборка без сеттера отвечала о правах вызывающему без удостоверения. Полярность
  инвертирована. Плюс гейт, работавший «если порты провязаны», и оракул
  существования объекта.
- **iam:** снято отношение `checkAuthorization`, которого в модели **нет**; комментарий
  утверждал, что оно зеркалит проверку шлюза — такой проверки не существует.
- **compute:** `InstanceGroup` снят целиком — объявлен в proto, разведён 21 маршрутом,
  не реализован нигде (404 на всех путях, 23 записи каталога гейтили пустоту), плюс
  чужое облако **в именах полей контракта**. Каталог 357 → 334.
- **ban #2 получил гейт** (`tools/foreignclouds`): 58 нарушений в дереве при отчётах
  «чисто». Сам гейт был дефектен — обходил файловую систему, а не содержимое репо,
  и сканировал артефакты сборки; теперь спрашивает git про игнорируемое. 58 → 0.
