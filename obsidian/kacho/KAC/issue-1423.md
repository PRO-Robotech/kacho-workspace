# #1423: отсутствие состояния объясняется неверной причиной

Часть эпика [#1016](https://github.com/PRO-Robotech/kacho/issues/1016) «единый поток изменений ресурсов». Линия работ — [[KAC/watch-unified-change-stream-2026-08]]. Найдена **по дороге** при закрытии задач клиентской страницы
([[KAC/issue-1389]] · [[KAC/issue-1390]]).

## Предмет

Когда отображение владельца возвращает отсутствие состояния **без ошибки** — то есть «у
этого журнала состояния для такого предмета нет и не бывает», — общий сервер подставляет
причину **«не удалось сериализовать»**.

Слово контракта означает **отказ механизма**. Подписчик читает его как «попробуй ещё» либо
«у владельца дефект», тогда как верное прочтение — «так устроено, состояния здесь не будет
никогда».

## Класс

**Комментарий и код об одном предмете, где верно одно** — но в форме, которую видит
клиент: не проза, а **значение перечисления**. Цена выше прозы: по значению принимают
решение машинно, и решение будет неверным.

## Предикат снятия

Ветвь «состояния нет и не бывает» несёт **своё** значение причины, отличимое от отказа
механизма. Смежно с [[KAC/issue-1382]]: пока владелец не может назвать причину вовсе,
подстановка остаётся у сервера, и правильной её сделать можно только выбором из того же
закрытого словаря.
