# ws#504: оснастку контура SDD-1 не звал ни хук, ни конвейер

Каталог `scripts/change-graph-gate/` нёс 196 кейсов матрицы, 46 инъекций с контролем и пять
проб — и всё это исполнялось только тогда, когда кто-то набирал команду руками. Хук отправки
**выводит** свой перечень из дерева (`git ls-files 'scripts/*/run-all.sh'`), поэтому каталог
без прогонщика оставался вне его *by construction*: молча и без строки в переписи. В
`ci.yaml` задания для контура не было вовсе.

## Разделение по цене — замер, а не догадка

Замер на `61fddcc`, одна машина, последовательно, свободная очередь:

| проба | полоса | цена |
|---|---|---:|
| `tests/run_matrix.py final` | `hook` | 31.8 с |
| `selftest/prove.py` | `hook` | 19.8 с |
| `selftest/prove_census_policy.py` | `hook` | 3.0 с |
| `tests/selfcheck/prove.sh` | `hook` | 2.8 с |
| `selftest/laneparity.py` | `hook` | 0.1 с |
| **итого `hook`** | | **57.5 с** |
| `selftest/inject.py` | `ci` | 865.7 с |
| `selftest/prove_run_progress.py` | `ci` | 73.6 с |
| `tests/selfcheck/prove_matrix_listing.sh` | `ci` | 58.0 с |
| `tests/selfcheck/inject.sh` | `ci` | 34.2 с |
| **итого `ci`** | | **17.3 мин** |

Граница совпала с **предметом**: дешёвое отвечает «работает ли контур», дорогое — «СПОСОБЕН
ли контур упасть». Второе дороже ровно потому, что доказательство падучести есть повторный
прогон испытуемого по разу на инъекцию.

**Решающий довод в пользу того, чтобы дешёвое было в хуке, а не только в конвейере:** PR
внутрь релизной ветки конвейером не проверяется (триггеры сужены по `main`). Значит на
протяжении всей релизной линии хук — **единственное**, что вообще гоняет контур; вынеси
дешёвую полосу целиком в конвейер, и её вердикт впервые прозвучал бы на MR, после
семнадцати минут ранера.

**Цена названа честно:** хук был ~15 с, стал 74.8 с — впятеро. Абсолютная величина остаётся
в пределах, за которыми хук начинают обходить.

## Что заведено

| артефакт | что делает |
|---|---|
| `lanes.py` | единственное объявление полос: полоса · путь · причина; прогон полосы; сверка ведомости с деревом; сверка объявления конвейера |
| `run-all.sh` | прогонщик набора; хук выводит его САМ, правки хука не потребовалось |
| `check-01` | дешёвая полоса прогоняется и зелена |
| `check-02` | ведомость покрывает КАЖДУЮ точку входа контура, в обе стороны |
| `check-03` | конвейер зовёт все три артефакта набора и срабатывает на стволе |
| `prove-all.sh` | дорогая полоса; зовётся заданием `change-graph-proofs` |
| `inject.sh` | доказательство падучести самого набора, 19 утверждений |

## Гейт на КЛАСС, а не на экземпляр

`check-02` — та половина, ради которой задача не сводится к «добавить job». Дефект родился
от того, что перечня не было: следующая заведённая проба выпала бы из обеих полос тем же
способом. Ведомость делает выпадение невозможным *by construction* — новая точка входа
обязана получить полосу либо строку `none` с написанной причиной, а строка, потерявшая свою
точку входа, краснеет как исключение без предмета.

Признак точки входа **структурный, а не по имени**: соглашение контура называет пробы
`prove*`/`inject*`, но `selftest/laneparity.py` под него не подходит — перечень по имени
потерял бы её молча.

## Чем заметно красное дорогой полосы, и чего это НЕ даёт

Задание `change-graph-proofs` объявлено на `pull_request: [main]` и `push: [main]` — оно
срабатывает на MR релизной линии в ствол, там, где работа садится, и красное видно в
перечне проверок PR.

**Остаток назван, а не обещан:** имя задания не входит в перечень обязательных контекстов
защиты ветки `main`, поэтому красное **видно, но слияние не блокирует**. Предикат:

```sh
gh api repos/PRO-Robotech/kacho-workspace/branches/main/protection \
  --jq '.required_status_checks.contexts[]' | grep -c 'оснастка контура'
```

Ноль означает, что вторая половина не закрыта. Закрывается она настройкой репозитория, а не
деревом, — то есть решением владельца.

## Что перемерено по дороге

- **Наборов в дереве было ПЯТЬ, а не четыре**: `scripts/adapter-gate/run-all.sh` приземлился
  той же линией (#482) и в постановку не попал.
- **`selftest/inject.py` больше не красен** — PR #505 влит 2026-09-02, `prove_run_progress.py`
  даёт 8 из 8. Обе поломки, названные в задаче, к моменту работы уже починены.
- **Числа «инъекций 42» и «46» — про разное**: ведомость несёт 42 записи, перепись печатает
  46 (42 инъекции плюс четыре структурных утверждения и контроль). Расхождения нет.
