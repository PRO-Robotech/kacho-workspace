# #1018: сервер потока живёт в фундаменте, а не в каждом сервисе

Часть эпика [#1016](https://github.com/PRO-Robotech/kacho/issues/1016) «единый поток изменений ресурсов». Линия работ — [[KAC/watch-unified-change-stream-2026-08]]. Фаза Ф2.

## Предмет

Сервер потока был написан **дважды и предметно** — в двух разных сервисах, один из них на
380 строк. Провязать это в остальных модулях копированием значило бы завести **седьмую**
копию одного механизма при правиле, требующем держать горизонтальное в фундаменте.

## Что сделано

Сервер поднят **один раз**: чтение очереди по курсору с пробуждением по каналу,
выделенное соединение **вне пула** (подписка держит его всё время жизни), предел числа
одновременных потоков с **явным отказом** вместо молчаливой очереди, применение фильтра по
трём осям, сужение по правам **на каждую отдаваемую строку**, срок жизни потока —
объявленная величина, а не зашитая.

**Сверх постановки:** задача принесла в фундамент наблюдение **границы устоявшегося** —
гарантию, без которой чтение по возрастающему номеру теряет писателя, взявшего меньший
номер и зафиксировавшегося позже. Технику нашёл рецензент в снимаемом «мёртвом» коде
([[KAC/issue-1043]]), и она закрыла часть предмета соседней задачи —
[[KAC/issue-1053]] — через восемнадцать часов после её заведения.
