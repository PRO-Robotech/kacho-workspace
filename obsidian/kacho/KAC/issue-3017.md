# kacho#3017: DKIM, SPF и DMARC домена отправителя профиля a8f60d

**Состояние на момент записи**: `test`. Часть в дереве влита в ветку эпика `2914-notify`
(#3108, 2026-10-08); в `main` не влито ничего. Публикация записей во внешнем DNS — шаг
владельца установки, в дереве его нет; задача открыта, PR несёт `Refs`, не `Closes`.

**Эпик:** [[KAC/issue-2914]]. **Роль из тела:** владелец установки (внешний DNS).

## Что и зачем

Записи DKIM, SPF и DMARC домена отправителя профиля `a8f60d` не опубликованы, поэтому по
решению Д102 notify в рендере этого профиля нет. Задача — довести домен до записей,
проходящих проверки Р19 приёмки NTF-1, чтобы отдельная полоса по Е17 вернула notify в
рендер профиля. Признак, предмет и предикат — в теле задачи.

## #3108 — что дерево даёт владельцу установки

Со слов описания PR и `git show --stat`; прогоны мной не перезапускались.

- Цель `make -C deploy installation-mail-dns STACK=<профиль> STEP=seed|records|verify` и
  скрипт `deploy/scripts/installation-mail-dns.sh`: объект ключа DKIM выпускается, только
  если его нет; три записи порождаются для публикации; опубликованное сверяется с
  порождённым. Публикацию скрипт не делает. Шаги ручные, в `stack-up` не провязаны.
- `deploy/stacks-mail-dns.txt` — строки SPF и DMARC профилей с признаком `relay`; запись
  DKIM не объявляется, а выводится из ключа объекта.
- `notify.returnDomain` профиля `a8f60d` — домен отправителя установки вместо домена
  стенда из нижнего слоя; выравнивание держит `deploy/notify_mail_domain_alignment_test.go`.
- Координата потребляемого ретранслятора внесена в `tools/foreignclouds` с причиной и
  сроком (истекает вместе со строкой SPF профиля).
- Сверка записей не берёт вердикт из трубы (`TestPipefailVerdictNeverComesFromAPipe`).

Разбор — дифф [#3108](https://github.com/PRO-Robotech/kacho/pull/3108).
