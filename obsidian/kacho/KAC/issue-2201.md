# Третий исход: перенос механизма из набора службы доступа в остальные семь

**Предмет.** Страж настройки харнесса (`harness config:` в имени утверждения) падает, когда
предмет шага обязан был создать НЕ продукт: адрес поверхности — прогонщик, субъект — посев
фикстур. Его отказ и отказ продукта приходят вердикту ОДНИМ слотом, поэтому различает их
метка в имени. Метку несли только коллекции iam.

**Замер до правки** (воспроизводится обходом порождённых коллекций): стражей 3174, помечено
2264, НЕ помечено **910** — vpc 378 · compute 245 · nlb 121 · storage 89 · gateway 38 ·
registry 21 · geo 18. Числа задачи сошлись до единицы.

## Что оказалось НЕ так, как ставила задача

**Вердиктный гейт у восьми наборов ОДИН, а не свой у каждого.** `.github/workflows/e2e-newman.yml`
запускает `services/iam/tests/newman/scripts/assert-suites-green.sh` для каждой суиты с
`working-directory` этой суиты; метку он берёт по `dirname "${BASH_SOURCE[0]}"`, то есть у
производителя iam, а не по cwd. Комментарий шага говорит это прямо: «ОДИН скрипт (живёт в
iam) применяется к КАЖДОЙ суите». Значит предикат задачи «вердиктный гейт **каждого** набора
читает метку у **своего** производителя» был выполнен ещё до правки — и его буквальное
исполнение завело бы **второй** вердикт рядом с первым, чего конвейер запрещает вслух
(«способ получить два разных ответа на один вопрос»).

**Следствие, которое стало несущим.** Раз читатель один и читает ОДНО объявление, набор,
объявивший другой текст метки, молча выпадает из третьей категории: его стражи снова
читаются находками, при том что метка у них есть. Поэтому согласие текстов держит гейт
дерева, а не строка в семи файлах.

**Производителей стража оказалось больше, чем два на набор.** После правки генераторов
осталось 9 непомеченных: рукописные стражи в файлах кейсов — gateway 3, storage 6. Тот же
третий род, ради которого заводилась ось 3 у пробы iam
(`services/iam/tests/newman/scripts/precondition_mark_test.py`, заведена #2187).
Кейсам текст пришёл ОТ производителя (константа впрыснута в пространство имён кейсов), а не
литералом: литерал в кейсе — это ручное выведение своего падения из находок.

## Чем держится

`internal/repohygiene/newmanpreconditionmark_test.go` — гейт дерева: объявление у каждого
набора со стражами, согласие текстов по всему дереву, каждый страж порождённых коллекций
несёт метку, файл кейса её не выписывает. Перепись печатает ОБЕ величины («стражей N ·
помечено M · НЕ помечено K»), падает на пустом обходе по трём осям сразу.

Инъекция — `newmanpreconditionmark_injection_test.go`, шесть осей плюс два предиката чтения,
включая **антимаску**: расхождение текстов не гасит непомеченных стражей, а литерал в кейсе
не гасит их же.

## Три прогона доказательства, а не два

| прогон | новый гейт | существующий контроль (`precondition_mark_test.py`) |
|---|---|---|
| всё цело | ok | rc=0 |
| снята метка у vpc | FAIL, называет vpc и 378 | rc=0 |
| вердикт перестал читать метку у производителя | ok | rc=1 |

Третий прогон нужен именно затем, чтобы молчание существующего контроля не было
неотличимо от молчания мёртвого.

## Пара «находка → третий исход», дословно

Одно и то же имя стража, настоящий вердиктный гейт, синтетический отчёт:

```
ДО    код 1 · TOTAL: … 1 failed … · TOTAL(категории): находок 1, УСЛОВИЕ НЕ СОЗДАНО 0
ПОСЛЕ код 3 · TOTAL: … 1 failed … · TOTAL(категории): находок 0, УСЛОВИЕ НЕ СОЗДАНО 1
```

`1 failed` не изменилось — метка ничего не вычитает. Проверено по каждому из семи наборов на
их СОБСТВЕННЫХ именах стражей, вместе с антимаской (находка рядом с помеченным даёт код 1).

## Найдено по дороге

Страж настройки харнесса, который называет предмет и НЕ отменяет запрос, — шаг идёт дальше и
следующее утверждение падает уже как находка о продукте. По дереву таких **1 из 3174**
(gateway, полоса машинного издателя). Это половина предмета #2196 (отмена запроса, а не
только называние), а не предмет этой задачи, — заведено своей задачей.

## Смежное

- [[invalid-run-arrives-as-a-red-verdict]] — тот же третий исход, но со стороны прогона:
  «не выполнилось» читается красным, если у него нет своего кода;
- ось внутри набора службы доступа остаётся за его собственной пробой
  (`services/iam/tests/newman/scripts/precondition_mark_test.py`, #2187);
- третья категория как понятие — `testing.md` §«Чтение вердикта».
