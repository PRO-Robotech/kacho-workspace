# Кто вправе говорить за пользователя — состояние по семи сервисам

Класс, найденный развёрткой 2026-07-27 и закрытый в тот же день в трёх сервисах.
Правило — `.claude/rules/security.md` §«Кто вправе ГОВОРИТЬ ЗА пользователя».

## Суть

`grpcsrv.principalIsTrusted` сверяет сертификат со списком доверенных отправителей
**только если список непуст**; на пустом возвращает `true`. Пустой список — это
«не сужаем», а **не** «запрещаем». Дальше присланная в метаданных личность кладётся
в контекст, и именно из неё строится субъект per-RPC проверки прав.

Следствие: сосед с сертификатом внутреннего CA присылает заголовки личности жертвы →
проверка идёт **от её имени** → чтение, изменение, удаление чужих ресурсов. Сетевые
политики этого не закрывают (у большинства сервисов их нет), TLS-слой имён не сверяет.

## Состояние по сервисам

| Сервис | Извлечение | Список | Boot-guard | Самоотчёт | Гейт оценивает |
|---|---|---|---|---|---|
| storage | trust-aware, оба | **есть** | **есть** | есть | да |
| registry | trust-aware, оба | **есть** | **есть** | есть | да |
| geo | trust-aware | есть | есть | есть | да |
| compute | trust-aware | есть | есть (счёт исправлен) | есть | да |
| nlb | trust-aware | есть | есть (счёт исправлен) | есть | да |
| **vpc** | **безусловный на публичном** | нет | нет | нет | **нет** |
| **iam** | trust-aware | **нет** | нет | нет | **нет** |

**Молчание гейта про vpc и iam — не одобрение.** Это записано намеренно.

## Два подкласса, оба были живыми

**Безусловный `UnaryPrincipalExtract` — строго хуже.** Личность честна вообще без
сертификатной проверки: в красном прогоне registry пир **без** verified-cert доходил
до обработчика как жертва. Его godoc ограничивает применение листенером, «куда не
дозвонится неконтролируемый peer» — публичный ClusterIP-порт этому не отвечает.
Список сам по себе это НЕ лечит: сначала trust-aware пара. Осталось в **vpc**.

**Guard считает `len()` сырого среза** — значение `","` его проходит, сервис
стартует, доверяя всем. Было у compute и nlb, закрыто: считают записи, которые
примет транспорт, и guard с самоотчётом используют ОДИН предикат.

## Законные отправители — по графу импортов, не по догадке

- storage: **шлюз И compute** (compute передаёт личность инициатора на пути attach —
  сужение до одного шлюза сломало бы привязку тома);
- registry: **только шлюз** (единственный импортёр stubs вне сервиса).

Догадка «наверное только gateway» здесь ошибочна, и это стоило бы рабочего пути.

## Дважды комментарий утверждал обратное

`permission_map.go` storage утверждал «не принимается ни от кого» при обратной
реализации. Правился **дважды**: сначала я привёл текст к реальности, не тронув дыру;
затем — к новому состоянию после фикса. Класс `security.md` §Hardening-5.
