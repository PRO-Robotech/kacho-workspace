# ws#502: норму «диагностика берётся из приёмки» не держала ни одна проверка

Норма контура: диагностику правила объявляет **приёмка**, реализация своей не заводит —
иначе контракт пишет исполнитель, а рецензент судит то, чего не утверждал. Норма держалась
**обзором**: ни `selftest/prove.py`, ни `selftest/inject.py`, ни `tests/caselib` не сверяли
множество диагностик правил с множеством диагностик приёмки.

**Класс тихий by construction**, и это главное в нём: код, которого приёмка не объявляет,
матрица кейсов **не предъявляет** — её кейсы выводятся из приёмки, — поэтому такой код не
краснеет ничем и от законного неотличим. Единственное отступление в дереве (ws#494) нашла
честность автора полосы, а не механизм; следующее было бы найдено так же либо не найдено
вовсе.

## Посылка перемерена первым действием — ПОДТВЕРДИЛАСЬ

Предикат задачи прогнан дословно на `56935d4d`:

```
правила объявляют: 134 · приёмка объявляет: 134
в приёмке НЕТ: ['CG_DRIVER_BIRTH_TRIPLE_INVALID']
без производителя: ['CG_OK']
```

**Числа равны, а множества разошлись** — ровно тот случай, ради которого перепись обязана
печатать обе величины: одно число здесь не изменилось бы вовсе.

Второе утверждение задачи («предикат снятия сегодня отвечает „отбор не совпал ни с одной
инъекцией из 42"») тоже подтвердилось дословно, с тем же числом. Единица счёта — **запись
ведомости `INJECTIONS`**; свой замер: `len(inject.INJECTIONS)` → **42**.

## Что заведено — секция `I` в `selftest/prove.py`

Дом выбран приёмкой §6: `selftest/` — сторона **implementation**, она читает
`cglib.registry`; `tests/**` принадлежит integration-tester и в реализацию не заглядывает.
Секция попадает в дешёвую полосу вместе с `prove.py`, поэтому её зовёт `run-all.sh` через
`check-01`, а его — хук отправки. Отдельной точки входа не заведено намеренно: новая точка
потребовала бы строки в ведомости полос `lanes.py`, то есть правки за пределами полосы.

| решение | почему так |
|---|---|
| перепись печатает **пять** величин, из них обе несущие | одно число скрывает ровно тот случай, что был в дереве: 134 и 134 при разошедшихся множествах |
| `codes − spec` — находка; `spec − codes` — **строка переписи** | `CG_OK` производителя не имеет *by construction* (это исход «правило не нарушено», а не правило); смешение направлений дало бы проверку, красную ВСЕГДА, — её отключили бы первой |
| пустой обход — находка «беспредметно» | иначе недосягаемая приёмка дала бы «мимо приёмки 134», а непрочитанный реестр — ноль находок, то есть зелёное на непрочитанном |
| ведомость **самоистекает** | запись, которой нечего исключать, — находка; предикат снятия у записи стоит **командой**, а не словами |
| пустая ведомость **проходит** | пустота и есть её цель; падение на достигнутой цели подталкивало бы держать запись ради зелёного |

Ведомость сегодня несёт **одну** запись — `CG_DRIVER_BIRTH_TRIPLE_INVALID`, предмет ws#494.
Она покраснеет **сама**, когда круг рецензии по приёмке код объявит: тогда записи станет
нечего исключать, и утверждение `I2` назовёт её по имени.

## Пара RED → GREEN

Секция внесена с **пустой** ведомостью и прогнана по настоящему дереву:

```
FAIL I1 … CG_DRIVER_BIRTH_TRIPLE_INVALID — правило объявляет диагностику,
     которой приёмка НЕ объявляет
утверждений: 188 · прошло: 187 · провалено: 1
```

Затем добавлена запись ведомости с предикатом снятия:

```
OK   I1 …
утверждений: 188 · прошло: 188 · провалено: 0
```

Красное пришло **только** от нового утверждения: остальные 187 остались зелёными, то есть
инъекция роняла проверяемое, а не соседа.

## Падучесть доказана на ДВУХ уровнях, и это не дублирование

**Синтетикой внутри секции** — по каждой оси пара «дефект / законный близнец»: код мимо
приёмки → находка **с именем кода**; код, приёмкой объявленный → молчание; запись без
предмета → находка с именем; запись с живым предметом → молчание; пустая ведомость →
молчание; «без производителя» → перепись, а не находка; пустой обход с **обеих** сторон →
«беспредметно», непустой вход → молчание. Односторонняя проба зеленела бы на сверке,
отвергающей всё.

**Инъекцией по настоящему дереву** — `selftest/inject.py`, отбор из предиката снятия задачи:

```sh
python3 scripts/change-graph-gate/selftest/inject.py 'диагностика мимо приёмки'
# инъекций: объявлено 43, к прогону 1
# OK контроль: нетронутое дерево зелено (25 с)
# OK диагностика мимо приёмки … -> покраснело ровно 2 ожидаемых утверждений (21 с)
```

Инъекция меняет **один факт**: ведомость называет не тот код. Следствий два, и оба
принадлежат секции — живой код остаётся без прощения (`I1`), прощение остаётся без предмета
(`I2`). Это и есть две стороны самоистечения, показанные на настоящих данных дерева.

## Что нашлось по дороге — песочница не видела приёмки вовсе

`inject.py` строит песочницу копией **одного** каталога оснастки; воркспейса над ней нет, и
выписанный `../../docs/...` указывал бы в пустоту. Замер в песочнице **без** ручки:

```
путь приёмки: None
перепись: диагностик правил 134 · диагностик приёмки 0 · мимо приёмки 134 …
```

То есть контрольный прогон краснел бы на **раскладке песочницы**, а не на инъекции. Путь
поэтому **выводится** обходом вверх, а песочнице передаётся готовым через
`CG_ACCEPTANCE_DOC` (`prove.acceptance_environment`). Ручка **переживает вложение**:
`prove_run_progress.py` кладёт песочницу в песочницу, и на втором этаже выводить путь
неоткуда, — поэтому уже стоящее в окружении значение не пересчитывается.

Ветвь «беспредметно» здесь не украшение: она сработала на настоящем условии, а не только на
синтетике.

## Чего эта задача НЕ закрывает

Само отступление `CG_DRIVER_BIRTH_TRIPLE_INVALID` — предмет **ws#494**, и снимается оно
новым кругом рецензии по приёмке (правка приёмки отзывает её вердикт, привязанный к SHA-256
файла). Здесь заведён только **механизм**, ловящий класс.
