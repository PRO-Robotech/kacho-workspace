# #2036: ось метки резолвит точечное имя порождённой таблицей, а не каталогом

**Предмет.** `relverdict/labelaxis.go` переводил имя типа в точечную форму через
`authzmap.DottedType` — таблицу, порождаемую из манифестов **сборкой**. Тип, заведённый
ПРИМЕНЕНИЕМ на ходу (глагол `InternalModuleService`, применитель пишет в `kacho_iam.catalog_*`),
в этой таблице отсутствует by construction: ось выбиралась по старому имени, метки спрашивались
у чужой таблицы, объект не находился — и «нет» было неотличимо от честного отказа по правам.

**Единица счёта названа, потому что она и была предметом спора.** Вызовов `authzmap.*`
**узлами** в не-тестовых файлах `relverdict/` — **1**. Поиск по тексту даёт **2**: второе
попадание в `catalogtype.go` — комментарий, пакет там не импортируется. Тот же разрыв шире:
по всему iam «читателей authzmap» по тексту **37**, по импорту — **19–20**.

**Промах эквивалентен by construction, а не по совпадению.** `catalogTypeName` на промахе
отдаёт вход как есть; ограничение `catalog_resource_object_type_form` запрещает точку в имени
модели, поэтому `iam.`-префикса у него не бывает — ровно то, чем прежде отвечала ветвь
`!known`.

**Форма пробы установлена перебором, а не выбрана.** Из трёх форм применения вердиктом
расхождение видно только на одной — передаче ресурса другому модулю (`iam.group` →
`directory.group`): она пересекает границу модуля, и ось меняется. Переименование внутри модуля
границы не пересекает; целиком новый тип план права отвергает раньше оси.
