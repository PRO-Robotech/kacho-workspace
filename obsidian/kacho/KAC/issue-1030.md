# Каталог модуля таблицами: составной ключ живости (#1030)

**Назначение.** Trail корневой задачи оси «каталог модуля как данные».
**Категория.** KAC (записка задачи).
**Состояние.** in-progress — приёмка APPROVED (круг 3), реализация идёт в `lane/1030-impl`.
**Чем сверено.** Дерево продукта, ствол `2fb27446e` (2026-09-01); четыре решения ниже —
собственный прогон PostgreSQL 16.15 в одноразовом контейнере, три пробы с контрольной.
**Связи.** [[release-modules-2026-09-01]] · [[issue-1088]] · [[issue-1028]] · [[resources/iam-role]]

## Что и зачем

Каталог модуля — модули, ресурсы, глаголы — живёт литералами в Go, а не строками БД. Поэтому
внешнего ключа с правила роли на каталог **не существует**, и не потому что забыли: у него нет
референта. Задача заводит таблицы каталога и составной ключ с колонкой живости.

Задача — **корень цепи**: от неё транзитивно зависят пять открытых задач линии (#1031, #1032,
#1034, #1035, #1036). Перечень выводится, а не выписывается:
`gh issue list -R PRO-Robotech/kacho --state open --label release:modules`.

## Четыре решения приёмки — установлены ОПЫТОМ, не рассуждением

Записаны здесь, потому что каждое стоило прогона, и каждое выглядит спорным для того, кто
прогона не делал.

| решение | что опровергнуто замером |
|---|---|
| `live` — **обычная** колонка под `CHECK`, не генерируемая | довод «на генерируемой не сработает ссылочный триггер» **неверен**: обе формы дают побайтово одинаковый исход. Решение осталось за обычной по другой причине, названной в приёмке |
| ключ объявляется `NO ACTION`, а не `RESTRICT` | без `DEFERRABLE` они **тождественны**; `RESTRICT + DEFERRABLE` молча инертен |
| ключа нужно **два**, а не один | `MATCH SIMPLE` при одном составном ключе пропускает проверку **целиком**, если хоть один столбец пуст: правило с незаданным глаголом потеряло бы и проверку ресурса |
| преемник снятого типа читается как **данные каталога** | отказ приходит из прерванной транзакции, где чтения нет. Точка сохранения делает чтение исполнимым — и ставит по одной точке **на строку** на горячем пути ради текста, нужного только на пути отказа |

Третье — несущее. Одним ключом инвариант не выражается, и это не видно ни в тексте схемы, ни
в обзоре изменения: проверка просто не срабатывает.

## Класс, найденный кругом 3 и стоящий отдельной записи

Сценарий требовал, чтобы **отказ называл преемника** снятого типа. Производителя такого текста
нет ни одного — и это второй экземпляр класса за одну приёмку. Первый: сценарий обещал, что
правило исчезнет из превью роли, тогда как код делает **обратное** — нерезолвящееся правило
намеренно берёт все глаголы платформы, поэтому после снятия типа превью показало бы **больше**.

Оба нашёл не рецензент, а автор, прогнав предикат «есть ли производитель» по **всем**
шестнадцати «Тогда», а не только по названному в замечании. Отсюда норма для этой линии:
замечание о неисполнимости одного сценария есть повод перебрать **весь** документ.
