# Kachō — vault

**Kachō — самостоятельная облачная control-plane платформа** (только control plane, без
data plane). Разработка ведётся в **одном** репозитории продукта `PRO-Robotech/kacho`
(монорепо, Go + React) и в воркспейсе `PRO-Robotech/kacho-workspace` (правила, спеки,
приёмки, этот vault). **Оба репозитория публичны** — всё, что попадает в git любого из
них, считается опубликованным в момент коммита, а не пуша.

Cross-repo граф, раскладка каталогов и рёбра рантайма — [[architecture]].

## Что где лежит в продукте

Семь сервисов, у каждого свой каталог в `services/`, своя БД и свои миграции
(database-per-service):

| Домен | Каталог | Ресурсы |
|---|---|---|
| IAM | `services/iam/` | Account · Project · User · ServiceAccount · Group · Role · AccessBinding |
| VPC | `services/vpc/` | Network · Subnet · SecurityGroup · RouteTable · Address · Gateway · NetworkInterface |
| Compute | `services/compute/` | Instance · MachineType |
| Storage | `services/storage/` | Volume · Snapshot · Image · DiskType |
| Geo | `services/geo/` | Region · Zone — leaf-owner оси размещения |
| NLB | `services/nlb/` | LoadBalancer · Listener · TargetGroup · Target |
| Registry | `services/registry/` | Registry · Repository · Tag (OCI) |

Плюс `proto/` (все контракты), `pkg/` (общий фундамент), `gateway/` (край), `deploy/`
(стенд), `ui-future/` (SPA). Прежние отдельные репозитории — сегодня эти каталоги;
записки-переходы: [[kacho-proto/README|proto]] · [[kacho-corelib/README|pkg]] ·
[[kacho-api-gateway/README|gateway]] · [[kacho-vpc/README|services/vpc]] ·
[[kacho-deploy/README|deploy]] · [[kacho-resource-manager/README|снятый менеджер ресурсов]].

## Категории записок

`resources/` — поведение ресурса, контракт ссылок, жизненный цикл, префикс id ·
`rpc/` — методы сервиса и их REST-отображение · `packages/` — экспортируемое API пакета и
кто его импортирует · `edges/` — межсервисные рёбра рантайма · `KAC/` — журнал работ ·
`runbooks/` — операционные процедуры.

Размеры категорий читаются из дерева, а не из этой строки:
`git ls-files obsidian/kacho/<категория> | wc -l`. Порядок величин на 2026-08-05:
KAC ≈ 200, packages ≈ 115, edges ≈ 70, resources ≈ 56, rpc ≈ 52. Точные числа сюда не
вписаны намеренно — их правят параллельные волны, и вписанное число устареет раньше, чем
его прочтут. Прежняя редакция называла «~140 файлов» и раскладку 20/29/68/12 — ни одно из
этих чисел не сходилось ни с одним каталогом.

> [!warning] Часть корпуса описывает подсистемы, СНЯТЫЕ с продукта — сверяй с деревом
> Прежде всего это записки эпохи «производственного IAM» (эпик [[KAC/KAC-127]]). Проверено
> по цепочке миграций `services/iam/internal/migrations/` на `kacho@96b2879a`: отдельными
> миграциями **физически дропнуты** таблицы SCIM, SAML, break-glass, конвейера push-событий
> безопасности и организаций. Контрактов в `proto/kacho/cloud/iam/v1/` у них нет; мост к
> внешнему SAML-провайдеру и работа с аппаратным модулем ключей — **ноль** файлов в дереве;
> конвейер аудита через шину и колоночную БД — тоже (один доменный тип очереди аудита ≠
> развёрнутый конвейер). Иерархия сегодня двухуровневая: **аккаунт → проект**.
>
> Записки про эти подсистемы **не удалены** — они верны как история, и разборы в них стоит
> читать. Но описанием сегодняшнего дня они не являются, а **прежняя редакция этого файла
> перечисляла их как действующую поверхность**: тремя абзацами ссылок подряд, ресурсы —
> RPC — рёбра — пакеты. Перечисление снято. Ищешь конкретный ресурс или RPC — начинай с
> дерева продукта, записку читай как контекст.

## Ключевые правила, которые стоит знать до чтения любой записки

Нормативный источник — `.claude/rules/*` воркспейса; здесь только указатели, чтобы vault и
правила не разошлись как два места об одном предмете.

- **Один Go-модуль, ноль `replace` на внутренние пакеты.** Прежняя редакция объявляла
  `replace ../kacho-*` «ключевым архитектурным правилом» — сегодня это прямо **запрещено**
  регламентом и невозможно по построению (`polyrepo.md`).
- **База на сервис**; cross-service FK нет. Ссылки через границу — по id, с проверкой у
  владельца на пути запроса, и dangling-ссылка обязана переживаться грациозно
  (`data-integrity.md`).
- **Инварианты внутри сервиса — на уровне БД** (FK / UNIQUE / EXCLUDE / CHECK / CAS), а не
  «прочитал → проверил → записал».
- **Чтение синхронно, мутации — через `Operation`**; клиент поллит. Публичного `Watch` нет.
- **Адресация — по неизменяемому `id`, никогда по `name`** (`00-kacho-core.md`, запрет #15).
- **Никаких сравнений с чужими облаками** в коде и документах (запрет #2). Конвенции Kachō
  — собственные; описывать их через чужой продукт нельзя, в том числе здесь.
- **Vault публичен.** Не собирай в одном месте координату + условие, при котором защита не
  действовала, + следствие для постороннего. Предмет, решение и следствие для контракта —
  можно; разбор, который иначе не написать, не коммитится вовсе (`security.md`
  §«Публичные артефакты»).

> [!important] Потолок объёма записки снят
> Решение владельца: прежнее ограничение «1-3 КБ» больше не действует — писать можно
> развёрнуто, ради контекста. Предмет экономии сменился: теперь это **точность и
> пригодность к переиспользованию**, а не число байт. Локальный [[CLAUDE|CLAUDE.md]] в
> этой части устарел и правится отдельно.
