# «Смёржена ли ветка» — предикат уровня дерева, а не графа

**Задача.** Десятки веток; надо разделить их на «работа в стволе, ветка мусор» и «работа не
влита, надо доделать или удалить осознанно». Граф на этот вопрос не отвечает: схлопнутое
слияние, черри-пик и переписанная история дают новый хеш, поэтому вершина ветки перестаёт
быть предком ствола (««0 коммитов впереди» значит смёржена», «команда мёржа, пушившая безусловно»).

**Что НЕ работает, и почему каждый способ выглядит убедительно:**

| Способ | Почему обманывает |
|---|---|
| `git branch --merged` | отвечает про граф, а не про содержимое |
| `git cherry` (patch-id) | требует ПОБАЙТОВОГО совпадения патча; ствол применил то же в другом контексте — «не найдено» |
| сравнение сообщений коммитов | сообщения переписываются по дисциплине публичного репозитория, и тогда своя же работа читается как чужая |
| `git diff base..branch` + сверка файлов | при переписанной истории общий предок уезжает далеко назад, и в «файлы ветки» попадает пол-дерева |
| `git diff main...b \| git apply --reverse --check` | ловит только точное совпадение контекста; ствол ушёл вперёд по тем же файлам — «расходится» на всём |

**Что работает.** Слияние без рабочего дерева:

```
git merge-tree --write-tree main <ветка>      # первая строка — ID дерева слияния
git diff --shortstat main <ID дерева>          # пусто = ветка НЕ привнесёт ничего
```

Пустой diff означает ровно то, что нужно: содержимое ветки уже в стволе, ветка мусор.

**Ловушка, на которой предикат врёт уверенно.** При конфликтах вывод `merge-tree`
**многострочный**: первая строка — дерево, дальше перечень конфликтующих путей. Взяв вывод
целиком за ID, получаешь неразрешимый аргумент, `git diff` тихо падает, а скрипт печатает
«ничего не привнесёт» — **для всех конфликтующих веток сразу**, то есть ровно для тех, где
ответ важнее всего. Признак подделки: «влиты все до одной». Лечится `head -1` плюс отдельным
счётчиком конфликтных строк — и он же обязан быть НАПЕЧАТАН, иначе тихий конфликт снова
станет «чисто» («объявленный предикат может быть негодным и лгать уверенно»).

**Границы.** На ветках со старой (переписанной) историей предикат отвечает «конфликт», а не
«да/нет»: слияние там бессмысленно by construction. Такие разбираются **по предмету** —
берёшь то, что ветка вводила (файл, гейт, приёмку), и спрашиваешь дерево, есть ли этот
предмет сегодня. Отсутствие файла при этом **не** доказывает потерю: подсистему могли снять
решением.

**Перед удалением.** Снять перепись «ветка → вершина → дата → исход» в файл вне репозитория:
пока объекты живы, по хешу восстанавливается всё. Работу, оказавшуюся невлитой, сначала
посадить, и только потом удалять ветку — иначе удаление становится необратимым в тот момент,
когда сборщик мусора дойдёт до объектов.

**Где наблюдалось.** Разбор 122 локальных веток монорепо 2026-08-11: 60 невлитых по графу, из
них реально несли работу три — конформанс аутентификации края, приёмка конформанса участия и
снимок незакоммиченных гейтов, спасённый при уборке рабочей копии. Первая версия предиката
объявила «влиты все» и была опровергнута тем, что один из известных мне гейтов в стволе
отсутствовал.

## Связанное

««0 коммитов впереди» значит смёржена» · «объявленный предикат может быть негодным и лгать уверенно» ·
«артефактные утверждения проверяются одной командой» · «слияние может молча откатить смёрженное» ·
«две копии на одной ветке готовят откат в индексе»
