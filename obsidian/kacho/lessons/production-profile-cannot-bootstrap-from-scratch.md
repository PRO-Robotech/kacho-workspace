# Профиль, который поднимается только поверх однажды поднятого

**Признак.** Профиль развёртывания много раз применялся и считается рабочим. На новом
кластере он не поднимает зависимость **вообще ни разу** — при том что на прежнем стенде
всё зелено. Разница между стендами — не в настройках сервиса, а в том, что на прежнем
**сохраняется том**: каталог данных переживает переустановку, первичная настройка
пропускается целиком, и та её часть, которая сломана, просто не исполняется.

**Механизм на конкретном случае.** Собственный `pg_hba` требовал пароль на unix-сокете и
на петле. Первичная настройка обязана подключиться к своей же базе, чтобы ЗАДАТЬ пароль, и
делает это до того, как пароль существует, — круг замыкается: «password authentication
failed for user postgres … User postgres has no password assigned». На стенде с постоянным
томом этого пути нет, потому что база уже инициализирована.

**Почему диагноз стоит дорого.** Симптом немой: вывод инициализации уходит в `/dev/null`,
пока не включена отладка образа, поэтому контейнер завершался кодом 2 **без единой строки
о причине**. Первые две гипотезы (объём памяти, версия образа) были правдоподобны и
неверны; версия образа при этом оказалась **отдельным настоящим дефектом** — восемь
инстансов из десяти ехали на неприпиненном умолчании чарта. Два дефекта в одной точке
маскируют друг друга: починив один, видишь тот же симптом и заключаешь, что не помогло.

**Противоядие для профиля.** Граница безопасности проходит по СЕТИ, и закрывать надо её:
по сети — только шифрованное соединение с паролем, нешифрованное отвергается явно. Сокет и
петля живут в сетевом пространстве самого пода; требовать пароль там значит ломать
собственный запуск, ничего не защищая.

**Противоядие для диагноза.** Прежде чем менять величины (память, потолки, версии),
**сними немоту**: включи отладочный вывод у одного экземпляра и прочитай настоящую ошибку.
Величина, изменённая по догадке, при совпадении даёт ложное подтверждение гипотезы.

**Чем держится.** Прогоном профиля на стенде БЕЗ постоянных томов, где каждый запуск
первичный. Стенд с сохранённым состоянием этот класс не отличает по построению — см.
[[setup-step-that-checks-its-own-mark-not-its-subject]], где та же пара «состояние
переживает / отметка переживает» даёт другой дефект.

**Где наблюдалось.** Развёртывание на управляемый кластер, 2026-08-11; починка —
`7fced686` (профиль) и `28a9fb76` (пин версии + гейт) монорепо.
