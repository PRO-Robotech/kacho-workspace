# Метка состояния переживает состояние, которое называла

## Признак

Метка `status:*` стоит на задаче, чьё состояние давно другое. Находится **переписью в обе
стороны**, и обе половины обязательны:

```sh
# закрытые, на которых метка осталась — предикат, ответ обязан быть пуст
gh issue list -R <репо> --state closed --label status:in-progress --limit 100 --json number -q length
gh issue list -R <репо> --state closed --label status:test        --limit 100 --json number -q length

# открытые — предиката НЕТ, требуется суждение по каждой:
# метка законна ровно пока есть артефакт работы, ЖДУЩИЙ ствола
gh issue list -R <репо> --state open --label status:test --limit 100 --json number,title
```

## Чем это дороже, чем кажется

Метка — единственное, по чему соседняя сессия отличает «взято» от «свободно». Пережившая
состояние метка не мусор: она **запрещает брать** задачу, которую никто не ведёт, — и
запрет невидим, потому что выглядит как чужая работа.

Обратная сторона того же: **закрытая задача с живым предметом хуже открытой**. Открытую
возьмут; закрытую не возьмёт никто, а предмет всплывёт в чужой отладке уже без места, где
написано, что он известен. Поэтому при малейшем сомнении метку снимают, а задачу оставляют
открытой.

## Замер, ради которого записка (2026-09-09, `PRO-Robotech/kacho`)

| ось | значение |
|---|---:|
| метка на **закрытых** | **26** (1 `in-progress` + 25 `test`) |
| метка на **открытых** | **44** |
| из них артефакт действительно ждал ствола | **0** |
| закрыто по прогнанному предикату | **40** |
| метку сняли, задачу оставили открытой | **4** |

Ноль в третьей строке — главное число. Ожидалось найти задачи, честно ждущие вливания; их
не оказалось ни одной. Все 44 были невидимо изъяты из работы.

## Причина — НЕ та, что кажется первой

Первое объяснение звучит как «`Closes #N` в схлопнутом коммите не срабатывает». **Оно
неверно, и это перемерено:** коммит с 43 ссылками `Closes` закрыл все 43, ни одна не
осталась открытой.

Настоящая причина проще: ссылки **не проставляли**. Работа приезжает накопительной линией
одним схлопнутым коммитом, дочерние задачи в его теле не названы, и закрывать их нечему.
Метка при этом не снимается **ничем** — автоматики на неё нет вовсе.

Это тот же класс, что [[checks-with-form-but-no-substance]], перенесённый на учёт: механизм
существует, выглядит работающим и не имеет производителя.

## Противоядие

- **метка снимается тем же действием, которым состояние меняется** — не «потом»;
- **закрытие несёт артефакт**: команда предиката, её вывод, номер PR или SHA. «Closed» без
  этого не отличить от «забили»;
- **перепись на закрытых обязана быть пуста** и прогоняется при завершении накопительной
  линии;
- у открытых предиката нет by construction — там работает вопрос: **есть ли артефакт,
  ждущий ствола**. Нет артефакта — метка означает «кто-то что-то делал», то есть ничего.

## Чем держится

**Вниманием.** Правила автоматизации, снимающей метку при закрытии, здесь не заведено, и
это сказано прямо, чтобы цену знали. Проверяемая половина — перепись на закрытых: она
машинная и обязана быть пуста.
