# Сдвиг пина приносит отказ старта, которого гейт профиля не моделирует

**Признак.** Профиль стенда проходит все деревянные гейты рендера, PR перепина зелёный и
влит, а служба на новом пине **отказывает в старте** — и узнаётся это только выкаткой.
Отказ верен: величина профиля действительно ниже пола, который служба требует.

**Механизм на конкретном случае.** Гейт бюджета памяти полосы входа переписывает у себя
часть стражей старта пиненного модуля: «ёмкость ≤ 0 — отказ» и арифметику «ёмкость ×
память проверки + резерв ≤ предел». Профиль стенда, чтобы уместиться в общий предел 448Mi,
сузил ёмкость до 1 — по этой модели законно. Сдвиг пина принёс **новое** правило старта:
ёмкость меньше 2 под церемонией OAuth — отказ. Гейт этого правила не знает, поэтому
противоречие между «ёмкость 1 по бюджету» и «ёмкость ≥ 2 по церемонии» не видит никто,
пока под не начнёт подниматься. Выход — ёмкость 2 и предел 512Mi, наименьший, при котором
ёмкость 2 проходит бюджет.

**Почему это не ловится рендером.** Рендер судит форму значений, а не их принятие
службой. Стенд в CI не поднимается, так что единственное место, где правило пина
исполняется против значений профиля, — живой старт. Модель стражей в гейте — копия, и
копия отстаёт от пина ровно на те правила, которые пин принёс после её написания.

**Противоядие.** Гейт, моделирующий стражи старта пиненного модуля, должен сверять
**полноту** своей модели с пином, а не только присутствие известных правил: перечень
отказов конфигурации у пина против перечня, который гейт моделирует, — и красный на
разнице. Для уже известного правила — проба пола ёмкости по всем стендам, где церемония
собирается. При перепине — прочитать у пина изменения стражей конфигурации до выкатки.

**Чем держится.** На `2afc06571c7` — ничем: гейт бюджета проверяет, что известные ему
правила у пина есть (`guardCapacityRuleIsModelled`), но не что других нет; правило
церемонии не читает ни одна проба `deploy/`. Сейчас класс держится выкаткой.

**Где наблюдалось.** Стенд `a8f60d`, 2026-10-04: ревизия релиза 3 failed, ревизия 4 —
перекатка теми же числами, затем они влиты в дерево. Trail — [[KAC/issue-3012]], дифф —
PR #3023 (`2afc06571c7`) монорепо.
