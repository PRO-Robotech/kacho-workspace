# Зарезервированное имя отвечает «есть» на вопрос о существовании

**Назначение.** Класс дефекта ПРОВЕРКИ: предикат «встречается ли имя поля в контракте»
на зарезервированном имени отвечает «да» и даёт ложное «всё в порядке».
**Категория.** lesson (класс дефекта).
**Состояние.** active.
**Чем сверено.** Дерево продукта `PRO-Robotech/kacho`, ствол `3a8a7d328`, 2026-08-31.
**Связи.** [[checks-with-form-but-no-substance]] · [[issue-1718]]

## Признак

Проверка сверяет документ, провайдера или пробу с контрактом и ищет **вхождение имени**.
На имени, снятом с контракта **правильно** — то есть через `reserved`, — она молчит,
потому что имя в файле присутствует.

```protobuf
reserved 11, 12;
reserved "deregistration_delay_seconds", "slow_start_seconds";
// живые поля — deregistration_delay=15 / slow_start=16, тип Duration
```

Замер, из которого выведено: `git grep -c 'deregistration_delay_seconds\|slow_start_seconds'`
по дереву контрактов даёт **13** вхождений, живых полей с такими именами — **ноль**.

## Почему это опаснее обычной слепой зоны

Резервирование — **правильный** способ снять поле (`api-conventions.md`
§«Принято-и-проигнорировано», исход 3: снять с контракта с резервированием номера И имени).
То есть предикат ломается ровно на том дереве, где всё сделано верно, — и тем громче
подтверждает «расхождений нет», чем аккуратнее велась работа.

Обратная сторона того же: документ, продолжающий обещать снятое поле, **не будет найден**.
Клиент читает страницу, шлёт поле, получает молчаливое игнорирование либо отказ — а гейт
зелен.

## Противоядие

Спрашивать про **живое поле**, а не про вхождение имени: разбирать контракт и брать
объявления полей, исключив блоки `reserved`. Для проверок над `.proto` это дескриптор либо
разбор, но никогда не поиск по образцу над текстом файла — там `reserved` неотличим от
объявления.

Проверяется одной парой в инъекции: имя, снятое **через `reserved`**, обязано считаться
отсутствующим; имя живого поля — присутствующим. Без первой половины пара односторонняя.

## Где наблюдалось

Междусессионный обмен 2026-08-31: соседняя линия нашла комментарий, перечисляющий
изменяемые поля снятыми именами, и назвала их «снятыми с контракта». Вывод верен по
существу; проверка замером показала, что имена **в контракте есть** — в резервировании.
Формулировка «снятые» и предикат «нет в контракте» разошлись бы на первом же гейте.

Класс шире `.proto`: тот же вопрос стоит перед всяким предикатом, который спрашивает
о существовании имени там, где язык умеет **объявлять его отсутствие**.
