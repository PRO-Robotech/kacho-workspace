# Приёмка сняла кейс, правило ещё производит его код

## Признак

Редакция приёмки снимает семейство кейсов, а код правил, производящих их диагностики, ещё в
дереве. Пока обе половины не влиты вместе, дерево несёт **контракт, написанный
реализацией**: правило производит коды, которых приёмка не объявляет, и рецензент судил бы
то, чего никто не утверждал. Это запрет №1 («не кодить без APPROVED-приёмки») с внутренней
стороны — не «код без приёмки», а **код сверх приёмки**.

Признак механический, одной строкой переписи:

```
перепись сверки диагностик: диагностик правил 135 · диагностик приёмки 127 · мимо приёмки 9
```

**Величины печатаются обе.** Одно число скрывает ровно тот случай, ради которого сверка
заведена: множества разошлись, а размер не изменился — так уже было, 134 и 134.

## Две стороны расхождения, и слышно только одну

| направление | что происходит | как узнаётся |
|---|---|---|
| **правило → приёмка** (громко) | код производит диагностику, которой приёмка не объявляет | утверждение сверки краснеет и **называет код**; набор даёт код 1 |
| **приёмка → дерево** (тихо) | фикстура, которую приёмка больше не называет, остаётся на диске | **не узнаётся ничем**: драйвер ведёт перечень ИЗ приёмки, осиротевший каталог никто не посещает |

Тихая сторона проверена прямым прогоном: одиночный запуск осиротевшей фикстуры отвечает

```
case SDD-1-ADAPTER-01
  в приёмке нет такого case ID; всего разобрано 185
HARNESS · HARNESS_CASE_UNKNOWN · exit 40
```

— это **третья категория**, «не выполнилось», а не красный вердикт. Матрица же обходит
объявленный перечень (`for case_id in order`), поэтому фикстур вне перечня не касается
*by construction*: её прогон честно печатает «185 из 185, поломок harness 0», и о
тринадцати каталогах на диске не говорит ничего.

## Где наблюдалось

`ws#666` / редакция приёмки SDD-1, 2026-09-18. Приёмка сняла тринадцать кейсов
`SDD-1-ADAPTER-01…13` надгробиями (номера сохранены, метки не переиспользуются), кейсов
стало **198 → 185**; семейство `cg.adapter` и тринадцать каталогов фикстур остались в
дереве обеих веток.

Воспроизведено в отдельной копии — приёмка с ветки редакции, код со ствола — и откачено с
доказательством (`git status --porcelain` пуст):

```
промежуток : рассмотрено проверок 4; пройдено 3, провалено 1 → код 1
             FAIL I1 · мимо приёмки 9 · из них прощено ведомостью 0
контроль   : мимо приёмки 0 · утверждений 192, провалено 0 → код 0
```

Девять кодов — по числу диагностик семейства, а не по числу снятых кейсов: тринадцать
кейсов объявляли девять диагностик.

## Противоядие

**Промежуток допустим, но у него обязан быть КОНЕЦ С ПРЕДИКАТОМ.** Приёмка вправе
опережать код — это и есть ban #1, — но редакция и снятие кода вливаются **вместе** либо
снятие идёт немедленно следом. Предикат конца называется числом: набор даёт код 0 и
«мимо приёмки 0».

**«Снимается» пишется будущим временем, пока предмет в дереве.** Круг 1 рецензии этой
редакции был отвергнут ровно за обратное: снятие объявили свершившимся при живых
координатах. Утверждение о дереве проверяется командой, а не намерением автора.

**Ведомость временных прощений ведёт полоса СНЯТИЯ КОДА, а не приёмка.** Иначе прощение
переживёт предмет: приёмка его не увидит, потому что её предмет — текст, а не дерево.

**Тихая сторона закрывается отдельным предметом.** Пока нет проверки «фикстура, которую
приёмка не называет», единственный её признак — сравнение двух чисел вручную:

```sh
ls -d <каталог фикстур>/*/ | wc -l                     # что лежит на диске
python3 <драйвер> --list | grep -cE '^<префикс>-'      # что объявлено приёмкой
```

Расхождение — находка. Совпадение ничего не доказывает о содержимом, только о числе.

## Чем держится

**Громкая сторона — гейтом.** Сверка диагностик правил с объявлениями приёмки краснеет,
называет код поимённо и различает два диагноза: «приёмка код упоминает, но не объявляет»
(прозой) и «правило объявляет то, чего приёмка не объявляет вовсе». Перепись печатает обе
величины и объявляет **пустой обход находкой**, а не чистотой.

**Тихая сторона — ничем**, и это сказано прямо: проверки «фикстура без объявленного кейса»
в дереве нет, предмет заведён задачей
[ws#672](https://github.com/PRO-Robotech/kacho-workspace/issues/672). До неё класс держится
вниманием того, кто правит приёмку.
