# Kachō — общий протокол воркспейса

Файл видят **оба конца** — диспетчер и исполнитель. Норм продукта здесь нет: правила закреплены
за исполнителями (`.claude/rules/MANIFEST.md` — колонка «закреплено за агентами»; этот файл
корпус **не** импортирует, см. ниже).

## Модель загрузки — решение владельца 2026-09-17

**Дословно:** «все рулы свести к агентам которые должны их использовать. Основной процесс
должен уметь выбирать агента, который будет решать конкретную задачу, выставлять
последовательность агентов. Мастер процесс загружает только базу которая позволит определить
какого агента в какой момент запускать. Все свои доп запросы он опрашивает через саб агентов.
Сам ничего не разведает только принимает решения основываясь на 1) данных полученные из агента
2) основываясь на рулах которые он читает на старте.»

Решение 2026-09-13 («весь корпус каждому») им **отменено**:

| что | как это сделано | чем держится |
|---|---|---|
| корпус правил не грузится ни диспетчеру, ни исполнителю автоматически | `.claude/settings.json` → `claudeMdExcludes: ["**/.claude/rules/**"]`; в этом файле нет ни одного `@import` правила | `scripts/rules-gate/` |
| главный поток — агент `dispatcher`, у него нет ни `Read`, ни `Bash`, ни `Edit` | `.claude/settings.json` → `agent: "dispatcher"`; тело `.claude/agents/dispatcher.md` заменяет системный промпт и является **единственной** базой маршрутизации | `scripts/rules-gate/` |
| правило попадает к агенту, который обязан его применять | у правила есть скилл-ссылка `.claude/skills/rule-<имя>/SKILL.md → ../../rules/<имя>.md`, агент перечисляет свои правила во `skills:` — харнесс грузит их при старте целиком | `scripts/rules-gate/` |
| правило по условию — по условию | «Правила по триггеру» тела агента: триггер → `Skill rule-<имя>` | вниманием агента |
| последовательность агентов выставляет только диспетчер | у исполнителя `disallowedTools: Agent` — вложенных запусков нет | `scripts/rules-gate/` |

Исключение, а не перенос каталога: **все** `.md` внутри `.claude/rules/` Claude Code грузит
сам, рекурсивно (измерено); не трогая адресов, это снимает лишь `claudeMdExcludes`.

Без диспетчера: `claude --agent <исполнитель>` (флаг перекрывает настройку).

## Контракт возврата: как исполнитель отвечает диспетчеру

Диспетчер ничего не разведывает сам и решает **только** по возврату. Последний блок ответа
исполнителя — ровно такой, поля обязательны, «—» если нечего сказать:

```
### ВОЗВРАТ
- статус: готово | блокер | вопрос-владельцу | не-выполнилось
- вердикт: — | ✅ принято | ⛔ возврат → <агент> | ⟳ прогон недействителен
- исход проверок: зелёных N · красных N · не выполнилось N | проверок не было
- посылка: подтверждена | опровергнута — <команда, которой проверил>
- артефакты: пути · ветка/worktree · sha · PR/issue URL
- доказательства DoD: URL комментария `DoD-proof` в каждой задаче | —
- факты: <утверждение> — <измерено <командой> @<ревизия> | прочитано в <файл:строка> | со слов <кого>>
- нужен следующий: <агент> — <задание одной фразой>
- вопросы владельцу: <вопрос>
- затронуто в vault: ресурсы · rpc · пакеты · рёбра
- урок: <класс> · <где предотвратить> | —
```

Чтение: «зелёный» без числа исполненного — не зелёный; «не выполнилось» ≠ «красное»; посылка без
строки — **непроверенная**; «нужен следующий» — заказ, порядок решает диспетчер; «вопросы
владельцу» — варианты, цена, рекомендация, «—» — вопроса нет (`flow-acceleration.md` fa-b4);
«урок» — `ai-tooling.md#at-lane-retro`. Норма и урок — при скорости не ниже, токенах не выше,
качестве кода не ниже, с числом (`ai-tooling.md#at-norm-criterion`).

## Перепись — потом массово (владелец 2026-10-16, безусловно)

«никогда нельзя решать проблемы по одному, сначала делается перепись, потом фиксится,
потом прогоняется тесты на внешнем кластере, потом в master ci. Если найдены ошибки так же сначала
перепись ошибок, массовое решение, дальше проверка только того что было красное, если все зеленое на
внешнем кластере гонится весь прогон и в CI». Любая проблема — полоса, сборка, хук, стенд, CI:
1. перепись — весь затронутый набор целями CI на внешнем кластере, без остановки на первом
   красном, цитата до класса корня; CI — по завершении ВСЕХ заданий (`ci-read.sh` код 3);
2. все корни — одной сборкой, по одному — нарушение;
3. только бывшее красным — на кластере (`stand-report.sh --of`); красное — снова п.1;
4. всё зелёное — полный там же: `stand-report.sh` код 0 той же головы;
5. затем ОДИН CI; ready и вливание без п.4 — отказ (`wave.js` mech:stand, `landing-precheck.sh
   --stand-report`); два красных CI подряд — стоп. Канон — `ai-tooling.md#at-red-ci-one-round`.

## Если ты исполнитель (сабагент)

- Твои правила уже в окне (`skills:`); по условию — `Skill` по разделу «Правила по триггеру».
  Других агентов ты **не запускаешь**: нужен другой — строка «нужен следующий».
- Строка «вопросы владельцу» — ДИСПЕТЧЕРУ, решает он сам (решение владельца 2026-09-20, §11 его
  базы); стоит предмет строки, а не вся задача.
- **Препятствие исходом не является.** Решение владельца 2026-09-20 дословно:
  «решения принимаешь ты на человеке не блокируемся». Встретив отказ, ищи ОБХОД; три исхода и
  доказательство недостижимости — `00-kacho-core.md#ban18-three-outcomes-at-obstacle`, «жду
  человека» не исход. Обход ищут СРЕДИ безопасных способов, а не вместо безопасности: отклонённое
  средой по безопасности обходом не считается и не повторяется.
- Работаешь в ветке и копии из задания и **коммитишь сам**: гейт судит коммит. Первая строка
  — `#<N> …`, N — задача ТВОЕГО репозитория о твоём предмете: `gh issue view N -R <репо>` до коммита.
- **«Готово» — после полного хука отправки на закоммиченной голове, отказов 0**, итог — в «исход
  проверок»: из чистой копии слотом (`heavy-slot.sh ci-local`) `git push origin
  HEAD:refs/heads/<ветка>`, при запрете отправки — с `--dry-run`. Консоль kacho — сперва `npm ci`
  как `ui.yml` (`ui-future` и `--prefix` каждого `STANDALONE`).
- До «готово» — в КАЖДОЙ задаче полосы комментарий `DoD-proof @<sha>`: команда, сырой итог, код
  возврата, без адресов и секретов; без него задача в PR — `Refs`, не `Closes`, и каскад волны её
  не закрывает (`cascade-census.sh --proof`; владелец 2026-10-04, архив `routing-base`).
- **Не жди.** Владелец 2026-10-11 дословно: «И реши проблему раз и навсегда что таски уходят в
  часовые таймауты и ничего не делают а мы ждем». Ни один вызов не держит ожидание дольше 10
  минут: долгое — отсоединённо (`setsid env --default-signal=PIPE …`, код — в `.rc`), шаг возвращает «идёт: pid,
  журнал, срок», исход дочитывает короткий шаг; слот тяжёлого — внутри него (занят — код 74 сразу).
  Циклы со `sleep`, `wait` после `&`, `tail --pid`, опрос CI отказывает хук `no-wait-guard`; срок
  истёк — возврат с остатком. Застой меряет `scripts/stall-census.sh` (`ai-tooling.md#at-agent-does-not-wait`).
- Свою ветку отправляешь сам, в переднем плане; PR, сборка, вливание, снятие ветки — `git-operator`.

## Топология

Продукт — один репозиторий `PRO-Robotech/kacho` (клон `project/kacho`).
**Оба репозитория публичны.** Управление доступом — отдельный продукт `PRO-Robotech/kaname`.
Спека — `docs/specs/0{0..4}-*.md`, раскладка монорепо — `.claude/rules/polyrepo.md`.

AI-оснастка — **одна**, в `.claude/` воркспейса: ни копий в продукте, ни раскатки, ни проекций
(владелец 2026-09-18); второго её представления в дереве не заводится. Канон — `.claude/rules/ai-tooling.md`.

## Локальная разработка

- Тяжёлое (-race, integration, ci-local, линт, docker, стенд, newman) — только
  `$WS/scripts/heavy-slot.sh <класс> -- <команда>` (`$WS` — корень воркспейса). Владелец 2026-10-02:
  «я расширил память еще на 32» — ≤ 70 ГБ, 3 слота по 10, старт при свободных ≥ 15; без слота —
  отказ `heavy-guard`. Тяжёлое и стенд — ТОЛЬКО во внешнем кластере, локально — лишь при
  недоступном, доказательство пишет слот (77 — «во внешний кластер»): `testing-verdict.md#external-cluster-first`.
- Потолок сессии ставит хук SessionStart (`scripts/session-memcap.sh`); сессию с ним запускают
  `$WS/scripts/session-memcap.sh --launch -- claude`: scope терминала (OOMPolicy=stop) его снял бы.
- Стенд: `cd project/kacho/deploy && $WS/scripts/heavy-slot.sh stand -- make stand-ns-up NS=t<N>-<коротко>` / `stand-ns-down`; `make dev-up` — лишь при недоступном
- Перезапуск сервиса: `… stand -- make reload-svc SVC=<vpc|compute|iam>` · логи: `make logs-svc SVC=…` · psql: `make psql SVC=…`
- Обновить рабочие копии: `./sync-all.sh`

## Permissions и хуки

`.claude/settings.json` — `agent`, `claudeMdExcludes` и хуки: vault-discipline
(`UserPromptSubmit` / `Stop`), `stall-signal` (там же), `class-guard` и `docfresh` (`PostToolUse`, срабатывают и внутри
сабагентов), `heavy-guard` (`PreToolUse` Bash, Monitor), `no-wait-guard` и `gh-api-guard` (`PreToolUse` Bash), `session-memcap` (`SessionStart`),
`change-graph-reminder`, rag-хуки. Пути — через `$CLAUDE_PROJECT_DIR`; в продукте файла нет.

Режима без подтверждений из дерева **нет**: `permissions.defaultMode` проектного и локального
слоёв харнесс игнорирует; режим даёт только личный `~/.claude/settings.json`,
policy или флаг (`ai-tooling.md`, at-bypass-not-from-repo-layer).

Хуки запроса и хода печатают **диспетчеру**, сам он ничего не делает: что каким агентом
закрывается — таблица сигналов в `.claude/agents/dispatcher.md`. Хуки записи и команд говорят
исполнителю, который их вызвал.
