# suites-gate — свойства, общие всем наборам проверок

Предмет набора — не дерево продукта и не корпус правил, а **сами наборы проверок**
воркспейса (`scripts/<набор>/run-all.sh`): как проверка берёт корень, различает ли
она «ноль осмотренного» и «ноль находок», печатает ли объём, зовёт ли конвейер
каждый набор, различимы ли адреса проверок, держатся ли числа в шапках, не берётся
ли вердикт из трубы. Каждое из этих свойств прежде держалось вниманием автора
очередного набора, и каждое уже стоило ложного зелёного.

Перечень наборов и проверок **выводится** переписью `scripts/lib/suites.py` из
индекса git: набор, заведённый завтра, попадает под все проверки этого набора сам,
без правки чего-либо здесь.

## Общие механизмы, на которых стоит набор

| механизм | файл | что держит |
|---|---|---|
| корень проверки | `scripts/lib/gate_root.py` | переопределение набора → `GATE_ROOT` → расположение файла; рабочий каталог не участвует |
| перепись наборов | `scripts/lib/suites.py` | что считается набором, проверкой и доказательством |
| прогон набора | `scripts/lib/suite-runner.sh` | три исхода и их коды; пустой обход — находка; ноль без напечатанного объёма — находка; рабочий каталог проверки — пустой чужой репозиторий; машинная строка переписи в `SUITE_SUMMARY` |

## Проверки

Таблица перечисляет проверки для чтения; прогон находит их **глобом** общего
прогонщика, и она не является перечнем исполняемого.

| проверка | задача | утверждение |
|---|---|---|
| `check-01-check-root-is-not-the-working-directory.py` | ws#757 | исход каждой проверки не зависит от рабочего каталога |
| `check-02-empty-tree-is-not-a-clean-verdict.py` | ws#762 п.3 | проверка, направленная на пустое дерево, не выходит нулём |
| `check-03-runner-demands-a-printed-volume.py` | ws#762 п.1–2, ws#757 | прогонщик каждого набора не засчитывает молчаливый ноль, исполняет проверки из пустого каталога и пишет перепись |

## Запуск

```sh
bash scripts/suites-gate/run-all.sh   # вердикт — код выхода: 0 · 1 находка · 2 без предмета
bash scripts/suites-gate/inject.sh    # доказательство: дефект краснеет, близнец молчит
```

Корень переопределяется `SUITES_GATE_ROOT` (так делает `inject.sh`) либо общим
`GATE_ROOT`.

## Форма прибора (ws#762) — каким пунктом что держится

| пункт формы | держатель |
|---|---|
| 1. исход не из одного канала | общий прогонщик: код 0 засчитывается только при напечатанном объёме |
| 2. объём осмотренного печатается всегда | общий прогонщик (строка с числом у каждой зелёной проверки) и `check-03` (каждый прогонщик это требует) |
| 3. «ноль находок» отличим от «ноль осмотренного» | `check-02`: пустое дерево не даёт нуля ни у одной проверки |
| 4. точка отсчёта снята перед действием | **этим набором не держится**: предмет пункта — приборы отправки и посадки (хуки, `branch-audit`, `merge-readiness`), их держатели заводятся своими задачами |
