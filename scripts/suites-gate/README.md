# suites-gate — свойства, общие всем наборам проверок

Предмет набора — не дерево продукта и не корпус правил, а **сами наборы проверок**
воркспейса (`scripts/<набор>/run-all.sh`): как проверка берёт корень, различает ли
она «ноль осмотренного» и «ноль находок», печатает ли объём, зовёт ли конвейер
каждый набор, различимы ли адреса проверок, держатся ли числа в шапках, не берётся
ли вердикт из трубы, задаёт ли доказательство своё окружение. Каждое из этих свойств прежде держалось вниманием автора
очередного набора, и каждое уже стоило ложного зелёного.

Перечень наборов и проверок **выводится** переписью `scripts/lib/suites.py` из
индекса git: набор, заведённый завтра, попадает под все проверки этого набора сам,
без правки чего-либо здесь.

## Общие механизмы, на которых стоит набор

| механизм | файл | что держит |
|---|---|---|
| корень проверки | `scripts/lib/gate_root.py` | переопределение набора → `GATE_ROOT` → расположение файла; рабочий каталог не участвует |
| перепись наборов | `scripts/lib/suites.py` | что считается набором, проверкой и доказательством |
| вывод перечня для конвейера | `scripts/lib/run-suites.sh` | конвейер исполняет каждый набор дерева и его `inject.sh`; код набора сверяется с его строкой переписи — строка есть, «исполнено» больше нуля, сумма исходов равна исполненному, код согласен с исходами; «наборов в дереве × исполнено» печатается числом |
| вызов скрипта конвейером | `scripts/lib/ci_calls.py` | путь в положении команды, вердикт доходит до задания, задание и шаг безусловны; незасчитанный вызов — с причиной; общий для `check-04` и `change-graph-gate/check-03` |
| части и окружение доказательства | `scripts/lib/proofs.sh` | вход `inject.sh` набора исполняет свои части `inject-<N>*.sh`, перечень выводится из каталога; `proof_own_environment` снимает унаследованные `KACHO_HOME_*` и переопределения корня |
| прогон набора | `scripts/lib/suite-runner.sh` | три исхода и их коды; пустой обход — находка; ноль без отдельного числа объёма — находка; двойка без строки `[VOID]` — находка; рабочий каталог проверки — пустой чужой репозиторий; машинная строка переписи в `SUITE_SUMMARY` |

## Проверки

Таблица перечисляет проверки для чтения; прогон находит их **глобом** общего
прогонщика, и она не является перечнем исполняемого.

| проверка | задача | утверждение |
|---|---|---|
| `check-01-check-root-is-not-the-working-directory.py` | ws#757 | исход каждой проверки не зависит от рабочего каталога — ни при переопределении корня (пара A/B), ни без него (пара C/D: копия проверки в другом дереве, запасная ветка получения корня исполняется) |
| `check-02-empty-tree-is-not-a-clean-verdict.py` | ws#762 п.3 | проверка, направленная на пустое дерево, отвечает «без предмета» (2) строкой `[VOID] <причина>`; ноль, код находки (1), двойка молча, двойка без строки `[VOID]` (код интерпретатора) и код вне трёх исходов — находки |
| `check-03-runner-demands-a-printed-volume.py` | ws#762 п.1–2, ws#757 | прогонщик каждого набора засчитывает ноль только при отдельном числе объёма (цифры адреса `check-NN` — не объём), двойку — только при строке `[VOID]`, краснеет на наборе без проверок, исполняет проверки из своего git-каталога (при `TMPDIR` внутри рабочей копии) и пишет перепись |
| `check-04-ci-calls-every-suite.py` | ws#753, ws#817 | конвейер зовёт каждый набор дерева и его `inject.sh` — выводом перечня (с `--proofs`) либо поимённо; вызов узнаёт общий распознаватель `scripts/lib/ci_calls.py`, и засчитывается он, только если вердикт доходит до задания (не `echo "…"`, не `|| …`, не звено трубы, не фон, не условие, без `if:` и `continue-on-error`); незасчитанный вызов и набор без `inject.sh` — находки |
| `check-05-check-numbers-are-unique-and-gapless.py` | ws#754 | номера проверок внутри набора различны и идут от 01 без разрывов; имя без номера и номер 00 — находки |
| `check-06-header-numbers-carry-their-predicate.py` | ws#760 | число-утверждение в шапке скрипта набора и общей библиотеки `scripts/lib/` стоит в одном абзаце с командой, которая его воспроизводит (обратная форма «Наборов 8.» — с точкой в конце предложения — тоже утверждение); единица счёта и словарь единиц объявлены в самой проверке; прочие `*.sh`/`*.py` под `scripts/` не судятся, но отдельная строка переписи называет их число по каталогам и число утверждений в их шапках |
| `check-07-no-verdict-from-a-pipe.py` | ws#395 | под `pipefail` вердикт не берётся из трубы в `grep`, выходящий на первом совпадении (`-q`/`-m`/`-l`/`-L`, длинные формы и их однозначные сокращения); звено узнаётся и по пути (`/usr/bin/grep`), и под обёрткой (`env`, `timeout`, `nice`, `stdbuf`, `command`, `exec`, `time`, `sudo`, `nohup`), и в группе (`{ …; }`, `( … )`), и под `!`/`if`; обход — все отслеживаемые файлы оболочки под `scripts/` (`*.sh` и по шебангу) и файлы, которые они подключают, где бы ни лежали; конвейер — логический (труба, продолженная на следующую строку, в том числе через строку-комментарий, и подстановка в двойных кавычках — код); где действует `pipefail`, выводится: `set`/`shopt -o` включают, `set +o`/`shopt -uo` выключают до следующего включения, подключение файлом под `pipefail` и подключение файла, включающего его; неразрешённое подключение — находка; место, про которое доказано, что писатель доживает до конца, помечается `# pipe-safe: <почему>`, пометка без трубы или в файле без `pipefail` — находка; вне обхода — не судится, но отдельная строка переписи называет число файлов и непомеченных форм по каталогам |
| `check-08-proof-owns-its-environment.py` | ws#757 | доказательство набора, чей исполняемый код читает `KACHO_HOME_*`, подключает `scripts/lib/proofs.sh` и зовёт `proof_own_environment` — исход доказательства не зависит от унаследованных указателей на деревья; что функция это обеспечивает, доказывает проба-пара в `inject.sh` (под указателем и без него: со снятием исходы равны, без — различаются) |
| `check-09-derived-run-reads-every-channel.py` | ws#753, ws#762 п.1 | копия `scripts/lib/run-suites.sh` судимого дерева в песочнице с синтетическими наборами краснеет на беспредметном наборе при `--void-is-failure`, неотчитавшемся наборе, строке переписи «исполнено 0» и строке, разошедшейся с кодом, красном и отсутствующем доказательстве при `--proofs`, красном наборе и пустой переписи; близнецы — 0 и 2 |
| `check-10-no-nested-suite-runner.py` | ws#753 | под `scripts/` нет отслеживаемого `run-all.sh` глубже каталога набора: перепись `scripts/lib/suites.py` и хук отправки (pathspec `scripts/*/run-all.sh`, `*` проходит через `/`) определяют набор по-разному и совпадают, только пока вложенного прогонщика нет |

## Запуск

```sh
bash scripts/suites-gate/run-all.sh   # вердикт — код выхода: 0 · 1 находка · 2 без предмета
bash scripts/suites-gate/inject.sh    # доказательство: дефект краснеет, близнец молчит
```

Корень переопределяется `SUITES_GATE_ROOT` (так делает `inject.sh`) либо общим
`GATE_ROOT`.

## Форма прибора (ws#762) — каким пунктом что держится

| пункт формы | держатель |
|---|---|
| 1. исход не из одного канала | общий прогонщик: код 0 засчитывается только при отдельном числе объёма, код 2 — только при строке `[VOID]`; `run-suites.sh` сверяет код набора с его строкой переписи |
| 2. объём осмотренного печатается всегда | общий прогонщик (строка с числом у каждой зелёной проверки) и `check-03` (каждый прогонщик это требует) |
| 3. «ноль находок» отличим от «ноль осмотренного» | `check-02`: на пустом дереве каждая проверка отвечает «без предмета» с причиной — ни нуля, ни находки |
| 4. точка отсчёта снята перед действием | **этим набором не держится**: предмет пункта — приборы отправки и посадки (хуки, `branch-audit`, `merge-readiness`), их держатели заводятся своими задачами |
