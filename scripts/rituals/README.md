# scripts/rituals — ритуалы потока скриптами, а не агентами

Постановка задачи ws#930 (подзадача эпика ws#896), пересказом: ритуалы — записи, события,
тела PR, закрытие волны, trail хранилища — исполняются скриптами, а не агентами.

| вход | что делает | отказ (код 1) |
|---|---|---|
| `scripts/pr-body.sh <вл>/<имя> <база> <голова>` (ws#1146; вход — в `scripts/`, логика — здесь) | тело PR в stdout из git: состав `база..голова` по полосам (слияния первого родителя, вложенные — уровнем ниже), каждый коммит — sha; `#N` — только номера первых строк коммитов диапазона (выражение пункта (в) landing-precheck), задача первой строки в полной форме (`kaname#719`) — полной формой `<вл>/<имя>#N`, прочие упомянутые — строкой без `#`; номер первой строки, которого в репозитории PR нет (трекер — 404), ищется в прочих репозиториях владельца из ведомости стволов `scripts/ci-read-expected.tsv` (ws#1164): задача ровно одного — `Refs <вл>/<имя>#N`, нигде либо в нескольких — строкой «без задачи» без `#`; `Closes` — лишь открытой задаче с комментарием `DoD-proof @<ревизия>`, чья ревизия — коммит диапазона, и не держателю записи долга (перечень `DEBT_LEDGERS` в `rituals.py`: ведомость своего репозитория — на голове, чужого — `origin/main` клона); прочим `Refs`; закрывающие строки последними | строка атрибуции в сообщении коммита или в собранном теле (предикат `scripts/hooks/attribution-rule.sh`) |
| `close-wave.sh <вл>/<имя> <волна> <sha вливания> [--next <N+1>]` | задачи волны с доказательством закрывает комментарием со ссылкой на него и на коммит вливания; остатку — комментарий «Остаток → волна #N+1» и перевод подзадачей; закрывает волну и перечитывает: открытых подзадач 0 | следующая волна закрыта; после действий у волны остались открытые подзадачи |
| `approval-event.sh <вл>/<имя> <документ> <запись> <задача-держатель>` | событие одобрения в задаче-держателе — заголовок из пяти полей (`role · verdict · subject · subject_revision · subject_sha256`, образец kaname#549, комментарий 5944671740); ТЕМ ЖЕ ВЫЗОВОМ блок `event` записи — `status: performed`, `published: true`, адрес, `effective_approval.issued: true` — и коммит записи с первой строкой `#<N> review: …`, где `N` — номер текущей ветки `<N>` либо `<N>-…` (ws#941) | ветки нет либо она не в форме `<N>` / `<N>-…` (`main`, `896x`, `0526`); отпечаток документа в HEAD не равен записи; `subject.sha256` не строка из 64 шестнадцатеричных знаков (отпечаток из цифр без кавычек YAML читает числом); запись судит другой документ; ревизия не на удалённом; запись не записываема, событие уже исполнено либо правка блока задела бы другие поля (всё — до публикации); правка или коммит не удались после публикации — печатается `СОБЫТИЕ ОПУБЛИКОВАНО` с адресом |
| `vault-trails.sh <вл>/<имя> <закрытая задача>…` | `obsidian/kacho/KAC/issue-N[-ws\|-<имя>].md` по оболочке записки: состояние (`done`, `wontfix` для не планируемой), PR, sha, ссылка на доказательство DoD; у существующей записки — только `status`, `prs` и блок закрытия; пересборка указателя и прогон `scripts/vault-gate` | задача открыта; генератор указателя вышел ненулевым кодом; исход ритуала — исход vault-gate |

Исходы у всех: 0 — сделано; 1 — отказ; 2 — не выполнилось (вход не прочитан, предпосылки нет).

**Доказательство DoD** — строка `DoD-proof @<ревизия>` в начале строки комментария задачи
(допустимы заголовок markdown и выделение `**` перед маркером; цитата и блок кода — не
доказательство). Распознаватель один на дерево — `scripts/lib/dod_proof.jq`; его подключают
ритуалы (через `jq`), `scripts/merge-readiness.sh`, `scripts/landing-precheck.sh`,
`scripts/lane-precheck.sh` и `scripts/cascade-census.sh --proof`. Своей копии выражения ни у
кого нет.

**Трекер — через `RITUAL_GH`** (по умолчанию `gh`), вызовы формы `api --method <М> <путь>
[--input -]`. Самопробы подставляют `fake_gh.py` с файлом состояния и в сеть не ходят.
`scripts/pr-body.sh` и `approval-event.sh` читают git рабочей копии `RITUAL_REPO_DIR`
(по умолчанию текущий каталог), ведомости чужого репозитория — `RITUAL_LEDGER_CLONES/<имя>` (по умолчанию
`project/` воркспейса; клона нет — строка «НЕ СВЕРЕНА» в stderr); `vault-trails.sh` пишет в воркспейс `RITUAL_WS` (по умолчанию
корень этого дерева).

**Чем держится.** Набор `scripts/rituals/run-all.sh` — самопробы `check-01`…`check-04` на
подставном репозитории и трекере, задание конвейера `tooling-gate`. Каждый отказ самопроба
судит по коду И по причине в выводе: красное от соседнего отказа пробу не проходит.
Доказательство `inject.sh` — мутанты `rituals.py` и общего `dod_proof.jq` (M1–M68 и близнецы T1, T3, перечень в
шапке файла), каждый обязан покраснить свою самопробу при зелёном контроле.

**Чего не делает.** Не судит отношение «перечень задач в теле волны» — это
`scripts/cascade-census.sh`; не пишет содержательную часть trail (что и зачем), только
оболочку и блок закрытия; не публикует PR — тело печатается для `gh pr create --body-file`.
