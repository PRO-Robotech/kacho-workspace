# scripts/rituals — ритуалы потока скриптами, а не агентами

Постановка задачи ws#930 (подзадача эпика ws#896), пересказом: ритуалы — записи, события,
тела PR, закрытие волны, trail хранилища — исполняются скриптами, а не агентами.

| вход | что делает | отказ (код 1) |
|---|---|---|
| `pr-body.sh <вл>/<имя> <PR>` · `pr-body.sh <вл>/<имя> <ветка> <база> <голова>` | тело PR в stdout: коммиты `база..голова`, перечень задач (имя ветки `<N>-…`, ссылки `#N`, `<вл>/<имя>#N`, адрес задачи своего репозитория); `Closes` — лишь открытой задаче с комментарием `DoD-proof @<ревизия>`, прочим `Refs`; закрывающие строки последними | строка атрибуции в сообщении коммита (предикат `scripts/hooks/attribution-rule.sh`) |
| `close-wave.sh <вл>/<имя> <волна> <sha вливания> [--next <N+1>]` | задачи волны с доказательством закрывает комментарием со ссылкой на него и на коммит вливания; остатку — комментарий «Остаток → волна #N+1» и перевод подзадачей; закрывает волну и перечитывает: открытых подзадач 0 | следующая волна закрыта; после действий у волны остались открытые подзадачи |
| `approval-event.sh <вл>/<имя> <документ> <запись> <задача-держатель>` | событие одобрения в задаче-держателе — заголовок из пяти полей (`role · verdict · subject · subject_revision · subject_sha256`, образец kaname#549, комментарий 5944671740); ТЕМ ЖЕ ВЫЗОВОМ блок `event` записи — `status: performed`, `published: true`, адрес, `effective_approval.issued: true` — и коммит записи | отпечаток документа в HEAD не равен записи; `subject.sha256` не строка из 64 шестнадцатеричных знаков (отпечаток из цифр без кавычек YAML читает числом); запись судит другой документ; ревизия не на удалённом; запись не записываема, событие уже исполнено либо правка блока задела бы другие поля (всё — до публикации); правка или коммит не удались после публикации — печатается `СОБЫТИЕ ОПУБЛИКОВАНО` с адресом |
| `vault-trails.sh <вл>/<имя> <закрытая задача>…` | `obsidian/kacho/KAC/issue-N[-ws\|-<имя>].md` по оболочке записки: состояние (`done`, `wontfix` для не планируемой), PR, sha, ссылка на доказательство DoD; у существующей записки — только `status`, `prs` и блок закрытия; пересборка указателя и прогон `scripts/vault-gate` | задача открыта; генератор указателя вышел ненулевым кодом; исход ритуала — исход vault-gate |

Исходы у всех: 0 — сделано; 1 — отказ; 2 — не выполнилось (вход не прочитан, предпосылки нет).

**Доказательство DoD** — строка `DoD-proof @<ревизия>` в начале строки комментария задачи.
Распознаватель один на дерево — `scripts/lib/dod_proof.jq`; его подключают и ритуалы (через
`jq`), и `scripts/merge-readiness.sh`, и `scripts/cascade-census.sh --proof`. Своей копии
выражения ни у кого нет.

**Трекер — через `RITUAL_GH`** (по умолчанию `gh`), вызовы формы `api --method <М> <путь>
[--input -]`. Самопробы подставляют `fake_gh.py` с файлом состояния и в сеть не ходят.
`pr-body.sh` в форме с веткой и `approval-event.sh` читают git рабочей копии `RITUAL_REPO_DIR`
(по умолчанию текущий каталог); `vault-trails.sh` пишет в воркспейс `RITUAL_WS` (по умолчанию
корень этого дерева).

**Чем держится.** Набор `scripts/rituals/run-all.sh` — самопробы `check-01`…`check-04` на
подставном репозитории и трекере, задание конвейера `tooling-gate`. Каждый отказ самопроба
судит по коду И по причине в выводе: красное от соседнего отказа пробу не проходит.
Доказательство `inject.sh` — мутанты `rituals.py` и общего `dod_proof.jq` (M1–M25, перечень в
шапке файла), каждый обязан покраснить свою самопробу при зелёном контроле.

**Чего не делает.** Не судит отношение «перечень задач в теле волны» — это
`scripts/cascade-census.sh`; не пишет содержательную часть trail (что и зачем), только
оболочку и блок закрытия; не публикует PR — тело печатается для `gh pr create --body-file`.
