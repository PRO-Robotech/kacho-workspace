# push-gate — механизм отправки воркспейса, судимый поведением

Предмет набора — то, что стоит между `git push` и «сервером»: переходники хуков в
`.git/hooks`, хук `scripts/hooks/pre-push` и инструменты отправки. Каждая проверка
заводит герметичную песочницу (синтетический клон и bare-«сервер» рядом, настройка git
машины отключена), провязывает хуки **тем же** установщиком `scripts/hooks/install.sh`,
что и настоящий клон, отправляет и читает исход: код, печать и ссылку на «сервере».
Текст хука не читается — читается его поведение.

| проверка | что утверждает | задача |
|---|---|---|
| `check-01-hook-stub-refuses-without-target.sh` | переходник без адресата останавливает операцию с причиной «условие не создано», обход один и явный (`--no-verify`); `install.sh check` печатает два состояния — «переходник есть» и «адресат исполним» — и зелен только при обоих; наш переходник без хука в дереве и переходник v1 — отказ; `core.hooksPath` — отказ | ws#751, ws#729 пп. 2–3 |
| `check-02-push-range-judges-identities.sh` | хук отправки судит ОТПРАВЛЯЕМЫЙ диапазон (коммиты, которых на сервере ОТПРАВКИ нет — спрошено `ls-remote`, а не ссылками отслеживания) против ведомости ОТПРАВЛЯЕМОЙ ревизии: автор, коммиттер или соавтор вне ведомости — отказ до публикации с sha, ролью и адресом; освобождённая личность отправляемый коммит не подписывает; адрес, внесённый в ведомость ревизии, снимает отказ, незакоммиченная запись — нет; ведомости или разборщика нет — отказ «судить нечем»; исход 2 суждения — отказ; уже опубликованное не судится повторно, устаревшая ссылка отслеживания и `pushurl` на другой сервер чужого не вычитают; посадка сервером (коммиттер из `committers`) проходит по URL и в зеркало, автором — отказ; строки, пришедшие с задержкой при вызове от git, судятся; хук без диапазона говорит «НЕ судились» | ws#729 пп. 1, 2, 4, 5; ws#700 |
| `check-03-neighbour-homes-are-derived.sh` | хук выводит соседние дома из канонического клона (`<канонический>/project/*` → `KACHO_HOME_<ИМЯ>`) и печатает каждый; вердикт из копии-worktree совпадает с вердиктом из канонического клона по строке «исполнено наборов», без предмета 0; отсутствующий дом не выдумывается; заданный снаружи не перебивается | ws#747 |
| `check-04-push-verdict-comes-from-the-remote.sh` | исход отправки — постусловие сервера: исполняет доказательство `scripts/push-verified-inject.sh` (ложный ноль тремя путями краснеет, законная отправка молчит); `install` ставит клону keepalive транспорта и не перебивает чужой; хук отправки называет свой код исходом проверок и печатает `git ls-remote` с отправленной sha | ws#776 |
| `check-05-preservation-denominator-is-the-lane.sh` | доказательство сохранности берёт знаменатель со всей полосы от `merge-base` и судит двумя осями, вторая — по каждой форме записи работы (текст по числу вхождений в обе стороны с поправкой на соседа, двоичное и подмодуль — объектом, режим, снятие файла): исполняет `scripts/preservation-proof-inject.sh` (потеря вне головного коммита, двоичного содержимого, бита исполнения, цели ссылки, указателя подмодуля, одного из повторов краснеет; законное слияние молчит) | ws#776 |

Запуск: `bash scripts/push-gate/run-all.sh` — вердикт в коде выхода (0 · 1 находка ·
2 без предмета). Доказательство способности упасть: `bash scripts/push-gate/inject.sh` —
однофактный мутант настоящего файла предмета на каждую проверку и близнец без мутации.
Предмет подменяется переменной `PUSH_GATE_SUBJECT` (корень дерева с файлами предмета).

Набор исполняется хуком отправки: `scripts/hooks/pre-push` выводит перечень наборов из
дерева (`scripts/*/run-all.sh`), поэтому отдельной провязки не нужно. Провязка в
конвейер воркспейса — вне этого набора.
