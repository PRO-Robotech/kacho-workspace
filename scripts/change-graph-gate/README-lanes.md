# Полосы прогона оснастки контура SDD-1

Каталог несёт три вещи, и до 2026-09-02 ни одну из них не звало **ничто**
(ws#504): ни хук отправки, ни конвейер. Хук выводит свой перечень из дерева
(`git ls-files 'scripts/*/run-all.sh'`), поэтому каталог без прогонщика
оставался вне его *by construction* — молча и без строки в переписи. Цена
измерена: за один разбор нашлись две поломки, обе жившие на стволе и обе
невидимые (`selftest/inject.py` падал `NameError` на любом полном вызове,
ws#503; `selftest/prove_run_progress.py` был красен 6 из 8).

## Разделение по цене — замер, а не догадка

Замер на `61fddcc`, одна машина, последовательно, свободная очередь:

| `selftest/prove.py` | `hook` | 19.8 с | 177 утверждений |
| `selftest/prove_census_policy.py` | `hook` | 3.0 с | 38 утверждений |
| `tests/selfcheck/prove.sh` | `hook` | 2.8 с | 34 утверждения |

| **итого `hook`** | | **57.5 с** | |
| `selftest/inject.py` | `ci` | 865.7 с | 46 инъекций с контролем |
| `selftest/prove_run_progress.py` | `ci` | 73.6 с | 8 утверждений |

**Граница совпала с предметом, и это не совпадение.** Дешёвое отвечает на вопрос
«работает ли контур»; дорогое — на вопрос «СПОСОБЕН ли контур упасть».
Доказательство падучести есть повторный прогон испытуемого по разу на каждую
инъекцию: 42 прогона `prove.py` по 20 с и дают те самые четырнадцать минут.

> [!note] Таблица — ЗАМЕР ревизии `61fddcc`, и после неё контур рос
> Числа выше верны для своей ревизии и здесь не подгоняются: подмена замера
> сегодняшними значениями стёрла бы основание, из которого выведена граница
> полос. Перемер на ветке ws#502: `prove.py` — **190** утверждений (было 177),
> `inject.py` — **44** инъекции (было 42), то есть дорогая полоса выросла
> примерно на два прогона испытуемого. Та же таблица объявлена в `lanes.py` и
> привязана к той же ревизии; второго перечня здесь не заводится.
>
> Прирост — секция `I` `prove.py`: диагностика правила берётся из **приёмки**, а
> не заводится реализацией. Круг M2 добавил к ней ось **разбора**: объявлением
> считается только вердиктная тройка приёмки, упоминание прозой — нет (пара
> `I8`/`I8-близнец` плюс своя инъекция). Предмет, форма объявляющей позиции с
> её замером и обе стороны доказательства — `selftest/README.md` §«Диагностика
> берётся из ПРИЁМКИ»; здесь это не пересказывается.

**Почему дорогое не в хуке.** Хук, отвечающий четверть часа, начинают обходить —
и тогда он не защищает ничего. Обход объявлен законным
(`KACHO_SKIP_PREPUSH=1`, `git push --no-verify`), то есть это не гипотеза.

## Где что исполняется

| артефакт | хук отправки | конвейер |
|---|---|---|
| `run-all.sh` (полоса `hook`, 58 с) | **да**, выводится глобом | **да**, шагом задания |
| `inject.sh` (доказательство падучести набора, 6.5 с) | нет | **да** |
| `prove-all.sh` (полоса `ci`, 17.3 мин) | нет | **да** |

**Конвейер обязан быть НАДМНОЖЕСТВОМ хука**, а не дополнением к нему: обход хука
законен, и полоса, которую зовёт только он, при обходе не гоняется никем. Это
проверяется, а не обещается — `check-03`.

## Чем заметно красное дорогой полосы

Задание `change-graph-proofs` объявлено на `pull_request: [main]` и `push:
[main]`, то есть срабатывает на **MR релизной линии в ствол** — в тот самый
момент, когда работа садится, — и на стволе после слияния. Красное видно в
перечне проверок PR.

**Чего это НЕ даёт, названо прямо.** Имя задания не входит в перечень
обязательных контекстов защиты ветки `main`, поэтому его красное **видно, но
слияние не блокирует**. Предикат остатка:

```sh
gh api repos/PRO-Robotech/kacho-workspace/branches/main/protection \
  --jq '.required_status_checks.contexts[]' | grep -c 'оснастка контура'
```

Ноль означает, что вторая половина не закрыта. Закрывается она **настройкой
репозитория**, а не деревом, — то есть решением владельца, и потому названа
остатком, а не обещанием.

## Ведомость полос — одно место, и она самоистекает

`lanes.py` несёт единственное объявление: полоса · путь · причина. Полоса `none`
— не дыра, а решение с написанной причиной: точка входа, пробой не являющаяся
(испытуемый, matrix command, подставной SUT, генератор fixtures), обязана иметь
строку.

`check-02` сверяет ведомость с деревом **в обе стороны**: точка входа без строки
— находка (проба выпала бы из обеих полос молча, ровно как выпал весь контур);
строка без точки входа — тоже находка (исключению нечего исключать).

Признак точки входа **структурный, а не по имени**: отслеживаемый файл в
`selftest/` либо `tests/`, несущий `if __name__ ==` для `.py` или шебанг для
`.sh`. Соглашение контура называет пробы `prove*`/`inject*`, но
`selftest/laneparity.py` под него не подходит — перечень по имени потерял бы её
молча.

**Граница признака названа, а не подразумевается.** Он смотрит в два каталога, и
это решение: испытуемый (`run.py`) и сама полосовая оснастка (`lanes.py`,
`run-all.sh`, `prove-all.sh`, `check-*.sh`, `inject.sh`) лежат ВЫШЕ них, поэтому
не требуют строк и не создают самоссылки. Цена: проба, заведённая **прямо в
`scripts/change-graph-gate/`**, мимо обоих каталогов, под признак не попадёт и
строки не потребует. Сегодня таких проб ноль, и место у проб контура объявлено
его же READMEs (`selftest/README.md` — испытуемый, `tests/README.md` — driver);
если это перестанет быть правдой, признак придётся расширять, а не дописывать
исключение.

## Прогон

```sh
bash scripts/change-graph-gate/run-all.sh     # дешёвая полоса, ~1 мин
bash scripts/change-graph-gate/inject.sh      # доказательство падучести набора, 21 утверждение, ~7 с
bash scripts/change-graph-gate/prove-all.sh   # дорогая полоса, ~17 мин
python3 scripts/change-graph-gate/lanes.py --list   # ведомость полос
```

Правя `check-*.sh` — зови `inject.sh` руками: конвейер скажет о потерянной
падучести только на MR.

## Три исхода, и третий не вычитается из вердикта

`0` — прошло · `1` — находка · `2` — без предмета. Код 2 не засчитывается за
успех и печатается отдельной строкой; находка объявляется **первой**, поэтому
беспредметная проверка не может стать маской для нарушения. Свойство держит
`scripts/tooling-gate/check-07-runner-void-distinct-from-finding.sh`, который
кладёт рядом с копией прогонщика заглушки с заданными кодами и читает исход.
