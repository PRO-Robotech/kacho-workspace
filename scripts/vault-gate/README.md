# vault-gate — записки хранилища знаний сверяются с деревом

**Предмет:** утверждения, которые записки `obsidian/kacho/` делают о дереве
соседнего монорепо. Такие утверждения устаревают **молча и в одну сторону**: код
уезжает, записка остаётся, и следующий читатель проектирует по механизму,
которого в дереве уже нет. Абзац «сверяйтесь с кодом» этого не ловит — ловит
исполняемый вопрос к дереву.

Набор устроен как `scripts/skills-gate/`: `check-NN-*.sh` выносят исход кодом
(`0` — чисто, `1` — находки, `2` — предпосылки нет), `run-all.sh` сводит один
вердикт из числа, `inject.sh` доказывает, что гейт **способен упасть** и
**способен смолчать**.

## Прогон

```bash
# Монорепо рядом (project/kacho) — находится само:
./scripts/vault-gate/run-all.sh

# Монорепо в другом месте (worktree, отдельный клон):
KACHO_MONOREPO=/path/to/kacho ./scripts/vault-gate/run-all.sh

# Доказательства работоспособности гейтов:
KACHO_MONOREPO=/path/to/kacho ./scripts/vault-gate/inject.sh   # единый вход: check-01 + все inject-<N>
./scripts/vault-gate/inject-02.sh                              # висячие ссылки
./scripts/vault-gate/inject-03.sh                              # оболочка записки
./scripts/vault-gate/inject-04.sh                              # свежесть указателя
```

## Три исхода, а не два

`project/` под gitignore, и в свежем клоне или worktree монорепо рядом нет
вовсе. Поэтому его отсутствие даёт **VOID (код 2)**, а не PASS: «проверить не
удалось» и «проверено, чисто» — разные вещи, и первое обязано быть видно.
`run-all.sh` не засчитывает VOID за успех и отказывается выносить вердикт, когда
проверок рассмотрено ноль.

## check-01 — записка-ребро не выдаёт снятый механизм за текущий

**Находка:** заголовок записки в `edges/` называет механизм, который дерево
**запретило потребителю**, а объявленное состояние записки не признаёт прошлое.

Запрещённые имена **выводятся из дерева** — из анализаторов сужения списков
каждого сервиса, — а не выписаны в этом скрипте. Рукописный список расходится с
деревом молча и ровно в ту сторону, где гейт перестаёт ловить.

Три вещи, которые находкой **не** являются, и это существенно:

- **записка в `rpc/`**, описывающая одноимённый RPC у владельца прав: запрет
  адресован потребителю, а сам RPC жив и обслуживается. Краснеть тут значит
  краснеть на правде;
- **механизм, названный в ТЕЛЕ** записки — объяснение «почему это снято» обязано
  существовать, иначе следующий вернёт снятое;
- **записка, объявившая состояние `removed`/`deprecated`/`superseded`** — она уже
  говорит, что описывает прошлое.

Все три проверены `inject.sh` как законные близнецы: гейт о них молчит.

## Что доказывает inject.sh

| Контроль | Ожидание |
|---|---|
| внесённый дефект (заголовок называет снятое, состояние текущее) | код 1 **и названа координата** |
| законный близнец A: то же, но состояние признаёт прошлое | молчание про этот файл |
| законный близнец B: механизм только в теле | молчание про этот файл |
| монорепо недостижимо | код 2 (VOID), не 0 |
| запрет в дереве монорепо исчез | код 2 (VOID), не 0 |

Контроли близнецов спрашивают **про свой файл**, а не про чистоту всего дерева:
иначе любая посторонняя находка красит контроль и о близнеце не говорит ничего.

## check-02 — ссылка между записками ведёт в существующий файл

**Находка:** wikilink, который не резолвится ни одним из трёх правил Obsidian
(путь от файла-источника → путь от корня хранилища → базовое имя где угодно).
Проверка, знающая одно правило вместо трёх, объявляет висячими полторы тысячи
живых ссылок — это проверялось и наблюдалось.

**Храповик двусторонний и по перечню, а не по числу.** Основание —
`dangling-baseline.txt`: цель и число ссылок на неё. Новая цель роняет гейт;
исчезнувшая — тоже, с требованием переписать основание тем же коммитом
(`--write-baseline`). Одно суммарное число сходилось бы случайно: одну ссылку
завели, другую починили — итог тот же.

**Что в основании лежит на самом деле.** Не поломка навигации, а **перечень
ненаписанного**: записки категорий, которых никто не написал (163 ссылки), уроки,
на которые ссылаются по имени (101), и номера KAC без trail (77). Опускать число,
переписывая ссылки в простой текст, запрещено: так исчезает единственный след
того, что предмет кто-то считал описанным.

Режим `--list` печатает цели с видом и примером источника — им пользуются
указатели категорий, чтобы не переписывать перечень руками.

## check-03 — у записки есть оболочка

**Находка:** записка фактической категории (`resources`/`rpc`/`packages`/`edges`)
без `title`, без `category`, с категорией, не совпадающей с каталогом, без
`status` или со `status` вне словаря.

**Словарь состояний выводится из контракта хранилища** —
`obsidian/kacho/CLAUDE.md`, таблица трёх вёдер. Рукописный список внутри скрипта
разошёлся бы с контрактом молча. Нет таблицы — VOID, а не PASS.

Гейт **не судит правдивость** состояния: «живо» вместо «истории» он не отличит.
Это предмет сверки с деревом (check-01 и волны сверки), а не оболочки.

## check-04 — перечень записок собран из дерева и не отстал

**Находка:** `obsidian/kacho/INDEX-notes.md` не совпадает с тем, что собрал бы
`scripts/vault-index/generate.py`. Прозаическую половину указателя (`INDEX.md`)
гейт не судит вовсе — краснеть на вводном тексте значило бы запрещать его писать.

Замер до введения генератора: 112 записок из 295 (38 %) в указателе не
упоминались, при том что все ссылки самого указателя резолвились — проверка одной
стороны показывала порядок.

Три исхода различаются: перечень отстал ИЛИ его нет вовсе — код 1 (записки
прочитаны, значит отсутствие перечня — расхождение); записок не прочитано ни
одной — код 2 (пустая перепись сходится тривиально); совпадает — код 0 с числом
рассмотренных.

## check-05 — указатель разделён, и машинная половина несёт посадку слияния

**Находка:** снята посадка слияния у `INDEX-notes.md`; посадка объявлена
**именованным** драйвером (такой держится `git config` в каждом клоне, а в клоне
без установки git молча вернётся к обычному слиянию); проза перестала ссылаться
на машинную половину; маркер генератора вернулся в прозу.

**Зачем отдельно от check-04.** Свежесть судит содержимое, эта — механизм,
которым содержимое доживает до слияния. Механизм отказывает молча: снимут
`.gitattributes` — перечень снова начнёт спрашивать человека, а гейт свежести
останется зелёным, потому что содержимое-то верное.

Замер до разделения (2026-08-18, синтетика на настоящем генераторе): две ветки от
одной базы, по записке в каждой — слияние падало конфликтом; в форме, где
конфликта не возникало (записки в разных разделах), перечень молча оставался
неверным. Пять слияний ствола в ветку: падений гейта свежести было 5 из 5, после
разделения и снятия сводных счётчиков — 0 из 5.

## Что доказывают inject-02 … inject-05

| Проверка | Дефект | Законный близнец | Предпосылка |
|---|---|---|---|
| `check-02` | ссылка в никуда → код 1 + названа цель | три живые формы ссылки (от корня, короткая, `../`) → молчание | пустое хранилище → VOID; устаревшее основание → код 1 |
| `check-03` | нет `status`; `status` вне словаря → код 1 + координата | полная оболочка и витрина категории → молчание | нет таблицы словаря → VOID |
| `check-04` | записка заведена, перечень не пересобран; перечень удалён целиком → код 1 + координата | пересобранный перечень и правка ПРОЗЫ → код 0 | ни одной записки не прочитано → VOID |
| `check-05` | посадка снята; посадка именованным драйвером → код 1 + координата | целое дерево → молчание | не git-дерево; хранилища нет → VOID |
| механизм | БЕЗ посадки две параллельные записки конфликтуют | С посадкой сливаются без вопроса; расхождение в ПРОЗЕ по-прежнему спрашивает автора | — |

Контроли близнецов спрашивают **про свой файл**, а не про чистоту всего дерева.

## Границы

`check-01` судит **заголовок и объявленное состояние**, а не содержание прозы. Записка,
чей заголовок честен, а тело описывает несуществующий поток, им не ловится — это
осознанный предел, а не недосмотр: предикат по прозе не имеет контроля в обе
стороны и краснел бы на правде. Прозу сверяет человек или следующая проверка с
собственным предметом.

Набор в целом судит **оболочку и связность**, а не содержание. Ни одна проверка
не отвечает на вопрос «правда ли то, что записка утверждает о дереве»: это
предмет волн сверки, у которых своя единица счёта и своя ревизия. Смешивать их
нельзя — гейт, притворяющийся сверкой, зеленел бы на верной форме при неверном
содержании.
