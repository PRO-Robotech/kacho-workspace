# Манифест домена: схема, генераторы, доказательства

Рабочие артефакты проработки к задаче
[PRO-Robotech/kacho#1087](https://github.com/PRO-Robotech/kacho/issues/1087) —
«домен описывается манифестом: права, роли и модель из одного YAML».

Это **не поставка и не приёмка**, а доказательная база решения: из чего оно
выведено, чем проверено и что именно опровергнуто по дороге. Перенос в дерево
продукта — предмет [#1088](https://github.com/PRO-Robotech/kacho/issues/1088).

> [!important] Числа этой проработки относятся к РЕВИЗИИ, а не к сегодняшнему дереву
> Снимки `tools/live-model.fga` и `tools/kacho-catalog.json` — копии
> отслеживаемых файлов продукта, снятые на `kacho@8fab73ab` (2026-08-23).
> Копия стареет молча, и здесь это уже случилось: за девять дней после снятия
> обе разошлись со стволом, а проверки, которые их читают, продолжали печатать
> «✓ идентично».
>
> Расхождение больше не молчаливо — его называет `tools/drift.py`. Прогоняй
> его ПЕРВЫМ, до всякого числа отсюда.

## Что здесь лежит

| файл | что это |
|---|---|
| `vpc.manifest.yaml` | манифест домена vpc целиком — 10 ресурсов, 6 ролей, раздел `seed` |
| `seed.schema.yaml` | JSON Schema раздела `seed` (draft 2020-12) |
| `tools/` | генераторы, сверки, валидаторы, наборы инъекций |
| `tools/live-*` | снимки живого состояния на `8fab73ab`, чтобы всё воспроизводилось без стенда |
| `generated/kacho` | манифесты, выведенные из каталога прав Kachō |

## Первое действие: насколько снимки отстали

```
$ python3 tools/drift.py
снимки сняты на ревизии 8fab73ab
осмотрено: типов vpc_* 9 · записей каталога 339
расхождений: модель 2 · каталог 7
```

Исходов три, и читать надо **код возврата**, а не вид вывода: `0` — вровень со
стволом · `1` — расхождение, перечислено поимённо · `2` — **без предмета**,
дерева продукта не видно и сверять не с чем. Третий в успех не засчитывается.

Дерево берётся из `KACHO_MONOREPO` либо из `project/kacho` рядом с корнем
воркспейса.

## Главное доказательство — и его сегодняшняя граница

```
$ cd tools && bash bytecmp.sh ../vpc.manifest.yaml
✓ идентично: 5932 байт, md5 17409a0052ae00fd5c0fc6812e0bc751
```

Порождённые из манифеста блоки типов `vpc_*` **побайтово** равны блокам модели
**на ревизии `8fab73ab`**. Не «совпадают по смыслу» — совпадают как файл:
модель есть контракт, и лишняя строка в ней это лишнее право.

**На сегодняшнем стволе побайтового равенства больше нет, и достичь его
нельзя.** Отношение `use` снято из модели задачей
[#1115](https://github.com/PRO-Robotech/kacho/issues/1115) вместе со всем
семейством; манифест держит его у `subnet` и `address`, потому что описывает
домен таким, каким тот был на ревизии снимка. Замер расхождения, если снять
`use` из манифеста и сверить с сегодняшними блоками:

| ось | значение |
|---|---|
| строк `define` расходится | **0** |
| строк расходится всего | **7** — шесть строк прозы о снятии плюс хвостовой перевод строки |

То есть равенство держится там, где оно про контракт, и не держится там, где
модель несёт **объяснение человека**. Генератор прозы о снятии не производит и
производить не должен. Ось доказательства ровно эта: `define`-строки, а не
байты файла; байтовое равенство было верно на своей ревизии и названо здесь
вместе с ней.

## Как перепроверить

Всё воспроизводится **без стенда**: снимки лежат рядом.

```sh
python3 tools/drift.py                      # ПЕРВЫМ: отстали ли снимки
cd tools
python3 gen.py                              # каталог Kachō → манифесты
python3 verify.py                           # 340 RPC каталога
bash    bytecmp.sh                          # модель — побайтово к 8fab73ab
python3 cmp.py                              # …и построчно по `define`
python3 roles.py                            # целостность манифеста
python3 live-verify.py ../vpc.manifest.yaml live-roles.txt vpc
```

Умолчание аргумента у четырёх инструментов указывало на `../vpc.yaml` — файла с
таким именем в каталоге нет, он называется `vpc.manifest.yaml`. Умолчание
приведено к факту; до этого `roles-inject.sh` без аргумента давал **0 из 38**
утверждений с текстом «правка не применилась», а `bytecmp.sh` — «генерация
упала». Это не ослабление проверок: с явным аргументом обе давали свои числа и
дают их сейчас.

## Чем доказано, что проверки способны падать

Инъекции в обе стороны — дефект обязан краснеть с координатой, законный
близнец обязан молчать:

| набор | утверждений | предмет |
|---|---:|---|
| `tools/roles-inject.sh` | **38** | валидатор целостности манифеста |
| `tools/schema-inject.py` | **31** | JSON Schema раздела `seed` |
| `tools/inject.sh` | **9** | эмулятор «каталог → манифест → каталог» |
| `tools/drift.py` (контроли ниже) | **4** | замер отставания снимков |

Замер отставания доказан четырьмя прогонами: сегодняшний ствол — красное с
координатами (2 + 7); дерево на ревизии снимка — **молчит**, код 0; дерева нет
— код 2; дерево есть, а нужных файлов в нём нет — тоже код 2, и «без предмета»
названо словом, а не выдано за «расхождений ноль».

## Границы — названы, а не умолчаны

- **`subjects` воспроизводит текст, но не поведение.** Резолвер прямой список
  игнорирует: `[user]` и `[user, service_account, group#member]` дают побайтово
  один план. Писать надо — модель есть контракт, — считать сужением нельзя.
- **JSON Schema судит форму.** Четыре свойства ей недоступны by construction
  (их держит `roles.py`): субъект заведён этим же посевом · роль существует ·
  группа кому-то выдана · **ключ остался строкой после разбора YAML**
  (`on`/`off`/`yes`/`no` — булевы литералы; поймано вживую).
- **Преднастроенной выдачи ролью в продукте нет ни одной из 5469.** Все 3335
  системных выданы отношением, все 2134 обычных ролью, без исключений в обе
  стороны. `seed.accessBindings[].roleId` описывает сочетание, которого пока
  не существует.
- **Ресурс называет свои действия ДВУМЯ словами, и это не решено.** Рукописный
  `vpc.manifest.yaml` пишет `verbs` — его читают `roles.py`, `live-verify.py`,
  `yaml2fga.py`, то есть все три инструмента, на которых стоят доказательства.
  Порождённые манифесты пишут `actions` — его читает только `dcl.py`. Предикат:
  `grep -l "'verbs'" tools/*.py` даёт 3, `grep -l "'actions'" tools/*.py` даёт
  1. Следствие наблюдаемое: `dcl.py ../vpc.manifest.yaml` отказывает
  `KeyError: 'actions'`. Сведение к одному слову — своя работа со своим
  предикатом, здесь оно не делается, чтобы не менять числа сходимости заодно.
- **Второй корпус — не в дереве.** Выразительность схемы проверялась ещё и на
  каталоге стороннего публичного API: 168 операций, сходимость 100 %, склеек 0.
  Сам корпус и работавшие с ним инструменты сюда **не сданы**: они называют
  чужого облачного провайдера, а это запрещено вторым непереговорным. Значит
  число 168 остаётся **записью о проработке**, а не воспроизводимым предикатом,
  и подавать его как проверку нельзя.

## Что НЕ сдано и почему

| что | почему |
|---|---|
| `tools/__pycache__/` (2 файла, 25 066 Б) | мусор прогона интерпретатора |
| корпус стороннего API и его инструменты (7 файлов, 78 832 Б) | ban #2 — чужое облако не называется ни в коде, ни в документации, ни в именах файлов |
| `vpc.generated.fga` (5932 Б) | побайтово равен `tools/live-vpc-blocks.fga`, один md5 `17409a0052ae…`; порождается на месте |

## Семь полей, снятых из схемы по дороге

Каждое было заведено и снято, потому что у него не нашлось читателя:

| поле | почему снято |
|---|---|
| `at`, `in` | описывали выдачи на аккаунт и проект, которых посев не делает |
| `openTo` | вступление гейтится правом `v_update` на группе |
| `declaredBy` | второй ключ к тому же адресу; порядок выводится из `joins` |
| `assignableAt` | «a SYSTEM role is assignable anywhere» — запрета нет |
| `clusterOnly` | все 22 вхождения дословно повторяли `parent: cluster` |
| `catalog` | равнялся `parent: cluster`, давал 26 «справочников» вместо 9 |

**Норма, из этого выведенная: поле заводится, только когда назван его
читатель** — код, который смотрит, или проверка, которая падает. Комментарий
читателем не является.

## Об идентификаторах

Снимки живого состояния очищены от идентификаторов стенда: в
`tools/live-bindings.txt` они заменены метками вида `<rol>` — числа замера от
них не зависят. Прочие снимки идентификаторов не несли (имена ролей и типов
объектов и так объявлены в публичных миграциях и в модели).
