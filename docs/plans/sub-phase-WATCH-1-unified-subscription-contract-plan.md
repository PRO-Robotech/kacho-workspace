# WATCH-1 — единая форма подписки: план реализации (фаза Ф1)

> **Для исполнителя-агента:** обязательный суб-скил — `superpowers:subagent-driven-development`
> либо `superpowers:executing-plans`. Шаги размечены чекбоксами (`- [ ]`).
> Перед первой строкой кода — `class-exposure-analyst` (см. §0).

**Цель.** Объявить **одну** форму подписки на изменения ресурсов, переиспользуемую всеми
модулями, и поставить гейты, которые не дадут завести вторую. **Поведения не меняется нигде:**
Ф1 не производит ни сервера, ни перевода доменов, ни снятия прежней формы.

**Приёмка — единственный нормативный вход:**
`docs/specs/sub-phase-WATCH-1-unified-subscription-contract-acceptance.md` (APPROVED,
30 сценариев, 8 расхождений с постановкой). **План не заменяет приёмку и не переопределяет
её. Расхождение плана с приёмкой — дефект плана.**

**Стек.** Go 1.2x, монорепо `project/kacho` (`github.com/PRO-Robotech/kacho`);
`proto/kacho/cloud/subscription/` (новый пакет контракта) · `internal/repohygiene`
(репо-широкие гейты, разбор AST и дескрипторов, обычный `go test`) · `buf` (lint/breaking) ·
плюс **отдельный коммит в другом репозитории** — `kacho-workspace`.

**Эпик/задача:** продукт [#1016](https://github.com/PRO-Robotech/kacho/issues/1016) (Ф1) /
[#1017](https://github.com/PRO-Robotech/kacho/issues/1017). Смежные предметы, заведённые
приёмкой: [#1043](https://github.com/PRO-Robotech/kacho/issues/1043),
[#1046](https://github.com/PRO-Robotech/kacho/issues/1046).

## §2 Как читать дерево на каждом шаге — перемер, а не перенос числа

Приёмка сверена с `origin/main` = `958e8fe0d`. **К моменту исполнения это число устареет** —
за время её написания общая копия продукта ушла на 99 коммитов. Поэтому первым делом каждого
шага:

```sh
git fetch origin main -q && git rev-parse --short origin/main    # база ЭТОГО шага
```

и все предикаты гоняются с явной ревизией (`git grep … origin/main -- …`), **не** по рабочей
копии. Числа приёмки — ориентир; расхождение перемера с ней — находка, которую надо назвать,
а не подогнать.

**Предикаты, которые понадобятся (все с областью — без неё они мерят другое):**

```sh
# форм потоковой подписки в контрактах
git grep -h 'returns (stream' origin/main -- proto | wc -l

# объявлений запроса подписки (несущий предикат Ф1)
git grep -c 'message WatchRequest\|message SubscribeRequest\|message .*SubscriptionRequest' \
  origin/main -- proto

# кто ИСПОЛНЯЕТ LISTEN (а не упоминает его)
git grep -lE '\.Exec\([^)]*"(UN)?LISTEN' origin/main \
  -- 'services/*/**/*.go' ':!*_test.go' | wc -l

# импортёры общего пакета — образец, по которому меряется «взяли ли форму»
git grep -l 'kacho/cloud/reference/reference.proto' origin/main -- proto | wc -l
```

## §3 Раскладка шагов — и почему порядок именно такой

```
Ш1  надгробие ─────────────┐  независим от контракта, закрывает ЖИВУЮ дыру → первым
Ш2  инъекционный стенд ────┤
Ш3  G1 единственность ─────┤  гейт ставится РАНЬШЕ того, что он сторожит
Ш4  контракт (сообщения) ──┤
Ш5  G2 форма контракта ────┤
Ш6  G3 не мёртвая + G4 окно┤
Ш7  конвенция (др. репо) ──┤
Ш8  постановка + trail ────┘
```

**Почему надгробие первым, а не последним.** Р4 — не подготовка к работе, а **действующая
дыра**: имя снятой формы не зарезервировано, и вернуть его может любой коммит между сегодня и
Ф3. Оно не зависит ни от контракта, ни от гейтов, поэтому платить за него задержкой нечем.

**Почему гейт раньше контракта.** Ban #12 и работающий образец оси типов: гейт, поставленный
после, проверяет то, что уже написано, и потому зелен по построению. Поставленный до — он
**красный на сегодняшнем дереве** (у compute свой запрос подписки), и зелёным его делает
запись послабления, у которой есть причина и предикат истечения. Это и есть RED → GREEN.

**Почему конвенция предпоследней.** Она в **другом репозитории**, и её коммит не должен
уехать раньше, чем контракт, который она описывает, окажется в стволе продукта, — иначе
правило будет утверждать о дереве то, чего в нём ещё нет.

### Задача 4.2: что объявляется — и что каждое поле обязано нести в комментарии

| элемент | требование приёмки |
|---|---|
| три оси фильтра — виды · проект · идентификаторы | все **необязательны**, конъюнкция; незаданная не сужает (WATCH-1-01/02) |

| словарь видов | принадлежит **владельцу**, не заперт на «ресурсы домена» (WATCH-1-22) |

# Ш5 — G2: форма контракта

> Один анализатор, несколько утверждений. Дробить его на семь гейтов не нужно: предмет один —
> **форма общей подписки**, и читается она одним разбором дескрипторов.

### Задача 5.1: закрытый перечень осей и их семантика

- [ ] Перечень имён осей — рядом с гейтом, с пометкой семантики (иммутабельная / мутабельная).
- [ ] Поле с мутабельной семантикой в общей форме → красное с именем поля (WATCH-1-07).
- [ ] Иммутабельная ось того же вида → молчание. **Без этой половины гейт ловит форму, а не
      существо, и первый же законный ввод его отключит.**

### Задача 5.2: структурные утверждения

- [ ] Все три оси **необязательны** — это несущее: на нём держится вывод §6.1 приёмки о том,
      что неотбираемая ось остаётся незаданной и ломающего изменения не возникает.
- [ ] Позиция различает **три** состояния.
- [ ] Исход «позиция утрачена» присутствует.
- [ ] Обязательного поля причины остановки в событии **нет**.
- [ ] Обязательного идентификатора ресурса нет — иначе предмет «отзыв доступа субъекта» в
      форму не помещается (WATCH-1-22).
- [ ] Перепись: полей прочитано, осей распознано, утверждений проверено.

**Выход Ш5:** форма проверяется разбором, а не вниманием ревьюера.

# Ш7 — конвенция: ДРУГОЙ репозиторий, отдельный коммит

> **Предикат, объясняющий шаг:** `git ls-tree -r origin/main --name-only | grep -c
> api-conventions.md` в монорепо → **0**. Файл живёт только в `kacho-workspace`.

- [ ] В `kacho-workspace`: `.claude/rules/api-conventions.md`, §«Форма ресурса» — утверждение
      «**Watch RPC не существует**» привести к дереву.
- [ ] Правка идёт **вместе** с оговоркой (WATCH-1-26), иначе она читается как разрешение
      «подписывайся вместо поллинга везде»:
      - мутация по-прежнему возвращает `Operation`, исход узнаётся поллом;
      - подписки на операции не заводится;
      - **одного потока ресурсов недостаточно**: событие пишется в той же транзакции, что и
        ресурсная строка, поэтому при отказе операции события нет вовсе — наблюдатель не
        отличит «ещё делается» от «упало».
- [ ] Отдельный коммит в отдельном репозитории (`polyrepo.md` §порядок работ). Без этой строки
      шаг тихо не делается — он единственный вне монорепо.

**Держится вниманием, и это сказано в приёмке §5:** проверка свежести документации сверяет
координаты, а это утверждение — проза без координаты. Хук на нём молчит при любом состоянии
дерева.
