# 09. Модель безопасности

Границы доверия, модель угроз и контроли. Главное отличие этого продукта от обычного
сервиса: **мы выполняем произвольный код клиента дважды** — при сборке и в рантайме. Всё
остальное следует из этого.

---

## 1. Границы доверия

| Зона | Доверие | Что в ней выполняется |
|---|---|---|
| Публичный вход | Нулевое | Запросы клиентов |
| Control plane | Полное внутри, но проверяет всех | Доменная логика, права |
| Пул сборки | **Отрицательное** | Произвольный код клиента с сетевым доступом |
| Тенантский рантайм | **Отрицательное** | Произвольный код клиента с сетевым доступом |
| Платформенный пул | Полное | Наши контроллеры |
| Хранилища | Полное, доступ по области | Секреты, образы, наблюдаемость |

Внутренний периметр **не** считается доверенным: каждое внутреннее соединение проходит
взаимную аутентификацию, каждый запрос — проверку прав. «Внутри — значит можно» — запрещённое
допущение: оно превращает одну скомпрометированную часть в компрометацию всего.

## 2. Модель угроз

| # | Угроза | Кто | Чем закрываем |
|---|---|---|---|
| 1 | Побег из контейнера рантайма | Арендатор | Пространства имён пользователей, сброс возможностей, профиль системных вызовов, отдельный пул. **Остаточный риск принят**, §4 |
| 2 | Побег из контейнера сборки | Арендатор | То же плюс отдельный пул и отсутствие учётных данных во время выполнения его кода |
| 3 | Выход во внутреннюю сеть из сборки по адресу, который называет арендатор | Арендатор | §5 — самая проработанная группа контролей |
| 4 | Кража чужого секрета | Арендатор | Область пути хранилища включает окружение; доставка только в своё пространство имён; значение недоступно на чтение |
| 5 | Кража чужого образа | Арендатор | Учётные данные на один репозиторий, короткий срок, отсутствие долгоживущих в пространстве имён |
| 6 | Отравление кэша сборки | Арендатор | Кэш на пару (арендатор, репозиторий), **никогда общий** |
| 7 | Чтение чужих метрик и журналов | Арендатор | Структурное разделение арендаторов плюс проверка перед хранилищем, §7 |
| 8 | Перехват соседского адреса через cookie родительского домена | Арендатор | Отдельная зона второго уровня, заявка в список публичных суффиксов, карантин освобождённых имён |
| 9 | Злоупотребление исходящим трафиком | Арендатор | §6 |
| 10 | Компрометация оператора кластера | Внешний | Оператор только тянет и отчитывается; из кластера нельзя изменить чужое намерение |
| 11 | Компрометация учётной записи клиента | Внешний | Область токена, журнал действий, отзыв |
| 12 | Внутренний доступ поддержки | Свои | Ограничение по сроку, запись в журнал, видимость владельцу, недоступность секретов |

## 3. Слои изоляции арендатора

1. **Пространство имён** на пару (приложение, окружение).
2. **Квоты и лимиты** — от шумного соседа внутри одного арендатора.
3. **Сеть** — запрет по умолчанию, шлюз исходящего трафика, закрытые метаданные и приватные
   диапазоны, точечные правила привязок.
4. **Сетка** — строгая взаимная аутентификация, запрет между пространствами имён.
5. **Узлы** — отдельный однородный пул с меткой недопуска.
6. **Сборка** — отдельный периметр, §5.

Каждый слой закрывает то, что не закрывает предыдущий. Пространство имён само по себе
границей безопасности не является — это область группировки и квотирования.

---

## 4. Принятый остаточный риск: общее ядро

Пространства имён пользователей убирают эскалацию до привилегий узла, но **не сокращают
поверхность системных вызовов**. Побег через уязвимость ядра остаётся межарендной
компрометацией, а не единичным инцидентом.

Аппаратная или синтезированная песочница — другой продукт и другие недели. Решение принято
сознательно и записано, чтобы никто не считал текущий набор эквивалентом песочницы.

**Следующий шаг** — песочница на пуле **сборки**, где недоверие максимально, а бюджет
времени в десятки секунд терпит замедление. Рантайм — после.

Отдельно: **политика сетки не является границей против самого арендатора** — перехват
трафика исключает служебный идентификатор процесса, а процесс арендатора может им стать.
Границей остаётся сетевая политика уровня сети. Обязателен негативный тест: процесс,
запущенный под служебным идентификатором, не выходит за пределы разрешённого.

---

## 5. Периметр сборки

Самый опасный узел продукта: инструкции сборки выполняют произвольный код на нашем железе,
а адрес источника называет арендатор.

### 5.1 Разведение фаз

| Фаза | Что доступно |
|---|---|
| Получение исходников | Ключ доступа к источнику. Кода клиента **не выполняется** |
| Сборка | **Ни ключа источника, ни учётных данных публикации.** Только рабочая копия и кэш |
| Публикация и подпись | Учётные данные публикации на один репозиторий. Кода клиента не выполняется |

Разведение фаз — главный контроль этой группы: без него инструкция сборки читает наши
учётные данные из собственного пода.

### 5.2 Адрес источника

| Контроль | Правило |
|---|---|
| Кто резолвит | Платформа, не сборщик |
| Когда отбраковываем | **После** резолва, по фактическому адресу |
| Что отбраковываем | Приватные, loopback, link-local (включая адрес метаданных), CGNAT, мультикаст, все не-глобальные |
| Как соединяемся | По **закреплённому** адресу; повторный резолв в процессе запрещён — это закрывает повторное связывание DNS |
| Переадресация | Не более трёх переходов, каждый проходит проверки заново |
| Порты | Только 22, 80, 443 |
| Подмодули | По умолчанию выключены; при включении каждый проходит все проверки адреса |

### 5.3 Прочее

Эфемерная служебная учётная запись на сборку · отсутствие сетевого доступа к control plane
и к хранилищам наблюдаемости · предельный срок, квоты процессора, памяти и диска · потолки
объёма исходников и числа файлов · безопасная распаковка архива (`04` §4.3) · **кэш на пару
(арендатор, репозиторий)**.

## 6. Исходящий трафик рантайма

Приложение клиента — произвольный сетевой клиент в интернете, работающий с наших адресов.

| Контроль | Правило |
|---|---|
| Почтовые порты | 25, 465, 587 закрыты по умолчанию, открываются заявкой |
| Потолки | Объём трафика и пакетов в секунду на окружение |
| Пул адресов | **Отдельный пул трансляции под платформу**, не пересекающийся с адресами почты и классического хостинга |
| Внутренние адреса | Закрыты, кроме точечных правил привязок |
| Реакция | Приостановка с актором, сигналом, видимым клиенту текстом и процедурой оспаривания |

Пункт про отдельный пул адресов — не перестраховка. У хостера в той же автономной системе
живёт почта: попадание диапазонов в списки блокировок бьёт по услугам, у которых с
платформой нет ничего общего. Это длинный организационный срок, и решать его надо в начале,
а не после первого инцидента.

## 7. Секреты

| Аспект | Правило |
|---|---|
| Хранение | Внешнее хранилище секретов. В базе — только метаданные и ссылка |
| Путь | Проект → приложение → **окружение** → компонент. Сегмент окружения обязателен |
| Область прав | Шаблонизируется по идентификатору окружения из привязки пространства имён |
| Чтение значения | **Не существует ни в одном методе**, включая пути поддержки |
| Доставка | Оператор внешних секретов в своё пространство имён, по событию от control plane |
| Перекат | Через хеш конфигурации в шаблоне пода |
| Запрет попадания | Не в журнал сборки, не в журнал приложения, не в события, не в метки, не в сообщения об ошибках |

**Почему сегмент окружения обязателен:** без него на компонент существует ровно один набор
секретов на все окружения, и непрод читает боевой ключ **успешно, без отказа**. Заявленная
защита «секреты не наследуются в непрод» в этом случае не просто плохо энфорсится — она
нереализуема.

## 8. Цепочка поставки артефакта

| Шаг | Правило |
|---|---|
| Подпись | Платформа подписывает каждый собранный образ |
| Состав | Прикладывается к образу как связанный артефакт |
| **Проверка при материализации** | Оператор проверяет подпись **и личность подписанта** перед развёртыванием; отказ — терминальный код |
| Режим подписи | Публичная общедоступная инфраструктура в горячем пути сборки **не закладывается**: её инцидент останавливает сборки у всех наших клиентов |
| Сканирование уязвимостей | Вне первой поставки |

Проверка при материализации обязательна: без неё подпись — файл, который никто не читает, и
называть её свойством продукта нельзя.

## 9. Модель доступа

| Субъект | Как получает доступ |
|---|---|
| Человек | Существующая авторизация Beget, права проекта |
| **Машина (CI)** | Токен **с областью**: приложение и окружение, набор действий, срок, отзыв, список выданных, отметка последнего использования |
| Оператор кластера | Собственная удостоверенная личность, только свои задания |
| Контроллер сборки | Собственная личность, только свои задания |
| Поддержка | Ограниченный по сроку доступ, запись в журнал, видимость владельцу |

Токен с областью — **требование к платформенному IAM Beget**, а не наша подсистема. Пока
его нет, единственный механизм для CI — токен всего аккаунта, который открывает домены,
DNS, хостинг и биллинг. Замораживать это требование надо вместе с моделью окружений: позже
оно превращается в ломающее изменение модели доступа.

**Авторизация выражается моделью прав, а не условиями в коде.** Хардкод-проверка, дублирующая
решение о доступе, не выдаётся, не ограничивается областью, не отзывается, не видна в аудите
и не понимает машинных субъектов.

**Асинхронное продолжение несёт личность инициатора**, захваченную в момент запроса: человек
нажал «выкатить», исполнитель доделывает под его личностью. Это передача контекста, а не
олицетворение. Машина, держащая токен человека, — запрещено: такой токен действует везде.

---

## 10. Приватность и журнал действий

**Журнал действий только на добавление:** кто выкатил релиз, кто читал журналы и переменные,
кто менял привязки и домены, кто из поддержки и когда получал доступ, чем закончилось.

**Персональные данные не логируются платформой.** Содержимое журналов приложения —
ответственность клиента; платформа не разбирает их содержимое и не индексирует по нему.

**Ответ на недоступный ресурс неотличим от ответа на несуществующий.** Различимый ответ
позволяет перечислить чужие ресурсы.

## 11. Что обязано быть проверено

| Контроль | Проверка |
|---|---|
| Периметр сборки | Тесты-ловушки: приватный адрес, имя, резолвящееся в приватный адрес, переадресация на такой адрес, подмодуль на внутренний адрес — **каждый** отвергается |
| Разведение фаз сборки | Инструкция сборки, пытающаяся прочитать учётные данные из окружения, ничего не находит |
| Распаковка | Архив с выходом за каталог, с символической ссылкой наружу, с высоким коэффициентом сжатия |
| Секреты | Значение не возвращается ни одним методом; отсутствует в журнале сборки, журнале приложения, событиях, метках, сообщениях об ошибках |
| Область окружения | Секрет production недоступен из пространства имён непрода — проверяется из пода |
| Сетка против арендатора | Процесс под служебным идентификатором не выходит за разрешённое |
| Изоляция наблюдаемости | Запрос с подставленным заголовком чужого арендатора отвергается перед хранилищем |
| Подпись | Образ с испорченной подписью не разворачивается |
| Скрытие существования | Ответы на чужой и на несуществующий ресурс совпадают побайтово |

**Каждый контроль проверяется на воспроизведённом дефекте:** сначала красный тест на
включённой уязвимости, потом зелёный после исправления. Проверка, которая никогда не была
красной, проверкой не является — у нас уже был случай, когда гейт рапортовал успех, потому
что читал конфигурацию вместо живого процесса.
