# Платформа приложений Beget — комплект документов для разработки

**Дата:** 2026-07-28
**Статус:** передаётся архитектору бэкенда
**Назначение:** описать услугу и то, как её разработать, в объёме, достаточном для
проектирования и декомпозиции работ без обращения к авторам.

Кода в комплекте нет сознательно. Есть: доменная модель, структуры методов, реестр
валидаций, контракты между компонентами, схема данных, юзер-флоу со сценариями отклонений
и план разработки с критериями готовности.

## Что уже решено и не пересматривается

| № | Решение | Где подробно |
|---|---|---|
| 1 | `Environment` — первоклассная область внутри приложения; по умолчанию ровно одно `production`, невидимое в интерфейсе | `02` §2 |
| 2 | Конфигурация: автоопределение → `beget.yaml` (форма кода) → API (правда окружения), владение непересекающееся | `02` §8, `04` §6 |
| 3 | Доставка в кластер: оператор **тянет** задание, пишет якорный CR, разворачивает через Server-Side Apply | `06` §3 |
| 4 | Маршрутизация — Gateway API `HTTPRoute`, Istio как реализация | `08` §4 |
| 5 | Изоляция подов — PSS `baseline` + жёсткий набор по умолчанию + пространства имён пользователей | `08` §6, `09` §4 |
| 6 | Сборка — отдельный периметр безопасности | `09` §5 |
| 7 | Подпись образа и SBOM входят в POC | `09` §8 |
| 8 | Арендатор наблюдаемости — аккаунт, а не метка | `10` §2 |
| 9 | Мутации асинхронны и возвращают `Operation`; `Operation` не источник истины ресурса | `03` §2 |
| 10 | Публичные идентификаторы — UUID v4; внутренние типизированные наружу не выходят | `02` §1 |

## Соглашения комплекта

- **«Обязательно»** означает, что без этого не принимается работа, а не пожелание.
- Формулировки ошибок, которые видит клиент, — **часть контракта**. Менять их можно
  только осознанно, вместе с обновлением `04` и тестов.
- Всё, что помечено «вне POC», описано, чтобы контракт был спроектирован с учётом этого,
  но в первую поставку не входит.
- Числовые лимиты, помеченные `подбирается`, определяются замером на этапе, указанном в `11`.
