# 06. Внутренние контракты

Как разговаривают части платформы между собой. Внутренний контракт **не является** частью
публичного API Beget и меняется без объявления ломающих изменений наружу — но внутри он
такой же строгий.

---

## 1. Части и их роли

| Часть | Отвечает за | Не отвечает за |
|---|---|---|
| Фасад Beget | Публичный контракт, токен, отображение внутренних состояний во внешние, отображение идентификаторов | Доменную логику |
| Control plane | Доменное состояние, операции, права, задания, размещение, машины состояний | Выполнение работы в кластере |
| Контроллер сборки | Получение исходников, определение, сборка, публикация, подпись, состав | Знание об окружениях и релизах |
| Оператор кластера | Материализация намерения, наблюдаемое состояние, откат чужих правок | Решение, что и когда выкатывать |
| Менеджер кластеров | Реестр кластеров, ёмкость, профиль возможностей, размещение | Прикладную логику |

**Ни одна часть не вызывает control plane синхронно на пути запроса клиента.** Исполнители
сами приходят за работой. Отсюда: нет рантайм-цикла, не нужен брокер, и компрометация
исполнителя не даёт доступа внутрь.

---

## 2. Принципы

1. **Тянущая модель.** Соединение всегда исходящее из исполнителя. Control plane не хранит
   учётных данных ни к одному кластеру.
2. **Взаимная аутентификация** на каждом внутреннем соединении. Внутренний периметр не
   считается доверенным.
3. **Аренда с сигналом жизни.** Задание клеймится на срок; сигнал продлевает. Истечение
   возвращает задание в очередь **в ту же операцию**.
4. **Доставка не менее одного раза, применение идемпотентно.** Повторное выполнение задания
   не создаёт второй сущности.
5. **Одна транзакция записи.** Ресурс, операция, задание и события исходящей очереди
   коммитятся вместе. Событие, отправленное без коммита ресурса, — источник расхождений.
6. **Наблюдаемое состояние возвращается отдельным вызовом**, а не выводится control plane
   из предположений.

---

## 3. Контракт исполнителя

### 3.1 `ClaimWork` — получить задание

**Вход:** тип исполнителя, идентификатор экземпляра, объявленные возможности (для
оператора — профиль кластера), максимум заданий за раз.

**Выход:** список заданий, каждое с идентификатором, типом, сроком аренды, номером попытки
и полезной нагрузкой.

**Правила выборки:**

- порядок — по приоритету, затем по времени постановки;
- **потолок одновременных заданий на аккаунт** проверяется в самой выборке, а не в коде
  исполнителя: иначе один арендатор выедает весь флот;
- задания, чей номер попытки достиг предела, не выдаются — они отравленные и ждут разбора;
- порядок внутри одного объекта сохраняется: задание не выдаётся, пока в очереди есть
  недоставленный предшественник того же объекта **с меньшим порядковым номером `seq`**.

Порядок задаёт именно `seq` — монотонный числовой ключ (bigint identity) в `work_task` и
`outbox`, а не внешний идентификатор `id`: он UUID v4, то есть случаен, и «меньший
идентификатор» не означает «поставлен раньше». Выборка опирается на частичный индекс
`(ключ_раздела, seq)` по недоставленным строкам.

### 3.2 `ReportStatus` — вернуть состояние

**Вход:** идентификатор задания, стадия, наблюдаемое состояние, отказ (код, сообщение,
хвост журнала), метрики выполнения.

**Правила:**

- отчёт **идемпотентен**: повтор с тем же содержимым не меняет состояние;
- отчёт о терминальном исходе закрывает задание и продвигает операцию;
- отчёт по заданию с истёкшей арендой **отвергается**: его уже мог взять другой исполнитель.

### 3.3 `Heartbeat` — сигнал жизни

Продлевает аренду и публикует профиль возможностей. Оператор публикует полный профиль
кластера (§5); контроллер сборки — доступную ёмкость.

### 3.4 Классификация отказов исполнителем

| Класс | Поведение |
|---|---|
| Временный | Повтор с отступом до предела попыток |
| Терминальный | Задание закрывается, операция в отказ |
| **Отказ в правах от внешней стороны** | **Терминальный**, а не временный |

Последняя строка — из собственного опыта: повтор идентичного запроса, отвергнутого по
правам, не может пройти. Классификация его как временного означает, что строка вечно
блокирует свою часть очереди, и очередь выглядит живой, будучи мёртвой.

## 4. Якорный объект в кластере

Оператор материализует задание как объект в пространстве имён арендатора и разворачивает
из него дочерние ресурсы с владением, чтобы удаление шло сборкой мусора кластера.

### 4.1 Что несёт якорь

| Группа | Содержание |
|---|---|
| Идентификация | Идентификаторы аккаунта, проекта, приложения, окружения, компонента, релиза |
| **Версия рендера** | Ставит control plane. Оператор не подставляет свою |
| Артефакт | Digest, репозиторий, ссылка на короткоживущие учётные данные, ожидаемая подпись |
| Форма | Тип компонента, команда, порт, проба, размер, диапазон масштабирования |
| Конфигурация | Ссылки на источники переменных и секретов, хеш конфигурации |
| Сеть | Маршруты, домены, правила исходящего доступа, включая точечные правила привязок |
| Размещение | Требуемый профиль возможностей |

### 4.2 Статус якоря

Условия: принят · подпись проверена · развёрнут · готов · деградация. Каждое — с причиной и
временем. Незнакомая версия рендера **не разворачивается**, а выставляет условие отказа:
отказ виден, а не молчалив.

### 4.3 Владение полями

Оператор применяет объекты с фиксированным владельцем изменений и **исключает из патча
поля, которыми владеют чужие контроллеры**:

| Поле | Чей |
|---|---|
| Число реплик при включённом автомасштабировании | Автомасштабирование |
| Аннотации внедрения прокси сетки | Сетка |
| Статусные поля маршрута | Контроллер шлюза |
| Содержимое секрета | Оператор внешних секретов |

Без этого правила сверка дрейфа отбирает реплики у приложения, которое только что выросло
под нагрузкой.

### 4.4 Сверка дрейфа — канал отката чужой правки

Периодическая, с ограничением скорости, **не** непрерывная по наблюдению. Сверяется с
версией рендера, **зафиксированной в якоре**, а не с текущей версией кода оператора.

Иначе апгрейд оператора становится веерным перекатом всего флота: шквал скачиваний в один
реестр, массовое перепрограммирование маршрутов и отказы релизов, которых клиент не
запускал.

## 5. Профиль возможностей кластера

Публикуется оператором в сигнале жизни; хранится менеджером кластеров.

| Поле | Зачем |
|---|---|
| Версии Kubernetes, containerd, runc или crun, ядра | Определяют доступность пространств имён пользователей |
| Поддержка пространств имён пользователей | Определяет, принимаются ли образы, работающие от root |
| Доступные классы рантайма | Песочница, если появится |
| Регион и зоны | Размещение |
| Свободная ёмкость | Допуск деплоя |
| Версии рендера, которые оператор умеет разворачивать | Управление выкаткой версий |

**Однородность тенантского пула по этим параметрам — инвариант размещения.** Смешанный пул
означает, что одно и то же приложение ведёт себя по-разному в зависимости от узла, — прямой
удар по воспроизводимости опыта.

Создание, продвижение и откат сверяют совместимость **до** создания релиза.

---

## 6. Распространение версии рендера

| Шаг | Правило |
|---|---|
| Новый релиз | Получает текущую версию рендера |
| Существующие релизы | **Не переносятся автоматически** |
| Изменение, не задевающее шаблон пода | Применяется ближайшей сверкой |
| Изменение, задевающее шаблон пода | Отдельная управляемая операция миграции: ограничение скорости, порядок «сначала непрод», возможность остановки |
| Оператор не умеет версию | Условие отказа на якоре, сигнал дежурному, задание не теряется |
| Любой другой веерный перекат флота | Та же дисциплина: ограничение скорости, сначала непрод, возможность остановки |

**Дисциплина миграции версии рендера распространяется на ЛЮБОЙ веерный перекат флота, а не
только на наш рендер.** Обновление платформенных компонентов — сетки, шлюза, оператора
внешних секретов, менеджера сертификатов, нашего оператора, версии Kubernetes — перекатывает
поды клиентов ровно так же, и потому идёт тем же путём: ограничение скорости, сначала непрод,
возможность остановки. Дежурный получает сигнал «идёт веерная миграция: доля флота».
Обновление, задевающее шаблон пода клиента, без этой дисциплины — тот самый класс аварии,
который для версии рендера объявлен недопустимым (§4.4); строки по каждому компоненту с
ответом «требует ли перезапуска пода клиента» — в разделе обслуживания.

## 7. Внешние рёбра

| Ребро | Направление | Синхронность | Поведение при недоступности |
|---|---|---|---|
| Control plane → права и проекты Beget | исходящее | на пути запроса | Отказ мутации, чтение из кэша допустимо |
| Control plane → услуги Beget (база данных) | исходящее | на пути привязки | Отказ привязки с причиной; работающее приложение не трогается |
| Control plane → домены и DNS Beget | исходящее | асинхронно | Домен в ожидании, повтор |
| Control plane → биллинг | исходящее | асинхронно | Копится в очереди, отправка не теряется |
| Control plane → Git-провайдер (`GitIntegration`) | исходящее | асинхронно, плюс проверка доступа на пути сборки | Обновление токена установки не прошло — интеграция в `DEGRADED`, повтор; доступ к репозиторию потерян — `INTEGRATION_REPO_ACCESS_LOST` |
| Контроллер сборки → внешний Git | исходящее | на пути сборки | Отказ сборки с различением класса |
| Контроллер сборки → реестр | исходящее | на пути сборки | Повтор, затем терминальный отказ |
| Оператор → control plane | **исходящее из кластера** | опрос | Кластер продолжает работать; новые релизы не приезжают |
| Оператор внешних секретов → хранилище секретов | исходящее из кластера | по событию | Работающие поды не трогаются |
| **Kubernetes → реестр** | исходящее | **на пути запуска каждого пода** | Отказ запуска с причиной. Радиус — **старты на узлах, где нужных слоёв нет**: замена узла, дренаж, рост автомасштабирования. Реестру назначается собственный показатель доступности **не ниже показателя доступности входа платформы**; смягчение — зеркало или сквозной кэш на кластер, предзагрузка типовых базовых образов на узлы, ограничение скорости дренажа узлов |

**Циклов нет:** ни одна часть, которую вызывают, не вызывает вызывающего обратно. Оператор
и контроллер сборки только тянут и отчитываются; услуги Beget про платформу не знают.

Реестр — **зависимость пути запуска**, а не пути сборки: под, уже работающий, его не
спрашивает, но каждый новый под спрашивает. Отсюда и требование к показателю доступности:
недоступный реестр не роняет флот, но останавливает его восстановление ровно тогда, когда
восстановление нужно.

Ребро к Git-провайдеру обслуживает установку на организацию: обновление короткоживущего
токена установки и проверку доступа к репозиторию перед сборкой. Установка, ожидающая
одобрения владельца организации, — `INTEGRATION_PENDING_APPROVAL`, отказ **нетерминальный**:
интеграция остаётся в `PENDING_APPROVAL` и ждёт. Отзыв установки — `INTEGRATION_REVOKED`,
истёкший токен — `INTEGRATION_TOKEN_EXPIRED`. **Исчерпание лимита провайдера
(`INTEGRATION_RATE_LIMITED`) классифицируется как временный отказ, а не как отказ в правах:**
общее правило §3.4 делает отказ в правах терминальным, и без этой оговорки ответ провайдера
«слишком часто» закрыл бы задание навсегда вместо повтора с отступом.

## 8. Доставка секретов

| Шаг | Правило |
|---|---|
| Запись | Только через control plane, значение сразу в хранилище секретов |
| Хранение | Путь включает **проект, приложение, окружение и компонент**. Сегмент окружения обязателен |
| Доставка | Оператор внешних секретов в пространстве имён арендатора, область — только своё окружение |
| Обновление | **По событию от control plane** (он и есть автор изменения), длинный интервал опроса — только страховка |
| Перекат | Хеш конфигурации входит в шаблон пода |

Периодический частый опрос заменён событийным обновлением сознательно: двадцать тысяч
окружений при пятиминутном интервале — это десятки обращений в секунду круглосуточно за
данными, момент изменения которых control plane знает точно.

Права политики хранилища шаблонизируются по идентификатору окружения, который оператор
секретов получает из привязки пространства имён. Без сегмента окружения в пути требование
«секреты не наследуются в непрод» **нереализуемо**: набор один на все окружения, и непрод
читает боевой ключ успешно, без отказа.

## 9. Учётные данные реестра

| Кому | Что | Срок |
|---|---|---|
| Контроллер сборки | Публикация в один конкретный репозиторий | На сборку |
| Kubernetes | Чтение одного конкретного образа | Короткий, обновляется оператором |
| Клиенту по запросу | Чтение своего образа по digest | Короткий |

Долгоживущих учётных данных к реестру в пространстве имён арендатора не существует.

---

## 10. Инварианты, за которые отвечает эта граница

1. Задание, взятое в работу, либо завершается, либо возвращается в очередь — **не теряется**.
2. Падение исполнителя **не создаёт новую операцию**.
3. Повторное применение задания не создаёт второй сущности.
4. Отказ в правах от внешней стороны классифицируется как терминальный.
5. Оператор не разворачивает версию рендера, которую не понимает, и говорит об этом.
6. Наблюдаемое состояние приходит от того, кто его наблюдает, а не выводится из намерения.
7. Число доставленных заданий за всю жизнь очереди — **наблюдаемая величина**. Ноль
   доставленных строк обязан быть заметен: у нас уже был случай, когда очередь не доставила
   ни одной строки за всю жизнь, а система выглядела исправной, потому что рядом работал
   синхронный путь.
