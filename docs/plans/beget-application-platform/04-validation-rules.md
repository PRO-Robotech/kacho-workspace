# 04. Реестр валидаций и кодов отказа

Что проверяется, когда, с каким кодом и каким текстом. Тексты, которые видит клиент, —
**часть контракта**: они меняются осознанно, вместе с тестами.

---

## 1. Принципы

1. **Синхронно отвергается всё, что можно проверить без внешнего обращения.** Формат,
   длина, диапазон, перечисление, взаимоисключение полей, ссылочная целостность внутри
   нашей базы. Такой отказ приходит до создания операции.
2. **Асинхронным отказом становится только то, что требует внешней стороны:** доступ к
   репозиторию, результат сборки, поведение контейнера, выдача сертификата.
3. **Проверка манифеста — сразу после резолва ссылки на коммит, до тяжёлой сборки.** Ошибку
   в `beget.yaml` нельзя узнавать через две минуты компиляции.
4. **Порядок в обработчике фиксирован:** формат → неизменяемость → состав маски → права →
   существование → предусловия состояния → квота. Нарушение порядка даёт клиенту неверную
   причину: например, неизменяемое поле, отвергнутое как «неизвестное».
5. **Код — на латинице и стабилен, сообщение — на русском и для человека.** Клиент
   ветвится по коду, читает сообщение. Разбор текста сообщения не является контрактом.
6. **Отказ называет поле.** Если отказ относится к полю запроса, его имя присутствует в
   ответе отдельным значением, а не только внутри текста.

## 2. Общие типы

| Тип | Правило | Код при нарушении |
|---|---|---|
| Идентификатор ресурса | UUID v4 | `INVALID_ID` |
| Имя (приложение, окружение, компонент) | 2–40 символов, `^[a-z][a-z0-9-]*[a-z0-9]$`, без двойного дефиса | `INVALID_NAME` |
| Зарезервированные имена окружения | `kube-*`, `istio-*`, `default`, `internal`, `system`, `admin`, `api`, `www` | `RESERVED_NAME` |
| Метка DNS | 1–63 символа, `^[a-z0-9]([a-z0-9-]*[a-z0-9])?$` | `INVALID_DNS_LABEL` |
| Полное доменное имя | ≤ 253 символа, метки по правилу выше, без подстановочных знаков | `INVALID_FQDN` |
| Описание | ≤ 1024 символа | `TOO_LONG` |
| Размер страницы | 1–100, по умолчанию 20 | `INVALID_LIMIT` |
| Смещение | ≥ 0 | `INVALID_OFFSET` |
| Ключ идемпотентности | 1–255 символов, печатные ASCII | `INVALID_IDEMPOTENCY_KEY` |

Размер страницы вне диапазона **отвергается, а не подрезается**: молча выданная не та
страница хуже отказа.

## 3. Приложение, окружение, компонент

| Поле | Правило | Код |
|---|---|---|
| `project_id` | Существует, доступен вызывающему | `PROJECT_NOT_FOUND` |
| `region_id` | Из справочника регионов, доступен для платформы | `REGION_NOT_AVAILABLE` |
| `name` | Общий тип имени | `INVALID_NAME` |
| Число приложений | ≤ потолка тарифа проекта | `QUOTA_APPLICATIONS_EXCEEDED` |
| `environment.name` | Уникально в приложении, не зарезервировано | `NAME_TAKEN`, `RESERVED_NAME` |
| `environment.tier` | `PRODUCTION` \| `NON_PRODUCTION`, неизменяемо | `INVALID_ENUM`, `IMMUTABLE_FIELD` |
| `environment.quota_share_percent` | 1–100; обязателен для непрода | `INVALID_RANGE`, `REQUIRED_FIELD` |
| Число окружений | ≤ потолка тарифа | `QUOTA_ENVIRONMENTS_EXCEEDED` |
| Удаление окружения по умолчанию | Запрещено, пока оно по умолчанию | `DEFAULT_ENVIRONMENT_PROTECTED` |
| Удаление последнего окружения | Запрещено | `LAST_ENVIRONMENT_PROTECTED` |
| `component.name` | Уникально в приложении, **неизменяемо** | `NAME_TAKEN`, `IMMUTABLE_FIELD` |
| `component.type` | `WEB` \| `WORKER` \| `STATIC`, неизменяемо | `INVALID_ENUM`, `IMMUTABLE_FIELD` |
| `component.port` | 1–65535, вне диапазона служебных портов сетки; только для `WEB` | `INVALID_PORT`, `FIELD_NOT_APPLICABLE` |
| `component.run_command` | ≤ 4096 символов; запрещён для `STATIC` | `TOO_LONG`, `FIELD_NOT_APPLICABLE` |
| `component.release_command` | ≤ 4096 символов; допустим для **всех** типов компонента, по умолчанию пуст | `TOO_LONG` |
| `release_command_override` | То же правило; задаётся в `ComponentEnvironmentConfig`, пустая строка означает «команды нет», отсутствие поля — «как у компонента» | `TOO_LONG` |
| `health.path` | Начинается с `/`, ≤ 2048 символов; только при типе `HTTP` | `INVALID_PATH` |
| `health.*_seconds` | 1–600; бюджет старта 1–1800 | `INVALID_RANGE` |
| `size` | Из перечисления, ≤ потолка тарифа | `INVALID_ENUM`, `SIZE_NOT_ALLOWED` |
| `scale.min` | ≥ 1 (масштабирования в ноль нет) | `INVALID_RANGE` |
| `scale.max` | ≥ `min`, ≤ потолка тарифа | `INVALID_RANGE`, `QUOTA_REPLICAS_EXCEEDED` |
| `scale.target_cpu_percent` | 1–100; обязателен, если `max > min` | `INVALID_RANGE`, `REQUIRED_FIELD` |
| `static_config.output_dir` | Относительный путь без `..`, ≤ 255 | `INVALID_PATH` |
| Удаление компонента | Нет активных релизов ни в одном окружении | `COMPONENT_IN_USE` |

## 4. Источник — самая ответственная группа

### 4.1 Формат

| Поле | Правило | Код |
|---|---|---|
| `type` | `GIT` \| `UPLOAD` | `INVALID_ENUM` |
| `repository_url` | Схема `https` или `ssh`; ≤ 2048; без учётных данных в самом адресе | `INVALID_URL`, `CREDENTIALS_IN_URL` |
| `ref` | ≤ 255, `^[A-Za-z0-9._/-]+$`, без `..`, не начинается с `-` | `INVALID_REF` |
| `context_dir` | Относительный путь, без `..`, без ведущего `/`, ≤ 255 | `INVALID_PATH` |
| `https_token` | Только на запись, ≤ 1024; никогда не возвращается | `TOO_LONG` |
| Взаимоисключение | Ровно один из `repository_url` и `upload_id` | `MUTUALLY_EXCLUSIVE` |

### 4.2 Защита периметра сборки — проверки, без которых периметр не закрыт

Адрес источника называет **арендатор**. Поэтому:

| Проверка | Правило | Код |
|---|---|---|
| Резолв имени | Выполняет **платформа**, не сборщик; результат закрепляется и используется для соединения | — |
| Отбраковка адресов | **После** резолва отбрасываются приватные, loopback, link-local (включая адрес метаданных), CGNAT, мультикаст и все не-глобальные диапазоны | `SOURCE_ADDRESS_FORBIDDEN` |
| Повторное связывание DNS | Соединение идёт по **закреплённому** адресу; повторный резолв в процессе запрещён | `SOURCE_ADDRESS_FORBIDDEN` |
| Переадресация | Не более 3 переходов, каждый проходит те же проверки заново | `SOURCE_REDIRECT_REJECTED` |
| Порт | Только 22, 80, 443 | `SOURCE_PORT_FORBIDDEN` |
| Подмодули | По умолчанию **не** клонируются; включаются явно, каждый проходит все проверки адреса, суммарная квота на глубину и объём | `SUBMODULE_FORBIDDEN`, `SUBMODULE_LIMIT` |
| Большие файлы (LFS) | По умолчанию выключены, включаются явно, с квотой объёма | `LFS_LIMIT` |
| Объём репозитория | ≤ потолка (подбирается) | `SOURCE_TOO_LARGE` |
| Число файлов | ≤ потолка | `SOURCE_TOO_MANY_FILES` |
| Глубина клона | Один коммит, если провайдер это позволяет | — |

Эти проверки существуют не «на всякий случай»: без них «разрешить доступ к источнику»
означает «разрешить исходящее соединение по адресу, который выбирает атакующий», из
периметра, объявленного закрытым.

### 4.3 Распаковка загруженного архива

| Проверка | Правило | Код |
|---|---|---|
| Контрольная сумма | Совпадает с заявленной | `UPLOAD_CHECKSUM_MISMATCH` |
| Сжатый объём | ≤ потолка | `UPLOAD_TOO_LARGE` |
| Распакованный объём | ≤ потолка; коэффициент сжатия ≤ порога | `ARCHIVE_BOMB` |
| Число записей | ≤ потолка | `ARCHIVE_TOO_MANY_ENTRIES` |
| Пути | Отбрасываются абсолютные, содержащие `..`, символические и жёсткие ссылки, ведущие за пределы каталога | `ARCHIVE_UNSAFE_PATH` |
| Специальные файлы | Устройства, сокеты, именованные каналы отбрасываются | `ARCHIVE_UNSAFE_ENTRY` |
| Срок жизни ссылки на загрузку | ≤ 1 часа | `UPLOAD_EXPIRED` |

## 5. Переменные, привязки, домены, бюджет

### 5.1 Переменные

| Поле | Правило | Код |
|---|---|---|
| `key` | `^[A-Za-z_][A-Za-z0-9_]{0,127}$` | `INVALID_VARIABLE_KEY` |
| Зарезервированные ключи | `PORT`, префикс `BEGET_` | `RESERVED_VARIABLE_KEY` |
| `value` | ≤ 32 KiB на переменную | `VALUE_TOO_LONG` |
| Суммарный объём | ≤ 128 KiB на компонент (ограничение окружения процесса) | `ENVIRONMENT_TOO_LARGE` |
| Секрет в области приложения | Запрещён | `SECRET_SCOPE_FORBIDDEN` |
| Смена признака секретности | Запрещена; удалить и создать заново | `IMMUTABLE_FIELD` |
| Правка переменной от привязки | Запрещена | `MANAGED_VARIABLE` |
| Чтение значения секрета | Не существует ни в одном методе | — |

### 5.2 Привязка услуги

| Поле | Правило | Код |
|---|---|---|
| `target_service_id` | Существует, **в том же проекте**, доступна вызывающему | `SERVICE_NOT_FOUND`, `SERVICE_WRONG_PROJECT` |
| `service_kind` | Совпадает с фактическим типом услуги | `SERVICE_KIND_MISMATCH` |
| `variable_prefix` | Правило ключа переменной; не занят другой привязкой | `INVALID_VARIABLE_KEY`, `PREFIX_TAKEN` |
| Возможность выдачи | Услуга умеет выдавать отдельные учётные данные | `SERVICE_BINDING_UNSUPPORTED` |
| Доступность | Услуга отвечает | `SERVICE_UNAVAILABLE` |

### 5.3 Домены

| Поле | Правило | Код |
|---|---|---|
| `fqdn` | Общий тип; **не в технической зоне платформы** | `INVALID_FQDN`, `RESERVED_ZONE` |
| Уникальность | Не привязан к другому приложению | `FQDN_TAKEN` |
| Владение | Домен принадлежит аккаунту либо подтверждён записью | `DOMAIN_NOT_OWNED`, `DOMAIN_VERIFICATION_FAILED` |
| Уровень окружения | По умолчанию только `PRODUCTION` | `CUSTOM_DOMAIN_NOT_ALLOWED_HERE` |
| Число доменов | ≤ потолка тарифа | `QUOTA_DOMAINS_EXCEEDED` |
| Тип компонента | Только `WEB` и `STATIC` | `FIELD_NOT_APPLICABLE` |

Запрет на привязку имени из технической зоны платформы — не формальность: иначе арендатор
объявляет своим адрес соседа.

### 5.4 Бюджет

`Budget` — ресурс уровня **проекта**, не более одного на проект.

| Поле | Правило | Код |
|---|---|---|
| `project_id` | Существует, доступен вызывающему | `PROJECT_NOT_FOUND` |
| `limit_amount` | Строго больше нуля; **не ниже уже потреблённого** `current_spend` текущего периода | `INVALID_RANGE`, `BUDGET_LIMIT_TOO_LOW` |
| `currency` | Из перечисления; совпадает с валютой плана проекта | `INVALID_ENUM` |
| `enforcement` | `NOTIFY` \| `STOP_NON_PRODUCTION` \| `STOP_METERED`; выбранный режим поддержан планом проекта | `INVALID_ENUM`, `BUDGET_ENFORCEMENT_UNSUPPORTED` |
| `thresholds` | 1–100 каждый, строго по возрастанию, без повторов, не более 5 значений | `INVALID_RANGE` |
| Остановка боевого сайта | Через `enforcement` недостижима: `STOP_METERED` останавливает сборки, непрод и исходящий трафик и **не трогает** боевой сайт | `BUDGET_ENFORCEMENT_UNSUPPORTED` |
| `current_spend`, `forecast`, `status` | Вычисляются платформой, на запись не принимаются | `IMMUTABLE_FIELD` |

Полная остановка проекта возможна **только** через `overdraft_policy = STOP_ALL` у плана
проекта: потолок расходов и решение «выключить боевой сайт за неоплату» — разные полномочия
и разные последствия, смешивать их в одном поле нельзя.

Наполнение бюджета фактическими цифрами упирается во внешний блокер 0.5 (биллинг Beget). На
этапе Э1 замораживается **форма ресурса**, а не срок наполнения: метод, принимающий потолок
расходов без модели за ним, — тот же класс, за который в первом раунде удалён режим
выделенного балансировщика. Клиент, включивший защиту, обязан получить либо работающую
защиту, либо явный отказ, но не молчаливый успех.

## 6. Манифест

| Проверка | Правило | Код |
|---|---|---|
| Размер файла | ≤ 256 KiB | `MANIFEST_TOO_LARGE` |
| Синтаксис | Разбирается; глубина вложенности ≤ 20; якоря и ссылки запрещены | `MANIFEST_INVALID` |
| `version` | Известная версия схемы | `MANIFEST_VERSION_UNSUPPORTED` |
| Неизвестное поле | **Отвергается**, а не игнорируется | `MANIFEST_UNKNOWN_FIELD` |
| Число компонентов | 1 … потолок тарифа | `MANIFEST_INVALID` |
| Ключ компонента | Правило имени | `INVALID_NAME` |
| Поля компонента | Те же правила, что в §3 | те же коды |
| Секрет в манифесте | Отвергается с именем ключа | `SECRET_IN_MANIFEST` |
| Расхождение с существующими компонентами | Манифест не может переименовать или сменить тип существующего компонента | `MANIFEST_CONFLICT` |

Неизвестное поле отвергается, а не проглатывается: молча принятый параметр создаёт у
клиента уверенность, что он применён.

## 7. Реестр кодов отказа

### 7.1 Синхронные — формат и предусловия

| Код | Сообщение (шаблон) |
|---|---|
| `INVALID_ID` | Неверный идентификатор «%s» |
| `INVALID_NAME` | Имя должно состоять из строчных латинских букв, цифр и дефисов, 2–40 символов |
| `RESERVED_NAME` | Имя «%s» зарезервировано платформой |
| `NAME_TAKEN` | Имя «%s» уже занято в этом приложении |
| `REQUIRED_FIELD` | Поле «%s» обязательно |
| `INVALID_ENUM` | Недопустимое значение «%s» для поля «%s» |
| `INVALID_RANGE` | Значение поля «%s» вне допустимого диапазона |
| `TOO_LONG` | Значение поля «%s» длиннее %d символов |
| `IMMUTABLE_FIELD` | Поле «%s» нельзя изменить после создания |
| `MUTUALLY_EXCLUSIVE` | Поля «%s» и «%s» нельзя задавать одновременно |
| `FIELD_NOT_APPLICABLE` | Поле «%s» не применимо к компоненту типа «%s» |
| `UNKNOWN_FIELD` | Неизвестное поле «%s» |
| `NOT_FOUND` | %s «%s» не найдено |
| `DEPLOYMENT_IN_PROGRESS` | В окружении «%s» уже идёт выкатка компонента «%s» |
| `COMPONENT_IN_USE` | У компонента есть активные релизы, сначала отключите его |
| `QUOTA_*_EXCEEDED` | Превышена квота проекта: %s |
| `SERVICE_WRONG_PROJECT` | Услуга «%s» принадлежит другому проекту |
| `CLUSTER_PROFILE_INCOMPATIBLE` | Целевое окружение размещено на узлах с другими возможностями |
| `BUDGET_LIMIT_TOO_LOW` | Потолок %s ниже уже потреблённого за период %s либо ниже минимального платежа плана |
| `BUDGET_ENFORCEMENT_UNSUPPORTED` | Режим «%s» недоступен для плана проекта |

### 7.2 Асинхронные — источник

| Код | Терминальный | Сообщение |
|---|---|---|
| `SOURCE_NOT_FOUND` | да | Репозиторий «%s» не найден |
| `SOURCE_ACCESS_DENIED` | да | Нет доступа к репозиторию «%s» |
| `SOURCE_ACCESS_PENDING` | **нет** | Ключ доступа выдан, ожидается добавление в репозиторий |
| `SOURCE_REF_NOT_FOUND` | да | Ветка или тег «%s» не найдены |
| `SOURCE_ADDRESS_FORBIDDEN` | да | Адрес репозитория недопустим |
| `SOURCE_PORT_FORBIDDEN` | да | Порт %d недопустим для источника |
| `SOURCE_REDIRECT_REJECTED` | да | Слишком много переадресаций либо переадресация на недопустимый адрес |
| `SOURCE_TOO_LARGE` | да | Объём исходников превышает %s |
| `SOURCE_TOO_MANY_FILES` | да | Слишком много файлов в исходниках |
| `SOURCE_AMBIGUOUS` | да | В контексте найдено несколько стеков: %s. Укажите сборщик или контекст |
| `SOURCE_NOT_RECOGNIZED` | да | Не удалось определить, как собирать: нет Dockerfile и не подошёл ни один бэкпак |
| `SUBMODULE_FORBIDDEN` | да | Подмодуль «%s» указывает на недопустимый адрес |
| `ARCHIVE_*` | да | см. §4.3 |

Разделение прежнего единого «источник недоступен» на четыре кода принципиально: «репозитория
нет», «нет доступа», «нет такой ветки» и «ждём ключ» требуют **разных действий** клиента.

Исчерпание лимита обращений к Git-провайдеру классифицируется как **временный** отказ
(`INTEGRATION_RATE_LIMITED`, §7.6), а не как `SOURCE_ACCESS_DENIED`. Иначе клиент, у которого
всё в порядке с правами, идёт перевыпускать доступ на пустом месте, а платформа скрывает
собственную нагрузку на провайдера под видом чужой ошибки.

### 7.3 Асинхронные — сборка

| Код | Сообщение |
|---|---|
| `MANIFEST_*` | см. §6 |
| `BUILD_FAILED` | Сборка завершилась с ошибкой на стадии «%s» |
| `BUILD_TIMEOUT` | Сборка превысила лимит времени %s |
| `BUILD_QUOTA_EXCEEDED` | Превышен лимит ресурсов сборки |
| `BUILD_CANCELLED` | Сборка отменена |
| `REGISTRY_UNAVAILABLE` | Реестр образов временно недоступен |
| `SIGNING_FAILED` | Не удалось подписать образ |

`BUILD_FAILED` **обязан** нести стадию, последние строки журнала и ссылку на полный журнал.
Отказ сборки без хвоста журнала бесполезен.

### 7.4 Асинхронные — запуск

| Код | Сообщение | Как отличается от соседа |
|---|---|---|
| `IMAGE_PULL_FAILED` | Не удалось получить образ %s | Контейнер не стартовал |
| `RELEASE_COMMAND_FAILED` | Команда релиза завершилась с кодом %d на стадии «%s» | Состояние `RELEASING`. **Обязана** нести стадию и хвост журнала. Трафик не переключён, предыдущий релиз продолжает отвечать |
| `RELEASE_COMMAND_TIMEOUT` | Команда релиза превысила предельный срок %s | То же состояние и те же последствия; отличается причиной остановки — свой предельный срок, отдельный от срока сборки и бюджета старта |
| `APP_CRASHED` | Приложение завершилось с кодом %d | Есть перезапуски |
| `APP_OUT_OF_MEMORY` | Приложение превысило лимит памяти %s (пик %s). Увеличьте размер до «%s» | Код завершения 137 и событие о превышении памяти. **Лимит ставит платформа — она обязана его назвать** |
| `APP_NOT_LISTENING` | Приложение запущено, но за %d с никто не слушает порт %d. Слушайте `$PORT` или укажите порт явно | Контейнер жив, перезапусков нет, проба не проходит |
| `APP_UNHEALTHY` | Проба состояния перестала отвечать | Было здорово, стало нет |
| `WORKER_EXITED` | Фоновый обработчик завершился с кодом %d | Только для `WORKER`: нет слушающего сокета и не должно быть |
| `IMAGE_RUNS_AS_ROOT` | Образ запускается от root, а целевые узлы это не поддерживают | Только на кластерах без пространств имён пользователей |
| `QUOTA_EXCEEDED` | Не хватает квоты проекта: %s | Отказ **до** размещения |
| `CAPACITY_UNAVAILABLE` | Нет свободной ёмкости в регионе | Отказ до размещения |
| `SCALE_DEGRADED` | Не удалось вырасти до %d реплик, работает %d | **Не отказ релиза.** Видимая деградация на пути автомасштабирования |
| `ROUTE_PROGRAMMING_FAILED` | Не удалось опубликовать маршрут |  |
| `SECRET_STORE_UNAVAILABLE` | Хранилище секретов недоступно |  |
| `INTERNAL` | Внутренняя ошибка, обращение %s | Последнее средство. Доля таких отказов — измеряемый показатель качества |

Различение `APP_CRASHED`, `APP_OUT_OF_MEMORY` и `APP_NOT_LISTENING` — принципиальное: это
три разных действия клиента. Слить их в «деплой не удался» значит отправить человека
разбираться самостоятельно.

Оба отказа команды релиза приходят из состояния `RELEASING` — между `QUEUED` и `DEPLOYING`,
то есть **до** переключения трафика. Команда выполняется один раз на релиз, на том же образе,
с теми же переменными и секретами, что и рабочий процесс, и запускается на **каждом** релизе,
включая продвижение артефакта и откат: за идемпотентность отвечает клиент. Отказ не трогает
предыдущий релиз — он остаётся боевым. Хвост журнала команды доступен по `release_log_ref`.

### 7.6 Асинхронные — интеграция с Git-провайдером

`GitIntegration` принадлежит **аккаунту**: установка ставится на организацию и переиспользуется
всеми проектами аккаунта. Поэтому её отказы приходят не из одного приложения и обязаны быть
различимы — «жди одобрения», «переустанови», «дай доступ к репозиторию» и «подожди» требуют
разных действий.

| Код | Терминальный | Сообщение |
|---|---|---|
| `INTEGRATION_PENDING_APPROVAL` | **нет** | Установка в организации «%s» ожидает одобрения её владельца |
| `INTEGRATION_REVOKED` | да | Установка интеграции отозвана на стороне провайдера, подключите её заново |
| `INTEGRATION_TOKEN_EXPIRED` | **нет** | Срок действия токена установки истёк, токен перевыпускается |
| `INTEGRATION_REPO_ACCESS_LOST` | да | Репозиторий «%s» больше не входит в область установки |
| `INTEGRATION_RATE_LIMITED` | **нет** | Провайдер ограничил частоту обращений, следующая попытка в %s |

`INTEGRATION_PENDING_APPROVAL` нетерминален намеренно: одобрение владельца организации приходит
за минуты или часы, и завершать релиз отказом на этом основании нельзя. `INTEGRATION_RATE_LIMITED`
— **временный** отказ, а не отказ в правах (§7.2). `INTEGRATION_RATE_LIMITED` и неудачное
обновление токена переводят интеграцию в `DEGRADED`, а не в `REVOKED`;
`INTEGRATION_PENDING_APPROVAL` оставляет её в `PENDING_APPROVAL` до одобрения. Разница между
«сейчас не отвечает» и «доступа больше нет» — это разница между ожиданием и повторной установкой.

## 8. Порядок проверок в обработчике

```
1. Формат пути и тела              → INVALID_ID / INVALID_*
2. Неизменяемые поля в теле        → IMMUTABLE_FIELD
3. Состав маски изменения          → UNKNOWN_FIELD
4. Права на проект и ресурс        → NOT_FOUND (недоступное неотличимо от несуществующего)
5. Существование ссылок            → *_NOT_FOUND
6. Предусловия состояния           → DEPLOYMENT_IN_PROGRESS, COMPONENT_IN_USE, …
7. Квота проекта                   → QUOTA_*_EXCEEDED
8. Совместимость профиля кластера  → CLUSTER_PROFILE_INCOMPATIBLE
9. Создание операции и заданий
```

Шаг 2 стоит **перед** шагом 3 не случайно: состав маски не содержит неизменяемых полей,
поэтому при обратном порядке клиент получит «неизвестное поле» вместо «поле неизменяемо».

Шаг 4 стоит перед шагом 5: сначала право, потом существование. Иначе по различию ответов
можно перечислить чужие ресурсы.

## 9. Что обязано проверяться тестом

| Класс | Проверка |
|---|---|
| Каждый код §7 | Хотя бы один тест, доводящий систему до этого кода **естественным путём**, а не подстановкой |
| Порядок §8 | Неизменяемое поле в маске даёт `IMMUTABLE_FIELD`, а не `UNKNOWN_FIELD` |
| Различение отказов запуска | Три разных приложения (падает, ест память, не слушает) дают три разных кода |
| Периметр источника §4.2 | Тесты-ловушки: адрес в приватном диапазоне, имя, резолвящееся в приватный адрес, переадресация на такой адрес, подмодуль на внутренний адрес — **каждый** отвергается |
| Распаковка §4.3 | Архив с `..`, с символической ссылкой наружу, с коэффициентом сжатия выше порога |
| Секреты | Значение секрета не возвращается ни одним методом; отсутствует в журнале сборки, в журнале приложения, в событиях и в метках |
| Хвост журнала | `BUILD_FAILED`, `APP_CRASHED` и `RELEASE_COMMAND_FAILED` несут непустой хвост |
| Команда релиза | Отказ команды даёт `RELEASE_COMMAND_FAILED` со стадией и хвостом, трафик **не** переключается, предыдущий релиз продолжает отвечать; превышение своего срока даёт `RELEASE_COMMAND_TIMEOUT` |
| Однократность команды релиза | На одном релизе команда исполняется ровно один раз при любом числе реплик; продвижение артефакта и откат исполняют её заново |
| Интеграция с Git-провайдером | Установка без одобрения владельца организации даёт **нетерминальный** `INTEGRATION_PENDING_APPROVAL`; отзыв установки — `INTEGRATION_REVOKED`; исчерпание лимита провайдера — **временный** `INTEGRATION_RATE_LIMITED`, а не `SOURCE_ACCESS_DENIED` |
| Область интеграции | Установка, поставленная в одном проекте аккаунта, видна остальным проектам того же аккаунта и не видна чужому аккаунту |
| Бюджет | Потолок ниже уже потреблённого отвергается `BUDGET_LIMIT_TOO_LOW`; порог вне 1–100 или не по возрастанию — `INVALID_RANGE`; неподдержанный планом режим — `BUDGET_ENFORCEMENT_UNSUPPORTED` |
| Действие бюджета | `STOP_METERED` останавливает сборки, непрод и исходящий трафик и **не останавливает** боевой сайт; боевой сайт останавливает только `overdraft_policy = STOP_ALL` |
| Отсутствие вечных ожиданий | У каждой стадии есть предельный срок; истечение даёт терминальный код с указанием стадии |
