# Дизайн-система Kachō — проектное решение

**Дата:** 2026-07-27 · **Редакция 2** (после семи критиков: 135 находок, 79 высоких)
**Предмет:** собственная дизайн-система вместо antd, выведенная из существующего интерфейса
`kacho-ui-future` и доведённая до системы.

---

## 1. Задача и рамки

Интерфейс Kachō уже сложился как связный язык: две темы, семантические переменные, своя
типошкала, поверхности, оболочка с рейлом. Но язык нигде не записан целиком, продублирован
в трёх местах и разъехался между девятью ремоутами.

Задача — **не заменить этот язык, а извлечь из него систему**.

**В рамках:** токены, примитивы, паттерны, правила, стратегия ухода от antd.
**Вне рамок:** миграция 228 файлов (отдельный проект), компактный режим плотности.

### Успех

1. Значение токена меняется в одном месте и доезжает во все девять ремоутов.
2. Ни один компонент не дублируется между ремоутами.
3. Экран собирается только из примитивов системы.
4. Доступность и производительность проверяются автоматически и роняют сборку.
5. antd отсутствует в зависимостях.

---

## 2. Принятые решения

| Решение | Обоснование |
|---|---|
| Светлая тема ведущая, тёмная равноправная | Так работает по факту: `:root` без атрибута — светлая |
| Один ряд высот **контролов**: 24 / 32 / 40 | Ряд antd преобладает; ряд shadcn уходит со слоем |
| **Высота строки таблицы — отдельный токен**, не из ряда контролов | Строка сегодня 38 (9px + 13px + 9px + рамка) и в ряд не попадает; смешение этих шкал — источник разнобоя |
| Базовый кегль 13 | Кегль antd |
| Одна плотность в первой версии | Компактный режим — отдельная задача |
| Единственный источник токенов | Дублирование в трёх местах — корень целого класса расхождений |
| Основание — headless-примитивы + свой слой | Radix уже в зависимостях |
| **Поиск и сортировка — серверные** | Сегодня и то и другое работает по одной загруженной странице (см. §4) |
| **Один набор иконок** | Сейчас два: `@ant-design/icons` в 156 файлах и `lucide-react`; смешение видно на экране |
| **Акцент для текста и акцент для заливки — разные токены** | Белый текст на `#3d8df5` даёт около 3.1:1 при норме 4.5 (см. §5) |

## 3. Токены — три слоя, один источник

```
tokens/
  primitive.json    сырьё: шкалы цвета, размеров, теней. Ролей не знает
  semantic.json     роли: surface.page, text.secondary, status.error.fg
  component.json    компонентные: button.primary.bg, table.row.height
```

Генерируются: `tokens.css` (обе темы) · `tokens.ts` · `tailwind.preset.js` (один вместо семи).
Правки в сгенерированное запрещены, гейт сверяет свежесть.

Слой сырья строится в **OKLCH**: одинаковый шаг светлоты воспринимается одинаково, поэтому шкала
даёт предсказуемый контраст, а тёмная тема получается инверсией светлоты. Выдача — `oklch()`
с запасным `#rrggbb`.

**Слой 3 не заводит абстракций, которых нет в слое 2.** Компонентный токен — это ссылка на
семантический с уточнением роли, а не новый цвет.

**Именование по роли, не по виду.** Компонент никогда не обращается к слою 1.

**Жизненный цикл темы.** Атрибут `data-theme` ставит **хост** и только он; выбор хранится в
`localStorage` (`kacho-theme`), начальное значение берётся из `prefers-color-scheme` до первой
отрисовки (инлайновый скрипт в `index.html`, иначе будет вспышка чужой темы). Ремоуты тему не
переключают и своего состояния темы не держат. `color-scheme` объявляется вместе с атрибутом.

**Градиент бренда — единственная неплоская поверхность.** Он живёт как отдельный токен
`brand.gradient` и применяется только к знаку и к пустым состояниям первого запуска. Текст поверх
градиента запрещён.

**Настройка `darkMode: "class"` удаляется** из всех конфигов: класс `dark` не ставится нигде.
**Запасной цвет внутри переменной запрещён** (`var(--x, #2f3138)`) — маскирует дефект и ломает
светлую тему.

**Нижняя граница движков:** последние две версии Chrome, Firefox, Safari и производные на
Chromium. Контейнерные запросы, `:has()`, `oklch()` и вложенность CSS считаются доступными;
полифилов нет. Граница записывается в `browserslist` и проверяется сборкой.

## 4. Примитивы

Слой поведения — Radix. Слой вида и API — наш.

### Состав первой версии

Выведен из реального употребления: `Typography` 134, `Button` 112, **`Form`/`Form.Item` 319**,
`Input` 71, `Space` 70, `Alert` 52, `Select` 48, `Tag` 46, `Modal` 41, `Spin` 38, `Tooltip` 36,
`Table` 21, плюс `Segmented`, `Descriptions`, `Tree`, `Cascader`, `Popconfirm`, `Result`.

**Основа:** `Text` `Heading` `Stack` `Inline` `Divider` `Surface` `Card` `Badge` `Tag`
`Spinner` `Skeleton` `Icon` `Kbd` `Code` `Copyable` `Descriptions`.

**Контролы:** `Button` `IconButton` `Input` `Textarea` `NumberInput` `Select` `Combobox`
`Checkbox` `Radio` `Switch` `Segmented` `Slider` `DatePicker`.

**Формы:** `Form` `Field` `FieldLabel` `FieldError` `FormFooter` — **самая массовая конструкция
в коде, поэтому проектируется первой, а не по остаточному принципу.** Контракт: модель значений
и ошибок, порядок валидации (на отправке, не на вводе), связь ошибки с полем через
`aria-describedby`, перевод фокуса на первое поле с ошибкой, блокировка повторной отправки.

**Наложения:** `Dialog` `Drawer` `Popover` `Tooltip` `DropdownMenu` `ContextMenu` `Toast`.

**Императивный слой:** `confirm()` `notify()` `prompt()` — замена `App.useApp()` antd.
Без него 41 место с `Modal.confirm` переписать не на что.

**Данные:** `Table` `CursorPager` `EmptyState` `ErrorState` `Alert` `Meter` `Timeline` `Tree`.

**Ссылки на ресурсы:** `ResourceLink` `ResourceRefChips` — переход между связанными ресурсами
самое частое действие инженера, и это отдельный примитив, а не «ссылка с иконкой».

**Оболочка:** `AppShell` `Rail` `Sidebar` `Header` `Breadcrumb` `Tabs` `CommandPalette`.

### Иконки — подсистема, а не набор файлов

Сейчас в коде **два набора одновременно**. Решение: один набор (`lucide`), фиксированная сетка
16/20/24, единая толщина штриха, собственные доменные знаки рисуются в той же сетке.
`IconButton` **обязан** иметь доступное имя — сегодня из 153 иконочных кнопок его несут две.
Отсутствие имени роняет сборку.

### Правила API

`size` (`sm` 24 / `md` 32 / `lg` 40), `tone` (`neutral` `primary` `danger`), `variant`.
Пропа `style` нет. Каждый интерактивный примитив пробрасывает `ref` и ARIA.

### Таблица — контракт, а не список возможностей

- **Поиск серверный** (`filter` из белого списка полей). Плюс короткое замыкание: вставленный
  идентификатор открывает объект напрямую через `Get`, без листания. Без этого обещание
  «Поиск по имени или идентификатору» невыполнимо.
- **Сортировка серверная**; сортируемые поля объявляет спека ресурса. Колонка, которую сервер
  не сортирует, **не кликается**. Клиентская сортировка над страницей запрещена — она молча
  врёт на объёме.
- **Курсор, а не страницы.** `CursorPager`: вперёд по токену, назад по стеку пройденных,
  **тотала не существует**. Подпись — «загружено N», не «N из M». Счётчик в шапке списка либо
  показывает загруженное, либо отсутствует.
- **Виртуализация обязательна.** Следствие: ячейка фиксированной высоты; многострочные значения
  (списки CIDR) сворачиваются в одну строку с раскрытием по требованию.
- **Ширина колонок задаётся, а не выводится из содержимого.** Спека ресурса объявляет долю и
  минимум; идентичность (имя) — липкая колонка, чтобы горизонтальный скролл не отрывал строку от
  её имени.
- **Массовые действия** — см. §8: N операций и одна групповая запись.
- **Состояние списка адресуемо.** Поиск, фильтры, сортировка и открытая вкладка живут в адресе
  строки, а не в локальном состоянии: иначе ссылку на отфильтрованный список нельзя передать
  коллеге, а «назад» браузера теряет контекст.

## 5. Доступность — гейт, а не пожелание

Целевой уровень — **WCAG 2.2 AA**, проверяется автоматически и роняет сборку.

**Честная правка после расчёта критиков:** текущий бренд `#3d8df5` с белым текстом даёт около
**3.1:1** — гейт покраснеет на первой же кнопке. Поэтому:

- Вводятся **два токена акцента**: `accent.surface` (заливка, к ней подбирается тёмный текст либо
  затемнённый вариант заливки) и `accent.text` (акцентный текст на обычной поверхности,
  затемнённый до ≥4.5:1). Бренд как узнаваемый цвет сохраняется, контраст обеспечивается парой.
- **Пилюли статусов поднимаются с 11px до 12px** и их тона пересчитываются: часть светлой темы
  сегодня стоит вплотную к порогу, один тон под ним.
- Требование к границам применяется **только к функциональным** (границы контролов, фокус,
  разделители, несущие смысл), а не к декоративным разделителям — иначе оно невыполнимо и его
  начнут обходить.

Остальное:

- Размер цели **≥ 24×24** (2.2), включая действия в строке таблицы.
- **Фокус видим и не перекрыт** (2.4.11, 2.4.13): собственное кольцо, проверка на липкой шапке
  и панелях.
- **Порядок фокуса и возврат фокуса** из наложений; ловушка фокуса в модальных.
- **Динамика объявляется**: живая область для операций и уведомлений.
- **Виртуализованная таблица** объявляет размер и позицию строк, иначе для скринридера в ней
  «десять строк из десяти» вместо тысячи.
- Цвет никогда не единственный носитель смысла.
- Три предпочтения: `prefers-reduced-motion`, `prefers-contrast`, `forced-colors`.
- Логические свойства вместо `left`/`right`.
- `lang` документа — русский (сейчас в двух точках входа объявлен английский).

## 6. Движение

Движется только то, что меняется прямо сейчас, не больше одного места на экран. Устойчивые
состояния статичны. 120 мс наведение, 180 мс раскрытие, 240 мс переход слоя. При
`prefers-reduced-motion` не теряется ни один смысл. Пульсация кнопок отправки удаляется.

## 7. Адаптивность и клавиатура

**Контейнерные запросы вместо страничных медиа** — но с оговоркой: `container-type: inline-size`
включает удержание раскладки, что конфликтует с липкими элементами внутри. Поэтому контейнером
объявляется **зона контента оболочки**, а липкие шапка и колонка живут внутри собственного
прокручиваемого предка. Кто объявляет контейнер — фиксируется в `AppShell`, ремоуты этого не решают.

**Страничные медиа остаются** для того, для чего они и нужны: указывающее устройство и
возможность наведения (`pointer`, `hover`) — телефон определяется этим, а не шириной.

**Приоритет колонок объявляет спека ресурса.** Сегодня таких данных нет вовсе, поэтому «прячем
второстепенные» нечем исполнить. Пользовательская видимость колонок имеет приоритет над
автоматической: система прячет только то, чего пользователь не трогал.

**Оболочка.** Текущая раскладка на `100vh` с запретом прокрутки тела ломается на мобильных
браузерах (панель адреса). Переход на `100dvh` и одну прокручиваемую область.

**Клавиатура — с нуля.** Во всём `shared` и `host` **нет ни одного обработчика клавиш**, поэтому
палитра команд и горячие клавиши — это новая подсистема, а не «включить существующее»:
слой регистрации команд, единый обработчик, отображение сочетаний в интерфейсе, отключение внутри
полей ввода. Пока её нет — не обещать её в интерфейсе.

**Телефон.** Список превращается в карточки; доступны чтение, разбор инцидента и узкий набор
действий. Формы создания инфраструктуры **скрываются из навигации**, а не «не открываются»:
отказ по факту перехода — это тупик, а не адаптация.

## 8. Асинхронность — запись и чтение

### Запись

- **Оптимистичное обновление запрещено** там, где результат неизвестен.
- **Владение общими сущностями.** Жила операций, уведомления и тема — **синглтоны хоста**,
  ремоуты получают их через общий скоуп. Сегодня очередь операций — «на один элемент» и живёт
  в памяти каждого ремоута, а уведомления скопированы в пять ремоутов: операция, запущенная в
  одном разделе, невидима в другом, а уход со страницы теряет её финал.
- **Журнал операций уровня приложения.** Все операции сессии с исходом и причиной, переживает
  перезагрузку. У упавшего создания сегодня **нет дома**: ресурса нет, значит и вкладки операций
  нет, а уведомление живёт четыре секунды. Журнал даёт ссылку либо на объект, либо на исходную
  форму с заполненными значениями для повтора.
- **Массовое действие** — это N операций и **одна групповая запись**: «удаление 12 подсетей:
  9 готово, 2 идёт, 1 ошибка», разворачивается построчно, упавшие остаются выделенными для
  повтора. Подтверждение группы — перечень объектов и подтверждение количества, а не набор имени
  каждого.
- **Прерывание операции** называется «Прервать операцию» и появляется только там, где вызов
  прерывания существует. Слово «Отмена» закреплено за закрытием формы и больше ни за чем.

### Чтение

- **Свежесть видима.** Единый индикатор «обновлено N назад» и ручное обновление. Сегодня опрос
  идёт каждые 3 секунды с нулевой свежестью и **без единого признака того, что он жив**.
- **Опрос приостанавливается**, пока открыто меню, форма, диалог или есть выделение строк.
  Иначе строка уезжает под курсором между наведением и нажатием — и действие применяется к соседу.
- **Остановка опроса видима.** После серии неудач состояние «обновление остановлено» показывается
  явно: во время инцидента застывший экран неотличим от живого.
- **Потеря сети** — постоянная полоса состояния, а не разовое уведомление; при восстановлении
  данные обновляются и полоса снимается.

## 9. Закрытые словари

**Состояния экрана:** загрузка · пусто · пусто по фильтру · проект не выбран · нет доступа ·
не найдено · ошибка сервера · **сессия истекла** · **сбой приложения** · **раздел не загрузился**.
Последнее — специфика федерации: любой из девяти модулей может не подгрузиться, и это не «ошибка
сервера», а частичная недоступность оболочки с сохранением остального.

**Тексты:** одно состояние — один текст. «Отмена» — только закрытие формы. Ошибки семейством
«Не удалось <действие>: <причина>». Текст отказа не сообщает о существовании объекта.

**Статусы:** таблица «статус → тон» закрыта и полна; подпись словами, не идентификатором.

**Грамматика:** спека ресурса несёт именительный, винительный и род.

**Форматы.** Дата и время, числа, размеры, длительности и адреса описываются одним набором
правил: разделители, порядок, часовой пояс (местный, с подсказкой исходного), относительное время
только для недавнего. Сегодня форматы разъехались между экранами.

## 10. Уход от antd

**Расширение.** Пакет `@kacho/ui` появляется рядом, токены генерируются и подключаются, старый
слой продолжает работать. **Доставка до девяти ремоутов решается здесь**: пакет и токены —
общий скоуп федерации с единственным экземпляром, версия одна на сборку; расхождение версий
между ремоутами роняет сборку.

**Переключение** по одному примитиву во всех ремоутах сразу: `Typography` и `Space` → `Tag`
`Alert` `Spin` → **`Form`** (самая массовая конструкция, 319 употреблений) → `Button` `Input` →
наложения → `Table` последней.

**Таблица переносится последней, но её требования проверяются раньше**: виртуализация, серверный
поиск и сортировка, курсорный догруз обкатываются на одном списке в начале переключения, иначе
самые дорогие решения проверяются в самом конце.

**Сжатие.** Удаление antd, копий компонентов из ремоутов, семи конфигов Tailwind, второго набора
иконок. Гейт: импорт antd отсутствует.

## 11. Проверки и бюджеты

**Где исполняются.** Сегодня в непрерывной сборке обязателен только контроль типов. Гейты ниже
добавляются в неё явно; гейт вне сборки не существует.

- **Дрейф токенов**: сгенерированное совпадает с источником.
- **Контраст**: все пары «текст на поверхности» обеих тем вычисляются. Ожидается, что первый
  запуск покраснеет на акценте и части тонов — это и есть цель.
- **Доступность**: проверки в настоящем движке (иначе фокус, наложения и виртуализация не видны),
  плюс отдельная проверка собранной оболочки — покомпонентная не видит того, что порождает
  федерация: дубли ориентиров, потерю фокуса при подмене раздела, конфликт живых областей.
- **Визуальные регрессии**: снимок на примитив в обеих темах.
- **Запрет обхода**: линтер запрещает произвольный цвет, `style` и импорт второго набора иконок.
- **Бюджет производительности**: вес пакета, время до готовности списка, кадр прокрутки
  виртуализованной таблицы на тысяче строк. Числа фиксируются при первом замере и не растут.

Каждый гейт **доказывается внедрением настоящего дефекта** — красный до, зелёный после.
Непроверенный гейт сам является дефектом.

## 13. Риски

| Риск | Что делаем |
|---|---|
| Контрастный гейт краснеет на бренде | Пара токенов акцента; решается до переключения, а не после |
| Клавиатурного слоя нет вовсе | Отдельная подсистема с собственным планом; до неё не обещать сочетания |
| Серверные поиск и сортировка требуют работы на стороне API | Проверяется на одном списке в начале переключения |
| Девять ремоутов переходят несинхронно | Общий скоуп с единственным экземпляром, гейт на расхождение версий |
| Система обрастает исключениями | Линтер и расширение только через новый токен |
