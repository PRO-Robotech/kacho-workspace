# RG1.2 — маршрут исполнения

> Статус: DRAFT — порядок для независимого рассмотрения; не трекер выполнения.
> Дата: 2026-09-11
> База продукта: `PRO-Robotech/kacho@d941344bd972b2e994263a9e964afa1491aff293`
> База workspace: `PRO-Robotech/kacho-workspace@364c7411b3f1a5f66a16b5388850ac3297cb4c4e`

Источники: [приёмка](../../specs/sub-phase-RG1.2-header-truth-acceptance.md), [держатели](rg1.2-holders.md), [замысел](rg1.2-design.md), [acceptance-review](rg1.2-acceptance-review.md), [initial class-exposure](rg1.2-class-exposure-initial.md). Порядок не переносит одобрение между отпечатками и не объявляет будущие действия завершёнными.

1. **Пересверить замысел до правки.** `class-exposure-analyst` связывает C1…C4 с текущим SHA-256 замысла. `design-reviewer` получает замысел, маршрут и актуальную пересверку; его одобрение регистрируется отдельным внешним событием. При правке замысла требуются новая пересверка и новый вердикт.

2. **Назначить одного исполнителя и сохранить исходное состояние.** Оркестратор выделяет ему четыре файла продукта из приёмки. Исполнитель фиксирует ревизию, статус и исходные байты, сверяет неизменность одобренной приёмки и держателей. Другие полосы работают параллельно; их изменения не сбрасываются. Оркестратор отдельно назначает владельца узких KAC-trail трёх задач и общего индекса.

3. **Получить исходные свидетельства.** Человеческий держатель заполняет таблицу достоверности и отклоняет исходные ложные утверждения по их действительным источникам. Исполнитель получает полные исходные результаты существующих команд из ведомости, включая CLI и обе пробы с настоящей БД. Ошибки предпосылок и прежние находки записываются с причиной; отсутствующий процесс не называется исходным падением проверки текста.

4. **Исполнить D1…D3 и сверить D4.** После требуемых одобрений исправляются только обычные комментарии в разрешённых частях четырёх файлов. Новые тесты, производственные функции, списки долга и исключения не пишутся. Полный дифф и сравнение защищённых байтов подтверждают границы. Если выявлена необходимость менять поведение, исполнитель возвращает предмет на уточнение приёмки и замысла до такой правки.

5. **Получить результаты после правки.** Повторяется та же смысловая сверка и существующие команды держателей. Для каждого RG1.2-ID фиксируются ревизия, отпечаток диффа, полный захват и один исход. Ноль выбранных тестов и SKIP не подтверждают сценарий. Отличия CLI сопоставляются по предмету, с объяснением изменений числа или координаты; предшествующие находки не исчезают из отчёта без разбора.

6. **Собрать общий результат.** Исполнитель передаёт дифф, таблицу сверки, результаты всех держателей и неразрешённые внешние предпосылки оркестратору. Назначенный владелец trail связывает каждую задачу с фактическими свидетельствами. Единый полный wave-reviewer рассматривает собранный дифф; применимые профильные и итоговые ревью, convergence и landing идут по change graph. Закрытие issue и публикация подтверждаются своими событиями, а не состоянием этого маршрута.

Команды и наблюдаемое поведение принадлежат ведомости и приёмке; здесь они не дублируются. Маршрут не расширяет scope RG1.2 и не заменяет проверки общего изменения текстовым успехом одной полосы.
