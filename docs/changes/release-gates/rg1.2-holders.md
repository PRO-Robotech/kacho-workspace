## Команды существующих проверяющих

Пробы мигратора, включая настоящую БД:

```sh
go test -count=1 -p 1 -json ./pkg/migratorcli
```

Набор проверки токенов и ведомости:

```sh
go test -count=1 -json ./tools/foreignclouds
go run ./tools/foreignclouds/cmd/verify-no-foreign-clouds .
```

Служебный обход compute и оставшиеся проверки формы подписки:

```sh
go test -count=1 -json ./services/compute/internal/commentlint
go test -count=1 -json ./internal/repohygiene -run '^TestSubscription(FormShape|Shape.*)$'
```

Проверка отрицательной координаты #2578:

```sh
git grep -n opendb -- pkg/migratorcli
git ls-files -- pkg/migratorcli/dialect_test.go pkg/migratorcli/notice_test.go pkg/migratorcli/noticethreshold_integration_test.go
```

Для `git grep` код `1` означает ожидаемое отсутствие совпадений после правки, код `0` — найденный текст, прочие коды — ошибку исполнения. Непустой список существующих файлов и чтение их содержимого служат контролем охвата; одно молчание поиска доказательством существующего покрытия не является. Имена тестов из приёмки сверяются с событиями `run` и завершающими событиями `pass`/`fail`/`skip` в JSON-выводе Go. Успех пакета при отсутствии выбранного имени не подтверждает сценарий.

## Смысловая сверка и применимость

Для обычных комментариев требуется таблица «утверждение → источник → держатель → условие пересмотра» до/после. Человеческий держатель отклоняет исходную несуществующую координату, неподтверждённое покрытие и обещание снятой ветви; после правки он читает полный изменённый вводный комментарий и проверяет те же предметы. Команды существования файлов и поиска строк помогают этой сверке, но не объявляются автоматическим анализатором истинности произвольного текста.

`go test` в командах выше не является новым зеркальным тестом шапки: он подтверждает сохранение существующих наблюдаемых свойств. Программы, проверки и списки данных не меняются. Неприменимость новых RPC/Buf/Newman/UI-проверок определена в приёмке; результаты полного CI общей волны здесь не подменяются.

Если CLI или тест не прошёл на исходном дереве, до правки сохраняется полный отказ, его предмет и связь с задачей общей волны. Итог после правки сравнивается с тем же предметом. Предшествовавший отказ не маскируется, новый не списывается на старый. Недоступность Docker/Postgres, незапустившийся процесс, пустой захват и отсутствие нужного теста — «не выполнилось», с указанием конкретного недостающего условия.
