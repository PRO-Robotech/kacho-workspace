# Proposed finite CLI/P9 routine addendum

Status: independent read-only proposal for root readback. No holder, source or live execution authorization. It refines invocation/artifact representation within accepted CI-RS D1–D3/D5/D8 and routine-v2; existing accepted files stay immutable.

1. A thin ordinary `internal/release/cli.go` routing function may reuse the exact existing `SupplyDependencies` type. Proposed signature: `RunSupplyCLI(ctx context.Context, args []string, deps SupplyDependencies, stdout, stderr io.Writer) int`. `tools/releasepreflight/main.go` passes only default dependencies and actual process streams/context and exits with the returned code. This is composition of the existing engines, not a new dependency member, fixture environment switch or predicate.
2. Explicit `--mode candidate|consumers|pins` routes unchanged arguments to `RunSupplyPreflight`; the existing full manifest/revision/final-main forms remain unchanged. Without --mode or the closed private P9 form, publisher arguments route unchanged to `RunSupplyPublisher`. Duplicate/unknown/mixed forms refuse; rejected invocation does not silently become another mode. The exact finite parser matrix is `parser-matrix.json`.
3. The private P9 route is one leading version positional plus exactly one `--consumers <file>` and `--revision <40hex>`, with either order of the two named pairs and no other arguments. The shell passes its already captured P5 HEAD_SHA; the adapter must not replace it with a later HEAD. Its cwd is the subject repository root. Public publish-version.sh flags remain the prior version/--skip-pack/help plus accepted --consumers; no new public --revision flag is introduced to that historical script. The adapter parses the declaration strictly, captures actual subject root/repository/module identity, and constructs only the existing consumers-mode full manifest using the supplied revision and default fixed budgets30/1800. The actual go.mod/program bytes come from that revision. It invokes the existing consumer engine, not a second import/archive algorithm.
4. New compiled CLI and new wrapper entrypoints emit one closed-schema JSON and transport exact 0/1/2/3. The historical publish-version.sh keeps its human output, P1–P8 accounting, finding-before-unasked precedence and zero-write contract; it captures the P9 JSON/rc separately and adds P9 to that accounting. Malformed/missing child JSON is unasked P9, never success. --skip-pack still leaves P8 unasked and still executes P9. Neither wrapper calls `go run` to transport semantic rc2/3. Ordinary wrapper builds are finite, use GOWORK=off/-mod=readonly, own an external temporary output directory, preserve caller cwd and relative input-path meaning, and return the actual binary exit code after cleanup. The publisher wrapper rejects preflight/private-P9 route selectors; the pins wrapper supplies --mode pins itself and rejects an additional mode/revision. Missing tool/build prerequisites must return schema NOT_EXECUTED without contaminating stdout with build logs; exact bootstrap reason/phase is a remaining root readback item below.
5. D8 distinguishes two already representable artifacts. `executable_closure` remains the complete tracked SourceFile set at F. The actual compiled CLI is an additional mandatory binary FileRef in a reviewed producer machine/regression `ProofSubject.runs.outputs`, with actual build command/cwd/runtime, source F, build streams and actual-binary test streams in the same reviewed proof subject. The FileRef is raw bytes and SHA256; it is not a claimed tracked source file. The proof flows into producer R/E and plan identity. Root verifies the same owned frozen artifact, complete F and applicability immediately before every live invocation, then directly executes that artifact. A new shell rebuild is not authorized by the earlier binary proof. Different bytes require new proof/review/authorization. All mandatory T5 producer tests still apply; an artifact hash or a self-written GREEN record alone grants nothing. No new schema field, runtime override flag, committed binary or self-referential hash is introduced. This is consistent with D8's complete source/executable provenance and its explicit per-invocation root-verifier responsibility; `producerIdentity` does not independently establish that the currently running executable equals the artifact, so root must perform the stated check rather than claiming the source check substitutes for it.
6. Historical inject fixtures may use canonical github.com module/origin identity and an owned test-only native Git transport adapter following the frozen d38 parser rules. Preserve `remote get-url`; remap only actual clone/fetch/ls-remote transport for exact known owned fixtures, capture original/actual argv and cwd, forward other arguments, and execute real Git without fabricated stdout/rc/ref state. Go remains real. This is an independent test process boundary, with no new product command/environment hook. Refuse undeclared endpoints and production refs. The existing snapshot-based no-write assertions remain executable and authoritative.

Remaining precise readback needed before an executable holder freezes: (a) approve the complete parser matrix and additive holder coordinates; (b) choose bootstrap missing-tool/build-failure JSON reason/phase, with no legacy human-output rewrite; (c) accept a closed declaration failure table—missing/unread file NOT_EXECUTED/SOURCE_UNAVAILABLE, malformed/duplicate/unknown/wrong-type declaration RED/CONSUMER_DECLARATION_INVALID, empty consumers or zero target imports RED/CONSUMER_CENSUS_EMPTY; (d) approve the narrow historical test-helper successor boundary. Pins CI manifest construction is deliberately a subsequent separate caller decision, not implicitly authorized here.
