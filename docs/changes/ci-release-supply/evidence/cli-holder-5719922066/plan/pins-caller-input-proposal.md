The two proposed source paths are scripts/release/internal-modules.json and the existing .github/workflows/ci.yaml. Use a named pins gate in the existing pull_request-to-main and push-to-main workflow, with its ordinary checkout and Go setup. Capture the actual checkout's `git rev-parse HEAD` and canonical origin. This actual SHA, not a guessed event SHA or later HEAD, is the Kacho product-tree revision. If a dedicated job explicitly selects PR head, its captured checkout must match that head; if it uses the existing merge checkout, evidence must name that actual revision. Do not conflate them.

For the second product tree the proposed choice is the exact SHA returned by one bounded fresh canonical `PRO-Robotech/kaname` main observation at the start of the CI invocation. Fetch/materialize that exact commit in an owned temporary Git repository, preserve canonical origin identity and record the observed main snapshot and resolved commit/tree. Later movement of main does not silently change this invocation. Missing/ambiguous refs, failed fetch or unavailable exact object close the caller; a module-cache directory is not a Git product tree. This scope checks the Kacho checkout and the then-observed Kaname main tree; it is not automatically the final T7 delivered-consumer proof. The final owner gate still runs a separately created manifest over actual final delivered consumer revisions, as already required by interface. If root intends CI to check a different pinned Kaname product revision, that selection must be named instead before freezing the holder.

No additional repositories are inferred from organization prefixes. Parse its raw bytes with duplicate-key and unknown-key rejection before composition. The manifest still goes through the engine's independent strict parser, owner completeness and full tracked-module census checks.

A bounded ordinary Python stdlib block in the exact named workflow step can compose the already accepted pins manifest, avoiding a new CLI builder mode or extra source helper. It receives only captured actual checkout paths/revisions and the raw reviewed mapping file; queries real `git ls-tree -r -z --full-tree <exact SHA>` for tracked go.mod paths; emits sorted exact module roots and the existing schema_version/product_trees/internal_modules/budgets object into an owned temporary regular file. Duplicate JSON keys must be rejected before json serialization. Neither a current worktree walk nor a glob limited to root go.mod is sufficient. The engine remains the policy owner and independently rejects omitted/malformed tracked module files; the block only binds existing input fields. No fallback to an empty mapping or one-product manifest is allowed.

The named step calls `scripts/release/assert-internal-pins-reachable.sh --manifest <that exact file> --final-main` and propagates its actual status under the existing bash pipefail behavior. Use finite external Git fetch/read budgets and owned cleanup; preserve existing permissions, triggers and main protections. No new permanent Kaname tool copy, historical assert-pin-reachable.sh rewrite, optional local caller or early Kacho PR is part of this path set.
