A same-plan merged object is reusable after readback; no duplicate branch push/PR/merge. Raw response failure does not erase an observed effect.
4. Release: reread accepted PR/merge provenance and target content; evaluate required checks and compatibility on the accepted receiving target, not producer HEAD or a newer current main. Fresh main may advance normally while target remains its ancestor. Tag write uses exactly one target:refs/tags/version push, never force/main/--tags. Read back peeled tag and ancestry afterwards. Keep TAG_PRESENT if later ancestry cannot be established; no dependent note/pin proof. Exact note lookup precedes one note write; its failure preserves the tag. Existing note identity is read, not rewritten.
5. Probe: no remote mutation. Resolve the same accepted target and same pre-tag floor, obtain actual public-proxy info/mod/zip, bind version/module/origin and validate archive contents, full package/non-Go payload equality and each declared consumer against that exact published ZIP. No raw-ZIP-byte equality shortcut. Only the resulting ARCHIVE_VERIFIED result opens downstream pin work.
6. Every boundary uses finite budgets: 1/2-second read retry within one deadline (max three), five-second checks polling with clipped final sleep, fixed Go/context limits. Write is never auto-retried. A lost response followed by absent/unavailable readback remains UNKNOWN; a terminal rejection plus actual absence is ABSENT. Report carries all prior confirmed effects and the last confirmed stage.
7. Freeze clean source before executing holders because their producer record binds HEAD and executable closure. Run the publisher holder for focused actual outcomes, then full internal/release regression once final source is fixed; retain every prior attempt and all actual Git/Go/HTTP records. Do not equate locally controlled GitHub/proxy evidence with live delivery.

## Compatibility applicability needing explicit root readback

D3/D4 retain the existing compatibility obligation. The existing breaking-since-release.sh evaluates owned protobuf contracts via Buf; it is not a general Go API comparator and assumes proto plus the historical Kacho release context. The current corelib receiving tree and the lawful tiny publisher fixtures contain no protobuf sources. Proposed bounded applicability: measure both exact baseline and target for owned protobuf source/config membership; if both are empty, record that measured empty domain and enforce version progression and the corelib leaf's lack of reverse PRO-Robotech requirements. This does not assert API/behavior compatibility from archive or build success. If either side contains protobuf sources, use the existing fixed Buf semantics against exact baseline/target with a supported frozen producer tool, preserving non-execution on unavailable/unsupported inputs; never return unconditional GREEN or run an arbitrary manifest command. A changed owned protobuf layout or unsupported policy must fail closed rather than being treated as empty. Root readback of this applicability requires **the full tracked protobuf census before Go ZIP omissions** on both exact baseline and target, with fixed repository/source identities and actual tool versions. A deleted last proto, absent expected directory, missing source or failed read never establishes the both-empty case. Legacy scripts and P1–P8 remain unchanged. The current script's v0 minor-on-break policy is not generalized to stable v1+: Buf zero permits only otherwise-valid version progression; Buf breaking in the same stable module major cannot be satisfied by a minor or patch bump and fails compatibility. Unsupported policy/layout/tool execution remains NOT_EXECUTED. This scope does not create a new general API compatibility system or weaken a preexisting receiving policy. Root message confirmed this boundary; final source authorization is still required.
