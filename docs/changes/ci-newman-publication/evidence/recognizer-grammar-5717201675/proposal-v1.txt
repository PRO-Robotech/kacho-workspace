## Proposed finite recognition boundary

This is an observable clarification of when text declares a supported carrier. It needs a recorded review before an independent holder and source transition. It does not grant exception lists for particular field names, scripts, filenames, or production archives.

1. **Explicit structures remain strict.** Top-level `.json` members/reports/verdicts must fully decode as strict JSON. Explicit `encoding` envelopes, Buffer arrays, structured authorization headers and typed Basic auth retain their declared-format obligations. Unknown encoding, bad base64 alphabet/padding/canonical bits, malformed Buffer, unsupported decoded bytes, duplicate decoded keys, non-finite JSON numbers, invalid UTF-8, and incomplete declared input remain refusal. Presence of protected values is still evaluated by the existing credential semantics, including null/empty distinctions.
2. **Implicit JSON must have a complete syntactic representation before ordinary text is treated as JSON.** A complete dict/list/string span found by the syntax parser is then passed to the existing strict decoder before walking: permissive span discovery never authorizes duplicate keys or non-finite values. A JSON object-key introducer (`{` + optional JSON whitespace + `"`) still positively recognizes an object; if that object cannot be completely parsed it remains MALFORMED. A bare `[`, number after `[`, or opening quote alone is insufficient to declare JSON. Consequently legal JS arrays with a trailing comma, progress fractions and quote-led text remain ordinary text when no complete JSON span is present. Continue scanning the *entire* original text and subsequent candidate spans, assignments, URL and encoded carriers; do not return early or skip an enclosing malformed/ordinary span and its contents. Nested recognizable objects/strings and secret assignments inside ordinary JS still undergo normal inspection. No JavaScript execution or new general JS parser is proposed.
3. **Typed unwrap does not invent a JSON declaration.** Once URL/base64/base64url/Buffer yields valid UTF-8, use the same complete-JSON recognition rule above to decide whether its representation is dict/list/string JSON or ordinary text. An encoded text beginning with a quote is allowed to be text. A recognized complete JSON representation must still undergo strict validation; a positively recognized malformed object remains refusal. One unwrap still costs one depth step and counts every node of the resulting typed representation; reclassification does not bypass recursive inspection or budget accounting.
4. **Basic in ordinary text requires credential shape, not the English word.** Structured authorization/proxy-authorization and typed Basic sources retain strict declared parsing. In otherwise free text, discover a possible Basic token without granting it validity; recognize a Basic credential only if decoding yields UTF-8 with the username/password separator `:`. For such recognized credential shape, require existing canonical base64 and inspect the password with the unchanged absence policy. Noncanonical encodings of credential shape still refuse. A following ordinary word which does not decode to credential shape is ordinary text and is still inspected by the other carrier rules. This does not weaken detection of Bearer, private-key, protected assignments, or explicit authorization fields.
5. **Everything else remains fixed.** The existing implicit base64 recognizer continues to reject recognized padded binary bytes as UNSUPPORTED_INPUT. The two historical binary-padding refusals are outside this correction. URL malformed-percent policy, recognition of noncanonical encoded supported structures, closed result schemas, diagnostics, safe projection, source binding and final ZIP checking remain unchanged.

The narrower implicit-JSON declaration boundary intentionally stops treating syntactically incomplete arbitrary quote/array text as a declared JSON document. That is bounded by the accepted lack of a promise for arbitrary implicit encoding, not a claim that such text is secret-free. Every original byte still passes ordinary-text inspection and opaque text still disappears from new publication.
