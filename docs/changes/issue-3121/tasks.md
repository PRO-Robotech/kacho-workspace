## 1. Правила маршрута

- **Код — по одобренной приёмке; замысел не ворота** (решение владельца 2026-10-04). Правка приёмки,
  если её потребует реализация, — новым кругом автора приёмки, а не кодом мимо неё.
- **Проба до кода** в каждой полосе кода: проба с ID сценария в имени (`NTF7-NN`, `NTF7_NN`) либо с
  номером заказа (`УК7-NN`) красная на базе полосы, вывод напечатан; затем код; та же проба зелёная —
  одним изменением (ban #12). Отрицательная проба — с близнецом §8 приёмки, отличным одним фактом.
- **Integration-группа** даёт один и тот же вердикт трижды подряд; число исполненного печатается.
- **Окна пина NTF-3** (CX3T-01; `docs/changes/issue-2918/tasks.md` §1 «Окна пина»). NTF-7 **не
  поднимает** пины corelib и kaname ни в одной волне: всё, что она читает у фундамента, есть на пинах,
  которые принесут В-2 (FM0: corelib `C1`, kaname `K0h`) и, если волна NTF-7 сядет после В-5, — P5
  (`C2`, `K2h`). Поэтому:
  - база каждой волны NTF-7 — голова `2914-notify` на момент старта; полоса стартует на пинах этой
    головы и печатает их в первом коммите (`go list -m github.com/PRO-Robotech/corelib
    github.com/PRO-Robotech/kaname`);
  - внутри окна В-2 (до вливания В-2) волн NTF-7 нет — все они после В-3 (§5);
  - внутри окна В-5 (от вливания Ф-C2/Ф-K2 до вливания В-5) волна NTF-7 **может** садиться, но её
    запрос строк пинов не меняет; нужна полосе голова фундамента после P5 — волна стартует на голове
    `2914-notify` после вливания В-5, а не поднимает пин сама (`ban20-atomic-move`);
  - **предикат окна** — у `git-operator` на каждом запросе волны NTF-7 в `2914-notify` до его открытия:
    `git diff <база запроса> <голова запроса> -- go.mod | grep -E '^[-+].*PRO-Robotech/(corelib|kaname) '`
    → пусто (0 строк). Непусто — запрос не открывается, полоса возвращается исполнителю. Скриптом
    окно пока не судится — заказ Е10 маршрута NTF-3 (`tooling-maintainer`).
- **Одна волна kacho за раз.** Волны NTF-7 встают в общий порядок `2914-notify` с волнами NTF-3 (В-4,
  В-5, В-6) и соседних маршрутов по готовности; одновременно открыт один запрос волны в ветку эпика.
- **Неделимая цепочка — одна волна.** Контракт → сервер `notify-api` → (если клиент консоли уже в
  ветке) разбор ветви клиентом садятся одним запросом волны Л-1 в порядке цепочки: гейт
  `TestEveryDescriptorFieldHasAReader` краснеет на контракте без читателя, а консоль с клиентом без
  разбора третьей ветви отвергала бы весь список подписок пользователя с селектором (замысел З11).
  Промежуточного состояния «поле есть, читателя нет» в ветке эпика нет.
- **Уровень полосы** — `scripts/lane-tier.sh` (воркспейс `origin/main`), объявленный не ниже
  вычисленного; R2 — полный набор ролей уровня (не больше трёх), R1 — один рецензент на собранную
  волну, R0 — без рецензентов.
- **Единица сдачи** — коммит исполнителя в ветке полосы; свою ветку исполнитель отправляет сам. Волна —
  единица запроса: полосы сводятся в одну ветку, проверки — на сведённом, запрос один. Сведение, запрос,
  вливание и снятие веток — `git-operator`. Посадка — только при коде 0 у `landing-precheck.sh` и
  `merge-readiness.sh`; заголовок запроса — `#3121 …`; тело — `git log <база>..<голова>`; `Closes` —
  только с комментарием `DoD-proof @<ревизия>` в задаче, иначе `Refs`. Атрибуции нет.
- **Выкатка — шаг после волны** (`deploy-engineer`, git — источник правды); сквозные пробы стенда —
  после выкатки, их вывод — комментарием `DoD-proof` к `kacho#3121`.
- **Каждая полоса кода сдаёт сверх своего предиката:** `go build ./...`, `go vet ./...`,
  `go test ./... -race` своих пакетов и `make lint` репозитория зелёные числом исполненного (TS — `tsc`,
  `jest` и `eslint` пакета); ни одного `TODO`/`SKIP`/заглушки в не-тестовом дереве (`ban11`,
  `TestNoDeferredWorkInTheTree`); самопроверку по критериям рецензентов уровня — security (поверхность,
  права, ничего не обходит аудиторию), db (инвариант механизмом базы, миграция новым файлом, `CHECK` и
  ключ — §2 З5 замысла), system-design (транзакция приёма без сетевых вызовов, идемпотентность приёма,
  стоимость события), proto-api (форма поля, комментарии, `buf breaking`), go-style (ошибки, контекст,
  журнал без ПД и без меток ресурса).
- **Размер:** S — до дня одного исполнителя, M — два-три дня, L — больше трёх.
