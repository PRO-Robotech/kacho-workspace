## Неудачная первая конструкция сохранена

Обычный go.mod дал rc0, один JSON-объект и ноль ошибок загрузки. Однократный FIFO
writer передал 46 байт корректного go.mod и закрыл свой fd, однако настоящий Go
повторно открывает go.mod: положительный и восстановленный положительный входы
остались ждать следующего writer и были отменены через 3 секунды. Этот вариант
NOT_PROVED и не объявляется RED продукта. Исходные result.json и четыре captures
сохранены без переписывания. Раннее сообщение автору root ошибочно назвало длину
44; измеренные payload, write и read равны 46, что связано hashes.

## Конструкция с отдельным EOF для каждого открытия

Писатель обслуживает повторные открытия того же FIFO в том же корне, передавая
каждому один и тот же документ, затем закрывая fd. Он не открывает следующего
писателя, пока у Go ещё открыт fd предыдущего чтения. Фикстура имеет собственный
конечный предел 16 write-сессий и внешний deadline 3 секунды; фактически нужны две
сессии. Это операционные пределы данного prerequisite, не изменение production
политики 120 секунд и не новая env-ручка gate.

На одном FIFO с неизменным inode, source и argv выполнена последовательность:

| Условие | Реальный результат |
|---|---|
| Writer предъявляет документ с EOF каждому чтению | rc0, один JSON-объект, ноль Error/DepsErrors/Incomplete; два write по 46 байт |
| Writer отсутствует | настоящий Go остаётся в блокирующем openat FIFO, wait_for_partner; через 3 секунды собственный процесс отменён SIGKILL и reaped |
| Writer восстановлен | снова rc0, один JSON-объект, ноль проблем; два write по 46 байт |

Ровно эта последовательность повторена под strace, ограниченным путём собственного
go.mod. Обе положительные трассы показывают по два успешных openat, два read по
46 байт, два read=0 (настоящий EOF), два close. Отрицательная трасса показывает
незавершённый openat до SIGKILL. Исполняется настоящий Go, а не подменный ответ
или спящий скрипт. Командный процесс и потоки захвачены; JSON разобран целиком.

Операционный parent посылает сигнал только собственной process group; в traced
контроле он завершает собственный Go tracee, затем дожидается tracer. Идентичности,
argv, executable, /proc state, момент deadline и задержка reap записаны в result.
Это доказывает пригодность OS-level входа и возможность ограниченной отмены.
Статус NOT_EXECUTED будущего command runner здесь не измерялся: протокол нового
gate ещё отсутствует, а cancellation выполнен внешним операционным parent.
Независимый holder должен отдельно доказать свёртку и применение deadline самим
согласованным runner; публичный production deadline этим запуском не покрыт.

## Состав и очистка

Всего 12 настоящих go-list процессов: 7 законных завершений и 5 ограниченных
отмен, включая два неудачных положительных входа первой конструкции. Четыре
процесса запускались под strace. Везде stdout/stderr имеют SHA256; версии Go,
strace и Python сохранены отдельными потоками. SKIP не применялся.

После завершения проверены отсутствие всех 16 известных Go/tracer PID и любых
процессов в 12 собственных process groups. Все три временных корня удалены; чужие
процессы, installation и настройки хоста не менялись. Рабочая копия e893 чиста.

Точки входа для независимого операционного воспроизведения: probe.py (сохранённый
неудачный one-write вариант), probe-repeat.py и probe-traced.py. Скопировать только
нужные scripts в новый пустой audit-каталог, затем запускать Python: каждый создаёт
собственный временный корень и удаляет его в finally. Файлы исходного capture
каталога повторным запуском не перезаписывать. Все commands уже завершены.

summary.json связывает три результата и точные EOF-счётчики. MANIFEST.json связывает
все доставленные bytes. Этот addendum передаётся root для независимого replay и
решения о design; он сам не меняет статус канонического DRAFT.
