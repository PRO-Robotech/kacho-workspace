# CI-EBT-1 — три исхода гейта исключающего признака сборки

Статус: DRAFT, только предложение для независимого review. Issue: PRO-Robotech/kacho#2672, OPEN, автор pointpu, комментариев при свежем чтении 0. Реализация и независимый holder этим документом не разрешаются.

## Предмет и граница

Сохранить предикат владельца: файл входит в обычную сборку, передача одного пользовательского тега исключает его, обычная сборка пакета проходит, а сборка под этим тегом сообщает настоящий дефект. Годный вход молчит; однофактный дефект краснеет и называет координату; пустой обход не зелёный. Внешний инструмент, который не дошёл до проверки пакета, даёт отдельное «не выполнилось» с исходной причиной.

Остаются прежними индексный корпус `.go`, разбор шапки до `package`, вычисление одиночного исключающего тега, отбор платформ самим Go, перечень инструментальных тегов и существующие четыре инъекции. Теги включающего класса #489, произвольные комбинации тегов, общий анализ всех поломок сборки и новый CI job сюда не входят. Непустой корпус без исключающих тегов законно зелёный; требовать ненулевую ведомость исключений запрещает testing-verdict.md §4.

## Наблюдаемый контракт

Публичный тест печатает перепись и один итоговый статус `CLEAN`, `FINDING` либо `NOT_EXECUTED`. Последние два приводят к ненулевому завершению Go-теста; это не предложение менять общепакетный TestMain или присваивать `go test` новый код 3. Машиночитаемая строка результата сохраняет различие причин при общей красной оболочке Go testing.

`CLEAN`: непустой Go-корпус полностью прочитан, все требуемые проверки выполнены, находок и невыполненных проверок 0. Законная пустая ведомость кандидатов даёт этот результат и честные нулевые числа сборок.

`FINDING`: предусловия выполнены, обычная сборка проверяемого пакета прошла, под тегом получена подтверждённая компиляторная диагностика; названы пакет, исключаемый файл, тег и полный диагностический текст с координатой пользователя символа.

`NOT_EXECUTED`: корпус пуст/не прочитан, не получен перечень платформ, обычная сборка неуспешна, загрузка зависимостей не завершилась, процесс не запущен/оборван либо ответ не позволяет подтвердить компиляторный исход. Обязательны стадия, пакет/тег при наличии, argv, причина и захваченный вывод. Нельзя подменять исход фразой «гейт не способен упасть», когда его предусловие не выполнено. Нельзя чинить это молчаливым снятием GOWORK, подстановкой Go или разрешением пропуска.

Если рядом есть доказанная находка и невыполненная проверка, итог `NOT_EXECUTED`: полного вердикта нет; обе записи и их отдельные счётчики сохраняются. Уже обнаруженная находка не исчезает, неполнота не становится CLEAN.

## Конечные сценарии Given–When–Then

Набор — 11 сценариев, подробные ожидаемые исходы и однофактные дельты в matrix.json. Каждый исполняет тот же публичный тест, которым судится дерево; тестовая копия алгоритма запрещена.

1. **CI-EBT-01. Законная связка.** Given реальный git-модуль, definer и caller под одним исключающим тегом; When публичный gate; Then CLEAN, 3 прочитанных Go-файла, 2 кандидата, выполненная обычная и tagged-сборки, нет находок/невыполненных.
2. **CI-EBT-02. Утраченный символ.** Given тот же вход с единственной дельтой — удалена исключающая шапка caller; When gate; Then FINDING с пакетом, файлом определения, тегом и настоящим `undefined` с координатой caller и именем символа. Прямой компилятор до gate независимо подтверждает baseline PASS/tagged FAIL.
3. **CI-EBT-03. Пустой обход.** Given git-модуль с отслеживаемым go.mod и без отслеживаемых Go-файлов; When gate; Then NOT_EXECUTED, GoFilesRead=0, ненулевой процесс, явно назван пустой корпус. Близнец — тот же индекс с одним корректным Go-файлом.
4. **CI-EBT-04. Непустой корпус без кандидатов.** Given корректный Go-файл без исключающей шапки; When gate; Then CLEAN, прочитано >0, кандидатов/сборок 0. Строка `//go:build` ниже package не создаёт кандидата. Сохраняется прежняя отдельная инъекция шапки.
5. **CI-EBT-05. Платформенная форма.** Given прежний lawful !windows input; When gate; Then CLEAN, платформа названа в переписи, нет вызова vet с искусственным -tags=windows. Существующая инъекция неизменна.
6. **CI-EBT-06. Сломан baseline.** Given законный CI-EBT-01 с единственной дельтой — выражение return содержит неизвестный символ; When gate; Then NOT_EXECUTED стадии baseline, пакет и настоящий текст компилятора сохранены, tagged-предикат этого пакета не засчитан выполненным и находок исключения нет. После восстановления выражения — CLEAN.
7. **CI-EBT-07. Чужой workspace.** Given тот же корректный вход; When меняется только GOWORK на существующий workspace, не включающий модуль; Then NOT_EXECUTED с реальным объяснением Go о workspace. Обратное GOWORK=off даёт CLEAN. Отдельно прежняя red-инъекция в этой среде называет сорванное предусловие и причину, а не утверждает потерю падучести.
8. **CI-EBT-08. Недоступная tagged-зависимость.** Given законная связка плюс Go-файл, включаемый тегом и импортирующий настоящий локальный replacement-модуль; When меняется только доступность каталога replacement; Then baseline по-прежнему проходит, итог NOT_EXECUTED tagged-load с полным объяснением загрузчика, находок исключения 0. Доступный каталог — CLEAN. Во время пары файлы/go.mod основного модуля идентичны.
9. **CI-EBT-09. Go не запускается.** Given тот же индекс и рабочий git; When из собственного PATH исчезает только доступ к go; Then NOT_EXECUTED платформенной/инструментальной предпосылки, причина запуска сохранена, сборок выполнено 0. PATH с тем же реальным Go — CLEAN. Ответы Go не подделываются.
10. **CI-EBT-10. Находка рядом с неполнотой.** Given два независимо корректных пакета; When в первом внесён CI-EBT-02, а для второго нарушена предпосылка CI-EBT-06; Then итог NOT_EXECUTED, доказанная находка первого и невыполненная проверка второго обе названы и посчитаны. Это композиционный контроль двух уже отдельно доказанных дельт, а не однофактная инъекция. Восстановление второго оставляет FINDING первого; восстановление первого даёт CLEAN.
11. **CI-EBT-11. Не прочитан отслеживаемый файл.** Given индекс с корректным отслеживаемым Go-файлом; When файл исчезает с диска при неизменном индексе; Then NOT_EXECUTED с путём и ошибкой чтения; восстановление тех же байтов — CLEAN. Без fallback на обход диска и без SKIP.

## Приёмка и состояние

До исходников независимый автор пишет holder, проверяет реальные фикстуры/прямые compiler controls, получает семантический RED на current main и фиксирует байты. Отдельный reviewer воспроизводит RED. После явного разрешения worker меняет только согласованный предмет; затем неизменные 11 сценариев, прежние 4 инъекции, публичный gate на реальном дереве и независимый GREEN. Ноль SKIP; ожидаемый отказ внутренней фикстуры — успешное утверждение внешнего holder, а не пропущенная проба.

Прежние 4 PASS и данная диагностика не закрывают #2672. Новая issue не требуется. Удалённые действия, публикация, merge, изменение policy/канонических approved-доков не выполнялись.
