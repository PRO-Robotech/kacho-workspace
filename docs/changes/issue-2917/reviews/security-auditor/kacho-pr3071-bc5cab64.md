## Находка (блокирующая)

**S1 · средняя · пороги стенда прогона уходят на цепочки, которые стендом прогона не являются.**

- Признак: слой `values.dev-prod.yaml` входит не только в цепочку `dev-prod`, но и в `a8f60d` и
  `prorobotech` (`deploy/stacks.txt`). Цепочка `a8f60d` по `deploy/stacks-mail.txt` — `relay`:
  письма уходят через внешний ретранслятор с настоящим доменом отправителя, стенд доступен снаружи.
- Предмет: ограничитель стоит на путях, которые ставят письмо на адрес из тела запроса. Рендер на
  голове: `a8f60d` и `prorobotech` получают FREE=400 / HARD=1000 (как `dev-prod`), `fe3455` — 3 / 100;
  на `2eba982e` у `a8f60d` действовали ориентиры базы (3 / 100). Анонимный клиент такого стенда
  получает на два порядка больше писем без вызова proof-of-work, чем до правки, и упирается только в
  жёсткие пороги на пределе стража; расход ложится на внешний ящик отправителя.
- Сценарий отказа: кто — анонимный внешний клиент стенда `a8f60d`; вход — серия запросов на путь
  регистрации или восстановления с одного источника; получает — пропуск без вызова на сотни
  запросов в окне, где до правки после третьего был вызов.
- Основание: приёмка NTF-2 §5 «Счётчики края на П1» относит послабление к **стенду П1** («Пороги проба
  берёт из рендера цепочки `dev`»), а не к любой цепочке, разделяющей средний слой. Проба
  `TestEdgeStandChain_AnonMailThresholdsAdmitTheSeedVolume` судит только `STAND_STACK`; обратного
  утверждения — «цепочки вне стенда прогона держат ориентиры поставки» — нет, поэтому перенос
  послабления на `relay`-цепочку зелёный.
- Направление (решает исполнитель): послабление объявляется только там, где поднимается стенд прогона,
  либо цепочки `relay` (и внешне доступные `stand`) возвращают ориентиры своим слоем; к пробе — близнец,
  падающий, когда цепочка с признаком `relay` в `stacks-mail.txt` получает FREE выше базы.
- Предикат:
  `helm template k deploy/helm/umbrella $(chain a8f60d) | grep -A1 ANON_MAIL_IP_FREE_LIMIT` → `"400"`
  (ожидается значение базы `"3"`); то же для `prorobotech`.
