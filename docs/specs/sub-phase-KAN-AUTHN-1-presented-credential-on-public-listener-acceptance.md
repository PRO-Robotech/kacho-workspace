## 0. Обзор

Служба доступа выносится самостоятельным продуктом **Kaname**, устанавливаемым в чужом облаке.
Личность на её публичном слушателе производится ровно двумя способами, и оба предполагают
**нашу** инфраструктуру рядом: клиентский сертификат проверенного пира и личность,
**переданная** разрешённым отправителем. В чужом облаке нет ни нашего края, чтобы передать, ни
модульного сертификата у человека — арендатору **нечем назваться**.

При этом служба чеканит токены сама, публикует набор ключей проверки и несёт авторитет отзыва.
Больше того: **полная проверка нашего собственного токена в дереве уже написана** — она стоит на
поверхности, которую служба **предоставляет другим**, и не стоит на пути её **собственного**
публичного вызова (§1.4). То есть предмет — не «написать проверяющего с нуля», а **поставить
читателя предъявленного на публичную цепочку** и снабдить его тем, чего у выданной наружу
проверки нет по построению: адресатом, типом токена и коротким кешем.

Эта приёмка закрепляет наблюдаемое поведение такого читателя: что он принимает, что отвергает,
чем отказы **неразличимы между собой**, почему отзыв обязан читаться **на предъявлении**, и
почему прежний путь при этом не отзывается.

## 1. Что верно в дереве сегодня

Каждое число снято названным предикатом на ревизии `caa48b770d`. Единица счёта названа у
каждого. Предикаты прогнаны **с контролем в обе стороны**: предикат, который умеет находить,
обязан это показать на заведомом примере, иначе «ноль находок» неотличимо от «ноль
прочитанного».

### 1.1 Читателя предъявленного удостоверения на публичной цепочке нет — и предикат задачи считает НЕ ТО

Задача #2077 приводит два предиката и оба дают ноль. **Оба воспроизведены, оба дали ноль.**
Единица счёта — не-тестовый файл Go, читающий метаданные `authorization`.

```sh
git grep -c '"authorization"' -- 'services/iam/**/*.go' ':!*_test.go'   # вывод пуст → 0 файлов
git grep -c '"authorization"' -- 'pkg/grpcsrv/**/*.go'  ':!*_test.go'   # вывод пуст → 0 файлов
```

**Второй предикат при этом негоден, и это надо сказать прямо.** Шаблон `pkg/grpcsrv/**/*.go`
требует промежуточного каталога, поэтому файлы, лежащие в `pkg/grpcsrv` **непосредственно**,
в предмет не попадают вовсе. Контроль:

```sh
git grep -l '"authorization"' -- 'pkg/grpcsrv/**/*.go' ':!*_test.go' | wc -l   # 0
git grep -l '"authorization"' -- 'pkg/grpcsrv/*.go'    ':!*_test.go' | wc -l   # 1
```

Единственное найденное вхождение — **перечень ключей, чьи значения не пишутся в журнал**, то
есть маркер «не логировать», а не читатель. Вывод задачи от этого не меняется, **её предикат —
меняется**: он под-читывает на один файл, и под-читанный файл читателем тоже не является.
Полоса, по которой предикат должен ходить, — каталог целиком (`-- pkg/grpcsrv`), а не шаблон
с двумя звёздами. Это тот же класс, что `testing.md` §«Твой СОБСТВЕННЫЙ разборщик — тоже
распознаватель»: форма записи, о которой выражение не знает, даёт не красное и не зелёное, а
молчание.

Тем же предикатом по **всему** дереву читателей ровно два, и оба вне Kaname:
`gateway/internal/middleware/auth.go` (край платформы) и упомянутый перечень в `pkg/grpcsrv`.

### 1.2 Звенья публичной цепочки — восемь, по порядку

Каталог композиционного корня **переехал**: задача называет `services/iam/cmd/kacho-iam/serve.go`,
в дереве это `services/iam/cmd/kaname/serve.go` (сборка `publicUnary`). Предикат:
`git grep -n 'publicUnary' -- services/iam`.

| # | звено | что производит |
|---|---|---|
| 1 | измеритель задержки | ряд длительности и кода **на весь** вызов, включая отказ по правам |
| 2 | перехват паники | паника ниже по цепочке → `Internal` на **один** запрос вместо падения процесса |
| 3 | разметка отказа | машиночитаемая причина на `PermissionDenied`; **иные коды не трогает** |
| 4 | личность из проверенного клиентского сертификата | личность модуля из SAN сертификата пира |
| 5 | личность, **переданная** разрешённым отправителем | личность конечного пользователя — **только** если (4) доказало проверенного пира из круга |
| 6 | политика вызывающего | кому вообще позволено звать этот RPC на этом слушателе |
| 7 | отсечка анонима | отказ мутации без личности; **чтение и белый список пропускаются** |
| 8 | дверь | пообъектный вопрос к модели доступа |

Звенья 4–5 — пара `PrincipalExtract*` общего транспортного пакета. **Читателя предъявленного
арендатором удостоверения среди восьми нет ни одного.**

### 1.3 Поверхность, которую это делает недосягаемой, — тринадцать публичных служб

Единица счёта — объявление `service` в контракте домена.

```sh
git grep -h '^service ' -- 'proto/kacho/cloud/iam/v1/*.proto' | wc -l              # 22
git grep -h '^service ' -- 'proto/kacho/cloud/iam/v1/*.proto' | grep -c '^service Internal'  # 9
```

**13** публичных служб против 9 внутренних. Ни одну из тринадцати арендатор чужого облака
позвать не может: назваться нечем, и отказ приходит честный и бесполезный.

### 1.4 Проверка нашего токена в дереве ЕСТЬ — но не на пути собственного запроса

Это главное уточнение к постановке задачи, и оно удешевляет работу.

| механизм | где стоит | что проверяет | достижим ли арендатором |
|---|---|---|---|
| авторитет отзыва (интроспекция) | **внутренний** слушатель, требует клиентского сертификата | подпись своим набором ключей, издателя, срок, критические заголовки, **отзыв** | нет |
| проверка на пути запроса | **край платформы**, не Kaname | оба издателя, с кешем набора ключей | нет — края в чужом облаке нет |
| проверка входящего **утверждения клиента** | полоса выдачи Kaname | подпись клиента перед выдачей ему токена | да, но это **вход в выдачу**, а не предъявление уже выданного |

Предикаты: `git grep -n 'func (h \*Handler) judge' -- services/iam/internal/handler/tokenintrospecthttp`;
`git grep -n 'func (v \*JWTVerifier) Verify' -- gateway/internal/middleware`.

Пакет авторитета отзыва объявляет в своей шапке ровно ту норму, ради которой заведена ось 4
решения (§2): контроль, действующий на выдаче и не действующий на предъявлении, отзывом не
является. **Авторитет построен; потребителя у него на публичной цепочке нет.**

**Чего у авторитета нет по построению** — и почему он не годится «как есть»: он объявляет
**отступления** от единого перечня проверок, и отступления эти суть адресат и тип токена,
названные свойствами **поверхности предъявления**, а не издателя. Публичный слушатель и есть та
поверхность. Кеша у авторитета тоже нет — на каждый вопрос идёт обращение к хранилищу.

### 1.5 Единый перечень проверок токена существует; носителей четыре, проб согласия — две

Перечень — `pkg/tokenpolicy`, одиннадцать проверок: подпись · допустимость подписи · связь
заголовка с ключом · издатель · адресат · тип токена · срок · момент начала действия ·
идентификатор ключа · критические заголовки · отзыв.

```sh
git grep -ln 'func (.*) DeclaredChecks()' -- '*.go' ':!*_test.go' | wc -l   # 4 носителя
git grep -ln 'MissingChecksExcept'        -- '*_test.go' | grep -v pkg/tokenpolicy | wc -l  # 2 пробы
```

Из четырёх носителей два принадлежат Kaname и **оба несут пробу согласия** с перечнем; два
принадлежат платформе и пробы согласия в своих пакетах **не несут**. Читатель, заводимый этой
приёмкой, — третий носитель Kaname, и он обязан нести пробу согласия по образцу двух уже
существующих. Расхождение двух платформенных носителей — **не предмет этой приёмки**, оно
названо в §11.

### 1.6 Возможность объявлена оператору и читателя не имеет

Посадка `own` уже объявляет оператору две величины, чьё назначение в её же документации названо
приёмом **на входе**: издателя, признаваемого своим, и перечень принимаемых подписей. Обе
величины судятся стражем старта. Читателя у перечня подписей в дереве **нет**:

```sh
git grep -n 'AllowedAlgorithmList' -- '*.go' ':!*_test.go'   # 3 строки, все в ОДНОМ файле
git grep -l 'AllowedAlgorithmList' -- '*.go' ':!*_test.go' | wc -l   # 1 — сам объявляющий файл
```

То есть величина объявлена, задокументирована, провалидирована при старте — и **не читается ни
одной проверкой**. Это `api-conventions.md` §«Неисполнимая возможность»: два правила об одном
поле, из-за которых объявленное не исполняется ни при каком входе. Заводимый читатель закрывает
это **по построению**: он и есть тот, кто обе величины читает.

### 1.7 Посадка `own` в дереве развёртывания не выбрана ни разу

```sh
git grep -n 'identityProvider:' -- deploy          # 1 вхождение, значение external
git grep -c 'identityProvider: own' -- deploy      # 0
```

Умолчания у ручки нет намеренно; базовый профиль чарта объявляет `external`, и **ни один**
профиль его не переопределяет. Следствие для этой приёмки: сценарии посадки `own` наблюдаются на
профиле, которого сегодня в дереве нет, и он заводится вместе с работой по §7. Это назван**о**, а
не подразумевается.

## 2. Решение о форме проверки — ПРИНЯТО, здесь оно не переоткрывается

Задача #2077 прямо говорит, что оси 2 и 3 её предиката требуют отдельного решения о **форме**.
Решение принято владельцем линии и приводится здесь как **вход** приёмки. Сценарии §4 описывают
его наблюдаемым поведением; спор о самой форме предметом этого документа не является.

| ось | решение | почему это несущее |
|---|---|---|
| **1. что читается** | предъявитель в метаданных запроса, стандартной формой | иной формы у арендатора нет — он приходит обычным клиентом |
| **2. чем проверяется подпись** | собственным реестром ключей службы | служба сама издатель ⇒ **внешней зависимости у проверки нет by construction**; для установки в чужом облаке это и есть условие исполнимости |
| **3. что ещё проверяется** | срок · момент начала действия · издатель (обязан быть собственным) · адресат | адресат и тип — свойства **поверхности предъявления**; у выданного наружу авторитета они объявлены отступлением (§1.4), и закрыть их обязан именно этот читатель |
| **4. отзыв читается НА ПРЕДЪЯВЛЕНИИ** | читателем служит полоса интроспекции, с коротким кешем; недоступность авторитета — **fail-closed** | контроль на выдаче отзывом не является: предъявленное проходило бы до истечения срока, и это состояние **не сходится само**. Окно тогда задаёт срок кеша, а не срок удостоверения |
| **5. отказы неразличимы** | все отказы аутентификации **побайтово** одинаковы | различимый отказ здесь — оракул: он сообщает предъявителю, какая половина неверна |
| **6. страж старта** | отказ в пуске, когда проверка включена, а материал не задан | величина, которую построение подставляет молча, предметом стража быть не может: он зелен при любом входе |
| **7. прежний путь не отзывается** | переданная личность от разрешённого отправителя остаётся; пустой круг по-прежнему означает «не сужаем», а не «запрещаем» | за нашим краем этот путь законен, и отзыв его сломал бы платформу ради установки, которой края не нужно |
| **8. обе формы разом — отказ** | предъявленный токен **и** переданная личность в одном запросе → fail-closed | неоднозначность о том, **кто звонит**, догадкой не разрешается |

**Что из этого НЕ является решением о реализации.** Приёмка утверждает наблюдаемое: какой исход
видит арендатор, оператор и соседняя служба. Достигается ли чтение отзыва обращением по полосе
интроспекции или тем же авторитетом внутри процесса — предмет замысла реализации, а не этого
документа; сценарии §4 верны при обоих и в обоих случаях требуют одного: **fail-closed при
недоступности авторитета** и **окно, равное сроку кеша**.

## 3. Сценарий → производитель

**Правило раздела.** Каждое «Тогда» требует текста, кода возврата, строки или значения, которое
**что-то в дереве производит**. «Производитель» здесь — **механизм**, эмитирующий наблюдаемое **на
той поверхности, которую сценарий наблюдает**, а не конкретная строка. Где производителя нет, он
назван, сценарий помечен `ждёт производителя` и **покрытым не считается**: исполнить его нельзя,
и в зачёт покрытия он не идёт.

| Семейство | Что наблюдает | Производитель сегодня | Состояние |
|---|---|---|---|
| **VER** — верификация предъявленного | арендатор чужого облака | **нет на этой поверхности.** Механизм проверки нашего токена в дереве есть (§1.4), перечень проверок есть (§1.5), харнесс публичной цепочки есть — читателя на публичной цепочке нет | **ждёт производителя** — заводится этим переходом |
| **DUP** — обе формы разом | арендатор | **нет**: чтобы отвергнуть неоднозначность, обе формы должны быть представимы, а первая не читается | **ждёт производителя** |
| **REV** — отзыв на предъявлении | арендатор + оператор | **нет на этой поверхности.** Авторитет отзыва построен и объявляет ровно эту норму (§1.4); потребителя на публичном пути нет, кеша нет | **ждёт производителя** |
| **DENY** — неразличимость отказов | арендатор | **нет**: отказов верификатора не существует. Базовый отказ по правам сегодня побайтово одинаков у трёх производителей публичной цепочки — образец есть, предмет отсутствует | **ждёт производителя** |
| **BOOT** — отказ старта | оператор | **есть**: страж настройки отвергает пуск списком, и в нём уже живёт образец формы «контроль включён, материал не задан»; таблица требований посадки `own` — тот же механизм; перечень обязательных величин **порождается** и сверяется гейтом | производитель есть, **ось заводится этим переходом** |
| **FWD** — прежний путь не отозван | соседняя служба, наш край | **есть и держится**: поведенческие замки публичной цепочки и страж размещения (§5) | производитель есть |
| **WIRE** — провязка читателя | инженер | **есть**: страж, читающий композиционный корень, и харнесс, собирающий цепочку **боевым** сборщиком | производитель есть, **новая проверка заводится этим переходом** |
| **POL** — согласие с единым перечнем | инженер | **POL-01: есть** — единый перечень и форма пробы согласия (§1.5). **POL-02: нет** — величину сегодня не читает ни одна проверка (§1.6) | смешанное, помечено по сценариям |
| **OPS** — что видит оператор чужого облака | оператор | **нет**: шаг проверки подъёма в руководстве установки предписывает проверять **через ваш край**, а в чужом облаке края нет | **ждёт производителя** |

**Сценариев всего 26. Ждут производителя — 17** (`VER` 7 · `DUP` 1 · `REV` 4 · `DENY` 2 ·
`POL-02` 1 · `OPS` 2). Все семнадцать заводят производителя **этим же переходом**: производитель
у них один — читатель предъявленного на публичной цепочке. **Производитель есть у 9**
(`BOOT` 3 · `FWD` 3 · `WIRE` 2 · `POL-01` 1).

Отдельно: **состояние держателя** (кто эти сценарии закрепит пробой) — другая ось, и она в §5.
Сегодня держатся два сценария, наполовину — один; остальные 23 не начаты, и это ожидаемо: кода по
приёмке до APPROVED не пишется.

## 4. Сценарии

Единица наблюдения — **арендатор чужого облака**, у которого нет ни нашего края, ни нашего
стенда, ни модульного сертификата. Всё, что он не может проверить у себя, наблюдаемым поведением
не является.

### VER — верификация предъявленного удостоверения

**KAN-VER-01 — годный токен собственной чеканки называет вызывающего** · E · *ждёт производителя*

**Given** установка Kaname в чужом облаке, посадка `own`: внешнего поставщика удостоверений нет вовсе
**And** арендатор получил токен у самой службы её штатной полосой выдачи
**And** токен не истёк, момент начала его действия наступил, он не отозван
**When** арендатор зовёт публичный RPC, предъявив этот токен обычной формой предъявителя
**Then** вызов доходит до обработчика
**And** вызывающий назван — это тот субъект, которому токен выдан, а не подставная системная личность
**And** дальше действуют обычные правила доступа: **право звать** этот RPC вопросом аутентификации не решается
**And** ни один шаг проверки не обращался к внешнему поставщику удостоверений — его в этой установке нет

> **Положительный контроль всего семейства.** Без него шесть отрицаний ниже зеленели бы на
> установке, которая отвергает вообще всё.

**KAN-VER-02 — истёкший токен отвергнут** · E · *ждёт производителя*

**Given** те же условия, что в KAN-VER-01
**And** тот же токен, отличающийся от годного **ровно одним фактом**: срок его действия истёк
**When** арендатор предъявляет его на том же RPC
**Then** вызов до обработчика не доходит
**And** отказ побайтово равен отказу KAN-VER-03, KAN-VER-04, KAN-VER-05, KAN-VER-06 и KAN-REV-01

**KAN-VER-03 — токен, подписанный не нашим ключом, отвергнут** · E · *ждёт производителя*

**Given** те же условия
**And** токен, отличающийся от годного ровно одним фактом: подпись поставлена ключом, которого нет в собственном реестре ключей службы
**When** арендатор предъявляет его
**Then** вызов отвергнут, и отказ побайтово равен отказам семейства
**And** решение принято **без** обращения к какому-либо внешнему авторитету: реестр ключей — собственный

**KAN-VER-04 — токен с чужим адресатом отвергнут** · E · *ждёт производителя*

**Given** те же условия
**And** токен нашей чеканки, нашим издателем, годный по сроку и подписи, но выданный **для другого адресата** — той полосы, которая публичным слушателем не является
**When** арендатор предъявляет его на публичном RPC
**Then** вызов отвергнут, и отказ побайтово равен отказам семейства

> Это тот сценарий, ради которого адресат назван осью 3 решения: у авторитета отзыва он объявлен
> **отступлением** и по построению не проверяется (§1.4). Токен, годный для одной поверхности,
> не обязан быть годен для другой.

**KAN-VER-05 — токен, чьё время ещё не наступило, отвергнут** · E · *ждёт производителя*

**Given** те же условия
**And** токен, отличающийся от годного ровно одним фактом: момент начала его действия в будущем
**When** арендатор предъявляет его
**Then** вызов отвергнут, и отказ побайтово равен отказам семейства
**And** допуск на расхождение часов применён **тот же**, что применяют остальные проверяющие продукта — второго значения этой величины не заводится

**KAN-VER-06 — подпись вне перечня принимаемых отвергнута** · E · *ждёт производителя*

**Given** те же условия
**And** установка объявила перечень принимаемых подписей (§1.6)
**And** токен, отличающийся от годного ровно одним фактом: его подпись в объявленный перечень не входит
**When** арендатор предъявляет его
**Then** вызов отвергнут, и отказ побайтово равен отказам семейства
**And** решение принято по **объявленному установкой** перечню, а не по тому, что заявлено в самом токене

**KAN-VER-07 — издатель, не являющийся собственным, отвергнут** · E · *ждёт производителя*

**Given** те же условия
**And** токен, отличающийся от годного ровно одним фактом: его издателем назван не тот, которым установка объявила себя
**When** арендатор предъявляет его
**Then** вызов отвергнут, и отказ побайтово равен отказам семейства
**And** незаданный издатель установки означает **не** «любой наш», а отказ старта (KAN-BOOT-01), поэтому состояния «принимаем издателя, которого никто не выбирал» не существует

### DUP — две формы личности в одном запросе

**KAN-DUP-01 — предъявленный токен и переданная личность разом отвергаются** · E · *ждёт производителя*

**Given** установка Kaname за нашим краем: круг разрешённых отправителей непуст, край в нём назван
**And** запрос, несущий **одновременно** годный предъявленный токен и переданную личность от разрешённого отправителя
**When** запрос приходит на публичный слушатель
**Then** вызов отвергнут
**And** отказ побайтово равен отказам семейства VER
**And** ни одна из двух личностей не выбрана — ни «предъявленная главнее», ни «переданная главнее»

> **Положительные близнецы — два, и каждый отличается ровно одним фактом.** KAN-VER-01: тот же
> запрос **без** переданной личности — принят. KAN-FWD-01: тот же запрос **без** предъявленного
> токена — принят. Без обоих утверждение «отвергается неоднозначность» зеленело бы на установке,
> отвергающей любую из форм по отдельности.

### REV — отзыв читается на предъявлении

**KAN-REV-01 — сквозь обе стороны: записали отзыв → предъявили → отказ** · E · *ждёт производителя*

**Given** арендатор, у которого есть годный токен, и этим токеном он **только что успешно** звал публичный RPC (KAN-VER-01)
**And** срок этого токена **не истёк** и до его истечения остаётся заметное время
**When** отзыв этого удостоверения записан штатным путём
**And** по истечении объявленного срока кеша арендатор предъявляет **тот же самый** токен на том же RPC
**Then** вызов отвергнут
**And** отказ побайтово равен отказам семейства VER

> **Сценарий обязан пройти СКВОЗЬ обе стороны одним прогоном.** Две пробы по половине — «отзыв
> записался» и «отвергнутое отвергается» — этого класса не ловят: каждая зелена о своей половине,
> а вопрос в том, **про один ли предмет** они говорят (`security.md` §«Разрыв, невидимый ни с
> одной стороны по отдельности»). Проба, не предъявляющая удостоверение после записи отзыва,
> сценария не закрывает.

**KAN-REV-02 — тот же токен без отзыва продолжает приниматься** · E · *ждёт производителя*

**Given** те же условия, что в KAN-REV-01, и тот же токен
**And** отличие **ровно одно**: отзыв не записан
**When** арендатор предъявляет токен после того же интервала ожидания
**Then** вызов доходит до обработчика, и вызывающий назван

> Положительный близнец KAN-REV-01. Без него утверждение «после отзыва отвергается» зеленело бы
> на читателе, отвергающем **всё** по истечении кеша.

**KAN-REV-03 — недоступный авторитет отзыва даёт отказ, а не проход** · E · *ждёт производителя*

**Given** арендатор с годным, неотозванным токеном
**And** авторитет, у которого спрашивают про отзыв, недоступен
**And** положительного вердикта по этому токену в кеше нет
**When** арендатор предъявляет токен
**Then** вызов отвергнут
**And** неполученный ответ **не** засчитан как «не отозван»
**And** отказ отличим **в журнале и в измерителях** — но не в том, что видит предъявитель

**KAN-REV-04 — окно отзыва задаёт срок кеша, а не срок удостоверения** · E · *ждёт производителя*

**Given** арендатор с годным токеном, чей срок жизни **заметно длиннее** объявленного срока кеша
**And** он только что успешно звал RPC — положительный вердикт закеширован
**When** отзыв записан
**And** арендатор предъявляет тот же токен **сразу**, не дожидаясь истечения кеша
**Then** вызов ещё может дойти до обработчика — это объявленное окно, а не дефект
**And** после истечения объявленного срока кеша тот же токен отвергается (KAN-REV-01)
**And** **отрицательный** вердикт не кешируется: восстановленный доступ не ждёт истечения записи

### DENY — отказы аутентификации неразличимы между собой

**KAN-DENY-01 — все отказы аутентификации побайтово одинаковы** · E · *ждёт производителя*

**Given** набор предъявлений, каждое негодное **своей** причиной: истёк · чужой ключ · чужой адресат · время не наступило · подпись вне перечня · чужой издатель · отозван · авторитет отзыва недоступен · обе формы разом
**When** каждое предъявляется на одном и том же RPC
**Then** ответы **побайтово равны между собой** — совпадают код возврата, текст **и** приложенные к ответу подробности
**And** равенство утверждается **сравнением байтов**, а не совпадением кодов: два отказа с одним кодом и разными подробностями различимы
**And** ни один ответ не называет, **какая** половина предъявленного неверна

> **Почему подробности названы отдельно.** На публичной цепочке стоит звено, приписывающее
> машиночитаемую причину отказам **по правам** (§1.2, звено 3). Отказ аутентификации, оформленный
> тем же кодом, получил бы такое приложение автоматически, и два отказа, равные по тексту, стали
> бы различимы по приложенному. Утверждение о равенстве обязано покрывать **весь** ответ.

**KAN-DENY-02 — годное предъявление даёт ДРУГОЙ исход** · E · *ждёт производителя*

**Given** тот же RPC и годный токен KAN-VER-01
**When** он предъявляется
**Then** исход **отличается** от общего отказа KAN-DENY-01

> Положительный близнец. Без него «все отказы одинаковы» — тождественная истина на установке,
> которая отвечает одним и тем же на **всё**.

> **Что это утверждение НЕ требует.** Отказ аутентификации не обязан быть побайтово равен отказу
> **авторизации**: это ответы на разные вопросы, и ни один из них не сообщает, существует ли
> названный субъект. Предмет требования — неразличимость **внутри** аутентификации.

### BOOT — страж старта

**KAN-BOOT-01 — проверка включена, материал не задан → служба не поднимается**

**Given** профиль установки, объявивший посадку `own` и включивший проверку предъявленного
**And** величина, без которой проверка не имеет предмета, не задана
**When** оператор поднимает службу
**Then** служба **не стартует**
**And** отказ называет **ключ настройки** и причину, по которой без него не пускаемся
**And** отказ приходит **вместе с остальными** найденными проблемами настройки, а не по одной за перезапуск
**And** значения самой величины в отказе нет — служба называет имя ручки, но никогда её содержимое

> Формулировка отказа — часть контракта оператора, и образец этой формы в страже уже живёт
> (§3, семейство BOOT). Текст отказа при отказе старта под запрет §10 **не подпадает**: без него
> стенд не поднять.

**KAN-BOOT-02 — материал задан → служба поднимается**

**Given** тот же профиль, отличающийся **ровно одним фактом**: величина задана
**When** оператор поднимает службу
**Then** служба стартует
**And** её собственное заявление о посадке называет, что проверка предъявленного включена

> Положительный близнец KAN-BOOT-01: без него «отказывает в старте» зеленело бы на страже,
> отвергающем любой профиль.

**KAN-BOOT-03 — перечень обязательных величин порождается и содержит новые ручки**

**Given** руководство установки, чей перечень обязательных величин **порождён** из таблицы стража, а не выписан
**When** к стражу добавлены величины проверки предъявленного
**Then** порождённый перечень содержит их строки
**And** сверка порождённого с таблицей стража сходится, и расхождение роняет прогон

### FWD — прежний путь не отзывается

**KAN-FWD-01 — переданная личность от разрешённого отправителя по-прежнему принимается**

**Given** установка Kaname за нашим краем, круг разрешённых отправителей непуст
**And** проверенный пир, названный в круге, передаёт личность конечного пользователя
**And** предъявленного токена в запросе **нет**
**When** запрос приходит на публичный слушатель
**Then** вызывающим назван **конечный пользователь**, а не системная личность

> Положительный близнец KAN-DUP-01, отличающийся ровно одним фактом (нет предъявленного токена).

**KAN-FWD-02 — переданная личность от непроверенного пира по-прежнему отбрасывается**

**Given** та же установка
**And** пир, чей сертификат не проверен либо в круге не назван, передаёт личность конечного пользователя
**When** запрос приходит на публичный слушатель
**Then** переданная личность **отброшена**, и вызывающий остаётся системной личностью
**And** введение читателя предъявленного этого не изменило

**KAN-FWD-03 — семантика пустого круга не изменилась**

**Given** установка, чей круг разрешённых отправителей пуст
**When** служба поднимается и принимает запрос с переданной личностью от проверенного пира
**Then** поведение **то же, что до введения читателя предъявленного**: пустой круг означает «не сужаем», а не «запрещаем»
**And** отдельный страж старта, требующий явно объявить круг либо явно от сужения отказаться, продолжает действовать без изменений

> **Что этот сценарий охраняет.** Соблазн «раз появился предъявитель, переданную личность можно
> и запретить» ломает платформу ради установки, которой края не нужно. Ось 7 решения (§2) это
> запрещает, и здесь она превращается в замок.

### WIRE — провязка читателя

**KAN-WIRE-01 — читатель стоит в публичной цепочке, и это утверждает дерево**

**Given** композиционный корень, собирающий цепочку публичного слушателя
**When** прогоняется страж размещения, читающий этот корень
**Then** страж требует присутствия читателя предъявленного в публичной цепочке
**And** снятие читателя из цепочки роняет прогон **с именем виновника**
**And** страж печатает объём осмотренного и падает на пустом обходе

**KAN-WIRE-02 — харнесс цепочки видит именно ту цепочку, что собирает боевой корень**

**Given** харнесс, которым проверяются поведенческие сценарии VER, DUP и REV
**When** читатель предъявленного добавлен в публичную цепочку
**Then** харнесс собирает цепочку **боевым** сборщиком и потому видит читателя
**And** публичная и внутренняя цепочки в харнессе перестают быть тождественными, если читатель стоит только на публичной

> **Ловушка, ради которой сценарий заведён.** Сегодня харнессы обеих цепочек собираются одним и
> тем же вызовом и потому **тождественны по телу**. Читатель, добавленный в публичную цепочку
> мимо общего сборщика, окажется вне харнесса — и все пробы VER, DUP и REV станут **вакуумными**,
> оставаясь зелёными. Это `testing.md` §«Гейт на класс», п. 6: тест, чей заголовок шире тела.

### POL — согласие с единым перечнем проверок

**KAN-POL-01 — состав проверок читателя сходится с единым перечнем**

**Given** единый перечень проверок токена (§1.5) и два уже существующих носителя Kaname, каждый со своей пробой согласия
**When** заводится третий носитель — читатель предъявленного
**Then** он объявляет свой состав проверок, и проба сверяет его с перечнем **в обе стороны**
**And** проверка, которую он не исполняет, обязана быть объявлена **отступлением с причиной** — иначе отступление неотличимо от пропуска
**And** перечень объявленных отступлений **непуст либо пуст осознанно**: адресат и тип токена, объявленные отступлением у авторитета отзыва, здесь исполняются

**KAN-POL-02 — объявленная оператору величина обрела читателя** · *ждёт производителя*

**Given** посадка `own`, объявившая перечень принимаемых подписей (§1.6)
**When** арендатор предъявляет токен, чья подпись в перечень не входит
**Then** он отвергнут **по этому перечню** (KAN-VER-06)
**And** величина, до сих пор не читавшаяся ни одной проверкой, имеет читателя в не-тестовом дереве

> Это закрытие `api-conventions.md` §«Неисполнимая возможность» на конкретном поле: исход
> «реализовать» из трёх законных выбран, потому что читатель заводится этим же переходом.

### OPS — что видит оператор и арендатор чужого облака

**KAN-OPS-01 — проверка подъёма исполнима без нашего края** · *ждёт производителя*

**Given** оператор чужого облака, поднявший Kaname по руководству установки
**And** ни нашего края, ни нашего стенда у него нет
**When** он выполняет шаг руководства «служба отвечает по своему публичному слушателю»
**Then** шаг исполним **средствами, которые у него есть**: он получает токен у самой службы и зовёт им публичный вызов
**And** руководство не предписывает ему проверять через край, которого в его установке не существует

> **Что здесь наблюдается.** Сегодня этот шаг руководства адресован установке, у которой край
> есть. Для посадки `own` он **не исполним** — и это первое, обо что арендатор чужого облака
> спотыкается. Предикат готовности выноса — «отдельный клон поднимается в боевой посадке» —
> этим шагом и проверяется.

**KAN-OPS-02 — отказ не рассказывает предъявителю, чем токен негоден** · *ждёт производителя*

**Given** любое из негодных предъявлений KAN-DENY-01
**When** оно отвергнуто
**Then** **наружу** уходит суждение, и только оно
**And** подробность — какая именно проверка не сошлась — доступна оператору **в журнале и измерителях** его установки
**And** различение исходов в измерителях считает **и выданные, и отвергнутые**: ноль в одном ряду иначе отвечает сразу на два вопроса — «отказов не было» и «сюда никто не приходил»

## 7. Объём работы, который APPROVED санкционирует

1. **Читатель предъявленного** на публичной цепочке: разбор предъявителя, проверка подписи
   собственным реестром ключей, срока, момента начала действия, издателя, адресата, типа,
   допустимости подписи и связи заголовка с ключом; чтение отзыва **на пути запроса** с коротким
   кешем положительного вердикта; fail-closed при недоступности авторитета.
2. **Отказ единой формы** — побайтово одинаковый для всех причин, включая приложенные к ответу
   подробности.
3. **Отказ обеих форм разом** — предъявленный токен вместе с переданной личностью.
4. **Ось стража старта**: проверка включена, материал не задан → отказ в пуске списком, с именем
   ключа; новые строки в порождаемом перечне обязательных величин.
5. **Профиль посадки `own`**, объявляющий это поле, — сегодня посадка `own` в дереве
   развёртывания не выбрана ни разу (§1.7).
6. **Провязка и её стражи**: присутствие читателя в публичной цепочке; харнесс, собирающий цепочку
   боевым сборщиком; проба согласия с единым перечнем проверок.
7. **Шаг руководства установки**, исполнимый без нашего края.
8. **Измерители**: выданные и отвергнутые считаются раздельно.

### Чего в объём НЕ входит

- **Свой мультиплексор REST** (#1109) — он этой приёмкой **разблокируется**, а не выполняется.
- **Отзыв или изменение прежнего пути** переданной личности — ось 7 решения запрещает прямо.
- **Пообъектная авторизация** — другой предмет, закрыт своей задачей.
- **Расписание ротации ключей подписи**: механизм в дереве есть, живого расписания нет. Это
  **отдельный предмет**, названный в §11, а не отсрочка внутри этого.
- **Проба согласия у двух платформенных носителей перечня проверок** (§1.5) — предмет чужой
  линии, чинится своей задачей (§11).
- **Пересмотр формы проверки** — решение §2 принято; переоткрытие требует своего решения владельца.

## 10. Публичность

Оба репозитория публичны. Предмет этого документа — **отсутствующая возможность**, и это делает
его безопаснее обычного: дефект даёт **лишний отказ**, а не лишнее разрешение, и раскрываемого
состояния у него нет.

Что здесь **написано**: предмет, принятое решение, следствие для контракта, требования к
поведению читателя, координаты уже существующих механизмов, которые он переиспользует.

Чего здесь **нет** и не будет: сборки «точная координата + условие, при котором защита не
действовала + следствие для постороннего»; описания того, какой именно вход сегодня проходит
какую именно поверхность; порядка действий, которым этим можно воспользоваться. Требования
сформулированы как требования — «отказы обязаны быть неразличимы», — а не как описание того,
что сегодня различимо.

**Три места из-под запрета выведены** и выхолащивать их не следует: текст отказа оператору при
отказе старта (KAN-BOOT-01) — без него стенд не поднять; имя и текст падения пробы — это
описание защищаемого свойства; комментарий у стража — без него страж снимут как непонятный.
