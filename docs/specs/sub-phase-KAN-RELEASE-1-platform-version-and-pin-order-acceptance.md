## Обзор

Служба управления доступом вынесена из монорепо самостоятельным продуктом **Kaname**.
Её модуль `github.com/PRO-Robotech/kaname` требует платформу
`github.com/PRO-Robotech/kacho` **версией**, а платформа версий не публикует. Отсюда
объявленный круг: линию нельзя влить без версии, версию нельзя выпустить до снятия
взаимности, взаимность снята только линией.

Приёмка отвечает на один вопрос — **какой порядок шагов исполним**, — и делает это,
опираясь на производителей, которые в дереве уже есть. Круг 2 нашёл, что исполнимость
упирается не в круг из трёх утверждений, а в одно требование к ревизии выпуска (§1.5):
она обязана нести пакет, который импортирует служба, — иначе выпущенная версия негодна
тому единственному потребителю, ради которого выпускается, и это необратимо. Она не заводит политики версий
с нуля: политика записана `docs/architecture/release-and-versioning.md` на линии, и
приёмка её **цитирует, а не переписывает**. Предмет приёмки — порядок, окно
несобираемости, судьба локальных ссылок и компенсация нарушенного порядка.

## 1. Перемер посылки: круг подтвердился НЕ ЦЕЛИКОМ

Каждое из трёх утверждений проверено своей командой на ревизиях, названных в шапке.
Числа перемеряются, а не запоминаются.

### 1.1. Утверждение «вливать линию нельзя без опубликованной версии» — **верно как решение, неверно как механика**

```sh
git show origin/release/kaname:services/iam/go.mod | grep 'PRO-Robotech/kacho '
#   github.com/PRO-Robotech/kacho v0.0.0-20260906212857-03c890c2da3c
git merge-base --is-ancestor 03c890c2da3c origin/main ; echo $?      # 1 — НЕ достижим
```

Пин линии достижим **ровно с одной** ссылки origin — самой `release/kaname`. Это
подтверждает посылку буквально. Но её **следствие** — «опубликованная служба перестанет
разрешать свою зависимость» — замером **опровергнуто**:

```sh
curl -sS -o /dev/null -w '%{http_code}\n' \
  'https://proxy.golang.org/github.com/!p!r!o-!robotech/kacho/@v/v0.0.0-20260906212857-03c890c2da3c.info'   # 200
curl -sS -o /dev/null -w '%{http_code}\n' \
  'https://proxy.golang.org/github.com/!p!r!o-!robotech/kacho/@v/v0.0.0-20260906212857-03c890c2da3c.mod'    # 200
```

Обе псевдоверсии **уже в кэше модуль-прокси** и раздаются им. Это тот же самый факт
необратимости, из-за которого нельзя переиздать опубликованную версию: прокси хранит
розданное. Значит потребитель, идущий умолчанием (`GOPROXY=https://proxy.golang.org`),
после схлопывания продолжит собираться.

**Круг 2 усилил это замером: в кэше лежит не объявление, а само дерево.**

```sh
curl -sSL -o z.zip -w '%{http_code} %{size_download}\n' \
  'https://proxy.golang.org/github.com/!p!r!o-!robotech/kacho/@v/v0.0.0-20260906212857-03c890c2da3c.zip'
#   200  31067146
unzip -l z.zip | tail -2      #   142867849 байт, 7031 file
```

Числа зависят от версии и от момента: круг 2 рецензии на своей ревизии получил 42 МБ и
9045 записей. Единица счёта одна — записи архива, — а величина дрейфует вместе с деревом;
довод от неё не зависит.

**И `GOPROXY=direct` сегодня отвечает кодом 0** — но ровно потому, что коммит ещё достижим
с живой ссылки:

```sh
GOPROXY=direct GOPRIVATE='github.com/PRO-Robotech/*' \
  go get github.com/PRO-Robotech/kacho@v0.0.0-20260906212857-03c890c2da3c ; echo $?   # 0
```

Это и есть точная граница утверждения: сегодня работают **оба** пути, прямой и через
прокси; после схлопывания без архивной ссылки останется **только** второй.

**Что при этом действительно теряется — и почему решение остаётся верным:**

| ось | после схлопывания без публикации |
|---|---|
| сборка через прокси | **работает** — версия в кэше |
| сборка `GOPROXY=direct` / первичное наполнение у нового потребителя | **отказывает**: коммита нет ни на одной ссылке |
| ответ на вопрос «какой код внутри версии» | существует **только в кэше третьей стороны** |
| воспроизводимость выпуска из VCS | **утрачена** |

Поэтому утверждение принимается как **решение** («не полагаться на кэш чужого прокси»),
а не как механическое препятствие. Разница существенна для порядка: она означает, что
у нарушенного порядка **есть компенсация** (§7), а не только последствия.

### 1.2. Утверждение «публиковать нельзя, пока в стволе взаимность» — **не подтвердилось**

Взаимность **как кросс-модульная** отсутствует **by construction**: контракты службы
лежат в модуле платформы.

```sh
# на линии контракты службы переименованы, но остались в модуле платформы
git ls-tree -r origin/release/kaname --name-only -- proto/kaname   | wc -l   # 40
git ls-tree -r origin/release/kaname --name-only -- pkg/api/kaname | wc -l   # 83
# корневой модуль службу НЕ требует
git show origin/release/kaname:go.mod | grep -c kaname                        # 0
# ни одного replace ни в одном из двух объявлений
git show origin/release/kaname:go.mod              | grep -cE '^\s*replace'   # 0
git show origin/release/kaname:services/iam/go.mod | grep -cE '^\s*replace'   # 0
```

Предикат задачи #1766 — `git grep -l "pkg/api/kacho/cloud/iam/v1" origin/main -- "pkg/*"
":!pkg/api/*"` → 0 — на линии **выполнен переименованием пути**, а не снятием
зависимости: тот же счёт по новому пути даёт **9** файлов (**6** прод-кода).

```sh
git grep -l "pkg/api/kaname/cloud/iam/v1" origin/release/kaname -- "pkg/*" ":!pkg/api/*" | wc -l              # 9
git grep -l "pkg/api/kaname/cloud/iam/v1" origin/release/kaname -- "pkg/*" ":!pkg/api/*" ":!*_test.go" | wc -l # 6
```

Это **не находка**: зависимость внутримодульная, взаимного требования версий она не
создаёт. Находка в другом — **предикат задачи #1766 измеряет имя пути, а не предмет**, и
после переименования он зелен при живой зависимости. Заведено задачей-преемником (§8).

**Что действительно блокирует выпуск — измерено прогоном производителя**, а не прочтением
задачи. Ниже — захваченный вывод `scripts/release/publish-version.sh` на вершине ствола
(`2171a6690a81`, рабочая копия заведена и снята, общая копия не тронута):

```

  ✓ П1  форма версии годна
  ✓ П2  мажор 0 согласован с путём модуля 'github.com/PRO-Robotech/kacho'
  ✓ П7  replace в go.mod нет (осмотрено строк go.mod: 147)
  ✓ П3  версия v0.1.0 на origin не занята
  ✓ П4  опубликованных версий на origin ноль — v0.1.0 становится точкой отсчёта совместимости
  ✓ П5  HEAD равен вершине origin/main (2171a6690a81)
  ✗ П6  локальных v*-тегов вне ствола 8 из 8: v0.1.0 v0.2.0 v0.3.0 v0.4.0 v0.5.0 v0.6.0 v0.7.0 v1.0.0 — побочный 'git push --tags' опубликует код вне ствола необратимо (#1762)
```

**Единственная нарушенная предпосылка — П6, восемь локальных ссылок (#1762).** Про
взаимность производитель не спрашивает вовсе, и это верно: она внутримодульная.

### 1.3. Утверждение «взаимность снята только на линии» — **предмета не имеет**

Следует из §1.2: снимать нечего. На линии выполнено **переименование** пути стабов
(`pkg/api/kacho/cloud/iam` → `pkg/api/kaname/cloud/iam`), и оно принадлежит идентичности
продукта, а не порядку выпуска.

**Факт Б. Пинов ТРИ, они расходятся, и ни один не достижим со ствола.**

| где | версия | достижим со ствола |
|---|---|:--:|
| `origin/main:services/iam/go.mod` | `v0.0.0-20260904231955-a30d906b8edf` | **нет** |
| `origin/release/kaname:services/iam/go.mod` | `v0.0.0-20260906212857-03c890c2da3c` | **нет** |
| `PRO-Robotech/kaname` (опубликован, публичный) `go.mod` | `v0.0.0-20260906100534-dbc084b73d32` | **нет** |

```sh
gh api repos/PRO-Robotech/kaname --jq .visibility                              # public
gh api repos/PRO-Robotech/kaname/contents/go.mod --jq .content | base64 -d | grep 'kacho '
for s in a30d906b8edf 03c890c2da3c dbc084b73d32; do
  git merge-base --is-ancestor $s origin/main; echo "$s → $?"                  # 1 1 1
done
```

Пин ствола резолвится **только потому, что живы шестнадцать веток полос линии**:

```sh
git ls-remote --heads origin | while read sha ref; do
  git merge-base --is-ancestor a30d906b8edf "$sha" 2>/dev/null && echo "$ref"
done | wc -l                                                                    # 16 на 2026-09-07T20:15+03:00
```

**Это число ДРЕЙФУЕТ, и вердикт по нему устаревает за минуты.** Круг 2 рецензии на своей
ревизии насчитал **17** голов и среди них `issue-2117`, которой в момент перемера
(20:15) на origin **уже нет**. Оба замера верны каждый в свой момент; неверно было бы
строить на любом из них утверждение вида «все они `lane/*`». Поэтому здесь стоит не
перечень имён, а **свойство**: все головы, удерживающие этот коммит, — **временные**
ссылки полос, и ни одна не переживёт штатной уборки веток.

**Ни один тег его не удерживает** — проверено отдельно, потому что предикат по головам
о тегах не спрашивает вовсе:

```sh
git ls-remote --tags origin | grep -v '\^{}' | while read sha ref; do
  git merge-base --is-ancestor a30d906b8edf "$sha" 2>/dev/null && echo "$ref"
done | wc -l                                                                    # 0 из 13 тегов
```

Ветка `integration/standalone-iam`, с которой этот коммит был снят, **на origin уже
отсутствует**. То есть окно несобираемости уже приоткрыто: ствол собирается за счёт
временных чужих ссылок, а не за счёт себя. Предмет заведён задачей продукта
[#2243](https://github.com/PRO-Robotech/kacho/issues/2243) (P0) — она запрещает чистить
ветки продукта до перевода пинов.

**Факт В. Сегодня со ствола зависимость службы резолвится — код 0.**

```sh
go mod download -C services/iam ; echo $?                                       # 0
go list -C services/iam -m github.com/PRO-Robotech/kacho
#   github.com/PRO-Robotech/kacho v0.0.0-20260904231955-a30d906b8edf
```

Значит окно несобираемости **сегодня закрыто**, и задача порядка — не открыть его.

### 1.5. НЕСУЩЕЕ: ревизия выпуска обязана нести пакет, который импортирует служба

Круг 1 этого не спрашивал, и из-за пропуска предлагал неисполнимый шаг. Круг 2 спрашивает
первым делом, потому что от ответа зависит **весь** порядок.

**Замер.** Сегодняшняя вершина ствола пакета, который импортирует служба, **не содержит**:

```sh
git ls-tree -r origin/main --name-only -- pkg/api/kaname            | wc -l   # 0
git ls-tree -r origin/main --name-only -- proto/kaname              | wc -l   # 0
git ls-tree -r origin/main --name-only -- pkg/api/kacho/cloud/iam   | wc -l   # 83
```

Линия импортирует **новый** путь широко:

```sh
git grep -c 'pkg/api/kaname/cloud/iam' origin/release/kaname -- '*.go' \
  | awk -F: '{s+=$NF} END{print s}'                                           # 411 вхождений
git grep -l 'pkg/api/kaname/cloud/iam' origin/release/kaname -- '*.go' | wc -l #  393 файла
```

**Решающий опыт — самим Go, с контролем в обе стороны.** Испытуемое: содержит ли версия,
выпущенная с сегодняшней головы ствола, пакет, который импортирует служба.

```
# ветка испытуемого — голова ствола 2171a6690a81
go get github.com/PRO-Robotech/kacho/pkg/api/kaname/cloud/iam/v1@v0.0.0-20260905141452-2171a6690a81
  go: module …@v0.0.0-20260905141452-2171a6690a81 found, but does not contain package
      github.com/PRO-Robotech/kacho/pkg/api/kaname/cloud/iam/v1
  КОД=1

# контроль — та же команда на версии линии
go get github.com/PRO-Robotech/kacho/pkg/api/kaname/cloud/iam/v1@v0.0.0-20260906212857-03c890c2da3c
  КОД=0
```

Три независимых способа — перепись дерева, перепись импортов, вызов инструмента — дают
одно: **версия, выпущенная с сегодняшней головы ствола, негодна службе by construction**.

**Это ТОТ ЖЕ довод, которым §5.3 отвергает «вливание с прежним пином».** Круг 1 применил
его к чужому пути и не применил к своему: `v0.1.0` в его порядке указывала ровно на ту
голову. Следствие, которое круг 1 назвал отсутствующим: `go build -C services/iam ./...`
отказал бы после перевода пина и **не починился бы вливанием линии**, потому что служба
берёт платформу **версией из кэша**, а не файлами соседнего каталога. То есть окно
несобираемости не «отсутствует», а **не закрывается никогда**.

**Отсюда несущее требование, связывающее любой порядок:**

> Ревизия, на которую ставится версия платформы, обязана нести `pkg/api/kaname` и
> `proto/kaname`. Иначе точка отсчёта совместимости задаётся версией, которую служба
> не может импортировать, — и это необратимо.

Способов доставить их в ствол ровно два, и оба рассмотрены: выделенной полосой (§3,
шаг 1а) либо вливанием всей линии (§5.8). **Различие только в способе доставки**, само
требование от выбора не зависит.

**Объём работы шага 1а — назван числом, а не «переименовать».** На стволе прежний путь
называют **409** файлов `.go`, из них **165 вне `services/iam`** — это и есть предмет
полосы; остальные 244 уезжают с линией. Линия готовое переименование уже несёт: тот же
счёт по новому пути даёт **145** файлов вне `services/iam`. Расхождение 165 против 145 —
не потеря: единица счёта одна (файл `.go`, называющий путь), а множества разные, потому
что линия за это время и добавляла, и снимала файлы. Полоса выделяется **из линии**, а не
пишется заново, поэтому её содержимое совпадёт с уже испытанным и вливание линии не даст
конфликта по этим файлам.

## 2. Политика версий — ЦИТИРУЕТСЯ, а не переизобретается

Политика записана `docs/architecture/release-and-versioning.md` (300 строк, линия
`release/kaname`). Приёмка её **не переписывает**: два места об одном предмете разошлись
бы молча. Здесь — только те её положения, которые связывают порядок, и по каждому назван
раздел-владелец.

| положение | владелец |
|---|---|
| версионируется **весь модуль** одной ссылкой `vX.Y.Z` в корне; отдельная нумерация контрактов отвергнута | §1 |
| фундамент переезжает **вложенным модулем того же репозитория** (`…/kacho/pkg`), поэтому ни один импорт не меняется | §1.1 |
| ссылку ставит **процесс конвейера по вызову человека**, а не человек руками | §2 |
| выбран **`v0.x`**: патч — совместимо, **минор — разрыв**; предикат перехода на `v1` — три выпуска подряд с пустым перечнем объявленных разрывов | §3 |
| ссылка обещает **четыре предпосылки**, ни одна не факультативна | §4 |
| точка отсчёта `buf breaking` — **та же ссылка версии**; «точки отсчёта нет» — третий исход, не зелёное | §5 |
| бампают **снизу вверх**, каждый шаг зелен до следующего | §6 |
| механизм версионирует **корневой модуль** и границы этого объявляет | §8 |

**Приёмка добавляет к политике ровно одно, чего в ней нет: порядок ПЕРЕНОСА самой
политики и её производителей в ствол.** Политика лежит там же, где заперта, — на линии,
которую нельзя влить. Пока она там, у неё нет ни одного читателя со ствола.

## 3. Предлагаемый порядок — восемь шагов, каждый с наблюдаемым следствием

**Правило порядка: всё, что принадлежит платформе, уходит в ствол ОТДЕЛЬНОЙ полосой
и до публикации. Линия вливается последней и уже с пином на выпущенную версию.**

Круг 1 применял это правило только к оснастке выпуска. Круг 2 применяет его и к **стабам
с контрактами** — они принадлежат платформе ровно так же, и без них выпущенная версия
негодна службе (§1.5).

| # | шаг | наблюдаемое следствие | предикат перехода к следующему |
|---|---|---|---|
| **0** | снять восемь локальных `v*` (#1762, исход 1) | П6 перестаёт быть находкой | `git tag -l 'v*' \| wc -l` → 0; в выводе `publish-version.sh v0.1.0 --skip-pack` строка `✓ П6 … осмотрено локальных тегов: 0`. **Код возврата при этом 3, а не 0** — П8 не спрошена, см. врезку ниже |
| **1а** | перенести **стабы и контракты** службы из линии в ствол отдельным PR: `pkg/api/kaname` (83 файла), `proto/kaname` (40), правка 165 файлов `.go` вне `services/iam` | голова ствола содержит пакет, который импортирует служба | `go get …/pkg/api/kaname/cloud/iam/v1@<псевдоверсия вершины ствола>` → **0** (сегодня → 1, §1.5) |
| **1б** | перенести **производителей выпуска** из линии в ствол отдельным PR (список — §1.4 факт А, строки «нет/есть») | ствол несёт `release.yml`, `publish-tag.sh`, `assert-trunk-green.sh`, `breaking-since-release.sh`, цели `release-*`, документ политики | `git ls-tree origin/main -- .github/workflows/release.yml` непусто; `go test ./internal/repohygiene/ -run '^TestVersionPublishingHasACallerInThePipeline$' -count=1 -v` печатает `--- PASS: TestVersionPublishingHasACallerInThePipeline` |
| **2** | холостой прогон производителя на вершине ствола | все предпосылки сошлись, **ничего не создано** | `gh workflow run release.yml -f version=v0.1.0 -f confirm=v0.1.0 -f publish=false` → прогон 0 |
| **3** | **публикация `v0.1.0`** — единственный необратимый шаг | ссылка `refs/tags/v0.1.0` на origin; `@latest` = `v0.1.0` | `scripts/release/probe-published.sh v0.1.0` → 0 **и** `go get …/pkg/api/kaname/cloud/iam/v1@v0.1.0` → 0 |
| **4** | перевести пин линии на `v0.1.0` | `services/iam/go.mod` линии не несёт псевдоверсии | `grep 'PRO-Robotech/kacho ' services/iam/go.mod` → `v0.1.0`; `go build -C services/iam ./...` в линии → 0 |
| **5** | влить линию в ствол | ствол зелен; служба резолвит **выпущенную версию** | `go list -C services/iam -m github.com/PRO-Robotech/kacho` → `v0.1.0`; `go build -C services/iam ./...` → 0 |
| **6** | перевести пин репозитория `PRO-Robotech/kaname` на `v0.1.0` | опубликованная служба не ссылается на псевдоверсию | тот же предикат в дереве `kaname`; его прогон зелен |

**Шаги 0–2 обратимы, шаг 3 необратим, шаги 4–6 обратимы.** Отсюда практическое
следствие: неверный номер ловится **до** шага 3 или не ловится вовсе.

> [!important] «П6 сошлась» — не то же самое, что «выпуск открыт», и код возврата это говорит
> После снятия восьми ссылок вызов `publish-version.sh v0.1.0 --skip-pack` даёт код **3**,
> а не 0: П8 (упаковка) уходит в «не спрошено», а не спрошенная предпосылка **не считается
> выполненной** и в вердикт не вычитается. Открытым выпуск объявляет только код 0, то есть
> вызов **без** `--skip-pack`. Читать надо `$?`, а не наличие галочки у П6.

### 3.1. Окно несобираемости — при предложенном порядке его НЕТ; при нарушенном оно НЕ ЗАКРЫВАЕТСЯ САМО

Круг 1 отвечал на этот вопрос неверно, потому что не спрашивал §1.5. Исправленный ответ:

| после шага | чем ствол резолвит платформу | собирается |
|---|---|:--:|
| 0 | прежний пин `a30d906b8edf` (жив временными ссылками полос **и** кэшем прокси) | да |
| **1а** | тот же прежний пин; стабы добавляются, ничего не снимается | да |
| **1б**, 2 | тот же прежний пин | да |
| 3 | тот же прежний пин; публикация ствол не трогает | да |
| 4 | ствол не менялся (пин переведён **в линии**), и в линии сборка проверена предикатом шага | да |
| 5 | **`v0.1.0`** — ссылка на ревизию, **несущую** `pkg/api/kaname` | да |
| 6 | ствол не менялся | да |

**Два вида нарушения, и они дают РАЗНОЕ окно:**

| нарушение | длительность окна | чем закрывается |
|---|---|---|
| линия влита до шага 3 | от вливания до публикации | само не закрывается: сборка держится кэшем прокси. Компенсация — архивная ссылка (§7) |
| версия выпущена до шага **1а** | **не закрывается никогда** | версия негодна службе by construction; лечится только выпуском следующей версии с ревизии, несущей стабы |

Второй вид — тот, который предлагал круг 1. Он хуже первого: первый чинится ссылкой,
второй — только новой версией, потому что выпущенную отозвать нельзя.

### 3.2. Почему шаги 1а и 1б — отдельные полосы, а не часть вливания линии

Три довода, каждый самостоятельный:

1. **предмет.** И стабы с контрактами, и производители выпуска версионируют **платформу**.
   Их место — релиз платформы, а не релиз выноса службы (`multi-agent-flow.md` §«Находка
   по дороге попадает в СВОЙ релиз»);
2. **исполнимость.** Без шага 1б шаг 3 делается **руками**, а `publish-tag.sh` прямо
   называет цену: «публикующий руками гейт обходит — и обходит молча». Ручная публикация
   спрашивает одну предпосылку из четырёх. Без шага 1а шаг 3 выпускает версию, которую
   служба не может импортировать (§1.5);
3. **размер вердикта.** Линия несёт **423** коммита и **3571** изменённый файл при ни одном
   вердикте конвейера; полосы 1а и 1б читаемы по отдельности.

> [!note] Числа этого пункта в круге 1 были ВЗЯТЫ ИЗ ЧУЖОГО ТЕКСТА и не перемерены
> Стояло «282 коммита и 2948 файлов» — величины из тела MR продукта #2118. Ни одна единица
> счёта их не воспроизводит; предикаты названы рядом, чтобы следующий не повторил ошибку:
>
> ```sh
> git rev-list --count origin/main..origin/release/kaname                # 423
> git rev-list --count --no-merges origin/main..origin/release/kaname    # 307
> git rev-list --count --first-parent origin/main..origin/release/kaname # 107
> git diff --name-only origin/main...origin/release/kaname | wc -l       # 3571
> ```
>
> Круг 2 рецензии на своей ревизии получил 421 и 3563 — та же единица, движущееся дерево.
> Довод от чисел только усиливается: линия больше, чем о ней было сказано.

## 4. Сценарии

Идентификатор — `KAN-RELEASE-1-NN`. Производитель каждого «Тогда» назван в §6.

### S1. Гигиена локальных ссылок — снятие блокатора П6

#### KAN-RELEASE-1-01 (отрицательный) — выпуск при живых локальных `v*` не открывается

**Дано** рабочая копия на вершине `origin/main`
**И** в ней есть локальные ссылки `v0.1.0`…`v1.0.0`, не являющиеся предками ствола

**Когда** позван `scripts/release/publish-version.sh v0.1.0 --skip-pack`

**Тогда** код возврата **1**
**И** в выводе стоит строка `✗ П6  локальных v*-тегов вне ствола 8 из 8: v0.1.0 v0.2.0 v0.3.0 v0.4.0 v0.5.0 v0.6.0 v0.7.0 v1.0.0`
**И** последняя строка — `ВЫПУСК НЕ ОТКРЫТ: предпосылки нарушены — публиковать нельзя`
**И** перепись печатает `предпосылок проверено 7, нарушено 1, НЕ спрошено 1`
**И** ни одной ссылки не создано и не отправлено

#### KAN-RELEASE-1-02 (положительный) — после снятия ссылок П6 сходится

**Дано** то же дерево
**И** локальные `v*` сняты (`git tag -l 'v*' | wc -l` → 0)

**Когда** позван тот же скрипт

**Тогда** в выводе стоит `✓ П6` со строкой `осмотрено локальных тегов: 0`
**И** П6 более не значится в перечне нарушенных

#### KAN-RELEASE-1-03 (отрицательный) — снятие ссылок не отменяет их публикации

**Дано** ссылки сняты локально

**Когда** спрошен origin — `git ls-remote --tags origin | grep -cE 'refs/tags/v[0-9]'`

**Тогда** ответ **0**
**И** заметок о выпусках ноль (`gh api repos/PRO-Robotech/kacho/releases --jq length` → 0)

> Исход #1762 выбирается **явно**: ссылки признаются черновыми и снимаются. Второй исход
> (признать выпусками и опубликовать) отвергнут — ни одна из восьми не является предком
> ствола, и что каждая обозначает, нигде не записано.

### S2. Производители выпуска переезжают в ствол

#### KAN-RELEASE-1-04 (отрицательный) — сегодня у операции «поставить версию» зовущего в стволе НЕТ

**Дано** ствол `origin/main`

**Когда** спрошено объявление процесса выпуска и рецепты сборки

**Тогда** `git ls-tree origin/main --name-only -- .github/workflows/release.yml` пусто
**И** `git show origin/main:Makefile | grep -c '^release-'` → **0**
**И** `git ls-tree -r origin/main --name-only -- scripts/release | wc -l` → **4** из четырнадцати

#### KAN-RELEASE-1-05 (положительный) — после переноса зовущий есть и гейт это утверждает

**Дано** полоса переноса влита в ствол

**Когда** прогнан
`go test ./internal/repohygiene/ -run '^TestVersionPublishingHasACallerInThePipeline$' -count=1 -v`

**Тогда** в выводе **наблюдается строка** `--- PASS: TestVersionPublishingHasACallerInThePipeline`
**И** объявление процесса разбирается, и каждый механизм, названный в его шагах, существует и исполняем

> [!warning] Утверждается НАБЛЮДЁННОЕ ПРОХОЖДЕНИЕ ПО ИМЕНИ, а не код возврата
> Круг 1 называл здесь имя `TestReleaseOperationHasACaller`, которого в дереве **нет ни на
> стволе, ни на линии** (0 вхождений). Прогон по такому имени даёт
> `ok … [no tests to run]` и **код 0** — то есть предикат «→ PASS» выполнялся бы, не
> исполнив ни одной пробы. Это ровно класс, который ловит сценарий 25 этого же документа,
> и круг 1 не применил его к себе. Настоящее имя —
> `TestVersionPublishingHasACallerInThePipeline` (`internal/repohygiene/releasewiring_test.go`,
> строка объявления 232 на ревизии линии `a9d41c7cd6ba`).

#### KAN-RELEASE-1-06 (отрицательный) — у производителя нет ни одного автоматического триггера

**Дано** ствол несёт объявление процесса выпуска

**Когда** прочитан его блок `on:` разобранным YAML

**Тогда** единственный вид запуска — ручной с входами `version`, `confirm`, `publish`
**И** ни `push`, ни `pull_request`, ни `schedule`, ни `tags` в нём нет
**И** гейт зовущего краснеет, если автоматический триггер добавлен

#### KAN-RELEASE-1-07 (отрицательный) — необратимый шаг без совпавшего подтверждения отвергается

**Дано** ствол с производителем

**Когда** `scripts/release/publish-tag.sh v0.1.0 --confirm v0.2.0 --publish`

**Тогда** код возврата **2**
**И** ничего не создано и не отправлено

#### KAN-RELEASE-1-08 (положительный) — холостой прогон спрашивает всё и не создаёт ничего

**Дано** ствол с производителем, предпосылки сошлись

**Когда** `scripts/release/publish-tag.sh v0.1.0 --confirm v0.1.0` (без `--publish`)

**И** `git tag -l v0.1.0` пусто — локальной ссылки не осталось

### S3. Политика версий: форма, монотонность, точка отсчёта

#### KAN-RELEASE-1-09 (отрицательный) — негодная форма версии отвергается с именем правила

**Дано** ствол

**Когда** `scripts/release/publish-version.sh 0.1` (без `v`)

**Тогда** код возврата **1**

**Дано** корневой `go.mod` объявляет `github.com/PRO-Robotech/kacho`

> было ложно. Перемер 2026-09-07T20:15+03:00: голова **одна** — `issue-2117` за это время
> с origin снята. Оба замера верны каждый в свой момент, и именно поэтому утверждение
> формулируется **свойством** ссылок («все временные»), а не их числом: число здесь

## 5. Что отвергнуто и по какой цене

Каждый путь рассмотрен и отвергнут **явно**, а не умолчанием.

### 5.1. Подмена пути модуля (`replace`) — запрещена, и цена двойная

| ось | цена |
|---|---|
| норма | прямой запрет `polyrepo.md` §«Правило зависимостей при полирепо-топологии» |
| производитель | предпосылка П7 `publish-version.sh` — код 1, выпуск не открывается |
| у потребителя | `replace` действует **только в главном модуле** и потребителем **игнорируется**: он получит ту редакцию, которую мы подменяли, — то есть редакцию, на которой мы ничего не проверяли |
| у нас | ломает собственную сборку при одиночном клоне (CI, сборка образа) |

Замер: `grep -cE '^\s*replace' go.mod` → **0** в обоих объявлениях обеих ревизий. Предмета
у пути нет и заводить его нельзя.

### 5.2. Рабочее пространство (`go.work`) — локальное средство, конвейер его не видит

Отвергнуто **фактом конвейера**, а не комментарием: `.github/workflows/ci.yaml` собирает
службу вызовами `go mod download -C services/iam` (строка 120) и
`go build -C services/iam ./...` (строка 126). Рабочее пространство в этих вызовах не
участвует — конвейер его не выкладывает, — поэтому зелёное локально означало бы ровно
ничего для ствола. Цена принятия: расхождение локального прогона с конвейером по
**составу зависимостей** — класс, который `testing.md` §«Локальный прогон обязан
воспроизводить конвейер» называет прямо.

Файл при этом действительно исключён `.gitignore`, но **опираться на его объяснение
нельзя**: комментарий рядом с записью говорит «в дереве один модуль», а их **два**
(`git ls-tree -r origin/release/kaname --name-only | grep -c 'go\.mod$'` → 2). Круг 1
цитировал этот комментарий как довод — то есть строил отказ на утверждении, пережившем
свой предмет. Довод перестроен на исполняемое; запись `.gitignore` остаётся полезной
(случайно созданный файл не уедет в индекс), а её объяснение — предмет отдельной правки
в дереве продукта.

### 5.3. Вливание с пином на прежнюю голову ствола — снимает симптом, заводит худшее

> [!important] Этот же довод отвергает и шаг 4 круга 1 — см. §1.5
> Круг 1 применил довод к чужому пути и не применил к своему: `v0.1.0` в его порядке
> указывала ровно на ту голову ствола, о которой идёт речь ниже. Отсюда шаг 1а.

Соблазн: взять псевдоверсию коммита, достижимого со ствола (например `2171a6690a81`,
сегодняшний `@latest`), и влить линию с ней.

| ось | цена |
|---|---|
| **редакция несовместима** | на этой голове ствола стабы службы лежат по пути `pkg/api/kacho/cloud/iam/v1` (83 файла), а линия импортирует `pkg/api/kaname/cloud/iam/v1`. Сборка службы отказала бы немедленно |
| точка отсчёта | по-прежнему отсутствует: `breaking-since-release.sh` → код 3 |
| «бамп до совместимой версии» | по-прежнему не операция |
| срок | откладывает выпуск на неопределённое время, а решение владельца требует обратного порядка |

Первая строка делает путь **неисполнимым**, а не просто нежелательным.

### 5.4. Ссылка на стволе до вливания линии — это и есть предложенный порядок

Отвергается **не сам путь**, а два его варианта, и оба круг 1 предлагал сам:

- **«до переноса стабов» (шаг 1а)** — версия негодна службе by construction, доказано
  вызовом инструмента с контролем (§1.5). Это худший из рассмотренных исходов: он не
  чинится ничем, кроме выпуска следующей версии;
- **«до переноса производителей» (шаг 1б)** — ссылку толкает человек руками, и это
  обходит `assert-trunk-green` и `breaking-since-release` целиком: `publish-tag.sh`
  называет цену прямо — «публикующий руками гейт обходит, и обходит молча». Стоимость
  обхода измерима: из четырёх предпосылок §4 политики ручная публикация спрашивает
  **одну**.

### 5.5. Автоматический выпуск на каждое слияние — отвергнут по существу

Номер версии — **суждение о совместимости**. Машина умеет доказать, что дельта контрактов
ломающая, и **не умеет** доказать, что изменение поведения ломающим не является. Ссылка на
каждое слияние обещала бы совместимость, которой никто не проверял, а отозвать обещание
нельзя (§S7). Владелец решения — `release-and-versioning.md` §2.

### 5.6. Отдельная нумерация контрактов — отвергнута

Два перечня версий об одном предмете расходятся молча: сборка потребителя остаётся
зелёной при разъехавшихся контрактах. Владелец решения — `release-and-versioning.md` §1.

### 5.7. Публикация восьми локальных ссылок вместо их снятия — отвергнута

Второй исход #1762 («признать выпусками и опубликовать») требует, чтобы до отправки было
записано, что каждая обозначает. Не записано **ни для одной**, и ни одна не является
предком ствола: публикация опубликовала бы **код вне ствола**, необратимо.

### 5.8. Порядок «влить линию с псевдоверсией и архивной ссылкой, потом выпустить» — ПРИНЯТ как альтернатива, не отвергнут

Круг 1 этот путь не рассматривал вовсе, и это был пропуск: он **растворяет** несущее
препятствие §1.5, не двигая переименование отдельной полосой.

**Устройство.** Создать архивную ссылку на коммит пина → влить линию → выпустить `v0.1.0`
со **слитого** ствола → перевести пин третьим шагом.

**Почему он исполним.** После вливания ствол несёт `pkg/api/kaname` и `proto/kaname`, то
есть несущее требование §1.5 удовлетворено — просто другим способом доставки. Между
вливанием и публикацией сборка службы резолвит платформу псевдоверсией, а та достижима
по архивной ссылке из VCS, а не только из кэша прокси.

**Сравнение с предложенным порядком — по осям, а не по вкусу:**

| ось | §3 (полосы 1а/1б) | §5.8 (вливание + архивная ссылка) |
|---|---|---|
| несущее требование §1.5 | удовлетворено шагом 1а | удовлетворено вливанием |
| решение владельца «версия из ствола ПЕРВОЙ» (эпик #2119, MR #2118) | **соблюдено** | **нарушено**: линия вливается до версии |
| работа по переименованию | выделить полосу: 165 файлов `.go` вне `services/iam` | **ноль** — линия несёт готовое |
| чем держится окно | окна нет | **архивной ссылкой**, созданной ДО схлопывания |
| цена забытой ссылки | — | коммит недостижим; остаётся только кэш чужого прокси (§1.1) |
| читаемость вердикта | две полосы читаемы по отдельности | один MR на 423 коммита и 3571 файл |
| ревизия точки отсчёта | ствол + две узкие полосы | ствол, только что получивший 423 коммита разом |

**Решение: принят как альтернатива, применяется по названному предикату.**

> Порядок §5.8 выбирается, если выделение полосы 1а из линии даёт конфликт хотя бы по
> одному из 165 файлов, — то есть если полоса перестаёт быть механическим выделением
> уже испытанного. Тогда цена §3 (ручное разрешение конфликтов в стабах) превышает цену
> §5.8 (одна архивная ссылка).

**Что в §5.8 обязательно и не подлежит смягчению:** архивная ссылка создаётся **до**
схлопывания, а не после. После схлопывания коммит уже недостижим, и создать ссылку на
него можно только из локальной копии, которая может не пережить уборку. Предикат:
`git ls-remote --tags origin | grep -c 'archive/'` вырос на единицу **прежде** чем
`gh pr merge` позван.

**Чего §5.8 НЕ отменяет.** Он не отменяет ни шага 1б (производители выпуска всё равно
обязаны быть в стволе до публикации — иначе версия ставится руками мимо гейтов), ни
шага 0 (П6 отказывает независимо от порядка).

## 7. Что делать, если порядок нарушен

Отзыв опубликованной версии **не существует в природе модулей Go**. Поэтому по каждому
виду нарушения назван не «откат», а **компенсация** и её цена.

| нарушение | компенсация | цена |
|---|---|---|
| выпущен неверный номер (мельче требуемого повышения) | `retract` в следующей версии + выпуск верной | старая версия остаётся навсегда и видна всем; `retract` виден всем |
| выпущена версия на красной ревизии | выпуск следующей версии на зелёной; старая **не отзывается** | обещание, которое мы не сдержали, остаётся в кэше прокси |
| **выпущена версия с ревизии, не несущей `pkg/api/kaname`** (§1.5) | **только** выпуск следующей версии с ревизии, которая их несёт | точка отсчёта совместимости задана версией, непригодной единственному потребителю; окно **не закрывается само** — служба не соберётся ни при каком пине на неё |
| ветка полосы снята до перевода пинов ([#2243](https://github.com/PRO-Robotech/kacho/issues/2243)) | архивная ссылка, если коммит ещё достижим локально | если не достижим — остаётся кэш чужого прокси; воспроизводимость выпуска утрачена |
| линия влита до публикации (окно §3.1) | **архивная ссылка** `archive/<предмет>` на коммит пина — коммит снова достижим, псевдоверсия резолвится из VCS | окно между вливанием и созданием ссылки: сборка держится кэшем чужого прокси |
| локальная ссылка `v*` уехала побочным `git push --tags` | ничего: код вне ствола опубликован необратимо | точка отсчёта совместимости испорчена; следующая версия обязана быть строго старше опубликованного мусора |
| три пина разошлись после шага 6 | привести к одной версии; расхождение наблюдаемо | сборки трёх деревьев испытаны на разных редакциях платформы |

**Практическое следствие, которое стоит сказать прямо:** единственный необратимый шаг —
третий. Всё, что до него, чинится правкой; всё, что после, — только новой версией.
Поэтому шаги 0–2 стоит проходить холостым прогоном столько раз, сколько нужно: они
бесплатны, а шаг 3 не бывает бесплатным никогда.

## 8. Остатки: чего эта приёмка НЕ решает

Каждый пункт заводится **задачей**, а не обещанием.

1. **Производителя компенсации архивной ссылкой не существует** (сценарий 37). Сегодня
   создание такой ссылки — жест человека, за которым никто не отвечает. Нужен гейт:
   «всякая псевдоверсия платформы, названная объявлением модуля в дереве, достижима
   хотя бы с одной ссылки origin». Предмет — задача продукта
   [#2230](https://github.com/PRO-Robotech/kacho/issues/2230).
2. **Предикат задачи #1766 измеряет имя пути, а не предмет** (§1.2): после переименования
   `pkg/api/kacho/cloud/iam` → `pkg/api/kaname/cloud/iam` он зелен при живой зависимости
   (9 файлов, 6 прод-кода). Предикат обязан спрашивать про **кросс-модульность**, а не
   про написание пути. Предмет — задача продукта
   [#2231](https://github.com/PRO-Robotech/kacho/issues/2231).
3. **Гейта «пин службы един и указывает на опубликованную версию» нет** (сценарий 35).
   Три дерева объявляют три разные псевдоверсии, и расхождение обнаружено чтением, а не
   проверкой. Предмет — задача продукта
   [#2232](https://github.com/PRO-Robotech/kacho/issues/2232).
4. **Выпуск вложенного модуля фундамента** (`pkg/vX.Y.Z`) — вне охвата: предмета нет,
   объявления `go.mod` в подкаталоге `pkg/` в дереве не существует. Форма переезда решена
   `release-and-versioning.md` §1.1, и эта приёмка её не переизобретает.
5. **Публичность фундамента под AGPL** — решение владельца, названное эпиком #2119
   («сперва версия платформы, потом публичность фундамента»). Приёмка порядка выпуска его
   не предрешает.
6. **Номер первой версии** (`v0.1.0` во всех сценариях — иллюстрация, не решение).
   Выбор номера — суждение владельца; машинная половина (`breaking-since-release.sh`) при
   нуле опубликованных версий отвечает кодом 3 и суждения не заменяет.
7. **Уборка веток продукта до перевода пинов** — предмет задачи
   [#2243](https://github.com/PRO-Robotech/kacho/issues/2243) (P0): пин ствола сегодня
   удерживают только временные ссылки полос, и ни один тег. Эта приёмка порядок выпуска
   задаёт, а запрет на уборку — её предмет, и он заведён отдельно.
8. **Регистрация в ведомости приёмок продукта** (`docs/acceptance-ledger.yaml`) **не
   требуется**: ведомость читает гейт миграций, а эта приёмка миграции не заводит.
   Названо, чтобы отсутствие записи не приняли за пропуск.
