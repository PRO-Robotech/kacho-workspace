# CI-PY-1 — три исхода Python-проб во всей цепочке вызова

> Статус: DRAFT. Дата: 2026-09-17. Автор: acceptance-author (/root/hygiene_audit).
> Задачи: PRO-Robotech/kacho #2281, #2629, #2705.
> Независимого acceptance-review и разрешения на реализацию пока нет.

## Предмет и authority

Разработчик и CI различают три результата: проверено без находок; проверено с
находкой; обязательная проверка не выполнилась. Отсутствие `pytest` сохраняет
третью категорию от исполнителя Python до итоговой сводки. Полный GREEN означает
полученный результат всех объявленных проверок, а не только отсутствие находок.

Исходные требования находятся в [#2281](https://github.com/PRO-Robotech/kacho/issues/2281),
[#2629](https://github.com/PRO-Robotech/kacho/issues/2629) и
[#2705](https://github.com/PRO-Robotech/kacho/issues/2705). Проверены тела и все
комментарии 2026-09-17; последние комментарии 10:19:35/39/44 UTC назначают общий
поток, нового разрешения на маску результата не содержат.

Фраза #2281 «не роняет на нём шаг» относится к шагу сбора категории. Последующее
решение владельца от 2026-09-12, сохранённое в kacho
`.github/scripts/stand-up.sh:47–62`, требует красного итогового задания при
недостающем обязательном вердикте. Этот документ сохраняет обе границы: сборщик
объявляет «УСЛОВИЕ НЕ СОЗДАНО», итоговый обязательный вердикт отклоняет неполноту.

Существующая одобренная приёмка KAN-HOME-1, HOME-06, описывает отказ на пустом
составе. Её сценарий остаётся действующим. Новый документ добавляет отсутствующие
оси условия исполнения, собственной самопроверки, счётчиков и вызывающих.
Поиск по docs/specs, docs/changes и запискам KAC выявил HOME-06 и историческое
упоминание отсутствия pytest в KAN-REST-1 §17.3; одобрения нижеследующих сценариев
там не найдено. Полный журнал границ поиска — в пакете CI-PY-1.

## Наблюдаемые величины

Перепись различает файлы, объявления Python-функций и исполненные экземпляры
проб. Параметризация может породить несколько экземпляров из одного объявления.
У каждой сводки названа единица: у Python — пробы/объявления; у прогонщика
самопроверок — вызовы самопроверок; у ci-local — выбранные верхнеуровневые проверки.
Объём найденного и объявленного не выдаётся за объём исполненного. «Не выполнено»
и «провалено» имеют отдельные числа; неполнота не увеличивает число успехов.

## CI-PY-01 — отсутствует обязательный исполнитель набора

**Дано** отслеживаемый непустой состав с двумя объявленными Python-пробами;
единственная отсутствующая предпосылка — модуль pytest выбранного интерпретатора.
**Когда** запускается обычный прогон Python-проб.
**Тогда** результат имеет отдельный код, отличный от 0 и 1; причина названа
«УСЛОВИЕ НЕ СОЗДАНО: нет pytest»; объявлено 2, исполнено 0, провалено 0.
Прогон объявлен неполным и не даёт PASS.

## CI-PY-02 — законный близнец: полный зелёный

**Дано** тот же состав CI-PY-01, модуль pytest доступен, оба утверждения истинны.
**Когда** запускается обычный прогон.
**Тогда** код 0; объявлено 2, исполнено 2, провалено 0, не выполнено 0;
результат полного прохождения привязан к этому исполненному составу.

## CI-PY-03 — настоящий дефект остаётся находкой

**Дано** условия CI-PY-02, одно из двух утверждений изменено на ложное.
**Когда** запускается обычный прогон.
**Тогда** код 1, названа координата упавшей пробы; исполнено 2, провалено 1;
наличие pytest не подменяет результат проб.

## CI-PY-04 — собственная самопроверка требует своей предпосылки

**Дано** исправный прогонщик и недоступный pytest.
**Когда** запускается его самопроверка, включающая исполнение pytest-файлов.
**Тогда** её результат — отдельный третий код и причина «нет pytest»; отсутствие
условия не описывается как провал девяти утверждений о прогонщике. Перепись
самопроверки отделяет объявленные проверки от действительно исполненных.
**И** при единственном изменении — доступный pytest — полный состав самопроверки
исполняется и даёт код 0; внесённый дефект поведения прогонщика при доступном pytest
даёт код 1 с координатой несовпавшего утверждения.

## CI-PY-05 — пустой предмет и пропущенная проба имеют собственный смысл

**Дано** работоспособное окружение и поочерёдно: пустой объявленный обход;
найденный файл без исполняемой пробы; набор с явно пропущенной пробой.
**Когда** запускается обычный прогон.
**Тогда** каждый вариант даёт код 1 с соответствующей причиной — пустой обход,
немой файл или запрещённый пропуск. В соседнем непустом законном наборе код 0.
Ни один из этих трёх дефектов состава не объявляется отсутствием pytest.

## CI-PY-06 — неполученный отчёт не превращается в исполненные пробы

**Дано** исполнитель был запущен, но обязательный отчёт результата отсутствует
либо непригоден для чтения.
**Когда** подводится итог Python-проб.
**Тогда** результат неполный, причина названа, неподтверждённые экземпляры не
зачтены как исполненные; полного GREEN нет. Рабочий отчёт близнеца даёт числа
из фактического результата. Настоящее упавшее утверждение с валидным отчётом
остаётся находкой CI-PY-03.

## CI-PY-07 — счётчики не застывают на историческом числе

**Дано** законный набор из одной параметризованной функции с тремя экземплярами.
**Когда** запускается полный прогон, затем тот же прогон без pytest.
**Тогда** полный прогон называет 1 объявление и 3 исполненных экземпляра;
неполный — 1 объявление и 0 исполненных экземпляров. Ни один вывод не приписывает
этому набору исторические «48 проб». При добавлении ещё одного объявления
перепись меняется по составу, без ручной поправки числа.

## CI-PY-08 — агрегация сохраняет находку рядом с неполнотой

**Дано** один независимый обязательный участник даёт находку, другой не
выполнился из-за отсутствующего условия.
**Когда** прогонщик сводит полученные исходы.
**Тогда** итог называет обе категории и координаты; находка остаётся находкой,
неполнота остаётся неполнотой, зелёных не прибавляется. Общее отсутствие находок
можно заявить только при нуле реальных находок, полный GREEN — ещё и при нуле
обязательных невыполненных участников.

## CI-PY-09 — самопроверки через Make сохраняют категорию

**Дано** все предпосылки прогонщика самопроверок созданы, кроме pytest; остальные
самопроверки корректны и исполняются.
**Когда** выполняются реальный прогонщик самопроверок и его цель Make.
**Тогда** сводка называет Python-самопроверку невыполненной и сохраняет причину;
количество проваленных самопроверок из-за этого не увеличивается. Вызывающий
различает этот исход и настоящую находку, хотя транспорт Make может дать один
код для разных причин.
**И** при доступном pytest весь объявленный состав исполняется; при настоящем
дефекте самопроверки тот же путь сохраняет отказ.

## CI-PY-10 — фактическая локальная цепочка без pytest

**Дано** исправное дерево, корректные версии helm/yq и материализованные локальные
зависимости; все пять проверок helm исполнимы, кроме Python-самопроверки без pytest.
**Когда** выполняется `scripts/ci-local.sh helm` через его настоящий путь
манифест-проверок и Make.
**Тогда** итог сообщает «не выполнено: нет pytest» с именем манифест-проверки,
отказов 0, не выполнено 1. Эта проверка не названа успешной; итог явно неполный.
**И** при единственном изменении — доступный pytest — получены прежние 5 из 5,
отказов 0, не выполнено 0. Настоящий дефект в той же цепочке даёт отказов 1,
а не снимается сообщением о pytest.

## CI-PY-11 — чужая или старая причина не объясняет текущий отказ

**Дано** предыдущий запуск был неполным из-за pytest, а текущий имеет другую
причину отказа; либо два запуска идут одновременно в разных рабочих каталогах.
**Когда** текущий вызывающий получает исход через Make.
**Тогда** он использует только исход своего запуска. Остаток прошлого запуска,
данные соседа, отсутствие текущего результата, повреждённый результат и
несогласованные числа не дают переклассифицировать настоящую находку в «нет pytest».
Исправный текущий неполный результат распознаётся своим законным близнецом.

## CI-PY-12 — CI называет причину и отказывает в полном вердикте

**Дано** объявлен обязательный прогон Python-проб в CI, но pytest отсутствует.
**Когда** исполняются шаг сбора исхода и итоговый обязательный вердикт задания.
**Тогда** сборщик публикует аннотацию «УСЛОВИЕ НЕ СОЗДАНО: нет pytest» и отдельные
числа исполненного/невыполненного; его транспортный успех не выдаётся за PASS.
Итоговое задание не GREEN, поскольку обязательного результата нет.
**И** при настоящей находке причина — упавшая проба; при полном законном прогоне
все объявленные Python-проверки подтверждены, и Python-часть допускает GREEN.

## CI-PY-13 — все реальные вызывающие участвуют в договорённости

**Дано** фактическое описание CI и текущий состав вызывающих обычный прогон и
самопроверку Python, включая общий прогонщик самопроверок.
**Когда** читается исполняемая структура процесса и исполняются найденные пути.
**Тогда** каждый реальный путь различает три категории до итогового вердикта;
комментарий с командой или объявление установки pytest в другом задании
не засчитываются вызовом и созданием условия. Ноль осмотренных вызывающих —
отказ проверки охвата, а не доказательство отсутствия разрыва.

## Границы и передача

Документ не требует глобальной установки pytest разработчику, переписывания
существующего набора проб или изменения правил допуска локального pre-push.
Код 0 локального транспорта при явной неполноте не доказывает полный GREEN;
действующий pre-push читает эту неполноту отдельно. Число 5 в CI-PY-10 —
базовый состав helm на b5fa093341f, не будущий рукописный лимит состава.

Пробы готовит независимый integration-tester после одобрения документа и замысла.
RED — несовпадение наблюдаемого поведения при исправной оснастке; намеренно
снятый pytest принадлежит испытуемому, а не интерпретатору самого проверяющего.
До одобрения и RED реализация не открыта. Изменение этого текста меняет предмет
будущего review: действительный вердикт привязывается к SHA-256.
