## Владелец и доставка

Горизонтальный инструмент получает двух независимых потребителей, поэтому его дом —
**corelib**. Канонический Python-модуль размещается в новом каталоге `ci/newman_publication/`
этого репозитория. Проекция и carrier scanner используют Python stdlib;
транспорт Actions использует небольшой общий Node-адаптер и запиненную официальную
библиотеку artifacts с lockfile в том же инструменте. Здесь предполагается
перенос и расширение поведения существующего Kaname-инструмента, а не переписывание
на другой язык ради доставки. Частный алгоритм Kaname снимается в той же логической
поставке. Нового экземпляра алгоритма в Kachō не появляется.

Оба продукта уже требуют corelib версией. Тонкий локальный запуск определяет каталог
именно этой версии из Go module graph при GOWORK=off и зовёт каноническую Python-команду
оттуда. Для GitHub publisher канонический `action.yml` и его исполняемые файлы
материализуются из **этого же** module pin в свежий фиксированный checkout-relative
runtime path; затем `uses: ./<runtime-path>` запускает JS action. Копия зависимости
на время задания не коммитится и не становится вторым алгоритмом. Новый каталог
создаётся заново, соответствие файлов исходному module pin проверяется до исполнения;
отдельного независимо движущегося action pin нет. Это доставка зависимости, не
скачивание произвольного скрипта по main. Ни committed replace, ни новый обратный импорт не нужны. Go module
archive должен реально содержать Python-файлы: это проверяется single-repo установкой
опубликованной версии у каждого потребителя до посадки, не предполагается по раскладке.
То же доказательство охватывает транспортный adapter, его lockfile и воспроизводимую
установку зависимостей в отдельный рабочий каталог, без записи в module cache.

Разрешены разные объявления входов: платформа знает свои services/gateway/shards,
служба — свой tests/newman. Их предмет — собственный состав. Разбор и очистка общие.
В workflow не остаётся второй реализации классификации секретов.

## Закрытая проекция и доверенная связь

Публичный пакет — версионированная проекция Newman, а не копия сырого отчёта с
regex-заменами. Выходные ключи выбираются из фиксированной схемы; значения — числа,
bool, конечные enum, постоянные заглушки и идентификаторы из отслеживаемого каталога
коллекций текущей ревизии. Имена output-файлов, записей архива, тестовых координат
и manifest полей производятся инструментом; они не берутся из входных path/key/name.
Artifact name строится из фиксированного префикса и числовых run/attempt/shard-index.

Полностью снимаются свободные body/URL/scripts, неизвестные input keys, error message,
произвольные test/collection names и текст логов. Для журналов остаются тип, число
строк/байтов и фиксированный исход обработки. Публичные ключи/несекретные идентификаторы
сами по себе не являются findings carrier scanner; это не означает, что любое такое
поле обязано копироваться в закрытую проекцию.

`run.stats`, кардинальность `run.failures`, HTTP-коды, итерации и исполненный состав
сохраняются. Связь с коллекцией/запросом берётся из доверенного каталога входного
source tree этой ревизии и проверяемой привязки отчёта к нему; свободное имя из отчёта
не является авторитетом. Передача адаптера reader допустима только как чтение этой
публичной схемы без изменения предиката теста/coverage. Неизвестная/неоднозначная
привязка запрещает публикацию. До реализации fixture настоящего Newman и существующие
readers доказывают, что связь конструируема, а не предполагается по названию поля.

Самые важные holders вызывают штатных читателей на исходном и projected package:
равны counts, test verdict и coverage как для полного зелёного, так и для finding
и неполного набора. Если текущему читателю нужен свободный текст, публиковать его ради
совместимости нельзя: узкий adapter читает те же факты по доверенным ID/индексам,
а прежний предикат сохраняется и имеет инъекцию обеих полярностей. Это часть передачи
формата публикации, а не смена утверждений Newman или их владельца.

## Поток данных и граница upload

1. Собрать объявленный состав текущего запуска из штатных производителей. Сырой
   каталог закрыт для публикации. Обработка исполняется и при красном Newman.
2. В собственном временном каталоге вне публикационного корня разобрать каждый вход
   и построить закрытую проекцию. Запрещены symlink, выход из корня и неизвестный
   бинарный тип. Отказ не оставляет результат, выглядящий готовым от прошлого запуска.
3. Создать ZIP с производимыми именами/метаданными, без filesystem extra fields или
   исходных archive comments. Manifest использует только закрытую схему и безопасные
   координаты. Verdict JSON проходят ту же проекцию, обходного upload для них нет.
4. Общий upload-адаптер **один раз читает ZIP целиком в собственный private bytes buffer**.
   Из этого buffer передаёт данные каноническому checker через закрытый IPC, получает
   проверенный schema verdict и full digest, затем отправляет **тот же buffer**.
   После проверки пути повторно не открываются, архив повторно из файлов не собирается;
   ссылка на buffer не передаётся постороннему producer. Превышение явного memory/size
   budget означает NOT_EXECUTED до первого сетевого upload byte.
5. Транспортный adapter использует поток из этого buffer для artifact create/upload/
   finalize. Он не зовёт path-based `uploadArtifact(files, root)` и не передаёт путь
   отдельному `actions/upload-artifact` шагу. Запиненный upstream SDK предоставляет
   транспорт, протокол не копируется в двух продуктах. Конкретный измеренный seam
   и pin названы ниже; executable compatibility holder закрепляется до RED реализации.
6. JS-action entrypoint закрывает диагностический вывод SDK до его вызова: stdout/stderr
   захватываются приватно, не ретранслируются в job log; upstream exception может
   содержать path или signed URL. Неконтролируемый exception также заменяется фиксированным
   кодом без исходного stack/message. Наружу выходит отдельная запись с
   фиксированным кодом, числовым artifact ID, размером и digest. Токен Actions передаётся
   только транспортному SDK; он не входит в пакет и не печатается.
7. Условие always() лишь даёт шанс обработать красный Newman. Missing/aborted checker
   запрещает upload и оставляет итог CI неуспешным с отдельной диагностикой.

Отдельный hash-check перед path-based uploader недостаточен. Проверено по upstream
[artifact uploader](https://github.com/actions/toolkit/blob/main/packages/artifact/src/internal/upload/upload-artifact.ts)
и [ZIP producer](https://github.com/actions/toolkit/blob/main/packages/artifact/src/internal/upload/zip.ts):
обычный путь собирает поток чтением файлов. Это основание выбора buffer boundary,
а не пин на upstream main; конкретная используемая версия должна быть зафиксирована.

CI-NP-04 держит эту границу принимающим upload-дублёром: сравнивает полные bytes, а
инъекция меняет исходный файл после последнего checker verdict и до первой отправки.
Изменение файла не может попасть в buffer; попытка передать другой buffer требует
новой проверки. Законный близнец получает исходный ZIP byte-for-byte. Повторный scan
скачанного Actions artifact подтверждает реальную, а не только локальную проводку.

## Конструктивность транспорта: точный SDK seam

Выбран **`@actions/artifact@6.2.1`**, установленный 2026-09-17 отдельно от продуктового
дерева с `--ignore-scripts`; package integrity:
`sha512-sJGH0mhEbEjBCw7o6SaLhUU66u27aFW8HTfkIb5Tk2/Wy0caUDc+oYQEgnuFN7a0HCpAbQyK0U6U7XUJDgDWrw==`.
Снимок полного dependency lock имеет SHA256
`fcb99bf7fb824e8ddb93269eca3f3537427fdbd13c2e556383d3bda2e39f422c`.
Пин и lock — часть будущего общего инструмента; не зависимость на latest.

Public exports пакета содержат только `.`. `DefaultArtifactClient.uploadArtifact`
принимает пути и для этой границы не подходит. Выбран **внутренний API**, явно с этой
границей поддержки: путь установленного пакета определяется через его public entry,
далее импортируются точные file URLs из того же проверенного пакета. SDK source не
копируется и не патчится. При несовпадении версии/наличия exports инструмент отказывает;
смена пина требует повторного compatibility и runtime доказательства.

| Installed coordinate относительно пакета | Используемая возможность |
|---|---|
| `lib/internal/upload/blob-upload.js` | `uploadToBlobStorage(signedURL, stream, contentType)` читает переданный поток; SHA256 файла `08cfc257f4a0b488bb0bfcf046c10902119e79fa0fcbfe1df95ea7b690333366` |
| `lib/internal/upload/stream.js` | `WaterMarkedUploadStream` пропускает chunks без изменения; **не** используется `createRawFileUploadStream` |
| `lib/internal/shared/artifact-twirp-client.js` | `internalArtifactTwirpClient()` предоставляет CreateArtifact/FinalizeArtifact |
| `lib/internal/shared/util.js` | `getBackendIdsFromToken()` получает runtime backend IDs; токен не журналируется |
| `lib/generated/index.js` | официальные message types, включая StringValue, для create/finalize |
| `lib/internal/upload/upload-artifact.js` | структурный эталон SDK Create→stream upload→Finalize, версия wire request 7; не копируемый файл |

Create/Finalize зовутся через SDK client, signed URL передаётся только SDK blob upload.
Публичный artifact ID допускается к выводу лишь после удачного Finalize и совпадения
возвращённого upload digest/size с проверенным snapshot. Ошибка metadata round-trip —
отказ публикации, а не успешный пустой объект. Файловых readers на этой границе нет.

Минимальная API-проба исполнилась на Node **24.21.0** (и отдельно 26.8.1): реальная установленная
`uploadToBlobStorage` получила `WaterMarkedUploadStream` из private snapshot; только
`BlobClient.getBlockBlobClient()` заменён записывающим транспортом. Исходный внешний
buffer изменён после фиксации snapshot. Получено 34/34 bytes, returned/received/checked
SHA256 совпали, recording transport вызван один раз, сетевых вызовов 0. Это доказательство
достижимости interface; не реальная Actions-загрузка и не RED publication holder.
Локальная запись: `area-ci-audit/contracts/newman-sdk-api-proof/{probe.mjs,proof-node24.json,proof-node26.json,package-lock.json}`.
Node24 взят из официального `node-v24.21.0-linux-x64.tar.xz`; SHA256 проверен по
официальному SHASUMS256: `fd8e59d5a511510f6a298afb548f18c7d2b1be404d8b4a27d94fbe49f56cb2d6`.

Зафиксированный lock требует Node >=22 у Azure dependencies. Каноническая action
объявляет **`runs.using: node24`** и исполняет SDK в том же Node runtime; bootstrap
на другой Node и перенос токена между шагами не нужны. Фактическая версия Node24
runner записывается в runtime evidence; работа самого SDK проверяется на этой посадке.

Это несущая предпосылка: официальный
[NodeScriptActionHandler](https://github.com/actions/runner/blob/main/src/Runner.Worker/Handlers/NodeScriptActionHandler.cs)
передаёт JS action `ACTIONS_RUNTIME_TOKEN` и `ACTIONS_RESULTS_URL`; обычный
[ScriptHandler](https://github.com/actions/runner/blob/main/src/Runner.Worker/Handlers/ScriptHandler.cs)
такой доставки не имеет. Поэтому `run: node publisher` не считается рабочей проводкой.
Токен не пишется в GITHUB_ENV/output и не экспортируется будущим шагам; Python checker
получает только свой закрытый IPC и очищенное окружение без транспортных credentials.
Отсутствующий runner runtime/SDK capability или credential даёт NOT_EXECUTED и запрещает
upload, а не scanner FINDING. Новая runtime materialization имеет holder на чистый
каталог, один module pin, совпадение содержимого и отсутствие committed алгоритмической
копии в обоих продуктах.

## Carrier scanner и честная граница его вывода

Набор форм в приёмке является входом матрицы. Классификатор нормализует имена полей,
проверяет auth/header/cookie/variable/body/URL/text носители и поддержанные упаковки.
Декодирование ограничено по глубине, размеру и числу объектов; достижение предела —
NOT_EXECUTED. Неизвестный **заявленный** encoding также не даёт CLEAN. Произвольное
неявное кодирование строку распознать не обещаем; в новой публикации весь opaque text
устраняет проекция, поэтому безопасность не зависит от такого распознавания.

Два утверждения разделены. Для новой публикации CLEAN подтверждает закрытую схему
конечного ZIP, доверенное происхождение разрешённых строк и отсутствие материала в
поддержанных carriers. Для исторического сырого артефакта CLEAN означает только
полное carrier-сканирование заявленной версии без узнаваемой находки. Оно не доказывает
отсутствия произвольного неизвестного секрета и не разрешает повторную сырую публикацию.
Неподдержанный явно объявленный carrier остаётся NOT_INSPECTED для retention.

Матрица включает raw/JSON/URL/base64/base64url/Buffer/nested JSON, а также filename,
JSON key, test/collection name, error, manifest и log carriers. Произвольная opaque
строка обязана исчезнуть из новой проекции независимо от recognizer. Harness смотрит
пакет, metadata и stdout/stderr; выводит только числа. В собственных ошибках инструмента
нельзя печатать traceback, repr входа, parser message или исходный path.

Scanner вызывается отдельно от преобразования. Обе команды используют одну семантику
carrier rules; независимое свидетельство исходит от injection corpus, принимающего
upload-дублёра и повторного скана скачанного пакета. Совпавшие счётчики одного producer
сами по себе не считаются независимым доказательством.

## Гейт провязки

Проверяется разобранный workflow: настоящие upload steps, их условия, порядок,
конкретные пути и связь с исходом подготовки. Шардовая перепись берётся у своего
производителя, не фиксируется числом прежнего IAM-набора. Неизвестная динамическая
форма пути не признаётся проверенной по подстроке имени. Расширение состава требует
принадлежности одному конечному пакету; новая сырая публикация даёт находку.

Держатель общего поведения живёт в corelib; провязка каждого локального workflow —
у своего потребителя. Межрепозиторную единственность и пины сверяет workspace.
Нельзя требовать текст конкретной функции внутри чужого исходника вместо вызова
публичной команды. Гейты также несут негативную инъекцию, законный близнец и пустой обход.

## Retention и локализация

Перепись использует все страницы metadata API и время среза. Контент пакетов читается
в закрытом локальном каталоге; наружу выходят только фиксированные коды, числа,
доверенные SHA и производимые aliases. Исходные artifact names остаются в локальном
закрытом контрольном манифесте для точной проверки, без копирования в stdout/публичный review.
Срез 2026-09-17 обнаружил 485 неистёкших newman-shard пакетов, inspected bodies 0:
это **NOT_INSPECTED**, а не признанные утечки и не чистые пакеты. Число не становится
константой реализации; перед действием и перед посадкой требуется новая перепись.

Последнее принятое containment #1810 относится ровно к десяти ранее проверенным
артефактам и не расширяется на остальные. Новое удаление допускает отдельный
content-verified manifest и независимый landing-reviewer: перед каждым действием
полностью сверяются метаданные и digest, после проверяется exact 404.
Runs и job logs не удаляются этой работой. Несовпадение или отказ чтения оставляет
явный непроверенный остаток. Для закрытия #1810 все доступные объекты текущего среза
должны получить доказанный исход, а publisher — новую проверенную форму. Отчёт closure
явно ограничивает исторический CLEAN поддержанными carriers указанной версии;
неизвестное содержимое не объявляется доказанно безопасным вне этой границы.

## Порядок и классы риска

Порядок: принятая приёмка → разметка классов → принятый замысел → тесты RED →
общий производитель в corelib → выпуск → оба consumer pins/провязки → независимые
инъекции → полный runtime → повтор retention → review посадки и main.
Локальное go.work допустимо для разработки; single-repo доказательство использует
опубликованный пин. Удаление старой частной реализации связывается с готовностью нового
потребителя и не выполняется раньше работоспособного вызова.

| Риск | Сценарии | Различающий опыт |
|---|---|---|
| очищен экземпляр, пропущено семейство | CI-NP-02, CI-NP-05, CI-NP-07 | матрица всех форм; новый upload; весь объявленный состав |
| очистка скрыла падение пробы | CI-NP-01, CI-NP-06 | красный тест остаётся красным, пустая подделка не зеленеет |
| не проверено, но разрешено | CI-NP-03, CI-NP-05 | обрыв/отсутствие scanner или verdict; upload не вызван |
| проверены другие байты | CI-NP-04 | mutation после последнего check; получатель видит только проверенный buffer |
| неизвестная упаковка выдана за распознанную | CI-NP-02, CI-NP-03 | opaque text снимается целиком; unknown declared encoding не CLEAN |
| секрет утёк через metadata/ошибку | CI-NP-02 | filename/key/testname/error/manifest/log canaries отсутствуют во всех выходах |
| проекция разрушила смысл отчёта | CI-NP-01, CI-NP-07 | существующие readers на обеих формах; full positive identity+all-platform verdict |
| форк общего производителя | CI-NP-05, CI-NP-07 | оба single-repo consumers используют одну опубликованную версию |
| ложное расширение containment | CI-NP-08, CI-NP-09 | metadata drift; чистый/неосмотренный пакет не удаляется |
