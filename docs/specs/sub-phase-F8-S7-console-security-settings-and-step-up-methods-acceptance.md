## §0 Обзор

### 0.1 Что реализуется

Экран `/settings` становится одним экраном **«Безопасность»** личного кабинета: сверху — сводка
защищённости учётной записи, ниже — разделы «Способ входа», «Второй фактор», «Ключи доступа»,
«Запасные коды», «Активные сессии», с навигацией по разделам. У каждого способа видно имя,
состояние, дату добавления и последнее использование. Опасные действия требуют подтверждения
вторым фактором и называют последствие словами. Окно подтверждения действия (повышения)
предлагает **любой** заведённый способ — ключ доступа, код из приложения, запасной код — и
выбирает по умолчанию самый сильный. Если ключи доступа на установке выключены, экран так и
говорит, вместо отказа о происхождении в конце церемонии (`kacho#3229` п. 4). Край
ретранслирует новый путь службы.

### 0.2 Почему отдельный документ серии F8, а не редакция F8

Приёмка экранов церемоний F8 одобрена на своём отпечатке; правка её сняла бы одобрение у всех
полос, идущих по ней (`change-graph` §3). Предмет «экран Безопасность» с F8 делит ровно три
решения — Р11 (раздел ключей), Р12 (окно свежести) и вид перечня сессий F8-S5; они заменяются
поимённо в §5, остальное F8, F8-S4, F8-S5, F8-S6 берётся ссылкой.

## §2 Решения (ратифицировать явно)

### Р1. Один экран «Безопасность» на прежнем адресе; разделы — в порядке задач человека

Адрес — `/settings` (F8 Р1, новой ручки нет). Заголовок страницы — **«Безопасность»**. Порядок
разделов фиксирован:

1. **Сводка** — карточка над разделами: «Вход» (адрес почты, признак подтверждения через
   `BoolFact`), «Подтверждение действий» (перечень доступных способов словами либо «не
   настроено»), «Активные сессии: N». Если `stepUpMethods` пуст — рекомендация «Включите второй
   фактор: без него действия, меняющие доступ, недоступны» с кнопкой «Настроить», ведущей к
   разделу «Второй фактор».
2. **Способ входа** — адрес почты и его смена (F8-S6), пароль (F8 Р13 без изменения), строка
   «Вход ключом доступа» — `BoolFact` от `accessKeys.available` и числа ключей.
3. **Второй фактор** — таблица способов (Р2).
4. **Ключи доступа** — таблица ключей (Р3).
5. **Запасные коды** — остаток, даты, перевыпуск (Р4).
6. **Активные сессии** — таблица своих сессий и «Выйти на всех, кроме этой» (F8-S5, вид — Р3).

Навигация по разделам — список ссылок-якорей в шапке страницы (`nav` с именем «Разделы
страницы») на пять разделов 2–6; сводка в навигацию не входит — она первой стоит под шапкой и
видна без перехода; прокрутка одна (`ui-page-single-scroll`). Каждый раздел — `section` с заголовком
второго уровня, на который ссылается его `aria-labelledby`.

**Отвергнуто:** отдельные адреса на раздел — второй адрес о параметрах учётной записи (F8 Р11);
вкладки — скрывают сводку и не дают увидеть все способы разом, а именно этого просит
решение владельца.

### Р2. Способ второго фактора — строка таблицы: имя, состояние, добавлен, последнее использование

Раздел «Второй фактор» — общая таблица (`ResourceTable`, `ui-shared-table-and-form-shell`),
три строки, по строке на способ словаря:

| имя строки | состояние (`BoolFact`) | «Добавлен» | «Последнее использование» | действие |
|---|---|---|---|---|
| Приложение-аутентификатор | «Настроено» / «Не настроено» / «Настройка не завершена» (`totp.enrolled`, `totp.pendingUntil`) | `totp.confirmedAt` | `totp.lastUsedAt`; ключа нет — «Ещё не использовалось» | «Настроить» либо «Отключить» |
| Ключи доступа | «Есть: N» / «Нет» / «Выключены на установке» | — (даты — у каждого ключа, Р3) | — | «Перейти к ключам» (якорь) |
| Запасные коды | «Осталось K из 10» / «Нет» | `backupCodes.issuedAt` | `backupCodes.lastUsedAt`; ключа нет — «Ещё не использовались» | «Перейти к кодам» (якорь) |

Даты — локальным форматом «14 окт. 2026, 21:04»; полный момент — подсказкой, приходящей и по
фокусу, и по наведению (канон консоли §8а). Прочерка на месте факта нет: ячейка без источника
не показывается (`ui-no-field-without-source`); «Ещё не использовалось» — сам факт, потому что
отсутствие ключа ответа контракт определяет как «не было» (SUA Р6).

Заведение кода: окно «Настроить приложение-аутентификатор» показывает **QR-код** адреса
`otpauth` и, как текстовую альтернативу, секрет с кнопкой копирования; затем поле «Код из
приложения» парой «имя — ввод» (`FormGrid`). QR-код рисуется в браузере кодом консоли:
секрет не уходит ни в один запрос, кроме ответа службы, который его выдал (перепись обращений).

### Р3. Ключи доступа и сессии — общей таблицей, у ключа — даты

Раздел «Ключи доступа» — `ResourceTable`, колонки: «Имя» (с описанием второй строкой, если
есть), «Добавлен» (`createdAt`), «Последнее использование» (`lastUsedAt`; нет — «Ещё не
использовался»), действие «Удалить». Под таблицей — «Добавить ключ доступа». Переименования нет
(у контракта Ф7 правки ключа нет — SUA §6). Перечень сессий F8-S5 переезжает в ту же таблицу без
смены поведения. Своих `<ul>` у перечней после правки — 0 (§1 → было по 1).

### Р4. Запасные коды: показ один раз, перевыпуск с предупреждением

Раздел «Запасные коды» — строки свойств: «Осталось» (`K из 10`, при `K ≤ 2` — предупреждение
«Запасные коды заканчиваются — выпустите новые»), «Выпущены» (`issuedAt`), «Последнее
использование». Действие «Выпустить новые коды» — опасное (Р6). Коды показываются **один раз**
— в ответе подтверждения заведения и перевыпуска: окно «Сохраните запасные коды» с кнопками
«Копировать» и «Скачать (.txt)» и подтверждением «Я сохранил коды», без которого окно не
закрывается кнопкой «Готово». После закрытия кодов нет нигде на странице: служба их больше не
отдаёт (SUA-60).

### Р5. Окно подтверждения предлагает любой заведённый способ; выбор по умолчанию — самый сильный

Перечень способов окно берёт из `stepUpMethods` (SUA Р6) — не выводит сам (F8 Р2). Порядок
показа — консоль: **ключ доступа → код из приложения → запасной код**. Способ по умолчанию —
первый доступный из `webauthn`, `totp`; запасной код по умолчанию не выбирается никогда (он
расходуется). Остальные способы — группой переключателей «Другой способ» (стрелки клавиатуры
внутри группы, `radiogroup`).

| `stepUpMethods` | окно открывается с | ещё предлагает |
|---|---|---|
| `["lookup_secret","totp","webauthn"]` | кнопкой «Подтвердить ключом доступа» | «Код из приложения», «Запасной код» |
| `["lookup_secret","totp"]` | полем «Код из приложения» | «Запасной код» |
| `["webauthn"]` | кнопкой «Подтвердить ключом доступа» | — |
| `[]` | текстом «Нет способа подтверждения» и ссылкой «Настроить второй фактор» | — |

Ветвь ключа: `POST /iam/v1/auth/step-up/access-key/begin` → церемония браузера
(`navigator.credentials.get` с выданными `allowCredentials`) → `POST /iam/v1/auth/step-up`
`{method: "webauthn", credential}` → повтор исходного действия (F8 условие C2).

Тексты окна на исходы службы (дословно; причина и действие выбираются по `code` и `reason`, F8 C2):

| исход | текст окна | окно |
|---|---|---|
| 401 `authentication failed` | «Подтверждение не прошло. Повторите или выберите другой способ.» | остаётся открытым, ввод сохранён у ключа — новое испытание по кнопке |
| 429 `TOO_MANY_ATTEMPTS` | «Слишком много попыток. Повторите через N мин.» (N — из `Retry-After`, вверх до минуты) | ввод заблокирован до срока |
| 400 `CHALLENGE_*` | «Время подтверждения ключом истекло — повторите» | новое испытание по кнопке |
| отказ церемонии браузером | «Подтверждение ключом прервано в браузере — повторите или выберите другой способ» | `step-up` **не** зовётся |
| `SECOND_FACTOR_NOT_ENROLLED`, `ACCESS_KEY_NOT_REGISTERED`, `ACCESS_KEYS_DISABLED` | перечень способов перечитывается, способ исчезает из выбора | остаётся открытым |
| 200 запасным кодом | «Осталось запасных кодов: K»; при `K ≤ 2` — предупреждение Р4 | закрывается после повтора действия |

Путь «Войти заново» (F8 Р12) остаётся **только** при `stepUpMethods = []` на отказе свежести:
для человека с ключом теперь есть прямой путь.

### Р6. Опасные действия — диалог с последствием словами и подтверждение вторым фактором

| действие | диалог называет | подтверждение |
|---|---|---|
| «Отключить» приложение-аутентификатор | «Коды из приложения и запасные коды перестанут работать.» Если после снятия `stepUpMethods` пуст — ещё «Действия, требующие второго фактора, станут недоступны, пока вы не настроите его снова.» | код из приложения либо запасной код в самом диалоге (служба снимает только кодом, Ф12 Р9) |
| «Удалить» ключ доступа | имя ключа; «Войти этим ключом будет нельзя.» Если ключ — единственный способ уровня «2» — ещё «Действия, требующие второго фактора, станут недоступны.» | окно повышения, если служба ответила указанием на уровень или свежесть (пол «2», SUA Р9) |
| «Выпустить новые коды» | «Прежние запасные коды перестанут работать сразу.» | код из приложения в диалоге |
| «Выйти на всех, кроме этой» | «Все другие устройства выйдут из учётной записи.» | окно повышения при отказе свежести |

Кнопка подтверждения диалога — опасного вида и называет действие («Отключить», «Удалить»,
«Выпустить», «Выйти»); фокус при открытии — на «Отмена». Отмена ничего не выпускает (F8-60).
Отказ «последний способ входа» показывается **дословно** текстом службы, ключ остаётся
(F8 Р11 без изменения: кнопка «Удалить» есть у каждого ключа).

### Р7. «Выключено на установке» — состоянием раздела, а не отказом

При `accessKeys.available = false`: в разделе «Ключи доступа» — пустое состояние со своим
рисунком (канон консоли §7) и текстом «Ключи доступа на этой установке выключены
администратором»; кнопки «Добавить ключ доступа» нет; уже заведённые ключи (если есть) показаны
таблицей с «Удалить». В окне подтверждения ключа нет (`stepUpMethods`). В сводке и строке «Вход
ключом доступа» — «Выключены на установке». Обращений `BeginRegistration` раздел при этом не
выпускает (перепись обращений).

Снятие ключа служба держит на полу «2» и при выключенных ключах (SUA Р7, редакция 2): «2» здесь
даёт только код. Поэтому у человека, у которого `stepUpMethods` пуст, «Удалить» ключ не ведёт в
окно подтверждения с «Настроить второй фактор» — этот путь у личности с ключом тоже требует «2»
(level-two Р4) и замкнулся бы в круг. Вместо окна — сообщение в `role="status"`: «Удалить ключ
сейчас нельзя: нужен второй фактор, а ключи на этой установке выключены. Попросите
администратора установки сбросить ваши ключи доступа.» — и обращений `Revoke` в переписи 0. У
человека с кодом «Удалить» ведёт в обычное окно подтверждения со способами `stepUpMethods`.

### Р8. Пустые состояния — на пустом ответе, с действием

| раздел | условие | текст | действие |
|---|---|---|---|
| Второй фактор | `totp.enrolled = false`, ключей нет | «Второй фактор не настроен. Он нужен для действий, меняющих доступ.» | «Настроить приложение-аутентификатор», «Добавить ключ доступа» (если `available`) |
| Ключи доступа | перечень пуст, `available = true` | «Ключей доступа нет. Входите и подтверждайте действия без пароля и кода.» | «Добавить ключ доступа» |
| Запасные коды | фактор не заведён | «Запасные коды появятся после настройки приложения-аутентификатора.» | — |
| Активные сессии | только текущая | «Других активных сессий нет.» | — (кнопка «Выйти на всех, кроме этой» не показана) |

Приглашение — только на пустом ответе края (`ui-empty-state-for-empty-answer`).

### Р9. Доступность — клавиатура и экранный диктор

- Каждое действие — кнопка, достижимая обходом и срабатывающая по Enter и пробелу; подписи,
  даты и признаки в обход не попадают (канон консоли §8а, обе стороны).
- Диалоги и окно подтверждения держат фокус внутри, закрываются по Esc, возвращают фокус на
  вызвавший элемент.
- Исход действия (ключ добавлен, фактор отключён, коды выпущены, сессии завершены, отказ)
  объявляется областью `role="status"` (отказ — `role="alert"`) текстом, а не только цветом.
- QR-код — изображение с именем «QR-код для приложения-аутентификатора»; секрет текстом рядом —
  его доступная альтернатива.
- Таблицы — с заголовками колонок; у кнопки строки доступное имя называет предмет:
  «Удалить ключ доступа «<имя>»».

### Р10. Край ретранслирует выдачу испытания повышения ключом

Запись ретрансляции `{Verb: "step-up-access-key-begin", Path: "/iam/v1/auth/step-up/access-key/begin", Target: RelayTargetForm}`
— тем же механизмом и с тем же флагом доступности до подтверждения адреса, что у `step-up`
(закрыта, F6b Р5). Записей становится 27. Гейт достижимости уровня
(`identity_second_factor_reachable_test.go`) сверяет `OWN_STEP_UP_METHODS =
["totp","lookup_secret","webauthn"]` со службой.
