# CI-PY-1 — предварительный технический замысел

> DRAFT, 2026-09-17. Независимого design-review нет. Код и новые тесты не написаны.
> Приёмка: sub-phase-CI-PY-1-python-outcomes-acceptance.md.

## 1. Измеренный разрыв и граница

Снимок kacho main: b5fa093341f1fdbe96adfc6a9555482690968253. Координаты относятся
к этому снимку, а не обещают неизменных строк. `execute()` в run-python-probes.py
уже возвращает 2 при недоступном pytest (:300–310), но не выводит итоговую
перепись и говорит об исторических 48 пробах. `self_test()` (:451–554)
сравнивает синтетические исходы с 0/1 и превращает отсутствие pytest в провал
утверждений. Общий run-gate-self-tests.sh (:468–504) уже читает 2 как unmet.
Make (`deploy/Makefile:1124–1126`, :1301) сворачивает ошибку рецепта в 2.
ci-local.sh:246–315 трактует этот код общей веткой как finding. Нужен ремонт
всей цепочки, а не замена одной цифры.

Прямой CI-вызывающий — ci.yaml:1323–1336 (самопроверка, обычный проход и отдельный
pr_verdict_test.py). Второй путь — ci.yaml:2531–2537, Make gate-self-test,
повторно через helm-manifest-test. Зависимость pytest уже устанавливается
в соответствующих заданиях, но установка не является свидетельством исполнения.

## 2. Решения для независимого review

**D1. Сохранить 0/1/2 у Python и общего прогонщика самопроверок.**
0 — полный проход, 1 — finding/дефект состава, 2 — подтверждённая неполнота.
В #2629 число 75 приведено как принятый пример, обязательный predicate — число,
отличное от 0/1. Живой непосредственный caller различает именно 2. Упомянутого
newman-suite-debt.py в этом main уже нет; 75 сейчас применяется в другом
контракте pgtest. Перевод одного Python-производителя на 75 сломал бы существующий
caller и потребовал лишней миграции. argparse usage также может вернуть 2:
одного кода недостаточно, чтобы признать отсутствие pytest.

**D2. Один результат запуска, одна перепись.**
Отделить сбор результата от печати/exit. Результат содержит объявленный состав,
исполненные экземпляры, находки, невыполненные участники и причины. Все ветви
завершаются общей сводкой, включая отсутствие зависимости. AST даёт объявления,
JUnit — подтверждённые экземпляры и их исходы. Не сравнивать эти разные единицы
на равенство при параметризации. Потерянный/неразбираемый отчёт даёт неполноту;
пустой состав, немой файл, запрещённый skip остаются finding. Ошибку импорта
pytest отличать от сбоя самого интерпретатора; причина «нет pytest» требует
свидетельства именно отсутствия модуля, а не любого ненулевого subprocess.

**D3. Самопроверка создаёт и проверяет собственные предусловия.**
Проверить доступность pytest до зависимых утверждений; отсутствие не кормить
в check(label, rc == expected). Независимые проверки можно выполнить, но итог
должен явно показывать оставшийся состав. Для нормальной самопроверки с pytest
сохраняются все нынешние инъекции и их положительные близнецы. Новые внешние
проверки этого поведения исполняются интерпретатором с созданной предпосылкой;
контролируемое отсутствие задаётся только дочернему испытуемому.

**D4. Минимальный общий транспорт категории через Make.**
Предлагается один небольшой формат JSON результата и одна общая реализация
записи/чтения на Python stdlib; не три независимых парсера русского вывода.
Опциональный путь результата передаётся только участникам этой цепочки.
Для вызова выделяется новый временный каталог вне git. Запись атомарная,
содержит версию, идентификатор текущего вызова, производителя, категорию,
причины, именованные счётчики; сообщение человеку строится из того же результата.
Общий прогонщик принимает дочерний код 2 как «нет pytest» только с согласованным
результатом этого Python-вызова. Остальные существующие rc2-причины сохраняются
с их собственными именами, без переименования в pytest.

Общий прогонщик публикует итоговую запись перед выходом. Make по-прежнему даёт
свой код; его двойка сама не является категорией. Локальный вызывающий читает
итог этого вызова: только подтверждённая неполнота без находок позволяет
увеличить skips вместо fails. Если prerequisite gate-self-test остановил Make,
его запись относится к этому остановленному пути. Когда самопроверки прошли,
их GREEN не объясняет более позднюю ошибку helm-manifest-test: такой отказ
сохраняется отказом, пока нет собственного текущего результата.

Старый файл, чужой ID, отсутствующий/повреждённый результат, противоречивые
счётчики и неизвестная категория не дают «нет pytest». Никакого eval/source,
общего файла отметки в checkout или поиска подстроки pytest во всём логе.
Детали имени файла/CLI выбираются реализацией в пределах этого формата после
review; новый универсальный framework результатов не нужен.

**D5. Агрегация не теряет соседний finding.**
При наличии finding код общего прогонщика 1, даже если рядом unmet. В сводке
обе категории. При отсутствии finding и наличии unmet код 2. Только полный
непустой исполненный состав даёт 0. У ci-local для отсутствующего pytest
сохраняется действующая политика локального skip; число не выполненных и
явное слово «неполный» обязательны. Resource-aborted rc3 не меняется.

**D6. CI разделяет сбор категории и обязательный итог.**
В прямом Python-пути сборщик захватывает код через cmd && rc=0 || rc=$?,
объявляет unmet аннотацией и структурированным результатом; третий исход может
завершить этот сборщик нулём. Отдельный обязательный шаг с always() требует
полного результата обычного прохода и самопроверки; неполнота/нет результата
дают failure итогового задания. Нельзя использовать success самого сборщика
как доказательство исполнения. Отдельный pr_verdict_test.py остаётся обязательным.

Путь общего run-gate-self-tests также публикует понятную категорию/причину в CI;
сам Make может остаться nonzero, поскольку его текущий aggregate job уже
отказывает при недостающем вердикте. Действующий assert-declared-verdicts-ran
сохраняет финальный контроль. Если в реализации понадобится collector=success
в этом пути, обязательный финальный читатель должен потреблять category,
а не только steps.*.conclusion; это изменение требует явной проверки CI-PY-12.

**D7. Состав вызывающих выводится, не перечисляется для удобного GREEN.**
Проверка workflow читает разобранный YAML, связывает шаги с заданиями и shell
командами. Она доказывается настоящими телами шагов, отсутствующим вызовом,
комментарием-подделкой и чужим заданием установки зависимости. Scope охвата:
обычный/--self-test Python, общий selftest-runner, цели Make, ci-local и CI.
Не менять весь tree discovery Python-проб в этой правке.

## 3. Законные близнецы и свидетельство RED

Пары различаются одним установленным фактом: наличие pytest в дочернем
интерпретаторе; истинность одного assert; пригодность одного отчёта; свежесть
одной записи. Драйвер сначала доказывает исправность своей оснастки и полный
положительный запуск. Поведенческий тест далее запускает реальные CLI,
run-gate-self-tests, Make и ci-local. Подмена returncode метода без запуска
цепочки не доказывает #2705. Полный helm-путь должен иметь реальные helm/yq и
зависимости; отсутствие этих условий — «проверка не состоялась», не RED реализации.

Радиус fixture не меняет пользовательский checkout: отдельный временный git
репозиторий или worktree с заданным исходником; убрать все унаследованные GIT_*
(#2274), задать TMPDIR вне дерева, GOWORK=off. Окружение venv создаётся для
проверяющего, глобальная установка не требуется. Захватить точную команду,
SHA/дифф, фактические binary/version, stdout/stderr, rc, исходный и итоговый
результат, declared/executed/finding/unmet по каждой границе.

## 4. Границы предварительного замысла

Все механизмы D1–D7 пока предложены. Ни один новый holder не считается
реализованным; отсутствуют runtime evidence и независимые approvals. Точный
состав новых файлов и команд holder выбирается после acceptance-review,
class-exposure revalidation и design-review, затем фиксируется до RED.
Нет изменений RPC, схем БД, секретов, production-развёртывания и quota.
Применимость профильных ролей устанавливается по фактическому будущему diff.
