## 0. Обзор

Продукт забирает вход человека себе и переносит существующие учётные данные. Перенос обещан
**дословным**: пароль не сбрасывается, проверочное значение переезжает как есть. Обещание
исполнимо ровно настолько, насколько продукт умеет **прочитать** то, что переехало.

Переехавшая популяция содержит **два** формата проверочного значения, а не один, и доля второго
растёт монотонно, потому что конфигурация объявляет его для каждого вновь заводимого пароля.
Проверяющих в продукте сегодня **ноль**, а план эпика называет **один**. Эта приёмка закрепляет:
проверяющих обязано быть столько, сколько форматов встречается в популяции; выбор между ними
идёт **по признаку самого хранимого значения**, а не по настройке; значение, формат которого
продукт не знает, отвергается **явно и громко**, а не пропускается молча.

## 1. Что верно в дереве и на стенде сегодня

Каждое число ниже снято названным предикатом на названной ревизии, и каждый предикат прогнан
**с контролем в обе стороны**: предикат, который умеет находить, обязан это показать на
заведомом примере, иначе «ноль находок» неотличимо от «ноль прочитанного».

### 1.1 Проверяющих пароля в продукте — ноль

**Единица счёта — вхождение в не-тестовом исходном файле.** Ревизия — `kacho@ba9527370`.

```sh
git grep -n 'CompareHashAndPassword\|crypto/bcrypt\|argon2\|scrypt\|pbkdf2' -- '*.go' ':!*_test.go'
```

Вывод пуст: **0** вхождений в **0** файлах. Перепись осмотренного: обход шёл по всему индексу
монорепо, а не по каталогу одного сервиса.

**Контроль «обязан находить» (a) — те же токены в дереве есть, значит написание findable:**

```sh
git grep -l 'argon2\|bcrypt' -- deploy/        # 5 файлов
```

**Контроль «обязан находить» (b) — синтетика.** Файл из трёх строк, содержащий обращение к
проверяющему, тем же образцом ловится: **2** совпадения. То есть ноль в прод-коде — свойство
дерева, а не сломанного предиката.

**Зеркальная форма предиката.** Обратный вопрос — «объявлено ли средство» — отвечает иначе:
`go.mod` несёт `golang.org/x/crypto v0.55.0`. Библиотека доступна, **читателя у неё нет**. Это
важно для чтения плана эпика: он опирается на доступность средства, а не на существование
проверяющего.

**Расширение по языкам.** Тот же вопрос вне Go (консоль, скрипты) — тоже ноль:

```sh
git grep -lI 'CompareHashAndPassword\|argon2id\|bcrypt.compare\|verifyPassword\|VerifyPassword' -- ':!deploy/' ':!docs/'
```

**Что это значит.** Проверку пароля сегодня целиком исполняет внешний компонент. Продукт не
теряет способность — он её **ещё не заводил**; предмет этой приёмки существует полностью
впереди.

### 1.2 Формат вновь заводимых значений задаёт **наша** конфигурация

Раздел объявлен в шаблоне, из которого собирается монтируемая карта настроек:

```sh
grep -n -A7 '^hashers:' deploy/helm/umbrella/charts/kacho-iam/templates/_kratos-identity.tpl
```

даёт `algorithm: argon2` и параметры (память 64 МБ, три итерации, четыре потока, длина соли 16,
длина ключа 32). Раздел лежит внутри определения `kacho.identity.configYaml`, а карта настроек
это определение **включает** — то есть объявление доезжает до смонтированного файла, а не
остаётся в шаблоне.

**Контроль «обязан пропускать».** Второго объявления формата в том же шаблоне нет:
`grep -c 'algorithm: bcrypt'` → **0**. Формат объявлен ровно одним местом.

**Авторитетно — что читает живой процесс.** Процесс службы личности получает **два** источника
настроек и сливает их по порядку; наш — второй, то есть он **замещает** одноимённый раздел
поставщика целиком. Прочитано в работающем контейнере: наш источник объявляет `argon2` с
параметрами выше; источник поставщика раздела `hashers` **не содержит вовсе** — до монтирования
нашей карты действовало умолчание поставщика.

**Следствие, которое и порождает предмет:** момент, когда наша карта впервые стала читаемой,
разделил популяцию надвое. Это ровно класс «конфигурация, впервые ставшая читаемой, перебивает
умолчание поставщика» (`architecture.md`), только последствие у него на этот раз не в полосе
входа, а **в данных**.

### 1.3 Форматов в живой популяции — два

Замер живой базы службы личности стенда a8f60d, 2026-08-27. **Единица счёта — строка способа
входа вида «пароль».** Признак формата берётся из самого значения — первый сегмент его
разметки:

```sql
SELECT ct.name,
       split_part(ic.config->>'hashed_password', chr(36), 2) AS marker,
       count(*)
FROM identity_credentials ic
JOIN identity_credential_types ct ON ct.id = ic.identity_credential_type_id
WHERE ct.name = 'password'
GROUP BY 1, 2 ORDER BY 3 DESC;
```

| признак формата | обозначение в этом документе | строк |
|---|---|---:|
| `2a` (bcrypt) | **формат A — наследуемый** | **76** |
| `argon2id` | **формат B — объявленный и растущий** | **7** |
| **итого строк способа «пароль»** | | **83** |

**Контроль «обязан различать».** Тот же предикат без сужения по виду способа даёт три разных
вида с разными числами (`password` 83 · `webauthn` 6 · `lookup_secret` 1) — значит соединение и
отбор действительно читают данные, а не возвращают одну корзину.

**Контроль «обязан дать ноль».** Тот же предикат на признаке, которого в популяции быть не
должно, отвечает **0**. Обе стороны пройдены, число называть можно.

**Даты заведения — они и доказывают монотонность, а не заменяют её словом:**

| дата | формат A | формат B |
|---|---:|---:|
| 2026-08-11 | 24 | 1 |
| 2026-08-12 | 33 | 0 |
| 2026-08-15 | 15 | 0 |
| 2026-08-16 | 1 | 0 |
| 2026-08-17 | 1 | 0 |
| 2026-08-20 | 1 | 0 |
| 2026-08-21 | **1** | 0 |
| 2026-08-24 | 0 | **4** |
| 2026-08-26 | 0 | **2** |

Производство формата A прекратилось **2026-08-21**; всё, что заведено с 2026-08-24, — формат B,
**6 из 6**. Числитель формата A заморожен, знаменатель растёт: доля формата B возрастает с
каждым новым паролем **строго**, без исключений.

### 1.4 Посылка эпика опровергнута — и она была неверна **в момент написания**

Тело #1266 и тело #1268 утверждают дословно: «пароли: 77 из 77 — bcrypt `$2a$12$`, иных форматов
0» и, как следствие, «Проверка пароля — `golang.org/x/crypto/bcrypt` по существующему хешу:
перенос дословный, сброс не требуется».

Соблазнительное объяснение — «замер был верен 2026-08-25 и устарел». **Оно неверно.** Тот же
предикат, суженный по дате замера эпика:

```sql
… WHERE ct.name = 'password' AND ic.created_at < '2026-08-26'::date …
```

даёт **76 формата A и 5 формата B**. Второй формат существовал уже тогда.

**Механизм ошибки назван самим телом задачи:** «77 из 77 **проверенных**» при `password = 80`.
Три строки из восьмидесяти осмотрены не были, а вывод («иных форматов 0») сделан обо **всей**
популяции. Это выборка, поданная переписью, — а не число, состарившееся со временем. Отсюда
практическое требование, которое эта приёмка закрепляет сценарием PWV-12: **перед переносом
делается перепись форматов, а не выборка**, и непокрытый формат обязан ронять перенос **до его
начала**, а не проявляться отказом входа после.

**Заодно замечено тем же замером** (предмет чужих под-задач, здесь не решается и приводится как
свидетельство того, что снимок эпика стареет целиком, а не в одной клетке): ключей доступа
**6**, а не 3; резервных кодов **1**, а не 0.

### 1.5 Сводка: что закрывает эта приёмка

| | план эпика | дерево сегодня | популяция сегодня |
|---|---:|---:|---:|
| проверяющих пароля | 1 | **0** | требуется **2** |

Разрыв двойной. Меньший — «ноль против одного» — закрывается работой, которая и так объявлена
(Ф2/Ф3). Больший — «один против двух» — не закрывается ничем: он **не назван** ни в одной
задаче, поэтому был бы обнаружен не переписью, а людьми, которые не смогли войти.

## 2. Цена отсрочки — числом

- **Сегодня не вошли бы 7 личностей из 83** (8.4 %) — те, чьё значение формата B, при плане,
  предусматривающем проверяющего только для формата A.
- **Доля растёт монотонно и строго.** Формат A заморожен на 76 с 2026-08-21; каждый новый пароль
  увеличивает и числитель, и знаменатель доли формата B. За последние трое суток заведено 6
  значений — **все** формата B.
- **Отсрочка не удешевляет работу, а меняет её род.** Пока проверяющего нет, речь идёт о
  ненаписанном коде. После переноса без него речь пойдёт об **утрате доступа** у живых людей, и
  единственным лечением останется принудительный сброс — ровно то, отказ от чего объявлен
  выигрышем эпика.
- **Отдельная, не арифметическая цена.** Отказ будет выглядеть как «неверный пароль»: человек
  введёт правильный пароль и получит обычный отказ. Такой дефект не диагностируется со стороны
  человека вовсе, а со стороны поддержки — только сравнением популяции с перечнем форматов, то
  есть той самой переписью, которую дешевле сделать заранее.

## 3. Норма, которую приёмка закрепляет

Пять решений. Каждое — ответ на вопрос, у которого иначе появится два ответа в разных местах.

**Р1. Проверяющий выбирается по признаку ХРАНИМОГО ЗНАЧЕНИЯ, а не по настройке.**
Настройка «формат новых паролей» отвечает на вопрос **что писать**. Хранимое значение отвечает
на вопрос **как читать**. Это разные вопросы, и у каждого ровно один хозяин. Слить их — завести
два правила об одном поле: смена настройки молча сделала бы нечитаемой уже лежащую популяцию.

**Р2. Перечень поддерживаемых форматов — закрытый, объявлен ровно одним местом, корзины «прочее»
не имеет.** Значение, чей признак формата в перечень не входит, — **наша** ошибка (данных либо
настройки), а не ошибка человека и не временный сбой соседа. Оно отвергается терминально и
громко; политики повтора у него нет.

**Р3. Отсутствие проверочного материала представимо отдельно от его несовпадения.**
«Материала нет» и «материал не совпал» не имеют общего представления ни в хранилище, ни в
исходе проверки, ни в наблюдаемости. Оба ведут к отказу — но различить их обязана уметь
поддержка, иначе повреждение данных читается как поток неверных паролей.

**Р4. Наружу все отказы неразличимы; внутрь — различимы.** Человек и посторонний получают один и
тот же отказ независимо от формата значения, от его наличия и от того, существует ли такая
личность вообще: различимый отказ был бы оракулом. Оператор получает **отдельный счётчик** на
каждый исход Р2 и Р3. Эти два требования не конфликтуют: они адресованы разным наблюдателям.

**Р5. Успешная проверка значения формата A переписывает его в объявленный формат.**
Принято ради **предиката снятия**: без переписывания проверяющий формата A живёт вечно, потому
что условия, при котором его можно снять, не существует. С переписыванием условие есть и
измеримо — перепись §1.3 по формату A даёт ноль. Границы решения названы в §4 и проверяются
сценариями PWV-08…PWV-11; главная из них: **неудача переписывания не отменяет состоявшийся
вход и не бывает тихой**.

**Параметры стойкости — требование, а не наблюдение.** Формат B заводится с параметрами не ниже
объявленных сегодня (§1.2) и не ниже объявленных в приёмке F4d. Документ не характеризует
стойкость формата A и не приводит его параметров: предмет здесь — **читаемость перенесённого**,
а сравнение стойкости форматов ни одного сценария не меняет.

## 5. Сценарии

Уровень при идентификаторе: **E** — наблюдаемо снаружи, через попытку входа; **I** — контракт
проверяющего как компонента; **P** — свойство дерева либо популяции, проверяемое переписью.

Уровень I в этом документе присутствует намеренно: предмет приёмки — **компонент**, чьё
единственное внешнее проявление (успех или отказ входа) по построению одинаково для всех
интересных случаев, потому что этого требует Р4. Утверждать различие там, где оно запрещено,
значило бы требовать оракула.

### Полоса «продукт читает то, что переехало»

**PWV-01 — вход перенесённым паролем наследуемого формата** · E

**Given** человек, чьё проверочное значение перенесено и несёт признак **формата A**
**And** пароль этого человека не менялся с момента переноса
**When** он предъявляет свой прежний пароль
**Then** вход состоялся
**And** ему не предъявлено требования сменить или сбросить пароль
**And** исход не зависит от того, какой формат объявлен настройкой для новых паролей

**PWV-02 — вход перенесённым паролем растущего формата** · E

**Given** человек, чьё проверочное значение перенесено и несёт признак **формата B**
**And** пароль этого человека не менялся с момента переноса
**When** он предъявляет свой прежний пароль
**Then** вход состоялся — **тем же исходом, что в PWV-01**
**And** ему не предъявлено требования сменить или сбросить пароль
**And** это тот сценарий, который сегодня неисполним: проверяющего формата B в продукте нет
(§1.1), и он затрагивает 7 личностей из 83, а завтра больше (§2)

**PWV-03 — неверный пароль отвергается одинаково на обоих форматах** · E

**Given** два человека: у первого значение формата A, у второго — формата B
**And** оба значения годны, и оба человека входят верным паролем — **положительный контроль**,
без него утверждение об отказе зеленело бы на любом сломанном проверяющем
**When** каждому из них предъявляется неверный пароль
**Then** вход не состоялся ни у одного
**And** отказ **побайтово одинаков** для обоих: ни кодом, ни текстом, ни временем ответа он не
сообщает, какого формата значение лежит у человека
**And** тот же отказ приходит на несуществующую личность — существование не разглашается
**And** новой пары «код + статус» этот сценарий не вводит: пара принадлежит полосе входа (#1269),
здесь утверждается только её **неразличимость**

### Полоса «негодное отвергается явно, а не пропускается»

**PWV-04 — признак формата не входит в перечень: терминальный отказ, названный нашей ошибкой** · I

**Given** в хранилище лежит значение, чей признак формата в объявленный перечень **не входит**
**And** рядом лежит значение с признаком из перечня, и по нему вход проходит — **положительный
контроль**
**When** человеку с непокрытым значением предъявляется любой пароль, включая верный
**Then** вход не состоялся
**And** отказ наружу неотличим от отказа при неверном пароле (Р4)
**And** в наблюдаемости событие сосчитано **отдельным** счётчиком, отличимым и от «пароль не
совпал», и от «зависимость не ответила»
**And** событие **терминально**: политики повтора у него нет, потому что повтор того же запроса
не может дать иного исхода
**And** ноль таких событий за всё время обязан быть отличим от того, что счётчика никто не
смотрит: величина публикуется всегда, а не только когда ненулевая

**PWV-05 — признак формата известен, тело значения не разбирается** · I

**Given** значение, чей признак формата в перечень входит, а тело негодно — усечено, повреждено
либо не отвечает разметке своего формата
**And** рядом лежит годное значение того же формата, и по нему вход проходит — **положительный
контроль**
**When** предъявляется любой пароль, включая верный
**Then** вход не состоялся
**And** отказ наружу неотличим от отказа при неверном пароле
**And** событие сосчитано как **наша** ошибка, отдельно от «пароль не совпал»
**And** ни при каком предъявленном значении неразбираемое тело не даёт успеха — в том числе при
пустом предъявленном пароле

**PWV-06 — отсутствие материала не есть его несовпадение** · I

**Given** строка способа вида «пароль» существует, а проверочного материала у неё нет
**And** та же строка с материалом даёт вход — **положительный контроль**
**When** предъявляется любой пароль, включая пустой
**Then** вход не состоялся ни при одном предъявленном значении
**And** «материала нет» и «материал не совпал» не имеют общего представления: их различает и
исход проверки, и счётчик
**And** отсутствие материала **не** приводится к пустому значению и не сравнивается с ним:
сравнение пустого с пустым дало бы успех на строке, у которой пароля не заведено

### Полоса «два правила об одном поле не заводятся»

**PWV-07 — выбор проверяющего не зависит от настройки** · P

**Given** в хранилище лежат значения обоих форматов, и по обоим вход проходит
**When** настройка «формат новых паролей» меняется на любой другой из перечня
**Then** исход проверки **не изменился** ни для одного из уже лежащих значений: оба входа
по-прежнему проходят
**And** та же смена настройки изменила формат **вновь заводимого** значения — **положительный
контроль** того, что настройка вообще действует и сценарий не зеленеет на мёртвой ручке
**And** перечень форматов и настройка «что писать» остаются двумя разными объявлениями с одним
хозяином каждое

### Полоса «формат A получает предикат снятия»

**PWV-08 — успешная проверка формата A переписывает значение в объявленный формат** · I

**Given** человек, чьё значение формата A
**When** он входит верным паролем
**Then** вход состоялся
**And** хранимое значение теперь несёт признак объявленного формата
**And** **повторный вход тем же паролем проходит** — без этого утверждения переписывание могло
бы заменить годное значение негодным, и человек потерял бы доступ ровно в момент успешного входа
**And** прежнее значение не сохраняется рядом: переписывание замещает, а не добавляет

**PWV-09 — неудача переписывания не отменяет состоявшийся вход и не бывает тихой** · I

**Given** человек, чьё значение формата A
**And** запись в хранилище недоступна
**When** он входит верным паролем
**Then** вход **состоялся** — проверка уже дала свой ответ, и отказ записи не пересматривает его
**And** значение осталось формата A, и следующий вход снова попытается его переписать
**And** событие сосчитано отдельным счётчиком: мягкий проход здесь законен только потому, что он
**слышен**; молчаливый мягкий проход сделал бы правило Р5 неисполняемым навсегда и незаметно
**And** при доступной записи тот же вход даёт переписанное значение — **положительный контроль**

**PWV-10 — конкурентные входы переписывают ровно один раз** · I

**Given** человек, чьё значение формата A
**When** два входа с верным паролем доходят до записи одновременно
**Then** оба входа успешны
**And** запись выполняется **ровно одна**: замещение обусловлено тем, что значение всё ещё то,
которое проверяли, — решение и его следствие не разнесены во времени
**And** второй не затирает результат первого
**And** после обоих вход тем же паролем проходит — **положительный контроль** того, что гонка
не оставила негодного значения
**And** последовательные входы того же человека дают тот же результат, что и одновременные

**PWV-11 — значение, уже отвечающее объявленному, не переписывается** · I

**Given** человек, чьё значение формата B, и все его параметры не ниже объявленных
**When** он входит верным паролем
**Then** вход состоялся
**And** записи в хранилище **не произошло**: иначе каждый вход всякого человека порождал бы
запись, и стоимость входа стала бы функцией числа входов, а не числа переносимых значений
**And** значение формата A при том же входе переписывается — **положительный контроль** (PWV-08)
**And** значение объявленного формата, у которого **хотя бы один** параметр ниже объявленного,
переписывается наравне с форматом A: «объявленный формат» и «объявленные параметры» — одно
требование, а не два

### Полоса «непокрытый формат находится переписью, а не людьми»

**PWV-12 — перепись форматов перед переносом, а не выборка** · P

**Given** источник переноса содержит значения нескольких форматов
**When** перепись форматов источника сопоставляется с объявленным перечнем продукта
**Then** множество форматов источника обязано быть **подмножеством** перечня
**And** формат, встречающийся в источнике и отсутствующий в перечне, роняет перенос **до его
начала**, называя признак формата и число затронутых строк
**And** перепись читает **все** строки источника: выборка исходом не является — ровно она и
породила посылку, опровергнутую в §1.4
**And** перепись, целиком покрытая перечнем, проходит и печатает **объём осмотренного** —
«форматов вне перечня ноль» обязано быть отличимо от «прочитано ноль строк» — **положительный
контроль**

**PWV-13 — перечень форматов закрыт, и у каждого проверяющего есть предикат снятия** · P

**Given** перечень поддерживаемых форматов объявлен ровно одним местом
**When** перечень сопоставляется с проверяющими, которые есть в дереве
**Then** у **каждого** объявленного формата есть проверяющий, и у каждого проверяющего есть
объявленный формат — расхождение в любую сторону есть находка
**And** проверяющего разрешено снять **только** когда перепись §1.3 по его формату даёт ноль:
снятие проверяющего при непустой популяции лишает доступа ровно тех, кого перепись насчитала
**And** запись перечня, у которой не осталось ни строк в популяции, ни проверяющего в дереве, —
тоже находка: исключение живёт, пока у него есть предмет

## 8. Чем свойство держится впредь

Правило без механизма есть пожелание, и здесь это сказано прямо: ниже названо, что именно
краснеет, а где механизма нет — так и написано.

| Свойство | Чем держится | Способность упасть доказывается |
|---|---|---|
| перечень форматов объявлен **ровно одним** местом | гейт дерева | второе объявление перечня — красное с координатой; одно объявление — молчит |
| у каждого объявленного формата есть проверяющий и наоборот | гейт дерева, сверяющий обе стороны | снятие проверяющего при живой записи перечня — красное; снятие обоих вместе — молчит |
| выбор проверяющего производен от **значения** | гейт дерева | чтение настройки на пути выбора — красное; чтение признака значения — молчит |
| у классификатора формата нет ветки «прочее» на успешном пути | гейт дерева | добавление ветки, ведущей к успеху либо к общему отказу без счётчика, — красное |
| обе полосы проверки живы | парная проба: формат × верный/неверный пароль, четыре клетки | снятие любого проверяющего роняет ровно свои две клетки, остальные молчат |
| переписывание не портит значение | проба PWV-08 с обязательным повторным входом | подмена записываемого значения мусором — красное; корректное переписывание — молчит |
| переписывание атомарно | проба гонки под детектором гонок | разнесение чтения и записи — красное **детерминированно**, а не в одном прогоне из десяти |
| непокрытый формат находится **до** переноса | предполётная перепись, роняющая перенос | синтетическая строка с признаком вне перечня — красное с числом строк; популяция в перечне — молчит, напечатав объём осмотренного |
| «ноль находок» отличимо от «ноль прочитанного» | перепись печатает объём осмотренного всегда | пустой источник даёт отдельный исход, а не успех |
| фикстура не снисходительнее продукта | подставной проверяющий обязан исполнять контракт настоящего **тем же кодом**, а не своей копией | синтетика: вход, на котором настоящий отвечает отказом, обязан давать отказ и на подставном |
| отдельные счётчики Р2/Р3 публикуются даже нулевыми | **вниманием, механизма нет** | — |
| отказ побайтово одинаков по времени ответа | **вниманием, механизма нет**: равенство текста и кода проверяется пробой, равенство времени — нет | — |

Две последние строки — честный долг, а не оговорка. Первая закрывается наблюдаемостью в той же
работе; вторая требует замера, который в этой приёмке не заказан, и её стоит завести отдельным
предметом, если она признаётся значимой.

## 9. Порядок работ после APPROVED

Порядок задан зависимостями, а не удобством: перечень форматов — предмет, на который смотрят
все остальные шаги.

1. **перечень форматов** и его гейт (PWV-13) — до первого проверяющего, иначе второй заводится
   копией первого и перечень рождается в двух местах;
2. **проверяющие обоих форматов** и выбор по признаку значения (PWV-01, PWV-02, PWV-07);
3. **отказы**: неизвестный формат, негодное тело, отсутствие материала, неразличимость наружу
   (PWV-03…PWV-06);
4. **предполётная перепись** переноса (PWV-12) — до того, как перенос будет прогнан хоть раз;
5. **переписывание при успешной проверке** и его границы (PWV-08…PWV-11).

Шаг 5 отделим: если он будет вынесен в отдельную задачу, приёмка остаётся исполнимой без него —
но тогда решение Р5 обязано быть **отозвано явно**, а вместе с ним исчезает предикат снятия
проверяющего формата A, и это надо назвать вслух, а не оставить умолчанием.

## 10. Что осталось решением, а не установленным фактом

Названо отдельно, чтобы ревьюер не принял выбор автора за измерение.

- **Р5 (переписывание при успешной проверке) — выбор, а не следствие замера.** Довод за:
  без него у проверяющего формата A нет условия снятия. Довод против: запись на пути входа.
  Разрешено в пользу «за», потому что запись происходит **один раз на значение**, а не один раз
  на вход (PWV-11), и потому что альтернатива — принудительный сброс, отказ от которого объявлен
  выигрышем эпика.
- **Требование «не ниже объявленных параметров» отнесено к тому же правилу, что и формат**
  (PWV-11). Это решение: их можно было развести. Сведены потому, что разведённые дают два
  условия переписывания в разных местах — то есть ровно тот класс, который закрывает Р1.
- **Уровень I в сценариях.** Выбран потому, что Р4 запрещает наружной различимости; предмет
  приёмки иначе непроверяем. Если ревьюер сочтёт, что уровень I выходит за жанр приёмки,
  альтернативы две: снять требование неразличимости (не предлагается) либо признать, что часть
  предмета проверяется только внутри.
- **Имя и раскладка компонента здесь не решаются** намеренно: приёмка говорит, **что** обязано
  быть верно, а не где это лежит.

## 11. Границы текста этого документа

Репозиторий публичен. Документ называет предмет, решение и следствие для контракта и **не**
содержит сборки «координата + условие, при котором защита не действовала + следствие для
постороннего».

Конкретно: параметры стойкости приведены как **требования** к тому, что продукт производит
(§1.2, Р5), а не как характеристика слабости чего-либо; стойкость наследуемого формата не
обсуждается и его параметры не приводятся, потому что ни одного сценария это не меняет; способ
обращения к живой базе назван предикатом на языке запросов, воспроизводимым тем, у кого доступ
уже есть, а не маршрутом до неё; учётные данные не приводятся нигде.

Числа популяции (§1.3, §2) публикуются осознанно: они и есть довод приёмки, они уже опубликованы
телом эпика в менее точном виде, и ни одно из них не сообщает постороннему ничего, чем он мог бы
воспользоваться.
