## §0 Обзор

Платформа заводит **базовый вид удостоверения**: однострочный непрозрачный секрет, который
предъявляется как есть — в `Authorization: Bearer` на крае и в поле пароля докер-полосы, — не
требует от клиента ни библиотеки JOSE, ни сборки подписанного утверждения, ни обмена.

Сегодня публичных глаголов выдачи удостоверений **два**, и оба возвращают **пару ключей** с
приватной половиной (§1.1). Клиент, попросивший «токен для доступа к API», получает материал, из
которого обязан **сам** собрать `client_assertion` по RFC 7523. Это законный и правильный вид для
федерации и долгоживущего доверия — и **неверный** вид для базового случая: `-p` не принимает
многострочный PEM, переменная сборочного конвейера — тоже, а приватная половина, уходящая по сети,
приватной быть перестаёт.

**Фаза разводит два предмета, сегодня слитых в один.** ES256-пара остаётся и ничего не теряет:
подпись утверждения, федерация внешнего издателя (#1124), долгоживущее доверие — её роль. Рядом
появляется второй вид с другой ценой: максимальная совместимость и минимум церемонии, оплаченные
коротким объявленным сроком, отзывом на предъявлении и узнаваемой маркой.

**Наблюдаемая цель фазы.** Человек и служебная учётка получают одной формой однострочный секрет,
показанный **один раз**; тот же секрет проходит на крае как `Authorization: Bearer` и в
`docker login -p`; отозванный секрет перестаёт проходить **на предъявлении**, в пределах
объявленного числом окна; в хранилище нет ни одной колонки, откуда секрет восстановим.

**Три вещи, которые определяют объём и легко пропускаются** — каждой посвящён свой раздел:

1. **Отзыв обязан действовать на ПРЕДЪЯВЛЕНИИ, а не только на выдаче** (§6). Контроль, который
   лишь перестаёт выдавать новое, отзывом не является: выданное продолжает проходить до истечения
   срока, и это состояние **не сходится само**. У долгоживущего секрета цена такого промаха равна
   его сроку.
2. **Секрет не существует нигде, кроме одного ответа** (§4.3). Строка ресурса, тело операции,
   журнал аудита и лента подписки — **четыре** пути записи, порождаемые одной выдачей, и
   утверждение «показывается один раз» ложно, пока не проверен каждый.
3. **Проверка предъявленного лежит на пути КАЖДОГО запроса** (§5.3). Её стоимость обязана быть
   названа числом и не быть функцией числа запросов: форма секрета даёт отказ негодному входу
   **до** обращения к соседу, а годный вход платит один вызов на удостоверение за окно.

## §1 Что верно в дереве — измерено, а не предположено

Каждое число — с единицей счёта и предикатом. Ревизия — `143ace3e5`
(`origin/release/identity-3`). Числа названы ради **объёма работ**; следствия для постороннего из
них не выводятся и не приводятся.

### 1.1 Публичных глаголов выдачи удостоверений — ДВА, и оба возвращают ключевой материал

```sh
git grep -c 'rpc Issue' origin/release/identity-3 -- 'proto/kacho/cloud/iam/v1/*.proto'
# → sa_key_service.proto:1, user_token_service.proto:1  (единица счёта — файл контракта)
git grep -c 'private_key_pem' origin/release/identity-3 -- 'proto/kacho/cloud/iam/v1/*.proto'
# → sa_key_service.proto:4, user_token_service.proto:2
```

Оба ответа выдачи несут `private_key_pem`, `public_key_pem`, `algorithm` и `key_id`. Готовый токен
доступа в **публичном** контракте не выдаёт никто — единственное вхождение `access_token` в
контрактах iam принадлежит внутреннему бутстрап-сервису на служебном слушателе.

**Что из этого следует для объёма.** Вид удостоверения вводится **у тех же двух глаголов**, а не
третьим сервисом. Довод — §2.5.

### 1.2 Колонок состояния и отзыва у обеих таблиц удостоверений — НОЛЬ; срок есть и допускает «бессрочно»

Единица счёта — колонка. У `kacho_iam.user_oauth_clients` и
`kacho_iam.service_account_oauth_clients` нет ни колонки состояния, ни колонки отзыва; есть
`expires_at timestamptz NULL`, где `NULL` означает «бессрочно», при ограничении
`expires_at IS NULL OR expires_at > created_at`. Отзыв исполняется **снятием строки**, и снятие
порождает отсечку отчеканенного триггерами миграции `898002`.

```sh
git show origin/release/identity-3:services/iam/internal/migrations/0046_user_oauth_clients.sql | grep -n 'expires_at\|state\|revoked'
git show origin/release/identity-3:services/iam/internal/migrations/898002_client_revocation_reaches_presentation.sql | grep -c 'CREATE TRIGGER'
```

**Что из этого следует.** Отзыв нового вида обязан оставаться **снятием строки**. Пометка
(`revoked_at` / состояние) потребовала бы третьего повода отсечки и второго правила чтения — два
места об одном предмете.

### 1.3 Срок в контракте выдачи допускает два года, и ноль означает «бессрочно»

```sh
git grep -n 'ttl_seconds' origin/release/identity-3 -- 'proto/kacho/cloud/iam/v1/*.proto'
# → sa_key_service.proto:95 и user_token_service.proto:128, оба `int64 … [(value) = "<=63072000"]`
```

`int64` в proto3 не различает «не задано» и «ноль» **by construction**, а комментарий поля
объявляет `0 → бессрочный`. Для вида «долгоживущий предъявительский секрет» бессрочность —
не опция; решение и разрешение коллизии — §7.

### 1.4 Окно вердикта об отзыве уже объявлено числом, и оно ОДНО на все полосы

| величина | значение | ручка |
|---|---|---|
| окно кэша вердикта | **5 с** | `KACHO_INTROSPECTION_CACHE_TTL_SECONDS`, умолчание `5` |
| бюджет одного вызова к авторитету | **1 с** | `KACHO_INTROSPECTION_TIMEOUT_MS`, умолчание `1000` |
| ёмкость кэша | 10000 | `KACHO_INTROSPECTION_CACHE_SIZE` |

Вопрос об отзыве нашего токена задаётся **внутреннему** слушателю iam (`:9097`, ручка формы
RFC 7662), поверх TLS с **обязательным клиентским сертификатом**: iam отказывается стартовать,
если слушатель сертификат не запрашивает.

**Что из этого следует.** Новая полоса **не заводит своей величины окна и своего адреса**. Второе
число об одном предмете разошлось бы молча, и «отзыв действует не позже N» стало бы означать разное
на разных полосах.

### 1.5 Механизма привязки к предъявителю нет ни в одном профиле

Единица счёта — файл значений развёртывания.

```sh
git ls-tree -r origin/release/identity-3 --name-only deploy/helm | grep -cE 'values.*\.yaml$'   # → 13
git grep -l 'enableDpop'                origin/release/identity-3 -- 'deploy/helm/**/values*.yaml' | wc -l   # → 0
git grep -l 'requireMachineTokenBinding' origin/release/identity-3 -- 'deploy/helm/**/values*.yaml' | wc -l  # → 1
```

Единственное вхождение второй ручки — **комментарий** о порядке раската; значения не задаёт ни один
из 13 профилей, обе ручки остаются `false` умолчанием. Решение по этой оси — §2.3.

### 1.6 Примитивов хранения секретов в дереве почти нет — и это удешевляет правильный выбор

```sh
git grep -n 'ConstantTimeCompare' origin/release/identity-3 -- '*.go' | grep -vc '_test.go'  # → 1
git grep -c 'argon2\|bcrypt\|scrypt\|pbkdf2' origin/release/identity-3 -- '*.go'             # → 0
```

Сравнение постоянного времени в дереве уже есть — одним вхождением, на пути аутентификации хука.

### 1.7 Гейт утёкшего креда объявил свою слепую зону, и она — ровно наш вид

`internal/repohygiene/committedcredential_test.go` объявляет в шапке прямо: непрозрачный кред
**без структуры** (случайная строка, ключ API без формата) под ключом вне словаря его осями не
ловится — «необъявленная слепая зона читается как покрытие, поэтому она объявлена».

**Что из этого следует.** Марка и контрольная сумма (§3) не косметика: они дают оси материала то,
за что зацепиться, и закрывают объявленную слепую зону **этим же** изменением.

### 1.8 Величины политики токенов стережёт гейт, и перечень стерегомого — закрытый

`pkg/tokenpolicy/policy.go` — единственное объявленное место для чисел политики
(`MaxTokenTTL = 30m`, `ClockSkew = 60s`, `MaxAssertionLifetime = 5m`,
`MaxFederatedAssertionLifetime = 1h`, вычисляемая `KeyRemovalGrace`). Гейт
`internal/repohygiene` `TestTokenPolicyQuantityIsDeclaredOnce` держит **три** величины из этого
перечня; величина, в перечень не внесённая, гейтом не стережётся.

**Что из этого следует.** Обе новые величины срока (§7) вносятся в перечень гейта **решением**, а
не умолчанием — иначе они объявлены, но ничем не удержаны.

### 1.9 Каталог пределов уже несёт трёхчастную форму вида и посеян умолчаниями

Форма вида — `^[a-z][a-z0-9]*\.[a-zA-Z][a-zA-Z0-9]*(\.[a-zA-Z][a-zA-Z0-9]*)?$`, то есть
`домен.родитель.ребёнок` законна и считается **внутри родителя**. Умолчаний посеяно **20**
(единица — строка `INSERT` в `0094_limit_kind_nested_form_and_seeds.sql`), среди них `iam.user` и
`iam.serviceAccount`.

**Что из этого следует.** Потолок числа удостоверений на принципала выражается **видом каталога**
и списывается в той же транзакции, что вставка строки (§8) — механизм существует, изобретать
нечего.

## §2 Решения по четырём осям — с обоснованием и предикатом удержания

Владелец назвал четыре оси. Каждая переведена в проверяемое требование; «предикат удержания» —
то, чем решение будет проверено **в дереве**, а не намерение.

### 2.1 БЕЗОПАСНОСТЬ: секрет невосстановим из хранилища, и хранение — быстрый хеш, а не медленный

**Решение.** Хранится `sha256(<id> || <секретная часть>)`, 32 байта, `bytea`. Сравнение —
постоянного времени. Медленной функции вывода ключа (argon2/bcrypt/scrypt) **не вводится**.

**Обоснование, а не вкус.** Медленная функция существует против **угадывания**, то есть против
входа низкой энтропии, который выбирает человек. Здесь вход выбираем **мы**: секретная часть — 130
бит из криптографического источника. Перебор невозможен арифметически, а не «дорог»; при этом
медленная функция положила бы процессорное время на путь **каждого** запроса — прямое противоречие
оси производительности (§2.2). Отдельно: параметры медленной функции — новая величина, которую
пришлось бы объявлять числом и удерживать гейтом (§1.8); величина, которой можно не заводить,
не заводится (LEAN, ban #11).

**Хеш покрывает id и секретную часть ВМЕСТЕ.** Половина одного удостоверения, приставленная к
половине другого, удостоверением не является — это следует из формы хеша, а не из проверки.

**Предикат удержания.**
- ограничение таблицы: у строки вида `SECRET` колонка ключевого материала пуста, а хеш непуст;
  обратное — для вида `KEYPAIR`. Нарушение невыразимо оператором `INSERT`/`UPDATE` (сценарии
  BAT-1-19, BAT-1-20);
- проба: полный дамп строки удостоверения не содержит ни одной подстроки предъявленного секрета
  (BAT-1-21), рядом положительный контроль — хеш в строке присутствует;
- гейт: `internal/repohygiene/committedcredential_test.go` получает ось нашей марки (§2.4), и
  законный близнец — пример из документации с **неверной** контрольной суммой (BAT-1-66).

### 2.2 ПРОИЗВОДИТЕЛЬНОСТЬ: три уровня отсева, и только третий стоит вызова к соседу

Проверка лежит на пути **каждого** запроса. Стоимость названа по уровням:

| уровень | что отсекает | цена | обращение к соседу |
|---|---|---|---|
| 1. марка | всё, что не наш вид | сравнение префикса | нет |
| 2. форма и контрольная сумма | обрезанный, опечатанный, подделанный наугад | одно хеширование ≤64 байт | **нет** |
| 3. вердикт авторитета | негодный, отозванный, истёкший, чужого владельца | один вызов **на удостоверение за окно** | да, с кэшем |

**Число.** Окно — **5 секунд**, то самое, что уже объявлено (§1.4), и второй ручки не заводится.
При `N` различных живых удостоверений стоимость равна `N/5` вызовов в секунду **независимо от
числа запросов**; бюджет одного вызова — 1 секунда, недоступность авторитета — отказ (§5.4).

**Ключ кэша — идентификатор удостоверения И отпечаток предъявленной строки, никогда сама строка.**
Отпечаток обязателен: без него неверный секрет при верном идентификаторе получил бы положительный
вердикт соседа по кэшу — то есть кэш стал бы обходом проверки. Сырой секрет в карту кэша не
попадает: это правило уже действует на соседней полосе и здесь не ослабляется.

**Отметка последнего предъявления обновляется на ПРОМАХЕ кэша, а не на запросе.** Иначе чтение
превращается в запись на горячем пути. Обновление — один оператор с предикатом «не раньше, чем
через **окно затирания**», не «прочитать и записать» (ban #10).

**Дроссель записи отметки назван числом и равен окну вердикта — 5 секунд**, и второй ручки под
него не заводится: промах кэша и есть момент, когда отметку можно обновить, поэтому более частый
дроссель недостижим by construction.

> **Здесь стояло «окно затирания», и это был ДРУГОЙ механизм** (замечание круга 2). Дроссель записи
> ничего не стирает; отсрочка затирания — та, что управляет, сколько ответ живёт в строке операции,
> — в круге 2 не была упомянута ни разу, а рядом стояло утверждение «иных неназванных окон в
> документе нет». Оно было **неверным**, и это худший вид ошибки в таком месте: молчание оставляет
> вопрос открытым, ложная полнота **закрывает его неверно**. Перечень ниже заведён вместо неё.

**Все окна фазы — перечнем, с числом и предметом у каждого:**

| # | окно | величина | чем управляет | где решено |
|---:|---|---:|---|---|
| 1 | вердикта о предъявленном | **5 с** | сколько живёт положительный вердикт в кэше края | §1.4 (уже объявлено, второй ручки не заводим) |
| 2 | гарантированная граница отзыва | **= 1** | не позже чего отозванное перестаёт проходить | §6 — то же число, названное один раз |
| 3 | дроссель записи отметки предъявления | **= 1** | не чаще чего обновляется отметка | здесь |
| 4 | **отсрочка затирания ответа операции** | **120 с** плюс запас подметальщика | сколько ответ выдачи живёт в строке операции **до** стирания | §4.3 — и к виду `SECRET` **не применяется**, потому что стирать нечего |

Первые три — **одно** число, названное один раз, и это по-прежнему верно. Четвёртое — **другое**
число другого механизма, и оно в 24 раза больше; называть его «тем же окном» было бы ровно тем
расхождением, ради недопущения которого перечень и заведён.

**Предикат удержания.**
- проба стоимости: `M` запросов одним удостоверением дают **ровно один** вызов к авторитету за
  окно; положительный контроль — второе удостоверение даёт второй вызов (BAT-1-33, BAT-1-34);
- проба ключа кэша: верный идентификатор с неверным секретом **не** получает вердикт из кэша и
  получает отказ (BAT-1-35), рядом положительный — верная пара проходит из кэша;
- проба уровня 2: негодная контрольная сумма даёт отказ и **ноль** вызовов к авторитету
  (BAT-1-07); утверждается **пара** — исход и число вызовов, потому что один код ответа этого
  свойства не измеряет.

### 2.3 ПЕРСПЕКТИВНОСТЬ 2026: привязка к предъявителю — НЕ СЕЙЧАС, и это названо, а не пропущено

**Решение.** Удостоверение этого вида **предъявительское by construction** и `cnf` не несёт
никогда. Ручки привязки (#1137) остаются выключенными, и **область фазы их не трогает**.

**Обоснование — несовместимость, а не отсрочка.** Привязка к владению ключом (RFC 9449) или к
клиентскому сертификату (RFC 8705) требует, чтобы предъявитель **доказал** владение при каждом
предъявлении. Докер-полоса шлёт `Basic` и доказать ничего не может; сборочный конвейер, кладущий
секрет в переменную, — тоже. То есть «однострочный секрет, работающий без обучения» и «токен,
связанный с предъявителем» — **противоположные концы одного размена**, и требовать оба от одного
вида означало бы объявить возможность, у которой нет исполнимого входа (`api-conventions.md`
§«ДВА ПРАВИЛА ОБ ОДНОМ ПОЛЕ»).

**Что фаза обязана сделать, чтобы «не сейчас» не стало долгом.** Привязка — свойство **ВИДА
удостоверения**, а не настройки развёртывания. Поэтому:

- страж старта **отвергает** конфигурацию, где требование привязки включено, пока выдаётся вид,
  который привязать нельзя. Это исход 2 из трёх законных («отвергать явно»), а не молчаливое
  сосуществование;
- **предикат ввода привязки назван:** она включается для вида удостоверения, способного доказать
  владение на **всех** поверхностях, где он принимается, — а не глобально ручкой. До появления
  такого вида требование остаётся невыполнимым, и страж говорит об этом при старте, а не отказом
  каждому машинному принципалу в рантайме.

**Второе решение той же оси: уровень удостоверения — «1», и следствие названо.** Выпуск и отзыв
удостоверений требуют повышенного уровня. Значит **человек**, предъявивший базовый секрет, не может
ни выпустить новое удостоверение, ни отозвать существующее — эти действия остаются за интерактивным
входом. Это намеренно: долгоживущий предъявительский секрет не должен уметь чеканить себе смену.
Машинный принципал от повышенного уровня освобождён общим правилом, и это не расхождение: у машины
интерактивного пути нет вовсе, и требование сделало бы глагол недостижимым ей by construction
(вторая цена, которую почти никогда не спрашивают).

**Предикат удержания.**
- проба стража старта: требование привязки включено ⇒ **отказ старта** с текстом, называющим
  ручку и причину; выключено ⇒ старт проходит (BAT-1-61, положительный контроль рядом);
- проба уровня: человек с базовым секретом получает отказ на выпуске и на отзыве удостоверения,
  и **проходит** на обычном чтении (BAT-1-58, BAT-1-59); машинный принципал проходит на своём
  глаголе (BAT-1-60);
- гейт полос: `cnf` у выданного этим видом — отсутствует; поле не заполняется ни одной веткой.

### 2.4 КОНКУРЕНТОСПОСОБНОСТЬ: одна строка, узнаваемая глазом и сканером, без обучения

**Решение.** Секрет — **одна строка**, которую копируют целиком: марка продукта, идентификатор
удостоверения, случайная часть, контрольная сумма (§3). Ни библиотеки, ни сборки утверждения, ни
второго шага.

**Обоснование.** Три свойства покупаются формой и ничем иным:
- **`docker login -p <строка>` работает** — многострочный PEM в этом поле непригоден в принципе;
- **утечка обнаружима**: марка даёт сканеру якорь, контрольная сумма — проверку без сети, поэтому
  случайная строка похожей формы находкой не становится. Это закрывает объявленную слепую зону
  гейта кредов (§1.7);
- **строка сама называет своё удостоверение**: журнал, история команд и поле `-u` показывают,
  **какое** удостоверение в игре, не раскрывая секретной части.

**Предикат удержания.**
- проба формы: одна объявленная функция производит и проверяет строку; вторая копия предиката
  не заводится, и гейт требует ровно одного объявления (BAT-1-65);
- проба документации: **все** примеры на страницах документации несут **неверную** контрольную
  сумму — иначе гейт кредов покраснеет на собственной документации (BAT-1-66);
- проба консоли браузером: выпуск → однократный показ с копированием → повторное открытие
  карточки секрета не показывает (BAT-1-62…64).

### 2.5 Вид заводится у СУЩЕСТВУЮЩИХ двух глаголов, а не третьим сервисом

**Решение.** `SAKeyService.Issue` и `UserTokenService.Issue` получают вид удостоверения
(`credential_kind`), а не появляется третий сервис со своими `Issue`/`List`/`Revoke`. Словарь
закрыт; **выдаваемых видов три — `KEYPAIR | SECRET | FEDERATED`**, и здесь речь именно о них:
в колонке хранилища тот же словарь **четырёхзначен**, потому что несёт ещё `LEGACY` — вид, который
**описывает уже лежащие строки и не выдаётся ни одним глаголом** (§4.1, §4.1.1). Квалификатор стоит
здесь, а не только там: «закрытый словарь из трёх» встречается читателем **раньше** оговорки, и без
него §2.5 и §4.1 читаются как два места об одном предмете, из которых верно одно.

**Видов ТРИ, потому что форм ответа три** (решение владельца, круг 2). Вид определяет, чем
удостоверение себя предъявляет, и это наблюдаемо в ответе выдачи: `KEYPAIR` — ключевая пара;
`SECRET` — секрет; `FEDERATED` — **ни того, ни другого**, потому что удостоверение предъявляет
внешний издатель по перечню доверенных субъектов (#1124). Схлопнуть третью форму в `KEYPAIR`
значило бы завести дискриминатор, который не дискриминирует: BAT-1-13 утверждает, что по виду
читатель узнаёт, какое поле ответа заполнено, — на схлопнутом словаре это утверждение стало бы
ложным о собственном механизме.

**Обоснование — три следствия, каждое самостоятельно достаточное.**
1. **Сужение круга чтения наследуется by construction.** #1133 сузил, кто читает перечень
   удостоверений человека, и сузил это **отношением** на объекте личности. Третий сервис потребовал
   бы вывести то же сужение заново — то есть повторить работу, ошибка в которой не видна.
2. **Отзыв на предъявлении наследуется by construction.** Снятие строки уже порождает отсечку
   триггерами `898002`, а каскад от снятия участия покрыт тем же поводом. Новая таблица потребовала
   бы четвёртого повода.
3. **Перечень, лента операций, консоль и страница документации — уже есть.** Второй
   перечень удостоверений означал бы, что арендатор смотрит в два места, чтобы узнать, чем в его
   продукт можно войти.

**Цена решения названа.** У запроса выдачи есть поля, осмысленные не для всякого вида:
`trusted_subjects` — признак **`FEDERATED`**, `audience` — только у `KEYPAIR` и `FEDERATED`.
Молчаливо принять их у вида `SECRET` запрещено; исход — **явный отказ с именем поля** (BAT-1-14,
BAT-1-15).

**Форма ответа по видам — таблица, а не правило «одно из двух»:**

| вид | ключевой материал | секрет | чем предъявляется |
|---|---|---|---|
| `KEYPAIR` | **непуст** | пуст | подписанное утверждение, ключ наш |
| `SECRET` | пуст | **непуст** | сама строка секрета |
| `FEDERATED` | **пуст** | **пуст** | утверждение внешнего издателя по перечню доверенных субъектов |

Прежняя редакция писала «ровно одно из двух непусто». Это верно для двух видов и **ложно** для
третьего, у которого пусты оба, — и пустота обоих есть его **определяющее свойство**, а не пробел
в ответе. Так и надо читать таблицу: она отвечает на вопрос «что заполнено», а не «что осталось».

**Таблица описывает ВЫДАЧУ, поэтому `LEGACY` в ней нет.** Четвёртый элемент словаря (§4.1.1) не
производится ни одним глаголом и формы ответа не имеет — у него есть только форма **строки**.
Внести его сюда значило бы объявить выдачу, которой нет; не назвать нигде — оставить в перечне
арендатора вид без объяснения. Поэтому он объявлен там, где живёт: в §4.1.1 и на странице
документации (BAT-1-70).

**Вид ЗАПИСЫВАЕТСЯ, а не вычисляется читателем** (решение владельца, круг 3). Колонка вида
заполняется при записи строки; ни один путь чтения вид не выводит.

**Классификаторов ДВА, и круг 2 их спутал — отсюда дыра.** Они над разными корпусами, и тотальность
у них разная:

| классификатор | корпус | сколько ветвей | почему столько |
|---|---|---|---|
| над **запросом выдачи** | вход нового выпуска | **три** | «ни материала, ни перечня» здесь означает `KEYPAIR`, и это не догадка: материал чеканим **мы**, поэтому строка получает его by construction. Дыры нет — она невозможна |
| над **содержимым существующих строк** | то, что уже лежит | **четыре** (§4.1.2) | материал чеканили не всегда мы; форма «ни того, ни другого» существует, и без своей ветви получила бы чужой вид молча |

Прежняя редакция описывала **один** классификатор — трёхветвевой над содержимым. Над корпусом
существующих строк он неполон, и неполон **тихо**: вход без вида не отвергается, а получает
ближайший. Это «корзина прочее» наоборот, и она опаснее обычной, потому что выглядит решением.

**Что остаётся из прежней редакции без изменений.** Клиент, сегодня присылающий непустой перечень
доверенных субъектов и никакого вида, продолжает получать `FEDERATED` — прежнее поведение
сохраняется дословно, изменение аддитивно. Названный явно вид авторитетен, и несогласие с перечнем
отвергается **с именем поля**: `FEDERATED` с пустым перечнем и не-`FEDERATED` с непустым — оба
отказ. `LEGACY`, названный явно, отвергается **всегда**: его не производит ни один глагол
(BAT-1-14).

## §3 Форма удостоверения

### 3.1 Состав строки

```
kacho_<id удостоверения>_<26 знаков крокфорда><6 знаков контрольной суммы>
```

| часть | что это | почему так |
|---|---|---|
| `kacho_` | марка продукта | якорь сканера; отличает наш вид **до** любого разбора |
| `<id>` | идентификатор строки реестра (`uoc…` / `soc…`) | второго имени у удостоверения нет (§3.3); ключ поиска — первичный ключ, не перебор |
| 26 знаков крокфорда | секретная часть, **130 бит** из криптографического источника | энтропия — довод §2.1, а не украшение |
| 6 знаков крокфорда | контрольная сумма от id и секретной части | отказ негодному входу **без** обращения к соседу и **без** обращения к базе |

Алфавит — крокфордов base32 в нижнем регистре: нет символов, путающихся при чтении вслух и при
переписывании; нет `+`, `/`, `=`, ломающих строку в URL и в оболочке.

### 3.2 Разбор — по ПОСЛЕДНЕМУ разделителю, и это не педантизм

Идентификатор удостоверения в этом дереве бывает формы `<prefix>_<17 знаков>` — то есть **сам
содержит разделитель**. Поэтому разбор отделяет **последний** сегмент по `_`: марка, затем всё до
последнего разделителя — идентификатор, затем ровно 32 знака — секретная часть с контрольной
суммой. Разбор «по первым двум разделителям» дал бы неоднозначность на легаси-форме
идентификатора; разбор по точке был бы хуже вдвойне — три сегмента через точку суть форма
подписанного токена, и два вида предъявленного перестали бы различаться.

### 3.3 Второго идентификатора не заводится

Строка называет своё удостоверение **тем же** идентификатором, каким оно адресуется в API и в
перечне. Второе имя было бы вторым написанием одного значения: два места, которые расходятся молча.

**Оба префикса удостоверений обязаны классифицироваться платформенным каталогом**
(`ids.KnownPrefixes()`), и проба утверждает **оба** — иначе идентификатор одного из двух видов
принципала не проходит там, где второй проходит (BAT-1-67).

### 3.4 Одна объявленная функция на чеканку, проверку и гейт

Производство строки, её разбор, вычисление и сверка контрольной суммы живут **в одном
экспортируемом месте**; чеканка, проверяющий и гейт утёкшего креда зовут **его**. Второй копии
предиката не заводится ни в каком виде — ни разбором текста чужого исходника, ни своей регуляркой
в гейте: копия разошлась бы молча и разошлась бы в сторону «принимаем больше», потому что
расширять проще.

## §4 Хранилище: инварианты — конструкциями таблицы, а не проверками в коде

### 4.1 Вид удостоверения — закрытый словарь, и взаимоисключение выражено ограничением

Обе таблицы удостоверений получают `credential_kind` и `secret_hash bytea NOT NULL DEFAULT ''`.
Словарь **закрыт, четырёхзначен и не одинаков у двух таблиц**, и это не небрежность:

| таблица | допустимые виды | почему так |
|---|---|---|
| `service_account_oauth_clients` | `KEYPAIR` · `SECRET` · `FEDERATED` · `LEGACY` | перечень доверенных субъектов есть только здесь |
| `user_oauth_clients` | `KEYPAIR` · `SECRET` · `LEGACY` | федеративного вида у личности нет **by construction** — в её контракте нет поля, которым он задаётся |

Ограничение таблицы личности допускает три значения из четырёх. Допустить четыре там, где одно
недостижимо, значило бы объявить состояние, у которого нет ни входа, ни производителя.

### 4.1.1 `LEGACY` — четвёртый вид, который ОПИСЫВАЕТ, но не ВЫДАЁТСЯ

**Решение владельца, круг 3.** Среди уже лежащих строк есть форма, у которой нет **ни** ключевого
материала, **ни** перечня доверенных субъектов, — удостоверение прежнего потока. Она существует
независимо от того, назвали мы её или нет; отнести её к `KEYPAIR` значило бы записать в колонку
вида **ложное значение** и получить строку, которая по своему виду обязана нести материал и не
несёт его.

| свойство `LEGACY` | значение |
|---|---|
| кто производит | **никто**: ни один глагол выдачи его не выпускает, и это записано в самом словаре, чтобы следующий не завёл под него выдачу |
| откуда берётся | **только** обратное заполнение по фактическому содержимому (§4.1.2) |
| ограничения сверх уже держащихся таблицей | **никаких** — вид описывает то, что уже лежит, и добавлять к нему требования значило бы задним числом объявить негодным то, что было годным |
| предикат снятия | строк этого вида в обеих таблицах **ноль**; тогда элемент словаря снимается вместе с последней строкой — исключение живёт, пока у него есть предмет |

**Взаимоисключение — одно ограничение на таблицу, по видам:**

- `KEYPAIR` ⇒ `secret_hash = ''`;
- `SECRET` ⇒ `secret_hash <> ''` **и** `public_key_pem = ''` **и** `key_algorithm = ''`
  **и** `trusted_subjects = '[]'` **и** `expires_at IS NOT NULL`;
- `FEDERATED` ⇒ `secret_hash = ''` **и** `public_key_pem = ''` **и** `trusted_subjects <> '[]'`;
- `LEGACY` ⇒ `secret_hash = ''` — и больше ничего.

Третье и есть «бессрочного секрета не бывает» — сказанное **оператором базы**, а не памятью
автора (ban #10).

> **Здесь стояло `KEYPAIR ⇒ public_key_pem <> ''` — ужесточение снято (круг 3).** Оно не входило
> ни в один предмет фазы: решение круга 2 касалось **ослабления** требования у колонки зеркала для
> вида `SECRET`, а вместе с ним в тот же перечень приехало **ужесточение соседней колонки**. Дерево
> его не выдерживает — строки прежнего потока ключевого материала не несут, — и обратное заполнение
> либо упало бы, либо ограничение пришлось бы объявить невалидируемым. Ни то ни другое не стоит
> того, чего никто не решал. **Урок, ради которого абзац оставлен, а не удалён:** правка,
> приехавшая «заодно» с решённым, выглядит его частью и проходит обзор вместе с ним.

**Колонка зеркала у поставщика названа явно, и её требование непустоты ослабляется.**
`hydra_client_id` описывает **регистрацию у внешнего поставщика**, а у вида `SECRET` такой
регистрации нет **by construction** — в этом и состоит предмет фазы. Значит требование непустоты
для него ложно **по смыслу**, а не по форме.

Исход — **новая** миграция (применённые не правим, ban #5), заменяющая проверку на **частичную**:
непустота требуется там, где зеркало есть. Форма правки не изобретается: та же самая уже применена
к таблице личности работой #1121 (`20260823180500_user_token_credential_needs_no_provider_mirror.sql`
— снятие `NOT NULL` и проверка, допускающая отсутствие значения), и новая миграция её **зеркалит**
для таблицы служебной учётки. Уникальность колонки при этом сохраняется — она продолжает делить
домен настоящих зеркал и **не** получает синтетических значений.

**Два отвергнутых исхода названы, чтобы к ним не вернулись.** Регистрировать клиента у поставщика
ради заполнения колонки — прямая отмена предмета фазы и второй путь отзыва. Класть в колонку
собственный идентификатор строки — синтетическое значение в домене настоящих зеркал: колонка стала
бы утверждать существование клиента, которого нет.

### 4.1.2 Обратное заполнение — по ФАКТИЧЕСКОМУ содержимому, четырьмя ветвями

Колонка вида заполняется **при записи** и читателем не вычисляется. Правило вывода по содержимому
живёт ровно на **одном** пути — обратном заполнении существующих строк, — и после него не
применяется никогда.

| что лежит в строке | вид |
|---|---|
| ключевой материал | `KEYPAIR` |
| перечень доверенных субъектов | `FEDERATED` |
| **ни того, ни другого** | **`LEGACY`** |

Четвёртая ветвь обязательна, и без неё правило было бы **двузначным классификатором над
четырёхформенным корпусом**: вход, которому не находится вида, получал бы чужой вид **молча** —
«корзина прочее» наоборот. Сужением это не чинится, оно развалилось бы на следующей форме.

**Миграция печатает число строк ПО КАЖДОМУ виду, а не общее.** Одно число не отличает «`LEGACY`
не встретилось» от «`LEGACY` не искали»; ноль по виду — законный **измеренный** исход, и он должен
быть виден как измеренный. **Ни одна существующая строка не теряет ни одного своего поля**, и ни
одна не перестаёт проходить прежним способом.

### 4.2 Частичный уникальный индекс по хешу — бэкстоп, и большего он не обещает

Частичный уникальный индекс по `secret_hash WHERE credential_kind = 'SECRET'` остаётся как дешёвый
бэкстоп от точного дубля строки — и **детектором испорченного источника случайности не является**.

Прежняя редакция объявляла его таким, и это было неверно: хеш покрывает **идентификатор вместе с
секретом** (§2.1), идентификаторы строк различны by construction, поэтому совпадение секретной
части хешей не сближает — ограничение не сработало бы **ни при каком** входе. Свойство «источник
случайности исправен» меряет **BAT-1-08**, который меряет именно его; отдельной колонки отпечатка
секретной части под это свойство **не заводится** — она платила бы миграцией и вторым индексом за
то, у чего предикат уже есть.

### 4.3 Секрет не существует ни в одной строке ни одной таблицы

Одна выдача порождает **четыре** пути записи, и утверждение «показывается один раз» ложно, пока не
проверен каждый:

| путь записи | что обязано быть верно |
|---|---|
| строка удостоверения | несёт **хеш**, не секрет |
| строка операции (тело ответа) | поля секрета **не несёт НИ В КАКОЙ МОМЕНТ** — см. ниже |
| журнал аудита | несёт идентификатор удостоверения и вид; секрета не несёт |
| лента подписки / фид операций аккаунта | то же |

Секрет существует ровно в одном месте — в теле ответа, который получил **вызывающий выдачи**.
Выдача вида `SECRET` завершается **на пути запроса** (`done=true` в ответе самого `Issue`), и это
не отступление от ban #9: предмет мутации закоммичен, а `done` означает ровно это.

#### 4.3.1 «Не попадает» ПРОТИВ «стирается позже» — это разные свойства, и фаза требует первого

Для тела ответа операции существует отложенный механизм: записанное стирается **позже**, по
объявленной отсрочке (окно 4, §2.2 — **120 с** плюс запас подметальщика). Он остаётся механизмом
**существующих** видов, и фаза его не меняет ни в одну сторону.

**К виду `SECRET` он не применяется — потому что стирать нечего.** Требование фазы: секрет в тело,
записываемое в строку операции, **не кладётся вовсе**. Отложенное стирание для долгоживущего
предъявительского секрета не годится by construction: величина отсрочки от нагрузки не зависит и
сама себя не сокращает, то есть свойство «показан один раз» стало бы означать «показан ещё
столько-то».

**Отсюда — требование к самой пробе, и оно несущее.** `BAT-1-22` обязана читать строку операции
**раньше**, чем истекла отсрочка затирания. Проба, читающая позже, **зеленеет и на отложенном
стирании тоже** — то есть не отличает свойство, которого фаза требует, от свойства, которого она
избегает. Момент чтения здесь — не деталь исполнения, а то, что проба вообще измеряет.

#### 4.3.2 Подметающий бэкстоп: поле обязано быть в его перечне (B5-bis)

Рядом живёт подметающий бэкстоп, обходящий таблицу операций по перечню «тип ответа → поля».
Свойство перечня объявлено им самим: **поле, которого перечень не называет, пропускается**, и
таблица читается чистой навсегда. Фаза добавляет новое поле-носитель секрета в сообщения, которые
он уже стережёт, — значит исход обязан быть назван, а не подразумеваться.

**Исход: поле вносится в перечень.** Обе меры держатся вместе и держат **разные** свойства:

| мера | что держит | чего не держит |
|---|---|---|
| секрет не кладётся в тело при записи (§4.3.1) | **конструкцию** — на том пути записи, который заводит фаза | второй путь записи, который заведут завтра и который о конструкции знать не будет |
| поле названо в перечне подметальщика | **бэкстоп** — любой путь, включая будущий | ничего: он не первичный путь, а страховка |

**И требование к перечню как к классу.** Перечень, который **выписывают**, расходится с контрактом
молча, и расходится в сторону «не называем» — потому что не назвать проще. Поэтому: гейт требует,
чтобы **каждое** поле контракта, помеченное носителем секрета, было названо в перечне; гейт
печатает объём осмотренного и доказан инъекцией в обе стороны (BAT-1-73). Без него отсутствие
записи в перечне неотличимо от «поле проверено и чисто».

**Чем именно поле помечается — §4.3.3, и это не деталь исполнения.** Пока механизм пометки не
назван, у гейта **нет производителя входа**: множество «все помеченные поля» не перечислимо, а
значит не перечислимо и множество законных близнецов, — то есть гейт, описанный этим абзацем,
построить нельзя (B13).

Утверждается **пара**: секрет в первом ответе есть **и** прочих полей ответа тоже нет в строке
операции — иначе «пусто» означало бы «ответа нет вовсе», и проба зеленела бы на сломанной выдаче.

#### 4.3.3 Пометка — ОПЦИЯ ПОЛЯ В КОНТРАКТЕ; производителей входа у гейта два, и оба уже есть (B13)

**Решение владельца, круг 4.** Носитель секрета помечается **опцией поля в контракте**. Опция
объявляется **отдельным аддитивным файлом аннотаций** платформенного уровня — своё
`extend google.protobuf.FieldOptions` со свободным номером расширения. У **полевых** опций заняты
`101501`…`101506`, `101510`, `101511`; берётся следующий свободный за ними. `101400` в этот счёт
**не входит**: он расширяет **`OneofOptions`**, а номера расширений считаются по расширяемому
типу — для `FieldOptions` он формально свободен. Названо это не ради педантизма: перечень
занятых, в который попал номер чужого расширяемого типа, читается следующим как «здесь тесно» и
переживает свой предмет. Брать его всё равно не будем — запас в сторону осторожности здесь
ничего не стоит.

**Почему отдельным файлом, а не правкой существующего файла полевых опций.**
`proto/kacho/cloud/validation.proto` импортируют **53** контракта **восьми** доменов (замер:
`grep -rl 'kacho/cloud/validation.proto' proto/kacho --include=*.proto | wc -l`), и правка его
вытягивает область фазы на всё дерево. Отдельный файл не обязан импортировать никто, кроме того,
кто пометку ставит. **Прецедент в дереве есть и он ровно этой формы:** отдельный файл аннотаций
прав `proto/kacho/iam/authz/v1/authz_options.proto` — объявляет опции, импортируется теми, кто их
ставит (66 контрактов), и читается генератором каталога из дескрипторов.

**Отвергнуто: общее объявление на стороне Go** (перечень имён рядом с подметальщиком). Области оно
не меняет, но гейт тогда сравнивает перечень **сам с собой**: новое непомеченное поле-носитель не
краснит его **никогда**. Это ровно «форма проверки без содержания» — класс, который эта же приёмка
ловит в §4.3.2, и заводить его в собственный гейт нельзя.

**Гейт читает ДЕСКРИПТОРЫ, а не текст.** Поиск по образцу над исходником не отличает объявление
поля от строкового литерала и от комментария, который эту же пометку объясняет, — и остаётся
зелёным при снятой пометке. Пометка перечислима из набора дескрипторов; так же уже устроен
генератор каталога прав, поэтому механизм в дереве не новый.

**Производителей входа ДВА, и оба — уже существующие соглашения контракта:**

| множество | чем производится | замер по дереву |
|---|---|---|
| поля-носители секрета | новая опция поля | заводится фазой; сегодня помеченных **0** |
| сообщения, попадающие в строку операции | аннотация операции у RPC, её поле `response` — оно **называет** тип, который кладётся в ответ операции | аннотацию несут **147** RPC, различных сообщений-ответов **41** (единица счёта и предикаты — сразу под таблицей) |
| тип ответа для перечня подметальщика | производится **из самого сообщения**, как уже делает подметальщик, а не выписывается строкой | — |

**Единица счёта названа, потому что рядом лежат ЧЕТЫРЕ разные величины и они не совпадают.**
Замер на объявленной базе `143ace3e5`, предмет — `proto/**/*.proto`, каждый предикат повторяем и
опровержим:

1. **RPC, НЕСУЩИХ аннотацию операции, — `147`.** Это и есть производитель входа.
   Предикат: `git grep -o 'option (kacho.cloud.api.operation)' 143ace3e5 -- 'proto/**/*.proto' | wc -l`.
   Вхождение приходится ровно на одно объявление RPC — проверено разбором блоков `rpc … { … }`:
   распределение «аннотаций на RPC» равно `{1: 147}`, то есть RPC с двумя аннотациями нет, и счёт
   по строкам совпадает со счётом по RPC не случайно.
2. **Различных имён сообщений-ответов — `41`.** Предикат:
   `git grep -oh 'response: *"[^"]*"' 143ace3e5 -- 'proto/**/*.proto' | sed 's/.*"\(.*\)"/\1/' | sort -u | wc -l`.
   Это та величина, которой **сужена ось 1**, и именно она решает; `147` названа ради объёма.
3. **RPC, ВОЗВРАЩАЮЩИХ `Operation`, — `150`** (разбор блоков со **снятыми комментариями**; по
   сырому тексту получается `151` — один пример стоит внутри комментария файла опций прав).
   **Это НЕ производитель входа**, и разница в три RPC показывает почему: у трёх, возвращающих
   `Operation` без аннотации, поля `response` нет вовсе — тип ответа не назван, и ключевать
   перечень подметальщика для них нечем. Считать по типу возврата значило бы назвать множество, из
   которого множество типов ответа не выводится.
4. **Голое имя опции по всему дереву — `152`**: `git grep -o 'kacho.cloud.api.operation' 143ace3e5 | wc -l`.
   Оно ловит сверх RPC ещё и объявление самой опции, её импорты и фикстуру гейта в
   непроизводственном дереве. Величина настоящая и к предмету отношения не имеет.

> **Здесь стояло `184`.** Число не воспроизводится ни одним из четырёх предикатов и не
> воспроизвелось у ревьюера круга 4. Решения оно не несло — ось 1 сужена числом `41`, и оно
> **подтверждено**, — но клетка озаглавлена «замер по дереву» и стояла **без предиката**, в
> отличие от всех чисел §1. Класс тот же, что ловит §4.3.2: величина без предиката проверяема
> только тем, кто повторит замер руками, и потому переживает свой предмет молча. Исправлено
> кругом 5: число заменено на воспроизводимое, единица счёта названа явно, соседние величины
> перечислены — чтобы следующий читатель не «уточнил» `147` до `150` или `152`, приняв другую
> единицу за ту же.

**Ось 1 — согласие пометки с перечнем, и она СУЖЕНА пересечением.** Помеченное поле сообщения,
**названного** аннотацией операции ответом, обязано стоять в перечне подметальщика для этого типа;
не названное — находка с координатой. Помеченное поле сообщения, которое ответом операции **не
является** (синхронный глагол), в перечне стоять **не обязано**, и требовать этого было бы неверно:
перечень ключуется типом ответа, а синхронный ответ в таблицу операций не попадает вовсе. Сужение
не косметическое — в дереве такой случай уже есть: `MintBootstrapTokenResponse` несёт
предъявительский секрет и ответом операции не является (замер: среди 41 сообщения-ответа его
**нет**). Без сужения гейт требовал бы вносить в перечень то, чего подметальщик увидеть не может, —
и был бы снят первым же ложным срабатом.

**Ось 2 — отсутствие НЕПОМЕЧЕННЫХ секретов на поверхности.** Поле, **чьё имя выглядит секретом**,
обязано быть **либо помечено, либо названо в ведомости исключений с причиной**. Без второй оси
случай «завели поле-носитель и забыли пометить» не ловится вовсе: первая ось на непомеченном
молчит by construction.

**Запись ведомости законна ТОЛЬКО для поля, носителем секрета НЕ являющегося; носитель
закрывается пометкой и ничем иным.** Без этого ограничения ведомость проглатывает ровно то поле,
ради которого фаза заведена: имя поля-носителя под образец `*secret*` попадает by construction,
запись «исключено, потому что …» формально законна — и тогда ось 1 отрабатывает на **пустом**
множестве («помеченных 0», находок ноль, гейт зелен), а требование §4.3.2 «поле вносится в
перечень подметальщика» остаётся держаться **одной прозой**. То есть ведомость, заведённая как
предохранитель против слепой зоны, сама становится способом её узаконить.

Ограничение не изобретено под этот случай — оно **следует из собственных примеров ведомости**
выше: обе её законные записи суть публичная половина ключа и **ссылка** на учётные данные, то
есть предметы, секретом не являющиеся. Ведомость перечисляет **ложные срабатывания образца**, а
не разрешения для истинных.

**Чем ограничение держится — двумя механизмами, и оба названы честно.** Гейт роняет
**противоречие**: поле, одновременно **помеченное** и **названное в ведомости**, — находка, потому
что одно из двух объявлений ложно; это проверяется механически и стоит отдельной инъекции.
Суждение же «вот это поле — носитель» из дескрипторов не выводится (см. «правильность пометки» в
таблице пределов ниже), и его держит **обзор изменения контракта** — тот же, что назван пределом
гейта. Ограничение при этом не декоративно: оно превращает «можно и так, и так» в «для носителя
путь один», то есть снимает **законный** способ обойти ось 1 — а обойти проверку законным путём
всегда дешевле, чем незаконным.

Перечень образцов **адъюдицирован по дереву**, а не выдуман (единица счёта — уникальное имя поля
среди `string`/`bytes`-полей контрактов `proto/kacho`, всего **253**):

| образец | попаданий | из них носители | почему включён |
|---|---:|---:|---|
| `*secret*` | 1 | 1 | слово называет предмет прямо; ложных ноль |
| `*private_key*` | 1 | 1 | то же; удерживает форму, под которой придёт `private_key_jwk`/`…_der` |
| `*password*`, `*passwd*` | 0 | 0 | сегодня попаданий ноль, и это **не** повод снять: предикат смотрит вперёд, ему не нужен предмет сегодня (в отличие от записи ведомости, которой предмет нужен) |
| `*_pem` | 2 | 1 | вторая половина — публичный ключ, уходит в ведомость **одной** строкой; образец удерживает класс «ключевой материал в PEM» |
| `*_token` (конец имени) | 3 | 1 | два из трёх — курсор постраничного чтения, **объявленный конвенцией платформы**; он вычитается **структурно, по имени конвенции**, а не записями ведомости: курсор встречается в **39** контрактах, и ведомость в десятки строк перестают читать |
| `*credential*` | 1 | 0 | сегодня ловит ноль и стоит **одной** записи (ссылка на кред, не сам кред); включён вперёд — слово называет класс точно |

**Отвергнуто, с числом:**

| образец | попаданий | из них носители | почему отвергнут |
|---|---:|---:|---|
| `*key*` | 9 | 1 | в этом продукте «key» чаще означает идентификатор, имя алгоритма или **публичную** половину; восемь ложных на одну истинную — ведомость становится шумом |
| голый `*token*` | 7 | 1 | то же: вид токена, его идентификатор, способ аутентификации у токен-эндпоинта и два имени курсора. Инструмент, у которого почти все находки ложные, перестают читать — а перестав читать, возвращаются к отсутствию проверки |

**Ведомость исключений ИСТЕКАЕТ САМА.** Запись, у которой больше нет предмета — поле снято либо
поле помечено, — **находка**, а не тишина. Иначе первая же запись переживёт свой предмет и
унаследует слепую зону следующему.

**Чего гейт НЕ держит — названо, чтобы его не сочли полным покрытием:**

| не держит | что держит вместо него |
|---|---|
| поле-носитель, **чьё имя ни на что не похоже** и которое не пометили: ось 1 молчит (не помечено), ось 2 молчит (имя не совпало) | **механического держателя нет.** Держит обзор изменения контракта — `proto-api-reviewer` на глаголе, который выдаёт удостоверение. Сказано прямо: здесь гейт кончается |
| **правильность** пометки: помеченное поле, секретом не являющееся, даёт лишнюю запись в перечне | ничего; последствие безвредно (лишняя запись подметает пустоту), и различить это гейт не может |
| **три остальных пути записи** из §4.3 — журнал аудита, лента подписки, строка удостоверения | §4.3 требованием и своими пробами; гейт покрывает **один** путь — строку операции |
| **поведение подметальщика в рантайме**: гейт утверждает согласие объявления с перечнем, а не то, что стирание происходит | интеграционная половина `BAT-1-73` |

## §5 Приём предъявленного

### 5.1 Полоса выбирается по МАРКЕ, а не по неудаче разбора другого вида

Вид предъявленного определяется **объявленной маркой в начале строки**. Запрещено «не разобралось
как подписанный токен — попробуем как секрет»: запасной путь, срабатывающий на неудаче,
превращает всякую негодную строку в вход второй полосы и делает диагностику невозможной.

Три исхода, четвёртого нет: марка наша ⇒ полоса секрета; форма подписанного ⇒ существующая полоса;
ни то ни другое ⇒ отказ. Строка, несущая нашу марку, получает вердикт **на слое аутентификации** —
полоса **терминальна** на обеих поверхностях. Полоса, не являющаяся терминальной, отдаёт негодное
удостоверение дальше как «удостоверения нет вовсе», и вызывающий получает отказ не той природы.

### 5.2 Полоса заполняет ровно те поля, которые читают нижележащие контроли

Проверенное удостоверение — единственный вход для отзыва, шага повышения уровня, вывода принципала
и служебных метаданных края. Поле, которое полоса не заполнила, делает контроль **пройденным
мимо**, а не успешно — и это неотличимо от исправной работы.

Поэтому требование: **у каждого поля проверенного удостоверения, читаемого хотя бы одним
контролем, у каждой полосы предъявления назван источник**; поле без источника — находка, а не
умолчание (гейт BAT-1-68). Для полосы секрета источники таковы: принципал и его отображаемое имя —
из ответа авторитета; идентификатор для отзыва — идентификатор удостоверения; уровень — константа
«1» (§2.3); срок — `expires_at` строки; `cnf` — отсутствует всегда.

### 5.3 Вопрос авторитету — тот же слушатель, тот же сертификат, то же окно

Резолв предъявленного идёт на **внутренний** слушатель iam, поверх TLS с обязательным клиентским
сертификатом края. Своей величины окна и своего адреса полоса **не заводит** (§1.4): «отзыв
действует не позже N» обязано означать одно и то же на всех полосах.

**Адрес и удостоверение края — пара.** Профиль, называющий адрес авторитета и не называющий
сертификат, которым край себя назовёт, даёт контроль, отказывающий **всегда и по одной причине**.
Требование: страж старта отказывает, когда объявлена половина пары (BAT-1-32), и декларативная
проба читает **объявления** профилей, а не отрендеренный шаблон.

### 5.4 Молчание авторитета — ОТКАЗ, и это решение, а не недосмотр

Удостоверение наше, отзыв наш, авторитет наш и живёт на том же внутреннем слушателе, к которому
край обращается на каждом запросе. Мягкий проход означал бы: выдаём, отзываем и **свой же отзыв не
исполняем**. Асимметрия с полосой прежнего издателя (где мягкий проход принят и задокументирован)
объявлена, а не выведена: там авторитет — третья сторона, её доступностью мы не управляем.

Отказ по недоступности авторитета отличим от отказа по негодному удостоверению **внутрь** (код
исхода, счётчик, запись) и **неотличим наружу** в той части, которая касается самого удостоверения
(§8).

### 5.5 Имя в докер-полосе: асимметрия ОБЪЯВЛЕНА, а не выведена

На крае личность несёт **сама строка**, и второго поля не требуется. В докер-полосе имя
(`docker login -u`) требуется **обязательно** и обязано совпадать с идентификатором, который несёт
предъявленная строка. Это **различие между полосами одного механизма**, и оно объявляется здесь —
иначе оно возникло бы как побочный эффект и никто бы его не решал.

**Почему полосы различаются.** Протокол докера требует непустого имени и хранит пару целиком;
поля, которое можно не заполнять, у него нет. Отсюда три законных исхода, и выбран третий:

| исход | почему отвергнут / выбран |
|---|---|
| имя игнорируется | **принято-и-проигнорировано** — запрещено прямо (`api-conventions.md`) |
| имя — постоянный литерал | одна строка входа у всех удостоверений: журнал и история команд перестают говорить, **какое** удостоверение в игре |
| **имя = идентификатор удостоверения, равенство обязательно** | ✔ выбран |

**Это не второе написание одного значения в контракте.** Идентификатор хранится в **одном** месте —
в строке реестра; на входе он предъявляется дважды **на одной поверхности**, и от этого он не
становится двумя источниками истины. Роль второго предъявления — та же, что у контрольной суммы:
перепутанная вставка отвергается **сразу и внятно**, а не тремя шагами позже и не своим именем.

**Цена названа:** пользователь копирует два значения вместо одного. Она принята сознательно, и
проверяемое следствие у неё есть — BAT-1-38 требует, чтобы расхождение давало отказ, **дословно тот
же**, что при неверном секрете (не оракул), а совпадение — проход.

**Предикат удержания.** BAT-1-38 (обе стороны) плюс проба сверки полос: перечень обязательных полей
входа у каждой полосы предъявления объявлен, и различие между полосами — **решение** в этом
разделе, а не расхождение реализаций.

## §6 Отзыв доходит до предъявления, и окно названо числом

**Отзыв — снятие строки** (§1.2). Предъявление резолвит строку по первичному ключу **одним**
оператором, чей предикат включает: существование строки · вид `SECRET` · совпадение хеша
(постоянное время) · непросроченность · активность владельца. Нет строки — нет удостоверения; это
и есть отзыв на предъявлении, полученный **конструкцией**, а не вторым механизмом.

**Гарантированная граница — окно кэша вердикта**: отозванное удостоверение отвергается **не позже
5 секунд** после того, как отзыв закоммичен. Типичная задержка меньше, но приёмка требует
утверждения **гарантированной** границы, а не типичной: проба, утверждающая типичное, зеленеет
на сломанной гарантии.

**Проба ставит вопрос СКВОЗЬ обе стороны** — отозвали → предъявили → отказ. Две пробы по половине
(«отзыв записался» и «отказ приходит») не доказывают ничего: это ровно тот класс, где каждая
сторона исправна, а вместе они про разный предмет.

**Что ещё обязано отзывать удостоверение, кроме глагола отзыва.** Снятие владельца, снятие участия,
перевод владельца в неактивное состояние — каждый из этих поводов обязан приводить к отказу на
предъявлении в том же окне. Перечень поводов привязан к **самому поводу** (снятию строки или
смене состояния), а не к перечню глаголов: перечень обязанных писать расходится с деревом, повод —
нет.

## §7 Срок: обязателен, и обе величины объявлены числом ровно один раз

**Решение.**

| величина | значение | где объявлена |
|---|---|---|
| потолок срока вида `SECRET` | **90 суток** | `pkg/tokenpolicy`, одним объявлением |
| умолчание, когда срок не назван | **30 суток** | там же |

**Разрешение коллизии «ноль».** У вида `SECRET` значение `0` означает **«срок не назван»** и
разрешается умолчанием; «бессрочно» у этого вида **не существует ни в каком написании**. Так
устранена коллизия §1.3: из области значений убрано одно из двух значений, а не введён второй
способ его написать. Цена названа честно: один и тот же ноль означает у двух видов разное.
Смягчение — в том, что неоднозначность живёт **только во входе** и снимается на границе: строка
удостоверения и ответ выдачи всегда несут **заполненный** срок, поэтому ниже по потоку двусмыслен-
ности нет ни у одного читателя.

**Срок сверх потолка отвергается, а не урезается** — иначе вызывающий получает успех и уверен, что
его параметр применён.

**Обе величины вносятся в перечень, стерегомый гейтом** (§1.8) — решением, а не умолчанием.
Величина, которой в перечне нет, не стережётся ничем.

**Комментарий поля контракта правится ТЕМ ЖЕ изменением — это исход, а не побочный эффект.**
Сегодняшний комментарий `ttl_seconds` объявляет `0 → бессрочный`. С введением вида `SECRET` он
становится полуправдой: верен для двух видов и неверен для третьего. Комментарий у контроля,
противоречащий коду, провоцирует «починку» кода под неверный комментарий — здесь она означала бы
возвращение бессрочного секрета. Исходов три, четвёртого нет, и выбран первый: **комментарий
называет смысл ПО ВИДАМ** (у `KEYPAIR` и `FEDERATED` — «бессрочно», у `SECRET` — «срок не назван,
применяется умолчание; бессрочного не бывает»), правится в том же изменении, и то же различие
называет страница документации (BAT-1-70).

**Арифметики отсрочки снятия подписного ключа это НЕ касается**, и сказано прямо, чтобы следующий
читатель не «починил» её под новое число: секрет ничем не подписан, переживание подписного ключа к
нему отношения не имеет, и `KeyRemovalGrace` остаётся функцией прежних трёх слагаемых.

## §8 Потолок числа удостоверений — ВЫНЕСЕН из области (решение владельца, круг 2)

Прежняя редакция вводила вид каталога пределов и объявляла фазу аддитивной. **Оба утверждения
одновременно верны быть не могут**, и это блокирующее замечание круга 1.

**Противоречие настоящее.** Потолок, считающий **все** удостоверения принципала, меняет поведение
**существующего** глагола: арендатор, у которого сегодня удостоверений больше умолчания, получил бы
отказ на выдаче обычной ключевой пары — то есть фаза, объявленная аддитивной, ломает работающий
путь. Потолок **только** по виду `SECRET` не спасает: имена видов учёта (`iam.user.token`) вводили
бы в заблуждение — считается не то, что назван, — а объявленная цена относилась бы к пустому
множеству, потому что удостоверений этого вида в момент ввода ноль.

**Исход: предмет выносится в задачу-преемницу**, предикат входа которой — закрытая эта фаза. Там
вопрос «что именно считать» решается без ломающего следствия: у него появляется собственная приёмка,
собственное решение о существующих строках и собственная величина умолчания.

**Что при этом НЕ теряется.** Стоимость страницы перечня ограничена сверху и без потолка — размером
страницы (`page_size <= 1000`), а стоимость проверки предъявленного ограничена окном вердикта
(§2.2) и от числа выпущенных удостоверений **не зависит**: цена равна числу **различных
предъявляемых** удостоверений за окно, а не числу лежащих в базе. Незакрытой стороны в контуре фазы
это не оставляет.

**Что переносится вместе с предметом** (чтобы преемница не выводила заново): производитель отказа
обязан остаться **единым** — `pkg/quota/refusal.go` и посаженная им конструкция схемы, — а не
заводить свою ветку в глаголе выдачи; код исхода — `RESOURCE_EXHAUSTED`/429, тот же, что у всех
прочих видов.

## §10 Единый отказ наружу, различимость внутрь

**Наружу — один отказ.** Неизвестный идентификатор, неверный секрет, истёкший срок, отозванное
удостоверение, неактивный владелец, вид, не принимаемый этой поверхностью, — **один и тот же** код
и **один и тот же** текст. Различимый текст есть оракул: по нему отличают «нет такого» от «есть, но
не ваш», то есть ровно то, что скрытие и должно закрыть.

**Внутрь — раздельно.** Счётчик по каждой причине отказа, счётчик промахов кэша, счётчик
недоступности авторитета. «Ноль отказов за всю жизнь контроля» обязано быть **заметно** — иначе
мёртвый контроль невидим; и «ноль осмотренных» обязано быть отличимо от «ноль находок».

**Недоступность авторитета — отдельный исход** и наружу тоже: это не отказ в удостоверении, а
неспособность края установить его состояние. Предлагать вызывающему переаутентифицироваться на
неисправность, которую не исправит ни одно его удостоверение, — вводить в заблуждение.

## §11 Порядок работ: первой красной ложится ФОРМА — она красна ПО ПРЕДМЕТУ

Порядок выбран так, чтобы самое дорогое к исправлению утверждалось раньше самого заметного — **и
чтобы каждая первая красная была красна ПО ПРЕДМЕТУ**, а не «нечем собрать».

**Замечание круга 1 принято.** Прежняя редакция ставила первой `BAT-1-21` (секрета нет ни в одном
пути записи). Собрать её до миграции нечем: вида `SECRET` не существует, выдать нечего, и краснота
означала бы отсутствие лесов, а не отсутствие свойства. Красное «по предмету» и красное «по
отсутствию предмета» неотличимы в отчёте — и второе зеленеет само, как только леса появятся, ничего
не доказав.

1. **BAT-1-01…08** — форма и её разбор. Красные первыми **по предмету**: это чистые модульные
   пробы над объявленной функцией, им не нужны ни схема, ни выдача, ни край. Функции нет — проба
   красна ровно потому, что нет свойства.
2. **BAT-1-19 / BAT-1-20 / BAT-1-24** — ограничения таблицы (словарь вида, взаимоисключение,
   обязательный срок, ослабленное требование у колонки зеркала). Пишутся прямо на хранилище,
   поэтому им довольно миграции и не нужен ни один глагол.
3. **BAT-1-21 / BAT-1-22 / BAT-1-23** — секрет не найден ни по одному из четырёх путей записи.
   Ставятся сразу, как появился минимальный путь выдачи: свойство дороже прочих к исправлению,
   потому что его нарушение чинится схемой и контрактом, а не кодом.
4. **BAT-1-09…18** — выдача: вид (все три **выдаваемых**; `LEGACY` не выдаётся и здесь не
   участвует), срок, отказ чужим полям, форма ответа по видам.
5. **BAT-1-42…48** — отзыв сквозь обе стороны, в объявленном окне.
6. **BAT-1-26…36** — приём на крае, полосы, кэш, fail-closed.
7. **BAT-1-37…41** — докер-полоса.
8. **BAT-1-49…61** — владелец, уровень, стражи старта.
9. **BAT-1-62…72** — консоль, единый отказ и наблюдаемость, гейты дерева, документация.

**Волна собирается целиком перед отправкой** (`multi-agent-flow.md` §14): полосы 3–8 трогают одни и
те же файлы края и iam, и зелёное каждой по отдельности о совместимости не говорит ничего.

## §12 Сценарии

Обозначения уровня пробы: **U** — модульная · **I** — интеграционная (Postgres в контейнере) ·
**E** — сквозная через край / живой контур · **G** — гейт по дереву · **B** — проба стража старта ·
**W** — проба браузером (playwright).

**Каждое отрицание несёт положительный контроль.** Сценарий, все утверждения которого ждут отказа,
зеленеет на проверяющем, отвергающем всё, — и это не гипотеза, а способ, которым такие пробы
ломаются чаще всего.

**Утверждается ПАРА** — HTTP-статус и gRPC-код (`api-conventions.md` §«gRPC-код → HTTP-статус»).
Отказ аутентификации — `UNAUTHENTICATED`/401; отказ формы запроса выдачи — `INVALID_ARGUMENT`/400;
недоступность авторитета — `UNAVAILABLE`/503. **Иных кодов фаза не производит**, и перечень закрыт
намеренно: код в преамбуле, у которого нет производителя ни в одном сценарии, читается как
объявленное поведение и не является им. (Здесь стоял `RESOURCE_EXHAUSTED`/429 — он уехал вместе с
предметом предела, §8; замечание круга 2.)

**ID: BAT-1-12** · U + I — **форма ответа проверяется по ВСЕМ трём видам**

**Then** `SECRET`: секрет непуст, ключевой материал пуст весь

собственное свойство перечня в том, что неназванное **пропускается**, поэтому отсутствие записи
неотличимо от «поле проверено и чисто»
**And** законный близнец: поле, носителем секрета **не** помеченное и в перечне не названное, —
молчание. Без него гейт требовал бы называть всё подряд и был бы снят первым же ложным срабатом
**And** второй законный близнец, задающий **границу** оси: помеченное поле сообщения, которое
ответом операции **не является** (синхронный глагол), в перечне не названо — и это **молчание**, а
не находка. Требовать записи для типа, которого подметальщик увидеть не может, значило бы завести
находку без предмета; в дереве такой случай уже есть (§4.3.3)

**Ось 2 — отсутствие непомеченных носителей на поверхности.**
**And** поле, **чьё имя совпало с образцом секрета** (перечень образцов и его адъюдикация — §4.3.3),
обязано быть **либо помеченным, либо названным в ведомости исключений с причиной**; ни то ни другое
— находка с координатой и с образцом, который совпал
**And** запись ведомости законна **только** для поля, носителем секрета **не** являющегося:
носитель закрывается **пометкой и ничем иным**. Поле, одновременно **помеченное** и **названное в
ведомости**, — находка с координатой: одно из двух объявлений ложно. Без ограничения ведомость
проглатывает поле, вводимое самой фазой, ось 1 отрабатывает на пустом множестве, и §4.3.2 остаётся
держаться прозой (§4.3.3)
**And** законный близнец оси 2: поле, чьё имя ни с одним образцом не совпало, — молчание
**And** второй законный близнец ограничения: запись ведомости на поле, секретом **не** являющееся
и **не** помеченное (публичная половина ключа, ссылка на кред), — молчание. Без него ограничение
краснело бы на обеих законных записях ведомости и было бы снято первым же ложным срабатом
**And** ведомость исключений **истекает сама**: запись, у которой больше нет предмета — поле снято
либо поле помечено, — **находка**, а не тишина
**And** без оси 2 гейт не ловит «завели поле-носитель и забыли пометить» **вовсе**: ось 1 на
непомеченном молчит by construction, то есть одна ось держала бы согласие двух объявлений между
собой, а не отсутствие секретов на поверхности

**Перепись и доказательство.**
**And** гейт печатает **объём осмотренного** — сколько сообщений-ответов, сколько полей прочитано,
сколько помеченных, сколько записей ведомости, — чтобы «находок ноль» было отличимо от «прочитано
ноль»; на **пустой** ведомости гейт **проходит**: пустая ведомость есть цель, а не поломка
**And** доказан инъекцией в обе стороны по **каждой** оси отдельно: снятие пометки у поля, стоящего
в перечне, — красное; изъятие поля из перечня при живой пометке — красное; переименование поля в
совпадающее с образцом без пометки и без записи — красное; **запись ведомости на помеченное поле
— красное**; законные близнецы обеих осей и **законная запись ведомости на непомеченное поле** —
молчание; запись ведомости, потерявшая предмет, — красное
**And** интеграционная половина: строка операции, в тело которой секрет положен **в обход**
конструкции §4.3.1, подметается бэкстопом — то есть перечень не только объявлен, но и действует
**And** назван **предел** гейта (§4.3.3): поле-носитель, чьё имя ни на что не похоже и которое не
пометили, не ловится **ни одной** осью; механического держателя у этого случая нет, его держит
обзор изменения контракта — и это сказано прямо, а не выдано за покрытие

## §14 Критерии для `acceptance-reviewer`

Ревьюер обязан проверить и назвать по каждому пункту «да/нет», а не «в целом»:

1. **Каждый сценарий ВЫЗЫВАЕМ.** По каждому — существует ли минимально-законный вход. Особое
   внимание к BAT-1-17 (срок), BAT-1-19/20/24 (ограничения таблицы), BAT-1-11…14 (виды) и
   BAT-1-25 (обратное заполнение): сценарий, состояние которого схема не допускает, Given не
   является. Круги 1 и 2 нашли здесь **три** блокирующих (B1, B2, B12) — проверять по-прежнему
   **замером**, а не чтением. Отдельно: `LEGACY` конструируем **только** обратным заполнением, и
   сценарий, требующий его выдачи, Given не имеет by construction.
2. **Каждое отрицание имеет положительный контроль**, и контроль стоит **в том же** сценарии, а не
   «где-то в наборе».
3. **Пара «статус и код»** утверждается там, где сценарий проходит через край.
4. **Ни одно решение §2 не осталось без предиката удержания**, и предикат называет пробу или гейт,
   а не намерение.
5. **Область §9.1 и сценарии §12 покрывают друг друга**: строка области без сценария — не покрытие;
   сценарий вне области — работа, которой документ не требует.
6. **Числа §1 воспроизводимы** названными предикатами на названной ревизии.
7. **Публичность выдержана**: в документе нет сборки «координата + условие + следствие для
   постороннего».
8. **Границы §9.2 названы с предикатом ввода**, а не обещанием: пункты 2 и 3 — особенно.
9. **Асимметрии объявлены, а не выведены**: fail-closed на нашей полосе против мягкого прохода на
   чужой (§5.4); освобождение машинного принципала от повышенного уровня (§2.3).
10. **Ни одно поле не принимается молча**: по каждому полю запроса выдачи, осмысленному не для
    всякого вида, назван исход из трёх.
11. **Пропуск в нумерации сценариев объявлен** и назван вместе с тем, куда уехал предмет: `56` и
    `57` (§9.4). Необъявленный пропуск неотличим от потерянного сценария.
12. **Каждая правка круга N сверена ПОИМЁННО с формулировкой круга N−1** — по записи этого круга
    (§16 — круг 2, §17 — круг 3, §18 — круг 4). Критерий переформулирован в круге 4: прежняя
    редакция называла **круг 2** поимённо и потому истекала вместе с ним — к третьему кругу она
    предписывала сверять то, что уже сверено, и молчала о том, что сверять надо. Новые
    идентификаторы круг заводит только вместе с новым предметом и объявляет это в своей записи;
    прочие правки идут **внутри** существующих сценариев, чтобы сверка шла по тем же именам.
13. **Круг N не переписывает подтверждённое БЕЗ НАЗВАННОЙ ПРИЧИНЫ; названная причина — законный
    ход.** Правка подтверждённого молча отменяет проверку, не имея предмета; правка с названной
    причиной — обычная работа.
    **Формулировка исправлена в круге 3 по замечанию ревьюера, и поправка принята к себе:** прежняя
    редакция запрещала переписывать подтверждённое **безусловно**, а подтверждение относится к
    **редакции, на которой оно снято**, и на изменившееся окружение автоматически не переносится.
    Безусловный запрет однажды защитил бы **устаревшее** подтверждение — то есть сделал бы ровно то,
    против чего писался.
14. **У каждого гейта, описанного этой приёмкой, НАЗВАН ПРОИЗВОДИТЕЛЬ ВХОДА.** По каждому гейту —
    из чего берётся множество, которое он обходит, и из чего берётся множество законных близнецов;
    оба обязаны быть перечислимы **механически** — из дескрипторов, из дерева, из уже
    существующего соглашения, — а не подразумеваться. **Гейт, у которого производителя входа нет,
    построить нельзя**: перечислить «все помеченные» невозможно, если не сказано, чем помечают, а
    «ноль находок» тогда неотличимо от «ноль прочитанного».
    **Критерий введён в круге 4 по замечанию ревьюера.** `B13` — блокирующее круга 3 — попал бы
    под него: `BAT-1-73` требовал перечислить «каждое помеченное поле», а механизма пометки
    документ не называл ни разу при четырёх вхождениях формулировки. Отдельно проверить: описание
    гейта, называющее источник входа **литеральным перечнем в коде**, производителя не имеет —
    такой гейт сравнивает перечень сам с собой и на новом элементе не краснеет никогда.

## §15 Что осталось нерешённым — названо, а не спрятано

1. **Величина потолка срока (90 суток) выбрана, а не измерена.** Довод — размен между стоимостью
   ротации для арендатора и радиусом утечки; наблюдения, из которого следовало бы именно это число,
   у нас нет. Предикат пересмотра: появление данных о том, как часто арендаторы ротируют на
   практике (отметка последнего предъявления, вводимая этой же фазой, такие данные и даёт).
2. **Умолчание предела числа удостоверений здесь НЕ называется** — предмет вынесен из области
   целиком (§8), и величина принадлежит той приёмке, где её можно выбрать вместе с решением о
   существующих строках. Назвать число здесь значило бы закрепить его вне того решения, которое
   его оправдывает.
3. **Узкое удостоверение для ЧЕЛОВЕКА сегодня невыразимо** (§9.2 п. 3), и у ограничения нет
   исполнимого обхода: служебная учётка — ответ для машины, не для человека. Это признанный
   остаток, а не забытая сторона.
4. **Отзыв ОДНИМ действием всех удостоверений принципала** («паника») этой фазой не вводится.
   Механизм отсечки по субъекту в дереве есть, и он покрыл бы случай, но глагола у него нет.
   Предикат ввода: первая же просьба владельца либо первый инцидент.
5. **Сокращение типичного окна отзыва событием** (§9.2 п. 5) остаётся возможностью; гарантию оно не
   меняет, поэтому и не введено. Если однажды потребуется гарантия меньше окна — вводить надо
   именно гарантию, а не «обычно быстрее».
