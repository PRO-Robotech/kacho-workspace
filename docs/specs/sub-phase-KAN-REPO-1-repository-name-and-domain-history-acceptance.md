## Обзор

Задача просит **решения**, а не работы: как назвать отдельный репозиторий вынесенной
службы и едет ли туда история домена. Приёмка отвечает на оба вопроса, называя **все**
исходы с ценой и выбранный, и делает это перемером — потому что за неделю, прошедшую с
заведения задачи, мир сдвинулся по обоим предметам сразу.

Перемер подтвердил принятое решение и внёс в него **две поправки, обе с числами**:

1. **Решение об имени ИСПОЛНЕНО** — и механизмом, которого в перечне исходов задачи не
   было. Прежний полирепо **переименован** в `kacho-iam-polyrepo-archive` и заархивирован,
   а имя `kacho-iam` отдано новому репозиторию, ныне `PRO-Robotech/kaname`. Это **четвёртый**
   исход, и он **сильнее** выбранного третьего ровно по той оси, ради которой третий и
   выбирался: старое имя не мертво — оно **перенаправляет на победившее**, поэтому внешний
   потребитель, склонировавший `kacho-iam`, получает сегодняшнюю службу, а не состояние
   полуторамесячной давности (§2, сценарии 01–04).
2. **Решение об истории НЕ исполнено, и класс, о котором предупреждала задача, УЖЕ
   реализовался**: `kaname` заведён снимком. `git rev-list --count HEAD -- .` в нём даёт
   **2** — ровно тот исход, который задача называла проигрышным. Значит предмет решения
   сместился с **предотвращения** на **починку**, и цена изменилась: переписывать придётся
   **опубликованную** историю (§3).

Сверх этого перемер разделил второе решение надвое, чего задача не делала, и это
разделение несущее: **раскол** даёт 894 коммита, **прививка** добавляет 67. То есть 93 %
ценности решения лежит в расколе, а прививка — семипроцентная добавка, чья польза измерена
(§3.2) и чья стена **не исчезает**: корень архива сам снимок (883 файла одним коммитом).
Оба шага при этом обязаны идти **одной переписью**: вторая перепись стоит столько же, что
первая, а окно, в котором перепись бесплатна, сегодня открыто и закроется первым же
опубликованным тегом (§3.4).

## 1. Перемер посылки

Правило простое: посылка задачи проверяется первой, и каждое её число — своей командой.
Из четырёх чисел тела **воспроизвелись все четыре** — но два из них только на **своей**
ревизии, и это надо сказать прямо, иначе следующий читатель решит, что автор ошибся.

### 1.1. Числа тела задачи — верны для ревизии дня заведения, не для сегодня

Задача заведена 2026-08-31T12:33:02Z. Вершина ствола продукта на тот момент —
`1b8f467fb496edce6e6a9763194816409f7c3654`.

```sh
r=$(git rev-list -1 --before='2026-08-31T12:33:02Z' origin/main)   # 1b8f467fb4
git rev-list --count "$r" -- services/iam   # → 866
git rev-list --count "$r"                   # → 2834
```

Оба числа тела воспроизводятся **дословно**. На сегодняшней вершине
`a10bfd208d4dc556c2a4c75ec813edb60f350b5d` те же команды дают **880** и **2848**.

| величина | тело задачи | сегодня | предикат |
|---|---:|---:|---|
| коммитов, тронувших `services/iam` | 866 | **880** | `git rev-list --count origin/main -- services/iam` |
| коммитов в стволе | 2834 | **2848** | `git rev-list --count origin/main` |
| веток у прежнего полирепо | 15 | **15** | `gh api repos/PRO-Robotech/kacho-iam-polyrepo-archive/branches --jq length` |
| незаархивированных зеркал | 12 | **12** | `gh repo list PRO-Robotech --limit 100 --json name,isArchived` + отбор `kacho-*` без `kacho-workspace` |

**Замечание об адресе, из-за которого число веток едва не разошлось.** Имя `kacho-iam`
сегодня **перенаправляет**, поэтому `gh api repos/PRO-Robotech/kacho-iam/branches --jq length`
отвечает **2** — это ветки `kaname`, а не архива. Пятнадцать веток живут у архива под его
новым именем. Спрашивать надо адрес, а не привычное имя: перенаправление отвечает молча и
правдоподобно.

### 1.2. Единица счёта: 866 ≠ 880 ≠ 894, и все три верны

Задача называет предикат снятия «866 при переносе». Он **недостижим** ни при каком верном
исполнении, и не потому, что перенос неверен, а потому, что три числа мерят разное:

| число | что считает | предикат |
|---:|---|---|
| **866** | коммиты, тронувшие путь, **на ревизии дня заведения** | `git rev-list --count 1b8f467fb4 -- services/iam` |
| **880** | то же **сегодня** | `git rev-list --count origin/main -- services/iam` |
| **894** | коммиты **расколотой истории** | `git subtree split -P services/iam -b iamhist && git rev-list --count iamhist` |

Разница 894 − 880 = **14**, и она **не одного вида** — это надо сказать, иначе следующий
объяснит её одними слияниями и ошибётся:

| | раскол | по пути | разница |
|---|---:|---:|---:|
| всего | 894 | 880 | **14** |
| слияний | 153 | 147 | 6 |
| без слияний | 741 | 733 | 8 |

Обе части даёт одно и то же: упрощение истории по пути отбрасывает коммит, чей результат на
этом пути совпал с результатом одного из родителей, а раскол его сохраняет. Предикаты —
`git rev-list --count [--merges|--no-merges] iamhist` и та же пара с
`origin/main -- services/iam`.

**Следствие для предиката задачи:** число сверки обязано браться **из раскола**, а не из
`rev-list` по пути, и обязано называть ревизию, на которой раскол сделан. Форма предиката
дана в §9.

### 1.5. Что перемер нашёл СВЕРХ посылки — четыре факта, и каждый меняет цену

**Факт А. Окно бесплатной переписи открыто, и оно узкое.** У `kaname` сегодня **0** тегов,
**0** заметок о выпусках, **0** форков, **0** звёзд, **0** наблюдателей, и **ни один модуль
его не требует**: объявление `services/iam/go.mod` называет путь
`github.com/PRO-Robotech/kaname`, но `require` на него нет ни в одном `go.mod` дерева
(объявлений модулей два — корневой `github.com/PRO-Robotech/kacho` и модуль службы).
Значит перепись истории сегодня не рвёт **ничего измеримого**. Первый же опубликованный
тег либо первый потребитель, пиннувший псевдоверсию, закрывает окно необратимо.

**Факт Б. Ветка `ci-bootstrap` — работа в единственном экземпляре, и она РАЗОШЛАСЬ, а не
отстала.** «Впереди на 2» было бы неверно и мягче правды:

```sh
git rev-list --count main..ci-bootstrap   # → 2
git rev-list --count ci-bootstrap..main   # → 1
git merge-base main ci-bootstrap          # → 5618c88 — КОРЕНЬ снимка
```

Общий предок — корневой снимок, то есть ветка отделилась от самого начала и своей стороной
`main` не поглощена. Перепись путей разделяет её содержимое честно:

| величина | значение |
|---|---:|
| путей у `ci-bootstrap` | 2194 |
| из них вне расколотой истории | 1216 |
| из этих 1216 — **были в корневом снимке** (прежняя раскладка, не работа) | **1210** |
| **уникальны для ветки** | **6** |

Уникальны ровно шесть, и все они — оснастка конвейера службы:
`.github/golangci.yml`, `.github/scripts/classify-integration-outcome.sh`,
`.github/scripts/go-test-verdict.py`, `.github/scripts/gosec-gate.sh`,
`.github/scripts/run-integration.sh`, `.github/workflows/ci.yml`. Каталога `.github` нет ни
у `kaname/main` (0 путей), ни у `services/iam` (0 путей), и все шесть отсутствуют у
`kaname/main` — проверено поимённо, 6 из 6. Всякий план, трогающий `kaname`, обязан эту
ветку **не тронуть**; преемник для этих шести назван остатком §8.

**Факт В. Корень архива сам снимок.** `1a4dbb2a7` «chore: initial public release»,
2026-06-28, **883 файла, +269 449** одним коммитом. Прививка **не убирает стену** — она
сдвигает её на **17 дней** назад.

**Факт Г. Охват прививки ограничен переработкой домена.** Из **918** путей вершины архива
до сегодняшнего дерева дожили **228** (из них `.go` — **149**). Остальные 690 переименованы
или сняты.

## 2. РЕШЕНИЕ 1 — имя репозитория

### 2.1. Исходы и цена каждого

| # | исход | цена |
|---:|---|---|
| 1 | **оживить `kacho-iam`** | имя противоречит собственному решению продукта о наименовании (#2076): репозиторий несёт прежнее имя домена, а не имя продукта. Наследуется 15 чужих веток и описание, пережившее свой предмет. Настройки (защита ствола, снятие головы при вливании) всё равно заводятся заново |
| 2 | **завести новое имя, прежнее оставить живым** | **два живых претендента**: поиск по прежнему имени отдаёт его первым, потребитель клонирует состояние 2026-07-15 и об этом не узнает. Расхождение не сходится само и ничем не наблюдаемо |
| 3 | **заархивировать прежнее имя на месте, завести новое** | второго живого претендента нет. Но прежнее имя остаётся **занятым архивом**: ссылка на `kacho-iam` продолжает вести на состояние 2026-07-15 — читаемое, доступное и устаревшее |
| 4 | **переименовать прежнее в архивное имя, отдать имя новому, заархивировать прежнее** | ссылка на `kacho-iam` **перенаправляет на победителя**: устаревшего состояния по прежнему адресу больше нет. Цена — архив находится только по новому имени, и всякий, у кого была ссылка на полирепо, попадает не туда, куда шёл |

### 2.2. Выбранный исход — **4**, и он уже исполнен

Исход 4 в перечне задачи отсутствовал; перемер (§1.3) показал, что дерево пошло именно им.
Он **доминирует** исход 3 ровно по оси, ради которой тот выбирался: задача называла риском
то, что «внешний потребитель склонирует и не узнает, что взял состояние на полтора месяца
старше ствола». Исход 3 этот риск **не снимает** — заархивированный репозиторий читается и
клонируется, — а исход 4 снимает его **построением**: по прежнему адресу устаревшего
состояния больше нет.

**Цена исхода 4 названа честно и она не нулевая.** Всякая внешняя ссылка на полирепо —
в статье, в закладке, в чужом README — ведёт теперь на `kaname`, то есть **не туда, куда
вела**. Внутри корпуса такие ссылки есть: **652** файла воркспейса упоминают `kacho-iam`
при 1532 отслеживаемых `.md` (предикат: `git grep -l 'kacho-iam' origin/main -- '*.md'`).
Переписывать их **нельзя**: записки свидетельствуют о сделанном, а не предписывают, и
переименование сделало бы ложными утверждения, которые были верны. Это осознанный остаток,
а не недоделка.

### 2.3. Что осталось незакрытым по решению 1

Описание архива сегодня гласит: «Архив прежнего полирепо домена IAM (до 2026-07-15).
Разработка ведётся в PRO-Robotech/kacho; **продукт для отдельной поставки —
PRO-Robotech/kacho-iam**». Названное имя перенаправляет на `kaname`, то есть строка
называет адрес, который больше не обозначает то, что обозначал. Исход — правка описания
(§7, действие наружу).

## 3. РЕШЕНИЕ 2 — судьба истории домена

### 3.1. Исходы и цена каждого

| # | исход | что получаем | цена |
|---:|---|---|---|
| 1 | **снимок** (исполнено 2026-09-05) | 2 коммита; дерево верно | `git blame` отвечает одной из двух дат на 764 531 строку; история домена теряется **второй раз** — первый был сборкой монорепо |
| 2 | **раскол** `git subtree split -P services/iam` | **894** коммита, 2026-07-15…сегодня | хеши иные, чем в монорепо (проекция, не тождество); перепись опубликованной истории `kaname`; `ci-bootstrap` остаётся при своём общем предке — корне снимка, — и после переписи `main` перестаёт делить с ней хоть один коммит |
| 3 | **раскол + прививка** к вершине архива | **961** коммит, 2026-06-28…сегодня | то же плюс шов, где 539 из 916 файлов приписываются коммиту импорта; стена **остаётся**, сдвинувшись на 17 дней; **и хеши эры архива тоже переписываются** — см. ниже |

> [!warning] Цена, которую легко не заметить: прививка ПЕРЕПИСЫВАЕТ и эру архива
> Материализация замены рождает новые коммиты **по всей** цепочке, а не только у раскола.
> Замер (сценарий 30): из **67** коммитов архива уцелело **2** — корень `1a4dbb2a7` и его
> прямой потомок `0ec2b0fd7`; у раскола уцелело **0** из 894 (эти коммиты и так были
> синтетическими).
>
> **Следствие, которое надо сказать прямо:** после переписи сверка «этот коммит архива и
> есть этот коммит службы» становится **невозможной для 65 из 67**. Архив остаётся
> единственным местом, где живут исходные идентификаторы полирепо-эры, и всякая ссылка на
> них — в записке, в задаче, в чужой статье — продолжает указывать **в архив**, а не в
> службу. Это не поломка, а свойство любой переписи; неназванным оно превращается в
> ловушку для того, кто попробует сверить два дерева по хешу.
| 4 | **оживить прежний репозиторий и вести службу там** | история непрерывна без прививки | отвергается решением 1: имя противоречит имени продукта; и это возврат к исходу 1 §2.1 |

### 3.2. Цена и польза раскола и прививки — ПОРОЗНЬ, потому что они разного веса

Задача считала раскол и прививку одним решением. Замер их разделяет:

| ось | раскол | прививка |
|---|---:|---:|
| коммитов добавляет | **894** | **67** |
| доля в итоговых 961 | **93 %** | **7 %** |
| охватывает период | 2026-07-15 → сегодня | 2026-06-28 → 2026-07-15 (**17 дней**) |
| убирает ли стену `blame` | да, для своего периода | **нет** — корень архива сам снимок (883 файла, +269 449) |
| файлов, до которых дотягивается | все 2394 сегодняшних | **228** доживших путей из 918 |

**Польза прививки измерена, а не предположена.** Из 149 доживших файлов Go (23 395 строк
сегодня) после прививки **14 321 строка** приписывается коммитам **до 2026-07-15**:

```sh
git blame -M --line-porcelain iamhist -- <файл> | grep '^author-time '
#   счёт строк с меткой времени раньше 2026-07-15
#   → файлов осмотрено 149, строк всего 23395, строк эры до 2026-07-15 — 14321
```

Это 61 % строк **в тех файлах, которые дожили**, и 3,3 % корпуса Go службы. Число названо в
обеих единицах намеренно: одна показывает, что прививка не пустая, вторая — что она не
несущая.

### 3.3. Выбранный исход — **3**, обоими шагами и ОДНОЙ переписью

Решение задачи подтверждается. Две поправки к его обоснованию:

- **несущее — раскол**, а не прививка. Довод задачи («история воссоединяется») верен, но
  93 % истории даёт раскол, и если бы прививка оказалась невозможна, решение не изменилось
  бы;
- **прививка берётся потому, что она почти бесплатна ВНУТРИ той же переписи**: отдельная
  вторая перепись стоила бы столько же, сколько первая, и второй раз потребовала бы снятия
  защиты ствола. Делать её позже — значит платить дважды за 7 %.

**Раскол проверен исполнением, а не объявлен.** Ключевые свойства (сценарии 09–11):

```sh
git subtree split -P services/iam -b iamhist
git rev-list --count iamhist                                    # → 894
git rev-parse iamhist^{tree}                                    # caa65753…
git rev-parse origin/main:services/iam                          # caa65753…  ← СОВПАЛИ
git rev-parse 95bdde5711^{tree}                                 # d8773438…
git rev-parse 5dbdbf6907:services/iam                           # d8773438…  ← СОВПАЛИ
```

Корень раскола в этом замере — `95bdde57111b141f5b66bfa31e16b150e629168b`. **Опираться надо
на дерево, а не на этот идентификатор**: он воспроизводится, только пока раскол делают той же
командой от той же ревизии, тогда как равенство деревьев верно при любом способе раскола и
именно оно доказывает, что содержимое не потеряно.

То есть раскол — **точная проекция**: дерево корня равно дереву службы на импорте, дерево
вершины равно дереву службы на сегодняшнем стволе. Содержимое не меняется, меняется только
форма истории.

**Прививка проверена исполнением тоже** (сценарии 13–15):

```sh
git replace --graft 95bdde571 c744f9561      # корень раскола ← вершина архива
git rev-list --count iamhist                 # → 961
git --no-replace-objects rev-list --count iamhist   # → 894  ← замена есть ВИД, не история
git rev-parse iamhist^{tree}                 # caa65753…  ← дерево не изменилось
```

### 3.4. Окно: почему сейчас, и что его закрывает

Перепись опубликованной истории `kaname` сегодня не рвёт ничего измеримого (§1.5, факт А).
Окно закрывают **три** события, любое достаточно:

| событие | почему закрывает |
|---|---|
| опубликован тег версии | версия раздана модуль-прокси Go; отозвать розданное нельзя, а перепись сделает её коммит недостижимым |
| посторонний модуль пиннул псевдоверсию | псевдоверсия называет коммит; после переписи `go mod download` у него откажет |
| появился форк или клон, ведущий свою работу | у него история, которой в стволе больше нет; сведение потребует ручного переноса |

Первое из трёх приходит **из соседней приёмки** — `KAN-RELEASE-1` описывает порядок, в
котором версия платформы публикуется, а пин службы переводится. Порядок между двумя
приёмками поэтому обязателен и назван: **перепись истории `kaname` идёт ДО первого
опубликованного тега службы**.

### 3.5. Порядок шагов

| # | шаг | команда | обратим? |
|---:|---|---|---|
| 0 | снять **страховочный** клон `kaname` целиком и убедиться, что `ci-bootstrap` в нём есть | `git clone --mirror <адрес> kaname-backup.git` · `git -C kaname-backup.git rev-parse --verify ci-bootstrap` | да |
| 1 | из чистой копии ствола продукта **с рабочей выкладкой** сделать раскол; сверить **оба** дерева | `git subtree split -P services/iam -b iamhist` (сценарии 08–11) | да |
| 2 | привить эру архива | `git replace --graft <корень раскола> <вершина архива>` (сценарии 13, 14) | да |
| 3 | **материализовать** замену | `FILTER_BRANCH_SQUELCH_WARNING=1 git filter-branch -f -- iamhist` — и сразу сверка: `git --no-replace-objects rev-list --count iamhist` → **961** (сценарий 30) | да |
| 4 | снять защиту `main` у `kaname` **на время** | `gh api -X DELETE repos/PRO-Robotech/kaname/branches/main/protection` | да |
| 5 | **отправить переписанную историю — ОДНОЙ названной ссылкой** | `git push --force <адрес> iamhist:refs/heads/main` | **НЕТ** |
| 6 | вернуть защиту `main` в прежний вид | `enforce_admins=true`, `allow_force_pushes=false`, `allow_deletions=false` (сценарий 22) | да |
| 7 | сверить в **свежем** клоне | `git rev-list --count HEAD -- .` → **961**; дерево вершины равно `services/iam` ствола | да |
| 8 | `ci-bootstrap` **не трогать** — работа в единственном экземпляре (§1.5, факт Б) | — | — |

> [!important] Шаг 5 отправляет ОДНУ ссылку — и это запрет, а не стиль
> **Запрещены `--mirror`, `--all` и `--delete`.** Копия раскола ветки `ci-bootstrap` не
> содержит **by construction** (она сделана из монорепо продукта, где этой ветки нет), а
> `--mirror` приводит удалённый набор ссылок к локальному — то есть **снимает** её вместе с
> шестью файлами, которых больше нигде нет. `--all` толкает все локальные ветки, включая
> служебные `base`/`archmain`/`iamhist-mat` из рабочей копии замера.
>
> Порядок обязан **закрывать** класс, а не только компенсировать его в §7: для необратимой
> операции компенсация — это уже ущерб. Поэтому ссылка называется дословно
> `iamhist:refs/heads/main`, а страховочный клон шага 0 существует **только** как
> восстановление и источником отправки не служит никогда.

Необратим **шаг 5**. Всё до него — правка; всё после — только новая перепись, которая
дороже первой ровно на то, что окно к тому времени может быть закрыто.

### S3. Раскол — точная проекция, а не пересказ

#### KAN-REPO-1-08 (отрицательный) — раскол не открывается на копии без выкладки

**Дано** копия ствола продукта **без рабочей выкладки** (голое хранилище либо клон
`--no-checkout`)

**Когда** позван `git subtree split -P services/iam -b iamhist`

**Тогда** код возврата **1**
**И** сообщение — `fatal: <путь>/git-subtree cannot be used without a working tree.`
**И** ни одной ветки не создано (`git rev-parse --verify -q iamhist` пусто)

> Полоса названа отдельно, потому что именно в неё упирается шаг 1 порядка: копия ствола
> заводится дёшево без выкладки, а раскол её требует. Сообщение здесь **верное** и называет
> верное лекарство — сделать выкладку; ловушка не в нём, а в соседней полосе (сценарий 29).
>
> **Текст локализован.** Под русской локалью то же сообщение приходит как «критическая
> ошибка: … нельзя использовать не имея рабочего каталога». Утверждать надо под
> `LC_ALL=C`, иначе кейс краснеет от настроек машины, а не от предмета.

#### KAN-REPO-1-29 (отрицательный) — выкладка есть, а пути нет: сообщение зовёт НЕ туда

**Дано** копия ствола продукта **с рабочей выкладкой**
**И** путь, которого в ней нет

**Когда** позван `git subtree split -P services/nosuch -b probe`

**Тогда** код возврата **1**
**И** сообщение — `fatal: 'services/nosuch' does not exist; use 'git subtree add'`
**И** ни одной ветки не создано

> **Вот здесь ловушка.** `git subtree add` **вносит чужое поддерево в текущее дерево** — то
> есть делает противоположное расколу. Исполнивший подсказку получит коммит, которого не
> хотел, в копии, из которой собирался только читать. Верное лекарство — проверить путь
> (`git ls-tree -r HEAD --name-only | grep '^services/'`), а не менять команду.
>
> Две полосы разведены намеренно: у них **разные** «Дано», **разные** сообщения и **разные**
> лекарства, а код возврата и «ветки не создано» у обеих одинаковы — то есть по коду их не
> различить, и кейс, утверждающий только код, сошёл бы за оба сразу.

#### KAN-REPO-1-15 (отрицательный) — замена есть ВИД, а не история

## 5. Что отвергнуто и по какой цене

### 5.1. Оставить снимок как есть — отвергнуто

Довод «дерево верно, история не нужна» защитим ровно до первой отладки. Цена: `git blame`
отвечает одной из двух дат на 764 531 строку; «когда и зачем это появилось» становится
вопросом к монорепо, у которого другой путь и другие хеши, то есть ответ приходится
восстанавливать вручную. Отдельно: исход **не истекает сам** — чем дольше он живёт, тем
дороже перепись (§3.4).

### 5.2. Перепись «когда-нибудь потом» — отвергнуто по цене окна

Сегодня перепись не рвёт ничего измеримого (сценарий 21). После первого опубликованного
тега она рвёт розданное, а розданное не отзывается. Значит «потом» — это не отсрочка, а
**другой** исход, и его цена не равна цене сегодняшнего.

### 5.3. Прививка отдельной, второй переписью — отвергнуто

Довод «сперва раскол, прививку добавим позже» стоит **двух** снятий защиты ствола и двух
переписей опубликованной истории вместо одной, ради 7 % коммитов. Вторая перепись при этом
попадает в то же окно риска, что первая, но уже с меньшим запасом.

### 5.4. Прививка ВМЕСТО раскола — отвергнуто

67 коммитов эры архива без 894 коммитов эры монорепо дают историю, обрывающуюся 2026-07-15,
и стену ровно там, где сегодня, только с другой стороны. Ценность решения — в расколе.

### 5.5. `filter-repo` как обязательное средство — отвергнуто, инструмента нет

`git-filter-repo` в этом окружении отсутствует (`command -v git-filter-repo` → пусто);
`git subtree` и `git filter-branch` присутствуют. Приёмка называет средство, которое
**есть**, а не то, которое принято рекомендовать.

Материализация замены выполняется парой «`git replace --graft` →
`FILTER_BRANCH_SQUELCH_WARNING=1 git filter-branch -f -- <ветка>`», и она **проверена
исполнением** (сценарий 30): код 0, 28 с, 961 и с учётом замен, и без него. Предупреждение
`filter-branch` о том, что средство устарело, гасится переменной осознанно — альтернативы в
окружении нет, а молчаливое предупреждение в выводе необратимого шага хуже явного глушителя.

**Круг 1 этого средства не называл, и это было блокирующим:** шаг 3 порядка требовал
«материализовать», а команды не было ни в одном разделе. Сценарии 13–15 доказывали, что
материализация обязательна, и ни один — что она выполнима. Правило §5.5 существовало и к
собственному единственному шагу без средства применено не было.

### 5.6. Оживить прежнее имя ради непрерывности истории — отвергнуто решением 1

Это исход 4 §3.1, и он возвращает исход 1 §2.1: имя домена вместо имени продукта. Прививка
даёт ту же непрерывность, не требуя сохранять имя, — то есть решение об имени и решение об
истории **разделимы**, и разделять их надо, иначе одно тянет за собой другое без довода.

### 5.7. Переписать 652 упоминания `kacho-iam` в корпусе — отвергнуто

Записки свидетельствуют о сделанном. Переименование сделало бы ложными утверждения, которые
были верны (репозиторий с таким именем существовал, и по этому адресу лежало то, о чём
записка говорит). Правится только то, что **предписывает** и адресует вперёд (§8, п. 2).

Наружу ведут четыре действия: архивация, заведение имени, отправка переписанной истории,
правка описания. Первые два уже исполнены (§1.3). По каждому нарушению назван не «откат», а
компенсация и её цена.

| нарушение | компенсация | цена |
|---|---|---|
| имя победителя занято **до** архивации проигравшего | архивация проигравшего под новым именем; перенаправление со старого адреса **не возникнет** — имя уже занято | ссылка на прежний адрес ведёт на победителя, но архив теряет перенаправление навсегда: его находят только по новому имени |
| проигравший заархивирован **без** переименования (исход 3 §2.1) | переименование архива и передача имени победителю | архив меняет адрес; все внешние ссылки на него ломаются — цена ровно та, что названа в §2.2 |
| **шаг 3 пропущен: отправлена непривитая история** | вторая перепись и вторая отправка | посажено **894** вместо 961 молча — код возврата нулевой, вершина верная, а эры архива нет; заметить можно только счётом (сценарий 15) |
| **отправка сделана `--mirror` либо `--all`** | восстановление `ci-bootstrap` из страховочного клона шага 0 | если клона нет — **шесть файлов оснастки конвейера утрачены**: их нет ни у `main` службы, ни в `services/iam`. Плюс `--all` толкает служебные ветки замера (`base`, `archmain`) в чужой репозиторий |
| **перепись отправлена до снятия защиты** | ничего: отправка не состоится, `main` не изменится | потерян заход; ущерба нет — это единственное безобидное нарушение |
| **защита не восстановлена после отправки** | вернуть четыре поля вручную | окно, в котором `main` принимает переписи и удаление, — и оно не наблюдаемо ничем, кроме повторного вопроса к API |
| **перепись отправлена после публикации версии** | только выпуск следующей версии; прежняя **не отзывается** | коммит, названный псевдоверсией, недостижим: у потребителя `go mod download` отказывает, и починить это может лишь он сам, сменив пин |
| **`ci-bootstrap` снята или перезаписана** | восстановление из клона `--mirror`, снятого шагом 0 | если клона нет — работа шести файлов CI утрачена: её нет ни в `kaname/main`, ни в `services/iam` |
| раскол сделан из копии, отставшей от ствола | повторить раскол на вершине; сверить оба дерева (сценарии 10, 11) | заход; необратимого нет, пока не сделан шаг 5 |
| прививка забыта, перепись отправлена | вторая перепись | второе снятие защиты и второе окно риска ради 7 % коммитов (§5.3) |
| описание архива не поправлено | правка описания | пока не поправлено, документ организации утверждает о дереве неправду; цена — чужое время на переход по адресу, который ведёт не туда |

**Практическое следствие.** Необратим ровно один шаг — отправка переписанной истории.
Шаги 0–4 и 7 повторяемы сколько угодно и ничего не стоят; шаг 5 не бывает бесплатным
никогда, а после публикации первой версии службы становится вредным.

## 8. Остатки: чего эта приёмка НЕ решает

Каждый пункт — задачей, а не обещанием.

1. **Двенадцать незаархивированных зеркал прежнего полирепо** (сценарий 28). Класс тот же,
   что решён здесь для одного имени, и шире его: у каждого зеркала свой живой адрес и своё
   описание. Предмет назван телом задачи #1763 и там же оставлен нерешённым; заводить
   его отдельной задачей.
2. **Два утверждения `.claude/rulebook/polyrepo.md` пережили свой предмет** (§1.6):
   «существуют и не заархивированы» — заархивирован один; «последний push — середина июля
   2026» — два зеркала двигались в августе. Правка корпуса — работа воркспейса, не этой
   приёмки.
3. **652 файла воркспейса упоминают `kacho-iam`.** Переписывать их запрещено (§5.7). Но
   отделить **свидетельство** от **предписания** никто не пробовал: строка раскладки
   каталогов в `README.md` и путь в `tests/authz-fixtures/README.md` адресуют вперёд, а не
   свидетельствуют. Разбор — отдельная задача.
4. **У сценария 25 нет производителя, и половину его предмета уже кто-то держит.**
   «Розданное прокси не отзывается» проверяется только наблюдением. Ближайший предмет —
   задача продукта [#2230](https://github.com/PRO-Robotech/kacho/issues/2230) («выпуск:
   псевдоверсия платформы в `go.mod` может указывать на коммит вне всех ссылок», OPEN):
   она заказывает гейт достижимости коммита, названного псевдоверсией. Это **половина**
   сценария 25 — та, где коммит становится недостижимым от переписи. Вторая половина —
   необратимость самой раздачи прокси — предмета не имеет и иметь не может: у неё нет
   производителя ни в каком дереве. Круг 1 ссылался на «`KAN-RELEASE-1`, остаток 1» вместо
   номера, и по такой ссылке проверить покрытие было нельзя.
5. **Шести уникальным файлам `ci-bootstrap` преемник не назначен.** Оснастка конвейера
   службы (`.github/workflows/ci.yml` и пять файлов рядом) существует **в одной ветке
   одного репозитория** и не поглощена ни `main` службы, ни `services/iam`. Порядок §3.5
   велит ветку не трогать — это защита, а не решение: пока эти шесть файлов не переехали
   куда-то, где их видит перепись, всякая уборка веток `kaname` их уничтожит. Заводить
   задачей.
6. **Номер и форма первой версии службы** — предмет `KAN-RELEASE-1`, не этой приёмки. Здесь
   от неё нужен один факт: перепись истории идёт **до** первого тега (§3.4).
7. **Регистрация в ведомости приёмок продукта не требуется**: миграций приёмка не заводит.
   Названо, чтобы отсутствие записи не приняли за пропуск.

## 9. Определение готовности стадии

Нумерация 1:1 с шагами §3.5.

| # | шаг §3.5 | условие | предикат |
|---:|:---:|---|---|
| 1 | — | решение об имени исполнено | `gh api repos/PRO-Robotech/kacho-iam --jq .full_name` → `PRO-Robotech/kaname` **и** `gh repo view PRO-Robotech/kacho-iam-polyrepo-archive --json isArchived` → `true` |
| 2 | — | настройки победившего имени заведены | `gh api repos/PRO-Robotech/kaname --jq .delete_branch_on_merge` → `true`; `.../branches/main/protection` — не 404 и не 403 |
| 3 | 0 | клон `--mirror` снят, `ci-bootstrap` в нём есть | `git -C <клон> rev-parse --verify ci-bootstrap` резолвится |
| 4 | 1 | раскол сделан и **сверен по обоим деревьям** | `git rev-parse iamhist^{tree}` = `git rev-parse <ревизия>:services/iam` **и** `git rev-parse <корень>^{tree}` = `git rev-parse 5dbdbf6907:services/iam` |
| 5 | 2 | прививка сделана | `git rev-list --count iamhist` → **961**; самый ранний коммит датирован 2026-06-28 |
| 6 | 3 | замена **материализована** названным средством | `FILTER_BRANCH_SQUELCH_WARNING=1 git filter-branch -f -- <ветка>` → код 0, и `git --no-replace-objects rev-list --count <ветка>` даёт то же число, что и с заменами (**961**) |
| 7 | 5 | перепись посажена **одной названной ссылкой** | отправка сделана формой `<ветка>:refs/heads/main`; в журнале отправки нет ни `--mirror`, ни `--all`, ни `--delete`; в свежем клоне `git rev-list --count HEAD -- .` → **961** |
| 8 | 6 | защита ствола восстановлена | `gh api repos/PRO-Robotech/kaname/branches/main/protection --jq '[.enforce_admins.enabled,.allow_force_pushes.enabled,.allow_deletions.enabled]'` → `[true,false,false]` |
| 9 | 7 | содержимое не изменилось | дерево вершины в свежем клоне равно `services/iam` ствола той ревизии, из которой сделан раскол |
| 10 | 8 | `ci-bootstrap` цела | `git ls-remote --heads https://github.com/PRO-Robotech/kaname.git` называет `ci-bootstrap`; её значение равно снятому шагом 0, и шесть уникальных путей на месте |
| 11 | — | описание архива приведено к факту | в описании нет адреса `PRO-Robotech/kacho-iam` как имени живого продукта |
| 12 | — | задачи-преемники §8 (пп. 1, 2, 3, 5) заведены | номера названы в комментарии к #1763 |

**Число сверки объявляется вместе с ревизией и командой, а не одним числом.** Предикат
задачи требовал «866 при переносе»; он недостижим (§1.2, сценарий 12). Действующая форма:
**961** при расколе с прививкой от ревизии `a10bfd208d4dc556c2a4c75ec813edb60f350b5d`,
командой `git rev-list --count HEAD -- .` в свежем клоне; при расколе без прививки — **894**;
всякая другая ревизия ствола даёт другое число, и оно обязано быть названо вместе с ней.

**Что эта приёмка НЕ доказывает.** Она не исполняет ни одного действия наружу: репозиториев
не заводит, ничего не архивирует, истории не расщепляет и не отправляет. Раскол и прививка
проверены **исполнением в одноразовой копии**, поэтому числа §3 и §4 — замер, а не расчёт;
но посадка (шаг 5) не производилась, и сценарии 26, 27 остаются **непроверенными** до неё.
