## §2 Блокирующие — РОД, предикат, напечатанное

### Б1 · РОД: вход замысла обесценен — отображается снятая редакция перечня классов

§3 объявляет своим входом первичный разбор `304d545e…` («13 `LAX-*` + 2 сквозных», строка 31) и
строит таблицу из **15 строк**, завершая её утверждением **«Все 15 отображены. Неотображённых
пунктов нет»** (строка 819). Действующий разбор на действующий отпечаток приёмки —
`initial/b755886f….md`, и в нём **22 пункта**.

```
sed -n '70,91p' …/initial/b755886f….md | grep -c '^| \*\*'   → 22
sed -n '801,818p' <замысел>            | grep -c '^| \*\*'   → 15
```

Утверждение «неотображённых пунктов нет» **верно для перечня из 15 и ложно для действующего
перечня из 22**. Это не арифметика: замысел судит себя по снятой мерке, поэтому его собственный
предикат снятия (строка 93) не может обнаружить пропуск — он построен ровно с той слепотой, ради
которой заведён. Корень всех Б2–Б10 здесь.

**Что закрывает:** §3 перестроить на действующий разбор — 22 строки, каждая с именем пункта; и
заменить утверждение о полноте на то, что проверяется предикатом по ДЕЙСТВУЮЩЕМУ перечню.

### Б2 · РОД: опровергнутый пункт — два места об одном предмете внутри одного файла, одно ложно

`LAX-16` действующего разбора и Р13 п. 3 приёмки требуют **ровно одного** параметра в строке
запроса перенаправления — `error`, и требуют этого для 29 **и** для 06/07, где присланный `state`
был валиден. Замысел говорит об этом **дважды и по-разному**:

```
sed -n '595,596p' <замысел>
595 (M11): …несёт `error=invalid_request` и **ни `state`, ни описания**…
596 (M12): …в перенаправление уходят **только** `error` и `state`…
```

Приёмка, названная входом этого же замысла, на строке 451 (сценарий 29): «в перенаправление
уходит **только** `error`: ни `state` … ни описание отказа». Реализация, написанная по M12,
**покраснила бы сценарий 29 одобренной приёмки**, а реализация по M11 сделала бы M12 ложью.
Наблюдаемым владеет приёмка (`change-graph.md` §1) — значит ложна M12.

Замысел уже ловил себя на этом классе однажды (З9 отменяет правку «302 → 303» ровно потому, что
замысел разрешил расхождение с приёмкой в свою пользу и не назвал этого). Здесь тот же класс
уцелел в соседней строке той же таблицы.

### Б3 · РОД: единица счёта не объявлена там, где разбор прямо заказал её замыслу (`LAX-15` б)

Пол `state` — 22. **В чём 22** — в байтах или в кодовых точках — не сказано ни разу.

```
grep -c 'кодов' <замысел> → 8      grep -c 'байт' <замысел> → 12
```

Каждое из двадцати вхождений прочитано: все они о размере бинаря, о `minimumSecretLength = 32`,
о потолке тела, о строках `go.sum` — **ни одно не о единице счёта `state`**. Приёмка единицу
назвать не обязана и не называет: её основание числа (запись `BASE64URL` от 16 случайных байтов)
лежит в ASCII-алфавите, где различия нет. Разбор адресовал заказ прямо замыслу («единицу обязан
объявить замысел»), и это один из двух незакрытых пунктов «вернуть в приёмку».

**Почему блокирует:** на не-ASCII входе две законные реализации дают **разный исход на одном и том
же `Given`** сценариев 29/30. Проба, написанная по такому замыслу, не может быть ни красной, ни
зелёной — она меряет неназванное.

### Б4 · РОД: граница утверждена односторонне — вид сравнения и заказанный близнец отсутствуют (`LAX-15` г, `LAX-17`)

```
grep -nE 'не ниже|≥|длиннее пола' <замысел> → (пусто)
```

Не названо, что сравнение — **«не ниже» (≥)**, а не равенство и не диапазон; заказанного разбором
случая «`state` **ДЛИННЕЕ** пола» нет. Имеющиеся близнецы 29/30 (21 символ ↔ ровно 22) ловят
«только снизу» и «отвергает любой `state`», но **не** ловят реализацию «ровно 22»: она проходит
обе стороны имеющейся границы. Тождественность пороговой проверки на обеих сторонах (`LAX-17`)
замыслом не утверждается ничем.

### Б5 · РОД: свойство безопасности, не названное ни разу, не имеет и держателя (`LAX-19` в)

Некэшируемость ответа, несущего удостоверение, не упомянута:

```
grep -c 'no-store' → 0   'Cache-Control' → 0   'Pragma' → 0   'кэш' → 0
```

Полоса **браузерная**: ответ уезжает в кэш браузера и в кэш всякого посредника на пути. Образца в
дереве для браузерной полосы нет — заголовки проставляет только токен-эндпоинт (измерено первичным
разбором), приёмка о заголовках молчит, значит это **предмет замысла**, а не чужой. Ось задета
дважды: безопасность (удостоверение переживает вкладку) и узнаваемость — RFC 6749 §5.1 требует
`Cache-Control: no-store` на ответе, несущем удостоверение, и всякий клиент OAuth этого ждёт.

### Б6 · РОД: форма цели перенаправления сужена до частного случая (`LAX-19` б)

Параметры добавляются к **РАЗОБРАННОМУ** `R` с сохранением его собственной строки запроса — не
отображено.

```
grep -n 'строку запроса' <замысел> → 1 вхождение, строка 596, и оно о другом предмете
```

Валидатор целей (измерено первичным разбором) требует `https`, без фрагмента, ≤512 байт, ≤16
записей, без дубликатов — **собственную строку запроса не запрещает**. Значит буквальная форма
`R?code=…&state=…` (сценарий 02) верна не для всякого законного `R`, и конкатенация через `?`
даёт битый URL на законной цели. Это второй незакрытый пункт «вернуть в приёмку».

### Б7 · РОД: разводка координаты держится премисой, которую дерево опровергает (`LAX-18`, усл. 3)

§5.2, ось 1: «Это разные слушатели и **разные внешние адреса**». Измерено мной, не принято со слов:

```
git -C project/kacho  grep -ln 'kind: Ingress' f445aaaa554 -- 'deploy/**'
  → deploy/helm/umbrella/templates/api-gateway-ingress.yaml   (ровно ОДИН файл)
git -C project/kacho  show f445aaaa554:…/api-gateway-ingress.yaml
  → host api.kacho.local · path: / · pathType: Prefix · backend: api-gateway  (край)
git -C project/kaname ls-tree -r cbbac984 --name-only | grep 'deploy/.*ingress'
  → только docs/deploy/templates/ingress.yaml (сайт документации), ингресса выдачи — НЕТ
```

Внешний адрес **один**, и его правило — **префиксное** `/` на край. Следствий два, и оба против
замысла: браузерная достижимость `GET /iam/v1/authorize` существующим развёртыванием **не
обеспечена**, а обращение к бэрому пути по единственному внешнему имени уходит **на край**, то
есть не к тому предмету. Условие разбора — «правило маршрутизации развёртывания, называющее эту
координату, объявляется ТОЧНЫМ совпадением, а не префиксом» — в замысле отсутствует целиком:

```
grep -c 'нгресс' → 0   'ngress' → 0   'умбрелл' → 0   'маршрутизации развёртывания' → 0
```

§5.3 отвечает «Ломается: ничего. Число — 0» — и это верно **про отслеживаемые файлы** (я
перемерил, см. §3 ниже), и не говорит ничего про правило маршрутизации. Держатель у оси 1 не
«слабый», его **нет**: три названные оси различения (§5.2) разводят предмет на уровне слушателей
процесса и ни одной — на уровне развёртывания.

### Б8 · РОД: изменение, обязанное идти тем же заходом, не заказано (`LAX-18`, усл. 4)

Две существующие страницы-тёзки службы (`kaname@cbbac984`):

```
git -C project/kaname ls-tree -r cbbac984 --name-only | grep -i authorize
  → docs/content/api/authorize.mdx
  → docs/engineering/components/19-authorize.md
```

Обе описывают **проверку доступа**; после A-1 под тем же именем существует церемония. Разбор
требует, чтобы обе получили различающую строку **тем же изменением**. В замысле их нет:
`grep -c 'authorize.mdx'` → 0, `grep -c '19-authorize'` → 0. Полоса L10 заказывает страницу
арендатора о церемонии — это другой предмет: новая страница не делает старые две менее
двусмысленными.

### Б9 · РОД: проба паритета между двумя отказами не заказана (`LAX-20`); сверх того `LAX-4` сужен

Побайтовое равенство отказов 04 («цель не та») и 05 («клиента нет/снят») **между собой** не
названо:

```
grep -n 'побайтов' <замысел> → 3 вхождения (400, 812, 1021) — все о шести исходах сценария 24
```

Приёмка требует «не называет» **внутри каждого** сценария и равенства **между** ними не требует —
значит проба паритета есть предмет замысла. Пока её нет, различимый ответ остаётся оракулом
существования клиента.

Тем же родом сужен `LAX-4`: три названные разбором оси нормализации не перечислены
(`grep -c 'процентн'` → 0, `'порт по умолчанию'` → 0, `'нормализ'` → 0), и заказанного близнеца
«`R` с хвостовым слэшем» нет — три вхождения `'хвостов'` все о косой черте в шаблоне маршрута §5.
«Точное равенство исходных строк» без перечня осей, по которым равенство НЕ нормализуется, —
утверждение, которое реализация выполнит и нарушит одновременно.

### Б10 · РОД: запрет на две способные разойтись ветви не выражен (`LAX-14`)

«Не прислан» и «короче пола» обязаны проходить через **ОДНУ** проверку и давать **ОДИН** исход —
две ветви, способные разойтись, запрещены. Наружу исход один, **для нас** два факта обязаны
различаться счётчиком/журналом именно по `state` (паритет с Р10).

```
grep -n 'счётчик' <замысел> → 407, 812, 817 — все о сценарии 24 и сквозном-2
```

Приёмка называет **наблюдаемое** («обе ветви `When` дают один и тот же исход», строка 453);
механизм, которым это достигается, и различимость для нас — предмет замысла, и его здесь нет.

## §3 Числа замысла: воспроизводимы ли — перемерено МОИМ предикатом

Взято четыре числа, три воспроизвелись, одно разошлось.

| утверждение замысла | мой предикат | что напечатал | исход |
|---|---|---|---|
| §1.5: отслеживаемых файлов с `/iam/v1/authorize` — **13** в службе допуска | `git -C project/kaname grep -l '/iam/v1/authorize' cbbac984 \| wc -l` | **13 шт файлов** | **сошлось** |
| §1.5: то же на платформе — **6** | `git -C project/kacho grep -l '/iam/v1/authorize' f445aaaa554 \| wc -l` | **6 шт файлов** | **сошлось** |
| §1.5 / §5.3: бэрый путь без суффикса — **0 и 0** | `git grep -P '/iam/v1/authorize(?![:_A-Za-z])' <ствол> \| wc -l` по обоим | **0 шт и 0 шт вхождений** | **сошлось** |
| §1.3: «прежний предикат `grep -c 'Задокументированное исключение'` даёт сегодня **0**, действующий `grep -c '^sec-exception'` даёт **2**» | оба предиката по обеим копиям правил | **разошлось**, см. ниже | **расхождение** |

**Расхождение названо с обеими единицами счёта.** Предикат замысла — о файле `.claude/rules/security.md`,
но дерева он не называет, а копий у файла две:

| дерево | единица | `^sec-exception` | `Задокументированное исключение` |
|---|---|---:|---:|
| рабочая копия воркспейса, `cd688278` | записей-исключений **в строковой форме**, шт | **2** | **0** |
| worktree `tmp/wt-line-a-1`, `4ccca1d1` — то самое дерево, где лежит замысел | записей-исключений **в прозаической форме**, шт | **0** | **2** |

То есть в дереве, которое несёт сам замысел, его «действующий» предикат даёт **0**, а объявленный
им устаревшим — **2**, ровно наоборот. **Ответ (две записи-исключения, ни одна не покрывает две
браузерные поверхности) в обеих копиях один и тот же**, поэтому основание заказа H8 не рушится и
блокирующим это не становится. Неверна названная **единица с ревизией**: число о дереве названо
без имени дерева — и названо в том самом абзаце, который объявляет, что «единица и предикат
называются рядом с числом».

## §4 Пять требований к продукту — «нет» по двум осям

Проверка применена к решениям церемонии, а не к документу. §10 замысла проверяет по пяти осям
**форму внесения движка, разводку, гейт, отзыв семейства и S1** — и не проверяет по ним саму

| ось | вердикт | чем |
|---|---|---|
| производительность | да | числа §1.2 воспроизводимы по построению одним прибором; к блокирующим не относится |
| **безопасность** | **НЕТ** | Б5 (удостоверение кэшируемо — не сказано ни слова), Б7 (единственное правило маршрутизации префиксное и ведёт бэрый путь на край), Б9 (два отказа различимы между собой — оракул существования клиента) |
| инновационность | да | поддерево с заменённой обвязкой и разорванной цепочкой каркасов, держатель — 883 пробы апстрима до и после выреза |

|---|---|---|
| сам движок и **36** модулей его обвязки ушли из графа | **построением**: прямой импорт при `GOPROXY=off` не собирается | да |

## §6 Коллизия координаты авторизации — разведена ЧАСТИЧНО

| уровень разводки | чем разведена | проверяемо |
|---|---|---|
| контракт | бэрого `GET /iam/v1/authorize` не объявляет ни один RPC; четыре координаты ReBAC — `POST …:verb` | **да**, перемерено мной: 0 шт бэрых вхождений в обоих стволах |

## §7 Находки БЕЗ блокирующей силы (чинить тем же заходом, вердикта не меняют)

1. **§1.3 — число о дереве без имени дерева.** Разобрано в §3 выше: ответ верен в обеих копиях,

2. **Шапка (строка 30) утверждает, что приёмке нужен новый круг и новое внешнее событие — дерево

Порядок обязателен — п. 1 и п. 6 суть условия `change-graph.md` §4, остальное без них не имеет

1. **Запись `security-auditor`** о поверхности безопасности (21 находка) заведена в дереве, и §2а
   ссылается на прочитанный документ, а не на слова. Без неё §2а не судится (Б11).
2. **§3 перестроен на действующий разбор `b755886f…`** — 22 строки, каждая с именем пункта;
   утверждение о полноте заменено предикатом по действующему перечню (Б1).
3. **M12 приведена в согласие с M11, Р13 п. 3 и сценарием 29**: в перенаправление уходит **ровно
   один** параметр — `error`, и это верно для 29 **и** для 06/07 (Б2).
4. **Единица счёта пола `state` объявлена** (байты либо кодовые точки), сравнение названо «не
   ниже» (≥), заказан случай «`state` длиннее пола» (Б3, Б4).
5. **Внесены условиями:** некэшируемость ответа с удостоверением (Б5); добавление параметров к
   разобранному `R` с сохранением его строки запроса (Б6); побайтовое равенство 04 ↔ 05 с пробой
   (Б9); три оси нормализации `redirect_uri` и близнец с хвостовым слэшем (Б9); одна проверка —
   один исход для `state` плюс различимость счётчиком/журналом (Б10).
6. **Разводка доведена до уровня развёртывания** (Б7): названо, каким внешним именем и каким
   правилом маршрутизации браузер достигает церемонии, и что правило объявляется **точным**
   совпадением, а не префиксом; названы две страницы-тёзки и различающая строка в каждой,
   вносимая тем же изменением (Б8).
7. **§10 дополнен строками о самой церемонии** по пяти осям.

Правка замысла **сменит его отпечаток** — значит потребуются новая пересверка
`class-exposure-analyst` на новый отпечаток и новый вердикт по замыслу; настоящая запись
относится к отпечатку `1e287a16…` и на другие редакции не переносится (`change-graph.md` §2).
