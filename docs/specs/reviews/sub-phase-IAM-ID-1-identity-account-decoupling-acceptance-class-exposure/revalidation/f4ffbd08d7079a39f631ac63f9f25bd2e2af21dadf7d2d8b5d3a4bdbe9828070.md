## Решения, которые вносит замысел (дельта 46d03ba4 → f4ffbd08)

Механизм редакции 18 закрывает блокер go-implementer прежней редакции («формирование объекта у
края — держателя на когерентность нет», решение 4 разбора `46d03ba4`), назвав ИСТОЧНИК аккаунтной
оси. Из этого рождаются самостоятельные решения:

1. **Аккаунт гейта берётся из КОНТЕКСТА вызывающего, не из запроса.** Поле аккаунта в запрос не
   добавляется (§2.3, §1.5 соблюдены). Осей именования объекта две, из **разных источников**:
   аккаунтная — вывод из контекста; user-ось — поле запроса `user_id`.
2. **Объект гейта `v_get`/`v_list` = «членство (аккаунт_вызывающего, user)».** У scope_extractor
   двух записей каталога меняется не только `object_type` (`iam_user → iam_membership`), но и
   источник аккаунтной оси (не `from_request_field`, а вывод из контекста).
3. **Канал «контекста» для человека — явно выбранный аккаунт СЕССИИ**, не утверждение токена
   (В-7: `kaname_active_account`/`kaname_account_id` сняты) и не поле запроса. Форму транспорта
   называет приёмка **предфазы S3.1** (её ещё нет); для служебной учётки аккаунт единствен и
   собственный. Решение владельца зафиксировано в записи вердикта acceptance-reviewer на `f4ffbd08`
   (`owner_decision_recorded`).
4. **Реализация атомарна и КРОСС-ПОЛОСНА — один logical change-set, четыре полосы:** модель+каталог
   (kaname) · ветвь `resource_scope_edge` для `iam_membership` миграцией (kaname) · материализация
   кортежей области по членству реконсайлером (kaname, НЕ на синхронном create-path, ban #9) ·
   извлечение аккаунта из контекста + сборка объекта на крае (kacho gateway). Половина отнимает
   доступ (fail-closed).
5. **IAM-ID-1-31 получил отрицательный «вызывающий не член аккаунта» с положительным близнецом**
   (дельта один факт — членство); IAM-ID-1-57 — клаузу «контекст A/B = аккаунт вызывающего». Счёт
   §9.3 не изменён (клаузы, не новый номер).

**Что механизм НЕ назвал (несущее для полос edge и reconciler):** каким СТРОКОВЫМ идентификатором
адресуется authz-объект `iam_membership`. В дереве членство адресуется **непрозрачным `mbr-<17>`**
(`internal/domain/membership.go:8`), а реконсайлер строит объект как `fmt.Sprintf("%s:%s", fgaType,
objectID)` — **один** `objectID` (`reconcile/tuples.go:69`). Врезка говорит «край **собирает**
объект `iam_membership:(callerAccount, user)`» и «объект членства адресуется парой» — это либо
композитный ключ `<аккаунт>:<user>`, который реконсайлер обязан материализовать тем же ключом, либо
опорный `mbr-<id>`, который край (у которого БД нет) обязан **резолвить** из пары — то есть новый
синхронный вызов на пути запроса. Схема ключа не названа, и два прочтения материально различаются
(см. решения B1/B3 ниже).

## Чего измерить нельзя (доказательство на пункт, не число)

- **B1 — когерентность ключа authz-объекта edge↔reconciler.** Предиката нет: край собирает
  `objectID`, реконсайлер материализует `objectID`; структурная красная полоса (`3ea98e55`) читает
  только каталог и компилирует модель — реального `Check` на **материализованном** объекте членства
  она не исполняет. Значит расхождение ключа (край собрал `<аккаунт>:<user>`, реконсайлер
  материализовал `mbr-<id>`, или наоборот) проходит обе пробы и в рантайме даёт fail-closed —
  админу СВОЕГО аккаунта тоже отказ. Класс `security-hardening §«Разрыв, невидимый ни с одной
  стороны»`. Держатель — только проба, ставящая вопрос СКВОЗЬ край: реальный `Check` на реально
  материализованном членстве. Заказ integration-tester.
- **B3 — схема ключа не названа, и два прочтения дают разную полосную структуру.** Композит
  `<аккаунт>:<user>` → край собирает без резолва, но реконсайлер обязан ключевать ТЕМ ЖЕ композитом,
  а не `mbr-id` (два написания идентичности, `code-authoring §5.1`). Опорный `mbr-id` → край (без БД)
  обязан РЕЗОЛВИТЬ его из пары → **новый синхронный вызов kacho→kaname на пути запроса** = новое
  runtime-ребро (`polyrepo §runtime edges`: объявить, per-call deadline, fail-closed) = **новый
  пункт перечня → новая пересверка** (`change-graph.md` §4). Что выбрано — не измерить; обязано быть
  НАЗВАНО до кода полос edge и reconciler. Естественная реализация (реконсайлер по образцу `iam_user`
  ключует на `mbr-id`) ведёт к резолву; врезка-«собирает» тянет к композиту — это и есть неназванный
  стык.
- **A2 — пустой/невыбранный аккаунт сессии.** Красная полоса fail-closed на пустом контексте не
  проверяет (канала нет вовсе). Держатель — integration-tester: пустая сессия → отказ, hide-existence.
