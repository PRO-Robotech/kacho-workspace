## Решения, которые вносит замысел

1. **`LAX-1` шов `LoginAuthority` + интеграция своего входа** (Р1/Р2) — новый внутренний порт
   `LoginAuthority.Resolve(запрос) → (субъект, момент, уровень) | не-аутентифицирован`;
   производитель — наш вход (поведение — контракт **Ф1**, APPROVED и посажен).
2. **`LAX-2` эндпоинт авторизации `GET /iam/v1/authorize`** (Р2, 02–09, 23) — новый
   браузер-обращаемый **внешний** класс поверхности.
3. **`LAX-3` конфиденциальный клиент + PKCE S256 ВДОБАВОК** (Р3, 06/10/12) — две проверки на
   обмене, не одна.
4. **`LAX-4` точная сверка `redirect_uri`, отказ БЕЗ перенаправления** (Р4, 04/05) — защита от
   открытого перенаправления.
5. **`LAX-5` хранилище кода: одноразовость + срок на DB-уровне; связку назначает выдача** (Р5,
   14/17/26/27) — новая таблица, миграция, атомарное потребление, sentinel «ещё не использован».
6. **`LAX-6` перенос `acr` + момента: сессия → код → предъявитель; вердикт по полу — края**
   (Р6, 10/19).
7. **`LAX-7` шаг вверх через повторную аутентификацию на эндпоинте авторизации** (Р7, 08).
8. **`LAX-8` `refresh_token` с ротацией; повтор кода и повтор ротированного токена → отзыв
   СЕМЕЙСТВА на ПРЕДЪЯВЛЕНИИ** (Р8, 13/20/21/28) — новое хранилище семейства, ротация, отзыв.
9. **`LAX-9` ни один пол не понижен, ни одно решение о доступе не введено** (Р9) — отрицательный
   инвариант.
10. **`LAX-10` единый анти-оракульный тон после того, как назван код** (Р10, 24).
11. **`LAX-11` метаданные обнаружения — публичное неаутентифицированное чтение** (Р11, 22).
12. **`LAX-12` согласие первопартийного клиента ПРОПУСКАЕТСЯ** (Р12/4а, 09).
13. **`LAX-13` монтаж эндпоинтов на внешней поверхности выдачи и НИГДЕ больше** (23).

## Чего измерить нельзя

- **Церемония OAuth своими силами** (эндпоинт авторизации, хранилище кода, полосы
  `authorization_code`/`refresh_token`, эндпоинт обнаружения, порт `LoginAuthority`) — её кода
  ещё нет by construction (предикаты A–H = 0). Проверяется **пробами реализации** после
  APPROVED замысла, не замером дерева. Доказательство на пункт: §9 приёмки помечает каждый
  такой «Тогда» «заказан производитель», отсутствие ожидаемо (ban #1).
- **Достаточность гранулярности отсечки для семейства** — предикатом не измеряется: это
  свойство ПОВЕДЕНИЯ (переживает ли независимая сессия того же субъекта отзыв семейства).
  Устанавливается пробой с двумя конкурентными сессиями, а не грепом (заказ ниже).
- **Байтовая идентичность анти-оракульного тона** после именования кода — свойство исполнения
  шести исходов, не текста; ловится пробой сквозь все шесть (24), не поиском по образцу.

## Ребро `LoginAuthority` → вход Ф1 — направление и вид

- **Вид:** **внутрисервисный шов** внутри `kaname` (граница ceremony/login), НЕ кросс-доменное
  рантайм-ребро (оба конца в `kaname`), НЕ ребро сборки, НЕ новая внешняя поверхность.
- **Направление:** церемония (эндпоинт авторизации, **потребитель**) → `LoginAuthority.Resolve`
  → наш вход (поведение — **Ф1**, **производитель**). Однонаправлено: вход церемонию не зовёт
  обратно → ацикличность тривиально держится.
- **Статус основания:** **удовлетворённое**, не отложенная зависимость. Ф1 APPROVED
  (`7bdef287…`, круг 11, `ban1_lifted=true`, actor `pointpu`) и **посажена** (проверяющий
  пароля + хранилища на `kaname@dd66b5be`). A-1 строит церемонию поверх уже одобренного и
  посаженного входа; санкция на код входа — у Ф1 (ban #1), уже выдана.
- **Что НЕ заводится ребром:** приём предъявителя A-1 краем (18) переиспользует существующий
  приём нашего издателя (F1/F1b) и отсечку на предъявлении (`kacho@ac33f733`,
  `sessionCutoffCheck`) — **нового** кросс-доменного рантайм-ребра A-1 не вводит. Браузер →
  `GET /iam/v1/authorize` и `GET /.well-known/…` — новая **внешняя** поверхность (вызывающий —
  арендатор/браузер, не наш сервис), в перечне рантайм-рёбер не участвует
  (`polyrepo.md`, нота F2).
- **Для trail (vault):** записать как внутрисервисный шов `kaname` (ceremony→login, удовл.
  основание) — не заводить `edges/<caller>-to-<callee>` (обе стороны в одном сервисе).

## Вернуть в приёмку

**Блокирующих — нет.** Приёмка APPROVED в силе; разбор её не обесценивает. Две неточности —
**не-блокирующие**, для переноса в редакцию замысла/пересверку, не для переоткрытия приёмки:

1. **§1: «посадка бинарна: External \| Own»** — enum тернарный (`Unset \| External \| Own`).
   By-construction вывод («переходный поверх провайдера невыразим») держится, поэтому вердикт
   приёмки не затронут; премиса числа неточна.
2. **§7: отсечка «переиспользуется … сама не меняется»** — отсечка субъект-широкая; для отзыва
   семейства это либо достаточно (если субъект-широкий отзыв на replay — ЯВНОЕ решение), либо
   требует более тонкой гранулярности. Это решение замысла, а не дефект приёмки; пересверка
   обязана его отобразить в конкретное решение и закрыть заказом пробы выше.
