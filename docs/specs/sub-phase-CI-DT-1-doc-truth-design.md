# CI-DT-1 — замысел узкой правки пояснений

> Статус: DRAFT. Дата: 2026-09-17. Независимого design verdict нет.
> Приёмка: [CI-DT-1](sub-phase-CI-DT-1-doc-truth-acceptance.md).

## Измеренное основание

На продукте `b5fa093341f1fdbe96adfc6a9555482690968253` автор повторил
непустую Go selection: 71 RUN, 71 PASS, 0 FAIL, 0 SKIP, rc 0.
AST содержит `mountAllow`: 22 элемента; `knownInertCatalogRows`: 108;
JSON каталога содержит 341 строку, из них 108 с префиксом `kaname.`.
AST вызовов `add` даёт 19 разных литералов `Kind` и 21 место; анкерённые
команды из шапки дают то же множество. Это измерения этой ревизии, не новые
константы программы и не независимый acceptance RED.

Авторский опыт с настоящим `corelib/api/corelib/subscription.SubscriptionEvent{}`
показал: carrier descriptor содержит две ветви, `WhichOneof` возвращает nil,
`proto.Marshal` успешен и выдаёт 0 байтов. Следовательно, представимость пустого
экземпляра не выводится из двух ветвей. `AuditSubscriptionFormShape` читает
proto-файл и `SubscriptionShapeExpectation`, не экземпляр события. Этот опыт
не исследует runtime-валидацию и доставку.

## Решения и отображение сценариев

| Решение | Техническая граница | Сценарии |
|---|---|---|
| D1 | В двух комментариях переписи назвать существующие тесты-производители вместо сегодняшних чисел; commit-bound наблюдения оставить | CI-DT-01 |
| D2 | Уточнить шапку формы и только два `Reason` в ветвях `carrier-not-a-choice`; точные строки принадлежат приёмке | CI-DT-02, CI-DT-03, CI-DT-04, CI-DT-05 |
| D3 | Комментарий помощника ссылается на канонические единицы; тело helper и прежний опыт не меняются | CI-DT-06 |
| D4 | Сравнение программных токенов/AST и непустой существующий прогон, плюс узкий новый holder только для наблюдаемых диагностик | CI-DT-07 |
| D5 | Исправить тот же тезис в каноническом proto; получить generated комментарий штатными плагинами и доставить через версию corelib | CI-DT-08, CI-DT-09 |

Текущие Go файлы правки: `internal/repohygiene/grpcmountparity_test.go`,
`catalogreachability_test.go`, `subscriptionformshape.go`,
`subscriptionformshape_injection_test.go` в том же каталоге. Первые два и
последний меняются только комментариями. Никакой список исключений не обновляется
под замер: фактические значения только показывают ложность прежнего описания.

Два `Reason` — два результата, а не два Go string token: каждый собирается из
нескольких литералов. Сохраняются дерево конкатенаций, `e.CarrierOneof`,
`fmt.Sprintf`, `%d`, `len(branches)` и все нетекстовые узлы. Меняются только
значения строковых листьев именно этих двух выражений. Нельзя маскировать все
строковые литералы файла: это скрыло бы изменение `Kind` и других диагностик.

## Держатели и минимальные опыты

1. **Семантический review комментариев** сопоставляет точные прежние утверждения
   с AST/JSON census и одноразовым descriptor-опытом. Законный близнец — нынешний
   производитель переписи и текст, явно ограниченный формой. Историческое число
   на своей ревизии не признаётся ложным сегодняшним замером. Это human holder:
   общего парсера естественного языка не предлагается.
2. **Новый предлагаемый `TestSubscriptionShapeReasonContract`** в отдельном
   `internal/repohygiene/subscriptionreason_test.go` вызывает существующий
   `shapeAudit` на законной форме, отсутствии oneof и третьей ветви. Сравнивает
   полный `Reason`, `Kind` и координату; baseline обязан дать честный RED
   точных строк при GREEN законной формы. Пустой вход проверяет существующая
   `TestSubscriptionShapeRefusesAnEmptyRead`, не новый зеркальный тест.
3. **Независимое сравнение программ** читает оба SHA через Git и Go parser/scanner.
   У трёх файлов совпадают последовательности `(token, literal)` без комментариев
   и AST без source positions/comments. У анализатора сначала проверяются обе
   точные итоговые строки; затем для сравнения заменяются только согласованные
   строковые листья этих двух AST-выражений их прежними значениями. Итог обязан
   совпасть целиком. Тестовый новый файл учитывается отдельно, не исключается
   из actual diff. Пустой набор или parse error дают отсутствие доказательства.
   Это малый одноразовый verifier с захватом собственного исходника и digest,
   не новый framework продукта.
4. **Существующий регрессионный прогон** указан в holders.yaml. JSONL должен
   подтвердить RUN/PASS каждого выбранного теста, отсутствие SKIP и полноту
   ожидаемого множества по `go test -list`. Нынешние 71 — baseline этой ревизии,
   не фиксированный порог для будущего дерева. Census утверждений формы
   сравнивается на одном и том же входе, не с числом Kind или add-site.

Новые holders пока предложены. Авторские измерения не заменяют birth inversion
и независимый RED. Проверяющий инструмента сравнения предъявляет законную
comment-only пару, одно изменение программного токена и пустой/нечитаемый вход.
Только после этих опытов его результат eligible как machine evidence.

## Ограничения и история

Нового внешнего runtime-вызова, runtime-ветви, sentinel, схемы или асинхронного пути нет.
Предмет не требует запускать сеть/кластер либо дублировать поведенческие пробы
подписки. Окружение Go: `GOWORK=off`, `TMPDIR` вне любого Git checkout, у всех
child Git-команд удалены унаследованные переменные `GIT_*`.

Сохраняются исторические наблюдения `89242e6b`, `bdafe2c4`, `af0ca8f3`,
`94352d9c` в затронутых файлах и рассказ об ослеплении первой ветви. Старые
WATCH-1 и свидетельства #1439 не редактируются. Для #1439 установлены PR #2593,
commit `13bdec4175cac89bf02a200e5e9839ef57f3cb53`,
`obsidian/kacho/KAC/issue-1439.md` в workspace и

## D5 — канонический источник и зависимая поставка

Read-only API срез 2026-09-17: corelib main
`34bc8104a832b67e53c868646ab2b1e0ac4c8562`, Kachō потребляет `v1.8.0`.
В обоих corelib деревьях нет `.proto`; generated header указывает на
`corelib/subscription/subscription.proto`. Источник принадлежит Kachō
`proto/corelib/subscription/subscription.proto`, а не является копией corelib.
Обычная Kachō `proto/buf.gen.yaml` генерирует только вход `kacho` во избежание
дублирующей регистрации типов. Его `tools/foundationexport/.../emitStubs`
сохраняет всю декларацию плагинов, меняя только inputs на нейтральные контракты.

Полный `assemble-foundation-tree` на базе этой работы проверен: rc 1,
«к переезду не отобрано ни одного файла». Причина — источник пакетов уже вынесен;
это ограничение whole-tree exporter, не RED документации. Подменять им нынешнее
дерево corelib нельзя. Ремонт общего exporter не входит в эту правку комментария.

Минимальный исполнимый способ регенерации использует ту же операцию emitStubs:
из exact Git SHA материализовать `proto/`, `go.mod`, `go.sum` во внешний TMPDIR;
в временной `buf.gen.yaml` сохранить prefix до `inputs:` побайтово, поставить
единственный input `corelib/subscription`; выполнить `buf generate` из staged
`proto/`. Здесь нет копии алгоритма или ручного редактирования generated кода.
Базовый опыт уже выполнен: rc 0, ровно четыре следующих файла, каждый побайтово
совпадает с v1.8.0 и указанным corelib main:

- `api/corelib/subscription/subscription.pb.go`;
- `api/corelib/subscription/subscription_service.pb.go`;
- `api/corelib/subscription/subscription_service.pb.gw.go`;
- `api/corelib/subscription/subscription_service_grpc.pb.go`.

Это baseline генерации, не утверждение о ещё не сделанном diff. После approval
меняется только ложный абзац canonical proto. Независимый verifier повторяет
генерацию до/после: прогноз — comment-only diff первого файла, три других
побайтово равны, программные токены/AST всех четырёх и serialized raw descriptor
первого равны. При другом diff работа возвращается на review, его не нормализуют
под ожидание. Semantics descriptor сравниваются без source info; raw descriptor
generated Go должен быть побайтово равен. Ноль output или отказ buf не GREEN.

Corelib рабочая копия и release управляются root; автор этого пакета их не меняет.
Root интегрирует только сгенерированный файл, проверяет corelib и выпускает
версию. Она может быть общей с CI-NP-1, но evidence CI-DT-09 остаётся отдельным.
Затем Kachō штатно обновляет `go.mod`/`go.sum`, verifier с `GOWORK=off` проверяет
публикуемый архив и повторяет selection. Новая версия не выбирается автором
заранее. Независимый proto-api-review теперь применим: N/A для него не предлагается.
